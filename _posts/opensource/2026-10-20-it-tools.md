## 한 줄 요약

**JSON 포맷팅, Base64, JWT 디코딩, UUID 생성, 서브넷 계산 같은 자잘한 개발 도구 86개를 한 웹앱에 모은 프로젝트**입니다. 모든 처리가 브라우저 안에서 이뤄지고, Docker 한 줄로 사내망에 띄울 수 있다는 점이 핵심입니다.

## 어떤 문제를 푸나

개발하다 보면 이런 일이 하루에도 몇 번씩 생깁니다.

- 로그에 찍힌 JWT 안에 무엇이 들었는지 보고 싶습니다.
- 크론 표현식 `0 3 * * 1-5`가 정확히 언제 도는지 헷갈립니다.
- `docker run` 명령을 Compose 파일로 옮겨야 합니다.
- `10.0.0.0/22`에 호스트가 몇 개 들어가는지 계산해야 합니다.
- 테스트용 UUID 몇 개, 랜덤 문자열 하나가 필요합니다.

보통은 검색해서 나오는 아무 웹사이트에 붙여 넣습니다. 문제는 그 데이터가 **토큰, 설정 파일, 고객 정보**일 수 있다는 점입니다. 그 사이트가 입력값을 서버로 보내는지, 로그를 남기는지 알기 어렵습니다. 사이트마다 광고와 UI가 제각각인 것도 피곤합니다.

IT-Tools는 이런 도구를 **한 곳에, 같은 UI로, 클라이언트 측에서만** 동작하게 모았습니다. 공개 사이트를 써도 되고, 민감한 데이터를 다루는 팀이라면 사내에 직접 띄워(셀프 호스팅) 외부로 나갈 여지를 아예 없앨 수 있습니다.

## 핵심 개념

### 클라이언트 측 전용 앱

IT-Tools에는 백엔드가 없습니다. Vite로 빌드한 정적 파일(HTML, JS, CSS)을 nginx 같은 웹 서버가 내려 주면, 이후 계산은 전부 브라우저의 JavaScript가 처리합니다. 이슈 템플릿에도 "IT-Tools는 클라이언트 측 전용이고 서버가 없다"는 확인 항목이 있어서, 서버가 필요한 기능은 처음부터 받지 않는 방침입니다.

여기서 **클라이언트 측(client-side)**이란 입력한 데이터가 내 브라우저 메모리 안에서만 처리된다는 뜻입니다. 단, 몇 가지 예외와 주의점이 있으니 아래 "실무 팁"에서 따로 정리합니다.

### 도구 = 독립된 모듈

각 도구는 `src/tools/<도구이름>/` 폴더 하나입니다. 보통 이렇게 구성됩니다.

- `index.ts`: 이름, URL 경로, 설명, 검색 키워드, 아이콘을 `defineTool()`로 선언
- `<도구>.vue`: 화면
- `<도구>.service.ts`: 순수 로직 (테스트하기 쉽게 분리)
- `<도구>.service.test.ts`, `<도구>.e2e.spec.ts`: 단위 테스트와 Playwright E2E 테스트

`src/tools/index.ts`가 이 모듈들을 카테고리별로 묶습니다. 화면은 지연 로딩(`component: () => import(...)`)되므로 도구가 많아도 첫 화면은 가볍습니다.

### PWA

빌드에 `vite-plugin-pwa`가 들어 있어 **PWA(Progressive Web App)**로 설치할 수 있습니다. 브라우저에서 "앱 설치"를 누르면 별도 창으로 뜨고, 서비스 워커가 정적 파일을 캐시합니다.

## 동작 원리

```
 Browser
 ┌──────────────────────────────────────┐
 │ IT-Tools SPA (Vue 3 + Naive UI)      │
 │  router: /jwt-parser, /hash-text ... │
 │  tool.vue ──> tool.service.ts        │
 │  libs: crypto-js, bcryptjs,          │
 │        node-forge, jwt-decode ...    │
 │  localStorage: favorites, prefs      │
 └──────────────▲───────────────────────┘
                │ static files only
 ┌──────────────┴───────────────────────┐
 │ nginx (Docker image, port 80)        │
 │  /usr/share/nginx/html               │
 │  try_files $uri /index.html          │
 └──────────────────────────────────────┘
```

Docker 이미지는 2단계로 만들어집니다. Node 이미지에서 `pnpm build`로 정적 파일을 만들고, `nginx:stable-alpine` 이미지에 복사합니다. nginx 설정은 모든 경로를 `index.html`로 돌려보내는 SPA용 최소 구성입니다. 그래서 **런타임에 바꿀 수 있는 설정이 거의 없습니다.** 하위 경로 배포 같은 변경은 빌드할 때 정해야 합니다.

설정 코드에는 Plausible(쿠키를 쓰지 않는 방문 통계 도구) 연동이 있지만 기본값은 꺼져 있고, 빌드할 때 `VITE_TRACKER_ENABLED` 같은 환경 변수를 줘야 켜집니다. 릴리스 워크플로는 별도 빌드 인자 없이 `Dockerfile`을 빌드하고 `Dockerfile`에도 이 변수가 없으므로, 코드상으로는 공개 Docker 이미지에서 통계 수집이 꺼진 채 빌드됩니다. 공개 사이트(it-tools.tech)는 배포 환경 변수를 확인할 수 없으니, 민감한 환경이라면 셀프 호스팅한 뒤 브라우저 개발자 도구의 네트워크 탭으로 외부 요청이 없는지 한 번 확인해 보길 권합니다.

## 주요 기능

`main` 브랜치의 `src/tools/index.ts` 기준으로 10개 카테고리, 86개 도구가 있습니다. 대표적인 것만 추리면 다음과 같습니다.

| 카테고리 | 개수 | 대표 도구 |
|---|---|---|
| Crypto | 11 | Token generator, Hash text(MD5, SHA1, SHA256, SHA3 등), Bcrypt, UUIDs/ULID generator, Encrypt/decrypt text(AES, TripleDES, Rabbit, RC4), HMAC, RSA key pair, Password strength analyser, PDF signature checker |
| Converter | 20 | Date-time converter, Integer base converter, Base64 string/file, Color converter, Case converter, YAML/JSON/TOML/XML 상호 변환, Markdown to HTML |
| Web | 16 | URL encoder/parser, Escape HTML entities, JWT parser, Basic auth generator, Open graph meta generator, OTP code generator, MIME types, User-agent parser, HTTP status codes, JSON diff |
| Images and videos | 4 | QR Code generator, WiFi QR Code generator, SVG placeholder, Camera recorder |
| Development | 14 | Git cheatsheet, Crontab generator, JSON prettify/minify, JSON to CSV, SQL prettify, Chmod calculator, Docker run to Docker compose converter, XML/YAML formatter, Regex tester |
| Network | 6 | IPv4 subnet calculator, IPv4 address converter, IPv4 range expander, MAC address lookup/generator, IPv6 ULA generator |
| Math | 3 | Math evaluator, ETA calculator, Percentage calculator |
| Measurement | 3 | Chronometer, Temperature converter, Benchmark builder |
| Text | 7 | Lorem ipsum, Text statistics, Emoji picker, String obfuscator, Text diff, ASCII Art Text |

공개 사이트는 `main`을 기준으로 배포되는 것으로 보이며, Docker `latest`(2024-10-22 빌드)에는 이후 추가된 일부 변경이 빠져 있을 수 있습니다.

그 밖의 편의 기능입니다.

- **검색 팔레트:** `Ctrl + K`(macOS는 `Cmd + K`)로 도구 이름이나 키워드를 검색해 바로 이동합니다.
- **즐겨찾기:** 자주 쓰는 도구를 고정하고 드래그로 순서를 바꿉니다. 목록은 브라우저 localStorage에 저장됩니다.
- **도구별 고유 URL:** `https://it-tools.tech/jwt-parser`, `/crontab-generator`처럼 각 도구에 주소가 있어서 북마크하거나 팀 위키에 링크하기 좋습니다.
- **다국어:** 영어, 프랑스어, 독일어, 스페인어, 중국어 등 9개 언어 파일이 있습니다. 한국어 번역은 없습니다.
- **다크 모드**를 지원합니다.

[it-tools.tech](https://it-tools.tech)에 접속하면 끝입니다. 회원가입이나 설치가 필요 없습니다.

### 2) Docker로 셀프 호스팅

README에 있는 명령 그대로입니다. Docker Hub와 GitHub Container Registry 두 곳에 이미지가 있고, `linux/amd64`, `linux/arm64`를 모두 지원하므로 라즈베리파이 같은 ARM 홈랩에서도 돌아갑니다.

```bash
# Docker Hub
docker run -d --name it-tools --restart unless-stopped \
  -p 8080:80 corentinth/it-tools:latest

# GitHub Packages
docker run -d --name it-tools --restart unless-stopped \
  -p 8080:80 ghcr.io/corentinth/it-tools:latest
```

브라우저에서 `http://localhost:8080`을 열면 됩니다. README는 이 밖에 Cloudron, Tipi, Unraid 앱 스토어도 안내합니다.

이미지 태그는 이렇게 되어 있습니다(2026-10-20 Docker Hub 기준).

| 태그 | 마지막 갱신 | 내용 |
|---|---|---|
| `latest`, `2024.10.22-7ca5933` | 2024-10-22 | 마지막 정식 릴리스 |

nightly 워크플로는 매일 돌지만 최근 24시간 안에 커밋이 없으면 건너뛰기 때문에, 커밋이 멈춘 지금은 사실상 갱신되지 않습니다.

### 3) 소스에서 빌드

```bash
git clone https://github.com/CorentinTh/it-tools.git
cd it-tools
corepack enable      # package.json의 pnpm@9.11.0 사용
pnpm install
pnpm dev             # 개발 서버 (기본 http://localhost:5173)
```

저장소의 `.nvmrc`는 Node 18.18.2를 가리킵니다. 빌드 스크립트는 타입 검사(`vue-tsc`)를 먼저 돌리고 `NODE_OPTIONS=--max_old_space_size=4096`으로 메모리를 넉넉히 잡으므로, 메모리가 작은 CI 러너에서는 빌드가 실패할 수 있습니다.

## 실전 예제

### 예제 1: 사내망에 Docker Compose와 리버스 프록시로 띄우기

팀 공용으로 쓰려면 Compose로 관리하고 앞에 HTTPS 프록시를 두는 구성이 무난합니다. 아래는 Caddy를 예로 든 구성입니다.

```yaml
# compose.yaml
services:
  it-tools:
    image: corentinth/it-tools:2024.10.22-7ca5933   # 태그 고정
    restart: unless-stopped
    expose:
      - "80"

  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "443:443"
      - "80:80"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data

volumes:
  caddy-data:
```

```
# Caddyfile
tools.internal.example.com {
    tls internal
    reverse_proxy it-tools:80
}
```

```bash
docker compose up -d
curl -kI https://tools.internal.example.com
```

- `tls internal`은 Caddy가 자체 CA로 인증서를 발급하는 설정입니다. 사내 CA나 공인 도메인이 있다면 그쪽으로 바꾸세요.
- **HTTPS가 생각보다 중요합니다.** Camera recorder처럼 카메라를 쓰는 기능이나 클립보드 복사, 서비스 워커(PWA)는 브라우저가 보안 컨텍스트(HTTPS 또는 localhost)에서만 허용하는 경우가 많습니다. `http://내부IP:8080`으로 접속하면 일부 기능이 조용히 동작하지 않을 수 있습니다.
- 앱 자체에 로그인 기능이 없습니다. 접근 제한이 필요하면 프록시 단에서 Basic 인증이나 SSO(예: oauth2-proxy)를 붙입니다.

### 예제 2: 하위 경로(`/tools/`)에 배포하기

`https://intra.example.com/tools/`처럼 하위 경로에 두고 싶다면, 공개 이미지로는 안 되고 **빌드할 때 `BASE_URL`을 지정**해야 합니다. `vite.config.ts`가 `process.env.BASE_URL`을 Vite의 `base` 옵션으로 쓰기 때문입니다.

```bash
# 끝의 슬래시까지 포함해서 지정
BASE_URL=/tools/ pnpm build
ls dist/   # index.html, assets/ ...
```

nginx에서는 이렇게 서빙합니다.

```nginx
location /tools/ {
    alias /srv/it-tools/dist/;
    try_files $uri $uri/ /tools/index.html;
}
```

Docker 이미지로 만들고 싶다면 저장소의 `Dockerfile` 빌드 단계에 `ENV BASE_URL=/tools/`를 추가하고, `nginx.conf`도 위처럼 바꿔서 직접 빌드합니다. PWA 아이콘 등 일부 경로는 `/`로 시작하게 하드코딩되어 있어서, 하위 경로에서는 아이콘이 깨질 수 있습니다. 가능하면 `tools.example.com`처럼 서브도메인을 쓰는 편이 깔끔합니다.

### 예제 3: 장애 대응 중 자주 쓰는 조합

새벽 배치가 실패했다는 알림을 받았다고 해 봅시다. IT-Tools만으로 확인할 수 있는 것들입니다.

1. **Crontab generator**에 `0 3 * * 1-5`를 넣으면 "At 03:00 AM, Monday through Friday"처럼 사람이 읽는 설명(cronstrue 라이브러리)이 나옵니다. 서버 시간대가 UTC라면 한국 시간으로는 정오라는 점도 이때 같이 떠올립니다.
2. **Date-time converter**에 로그의 Unix 타임스탬프(`1760929200`)를 넣어 ISO 8601, UTC, 로컬 시간으로 바꿔 봅니다.
3. **JWT parser**에 API 호출에 쓴 토큰을 넣고 `exp` 클레임이 이미 지났는지 확인합니다. 클레임마다 설명과 사람이 읽기 쉬운 날짜가 같이 표시됩니다.
4. **IPv4 subnet calculator**에 `10.20.0.0/22`를 넣어 네트워크 주소, 브로드캐스트 주소, 사용 가능한 호스트 범위를 확인합니다. 방화벽 규칙에 새 서버 IP가 포함되는지 볼 때 유용합니다.
5. **Chmod calculator**로 `640`이 `rw-r-----`인지 확인하고 `chmod 640 파일` 명령을 복사합니다.

같은 확인을 터미널에서 할 수도 있습니다. 결과를 교차 검증할 때 참고하세요.

```bash
# Unix 타임스탬프 → 날짜 (GNU date / macOS date)
date -u -d @1760929200
date -u -r 1760929200

# JWT payload만 디코딩 (서명 검증 아님)
echo "$JWT" | cut -d. -f2 | tr '_-' '/+' | base64 -d 2>/dev/null; echo
```

> JWT parser는 `jwt-decode` 라이브러리로 **헤더와 페이로드를 디코딩만** 합니다. 서명이 올바른지는 검증하지 않으니, "토큰이 위조되지 않았다"는 확인 용도로 쓰면 안 됩니다.

### 예제 4: Encrypt / decrypt text 결과를 OpenSSL로 풀기

Encrypt/decrypt text 도구는 내부적으로 `crypto-js`의 비밀번호(passphrase) 방식 암호화를 씁니다. AES로 암호화하면 `U2FsdGVkX1`로 시작하는 Base64 문자열이 나오는데, 이는 OpenSSL의 `Salted__` 헤더를 Base64로 인코딩한 모양입니다. 그래서 OpenSSL로도 복호화할 수 있습니다. 아래 명령은 이 글을 쓰면서 crypto-js 4.x와 OpenSSL 3으로 직접 확인했습니다.

```bash
# 도구의 기본 예시 암호문과 기본 키("my secret key")
echo 'U2FsdGVkX1/EC3+6P5dbbkZ3e1kQ5o2yzuU0NHTjmrKnLBEwreV489Kr0DIB+uBs' \
  | openssl enc -d -aes-256-cbc -md md5 -a -A -pass pass:'my secret key'
# => Lorem ipsum dolor sit amet
```

OpenSSL이 "deprecated key derivation used" 경고를 띄우는데, 이것이 바로 이 방식의 한계입니다. 키 유도에 MD5 한 번만 쓰는 오래된 방식(EVP_BytesToKey)이라 무차별 대입에 약합니다. 메모를 잠깐 가리는 정도로만 쓰고, **실제 비밀 정보 보호에는 age, GPG, 또는 PBKDF2/Argon2를 쓰는 도구**를 쓰세요.

### 예제 5: 나만의 도구 추가하기

팀에서 자주 쓰는 변환기를 직접 넣을 수 있습니다. 예를 들어 바이트 수를 KB/MB/GiB로 바꿔 주는 도구를 만들어 보겠습니다. 먼저 스캐폴딩 스크립트를 실행합니다.

```bash
pnpm run script:create:tool byte-size-formatter
```

이 스크립트(`scripts/create-tool.mjs`)는 `src/tools/byte-size-formatter/`에 `index.ts`, `.vue`, `.service.ts`, 단위 테스트, E2E 테스트 파일을 만들고, `src/tools/index.ts` 상단에 import 줄을 추가합니다. **카테고리 배열에 넣는 것은 직접 해야** 화면에 나타납니다.

로직은 서비스 파일에 둡니다.

```ts
// src/tools/byte-size-formatter/byte-size-formatter.service.ts
export function formatBytes(bytes: number, { binary = false } = {}): string {
  if (!Number.isFinite(bytes) || bytes < 0) {
    throw new Error('Invalid byte value');
  }
  const base = binary ? 1024 : 1000;
  const units = binary
    ? ['B', 'KiB', 'MiB', 'GiB', 'TiB']
    : ['B', 'kB', 'MB', 'GB', 'TB'];
  let value = bytes;
  let i = 0;
  while (value >= base && i < units.length - 1) {
    value /= base;
    i++;
  }
  return `${Number(value.toFixed(2))} ${units[i]}`;
}
```

```ts
// src/tools/byte-size-formatter/byte-size-formatter.service.test.ts
import { describe, expect, it } from 'vitest';
import { formatBytes } from './byte-size-formatter.service';

describe('formatBytes', () => {
  it('formats decimal units', () => {
    expect(formatBytes(1500)).toBe('1.5 kB');
  });
  it('formats binary units', () => {
    expect(formatBytes(1073741824, { binary: true })).toBe('1 GiB');
  });
});
```

화면은 기존 도구(Slugify string 등)와 같은 공용 컴포넌트를 씁니다. `ref`, `computed`는 자동 import 설정 덕분에 따로 가져오지 않아도 됩니다.

```vue
<!-- src/tools/byte-size-formatter/byte-size-formatter.vue -->
<script setup lang="ts">
import { formatBytes } from './byte-size-formatter.service';
import { withDefaultOnError } from '@/utils/defaults';

const input = ref('1073741824');
const decimal = computed(() =>
  withDefaultOnError(() => formatBytes(Number(input.value)), ''));
const binary = computed(() =>
  withDefaultOnError(() => formatBytes(Number(input.value), { binary: true }), ''));
</script>

<template>
  <div>
    <c-input-text v-model:value="input" label="Bytes" placeholder="e.g. 1073741824" mb-5 />
    <c-input-text :value="decimal" label="Decimal (SI)" readonly mb-5 />
    <c-input-text :value="binary" label="Binary (IEC)" readonly />
  </div>
</template>
```

마지막으로 `src/tools/index.ts`의 원하는 카테고리(예: `Converter`)의 `components` 배열에 `byteSizeFormatter`를 추가하고 확인합니다.

```bash
pnpm dev     # http://localhost:5173/byte-size-formatter
pnpm test    # vitest 단위 테스트
pnpm lint
```

원본 저장소는 PR이 거의 병합되지 않는 상태라, 지금은 **사내 포크에 넣어 직접 빌드**하는 용도로 생각하는 편이 현실적입니다. GPL-3.0이므로 수정본을 외부에 배포한다면 소스 공개 의무도 함께 따져 봐야 합니다.

## 실무 팁 & 자주 겪는 문제

**보안과 개인정보**

- **Token generator는 암호학적으로 안전한 난수를 쓰지 않습니다.** 소스를 보면 `Math.random()` 기반 셔플로 문자열을 만듭니다. 테스트 데이터에는 충분하지만 API 키, 비밀번호, 시크릿에는 `openssl rand -base64 32`나 `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`를 쓰세요. `main` 브랜치 코드 기준으로 기본 알파벳에 대문자 `N`과 소문자 `n`이 빠져 있는 점도 눈에 띕니다.
- **입력값이 브라우저에 남을 수 있습니다.** JSON prettify 도구는 입력한 JSON을 localStorage(`json-prettify:raw-json`)에 저장하고, Regex tester는 정규식을 URL 쿼리나 localStorage에 남깁니다. 공용 PC에서 민감한 데이터를 넣었다면 사이트 데이터를 지우세요.
- 클라이언트 측 처리라도 **공개 사이트의 코드는 언제든 바뀔 수 있습니다.** 정말 민감한 데이터를 다루는 팀이라면 특정 태그로 고정한 이미지를 사내에 띄우는 것이 원칙적으로 더 안전합니다.
- Hash text는 MD5, SHA1도 제공합니다. 무결성 확인용 체크섬으로는 괜찮지만 비밀번호 저장용 해시로는 쓰면 안 됩니다. 비밀번호에는 Bcrypt 도구 쪽이 맞습니다.

**배포와 운영**

- 컨테이너가 떴는데 빈 화면이 나오면 리버스 프록시가 `/assets/...` 요청을 다른 곳으로 보내고 있지 않은지 확인합니다. 하위 경로 배포라면 예제 2처럼 다시 빌드해야 합니다.
- 업데이트했는데 화면이 그대로라면 PWA 서비스 워커 캐시 때문일 수 있습니다. 강력 새로고침을 하거나 개발자 도구에서 서비스 워커를 해제합니다.
- 오래된 이미지라 기반 nginx와 JS 의존성에 알려진 취약점이 쌓였을 수 있습니다. 보안 스캐너(Trivy 등)가 경고를 낸다면 소스에서 최신 베이스 이미지로 다시 빌드하는 것을 검토하세요. 저장소에는 `renovate/npm-*-vulnerability` 같은 의존성 보안 업데이트 브랜치가 여럿 있지만 병합되지 않은 상태입니다.

**사용 팁**

- 도구가 86개라 메뉴에서 찾기보다 `Ctrl/Cmd + K` 검색이 훨씬 빠릅니다. 키워드 검색이라 "base64", "uuid", "cron"처럼 영어로 치는 편이 잘 맞습니다.
- 팀 위키의 "자주 쓰는 링크"에 도구별 URL(`/jwt-parser`, `/ipv4-subnet-calculator` 등)을 정리해 두면 온보딩 때 유용합니다.
- Docker run to Docker compose converter는 composerize 라이브러리를 씁니다. 복잡한 옵션은 누락되거나 다르게 변환될 수 있으니 결과를 꼭 검토하세요.

## 비슷한 도구와 비교

아래 비교에서 라이선스와 저장소 활동은 GitHub에서 확인한 값이고, 기능 설명은 각 도구의 일반적으로 알려진 특성을 바탕으로 한 개략적인 정리입니다. 세부 기능은 바뀔 수 있으니 각 프로젝트에서 확인하세요.

| 항목 | IT-Tools | DevToys | CyberChef | transform.tools |
|---|---|---|---|---|
| 형태 | 웹앱 (PWA), Docker 셀프 호스팅 | 데스크톱 앱 | 웹앱 (단일 HTML로도 배포) | 웹앱 |
| 처리 위치 | 브라우저 | 로컬 앱 | 브라우저 | 대부분 브라우저 |
| 강점 | 넓은 범위의 일상 도구, 깔끔한 UI | OS에 통합된 오프라인 도구, 확장 기능 | 여러 연산을 "레시피"로 연결, 보안/포렌식 분석 | JSON을 TypeScript 타입, 스키마 등 코드로 변환 |
| 도구 연결 | 도구별 독립 | 도구별 독립 | 체인 구성 가능 | 변환 1회 |
| 셀프 호스팅 | Docker 한 줄 | 해당 없음 (로컬 설치) | 정적 파일 배포 | 정적 배포 가능 |
| 저장소 활동 (2026-10 확인) | 2024-10 이후 사실상 정체 | 최근 push 있음 | 최근 push 있음 | 최근 push 있음 |
| 라이선스 | GPL-3.0 | MIT | Apache 2.0 | MIT |

- **DevToys**는 설치형 데스크톱 앱이라 브라우저 탭을 열 필요가 없고 완전히 오프라인입니다. 개인 PC에 설치가 자유롭다면 좋은 대안입니다. 반대로 팀 전체에 URL 하나로 배포하기에는 IT-Tools가 편합니다.
- **CyberChef**는 "Base64 디코딩 후 gzip 해제 후 16진수 덤프"처럼 여러 단계를 이어 붙이는 데 강합니다. 보안 분석, CTF, 포렌식에서는 CyberChef가 한 수 위입니다. 대신 UI가 복잡해서 가벼운 일상 작업에는 IT-Tools가 빠릅니다.
- **transform.tools**는 JSON을 TypeScript 인터페이스, Go 구조체, Zod 스키마 등으로 바꾸는 "코드 생성형 변환"에 특화되어 있습니다. IT-Tools는 데이터 포맷 간 변환(YAML, JSON, TOML, XML)은 있지만 코드 타입 생성은 없습니다.

## 장점과 한계

**장점**

- 86개 도구가 같은 UI, 같은 검색창 아래 모여 있어 찾고 쓰기가 빠릅니다.
- 서버 없이 브라우저에서만 처리하므로 셀프 호스팅하면 데이터가 외부로 나갈 여지가 매우 적습니다.
- Docker 한 줄, amd64/arm64 지원으로 홈랩이나 사내망 배포가 쉽습니다.
- 도구 하나가 폴더 하나인 구조와 스캐폴딩 스크립트 덕분에 사내 전용 도구를 추가하기 쉽습니다.
- PWA, 다크 모드, 즐겨찾기, 도구별 URL 등 일상 사용 편의가 잘 갖춰져 있습니다.

**한계**

- **유지보수가 사실상 멈췄습니다.** 마지막 릴리스가 2024년 10월이고 PR과 이슈가 처리되지 않고 있습니다. 버그나 의존성 취약점이 생겨도 원본에서 고쳐 줄 가능성은 낮습니다.
- **일부 도구의 보안 성질을 오해하기 쉽습니다.** Token generator는 CSPRNG가 아니고, JWT parser는 서명을 검증하지 않으며, 텍스트 암호화는 오래된 키 유도 방식을 씁니다. "보안 도구처럼 보이지만 편의 도구"라는 점을 알고 써야 합니다.
- 런타임 설정이 거의 없어서 하위 경로 배포, 기본 언어 변경, 도구 숨기기 같은 맞춤은 대부분 소스 수정과 재빌드가 필요합니다.
- 인증, 사용자 관리 기능이 없습니다. 접근 제어는 프록시 등 외부에서 해결해야 합니다.
- 한국어 UI가 없습니다.
- 도구 간 연결(파이프라인)이 없어서 여러 단계 변환은 복사, 붙여넣기를 반복해야 합니다.

## 이런 분께 추천

- 민감한 데이터를 아무 웹사이트에 붙여 넣는 습관을 팀 차원에서 없애고 싶은 분
- 홈랩이나 사내 인프라에 "개발자 공용 도구 포털"을 가볍게 하나 두고 싶은 분
- JSON, YAML, Base64, 타임스탬프, 서브넷 계산처럼 자잘한 변환을 자주 하는 백엔드, 인프라 엔지니어
- Vue 3 프로젝트 구조를 참고하거나, 사내 전용 변환 도구를 빠르게 붙여 보고 싶은 프런트엔드 개발자

## 이런 경우엔 다른 도구

- 꾸준한 업데이트와 새 도구가 중요하다면 활발히 갱신되는 커뮤니티 포크(예: [sharevb/it-tools](https://github.com/sharevb/it-tools))를 검토하되, 관리 주체와 변경 이력을 직접 확인하세요.
- 여러 단계 디코딩, 보안 분석이 주 용도라면 **CyberChef**가 맞습니다.
- 브라우저 없이 완전히 오프라인인 개인용 도구를 원한다면 **DevToys**가 편합니다.
- JSON에서 타입 정의나 스키마 코드를 생성하는 일이 많다면 **transform.tools**가 낫습니다.
- 실제 비밀 값을 만들거나 암호화하는 일은 웹 도구 대신 `openssl`, `age`, `gpg`, 비밀 관리 도구(Vault 등)로 처리하세요.

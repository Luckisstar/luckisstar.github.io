# [오픈소스 소개] REA: AI 에이전트로 무엇이든 리버스 엔지니어링하기

- **저장소:** [morluto/rea](https://github.com/morluto/rea) · [공식 사이트 rea.tools](https://rea.tools/) · [npm: rea-agents](https://www.npmjs.com/package/rea-agents)
- **라이선스:** MIT
- **언어:** TypeScript (Node.js 22.19+ / 24.11+ / 26+)
- **현황 (2026-10-20 기준):** GitHub 스타 약 33.7만 개, 포크 약 8.5만 개, 최신 릴리스 v6.7.0 (10월 18일)

## 한 줄 요약

**"마음에 드는 앱 기능을 보면, 그 기능이 어떻게 동작하는지 바이너리 수준까지 파헤친다."**
REA(Reverse Engineer Anything)는 Claude Code, Codex 같은 AI 에이전트가 소스 코드 없이도 앱을 분석할 수 있게 해주는 **MCP 서버 + CLI 도구**입니다.

## 무엇을 해주나

AI 에이전트에게 이렇게 요청하면 됩니다.

```text
Notes 앱에서 검색 기능이 어떻게 동작하는지 알아내고, 근거를 보여준 다음,
내 프로젝트에 비슷한 기능을 만들어줘.
```

에이전트는 REA를 통해 다음 순서로 작업합니다.

1. 대상 앱을 검사합니다.
2. 관련 코드를 추적합니다.
3. 결과를 **근거(evidence)와 한계점**과 함께 돌려받습니다.
4. 이를 바탕으로 동작을 설명하거나, 비슷한 기능을 직접 구현하고 테스트합니다.

**모든 분석은 로컬에서 실행됩니다.** 다만 분석 결과는 에이전트에게 전달되므로, 그 결과에는 해당 AI 모델 제공사의 데이터 정책이 적용됩니다.

## 동작 방식

```
에이전트 ──(MCP)──▶ REA ──▶ 분석 도구 (Hopper / Ghidra / IDA / JADX / 브라우저 등)
   ▲                                  │
   └──── 코드, 참조, 근거, 모르는 부분 ◀─┘
```

- 에이전트는 MCP(Model Context Protocol)로 REA의 도구를 호출합니다.
- 터미널에서 CLI로도 같은 기능을 쓸 수 있습니다.
- 바이너리 같은 네이티브 분석에는 이미 설치된 **Hopper, Ghidra, IDA** 중 하나를 사용합니다. Hopper는 설치 과정에서 사용자 승인을 받아 자동으로 설치할 수도 있습니다.
- JavaScript/Electron이나 .NET 정적 분석은 별도 분석 엔진 없이 동작합니다.

## 분석할 수 있는 대상

지원 범위가 매우 넓습니다. 주요 대상만 추리면 다음과 같습니다.

| 대상 | 얻을 수 있는 결과 | 필요한 것 |
|---|---|---|
| 네이티브 바이너리 | 의사코드, 어셈블리, 문자열, 심볼, 호출·참조 관계 | Hopper, Ghidra, IDA 중 하나 |
| JavaScript / Electron | 모듈, import, 소스맵, 라우트, IPC, 네이티브 애드온 관계 | Node.js, npm |
| 웹사이트 | 페이지 구조, 스크립트, 네트워크 요청, 스크린샷 | Chrome 계열 브라우저 |
| .NET 어셈블리 | 메타데이터, CIL 명령, 네이티브 의존성 | 없음 (정적 분석) |
| Android APK | 매니페스트, 클래스, 디컴파일된 메서드 | JADX, JDK |
| Go / Rust 바이너리 | 컴파일러 버전, 모듈·크레이트 의존성 정보 | 없음 (내장 기능) |
| Unity IL2CPP, Godot PCK | 타입·메서드 이름, 아카이브 목록 | 없음 (내장 기능) |
| 네트워크 캡처 (HAR, pcap) | 요청·응답, DNS, TLS SNI, 프로토콜 분포 | 대상에 따라 TShark 등 |
| 펌웨어 | 영역 분석, 추출 결과 | Binwalk / Unblob (Linux) |
| 그 밖에 | SQLite DB, WASM, EVM 바이트코드, Flutter 앱, 크래시 기록 등 | 대상별로 다름 |

## 빠르게 시작하기

**1. 에이전트에 연결하기**

```bash
npx rea-agents setup
```

- 사용할 에이전트를 고르고, 변경 내용을 확인한 뒤 승인하면 됩니다.
- REA MCP 서버와 작업 지침(skill)이 등록되고, 기존 설정은 백업됩니다.
- 설정이 끝나면 에이전트를 재시작하세요.
- 지원 에이전트: Claude Code, Codex, Cursor, Gemini CLI, Grok Build 등

**2. 터미널에서 바로 써보기 (Electron 앱 분석 예시)**

```bash
npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json
```

**3. CLI 설치와 업데이트**

```bash
npm install --global rea-agents
rea --help
rea update   # 업데이트가 잦으니 자주 실행하는 것을 권장
```

## 사례 (Showcases)

- **DX-Ball:** 게임의 사운드 좌우 위치 계산 함수를 C로 복원했습니다. 원본 x86 테스트 3,205건을 통과했고, 컴파일된 함수 63바이트를 그대로 재현했습니다.
- **Notion:** 렌더러의 클립보드 API에서 시작해 preload, IPC를 거쳐 메인 프로세스까지 Electron 클립보드 연결 구조를 추적했습니다.
- **동방 TH04:** PC-98용 DOS 게임의 16비트 명령을 분석해 탄막 각도 계산을 C++로 복원했습니다.

자세한 내용은 [rea.tools/showcase](https://rea.tools/showcase/)에서 볼 수 있습니다.

## 사용 시 주의할 점

REA는 **합법적인 용도로만** 쓰도록 명시하고 있습니다. 예를 들면 보안 연구, 악성코드 분석, CTF·교육, 상호운용성 확보, 소프트웨어 보존, 그리고 본인이 소유했거나 분석 권한이 있는 소프트웨어의 디버깅·감사입니다.

다음 용도는 지원하지 않는다고 분명히 밝히고 있습니다.
- DRM, 라이선스 검사, 안티치트 우회
- 게임 핵 개발, 온라인 서비스 조작
- 권한 없는 시스템의 인증·접근 제어 우회
- 상용 소프트웨어의 코드나 에셋 복제

그 밖에 알아둘 점도 있습니다.
- IDA Pro, Hopper, JEB 같은 상용 도구는 **각자 정식 라이선스로** 사용해야 합니다.
- 나라나 소프트웨어 라이선스에 따라 리버스 엔지니어링 자체가 제한될 수 있습니다.
- 공식 배포처는 GitHub(morluto/rea), rea.tools, npm(rea-agents) 세 곳뿐입니다. 비슷한 이름의 복제 저장소를 조심하라고 안내합니다.

## 생각해볼 점

예전에는 리버스 엔지니어링을 하려면 Ghidra나 IDA 같은 도구를 직접 다룰 줄 알아야 했습니다. REA는 이 과정을 **AI 에이전트에게 맡기는 형태로** 바꿨다는 점이 흥미롭습니다.
특히 "근거와 한계를 함께 돌려준다"는 설계 덕분에, 에이전트가 그럴듯하게 지어낸 설명과 실제로 확인된 사실을 구분할 수 있습니다.

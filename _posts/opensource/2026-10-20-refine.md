# [오픈소스 소개] Refine: 관리자 페이지와 사내 도구를 위한 헤드리스 React 프레임워크

- **저장소:** [refinedev/refine](https://github.com/refinedev/refine) · [refine.dev](https://refine.dev) · [문서](https://refine.dev/docs)
- **라이선스:** MIT
- **언어:** TypeScript
- **현황 (2026-10-20 기준):** GitHub 스타 약 3.6만 개, 최신 릴리스 `@refinedev/core@5.0.12` (2026-04-02)

## 한 줄 요약

**인증, 권한, 라우팅, 데이터 요청, 상태 관리처럼 CRUD 앱에서 반복되는 부분을 훅(hook)과 프로바이더로 제공하고, 화면은 원하는 UI 라이브러리로 직접 그리게 하는 React 메타 프레임워크**입니다. README는 스스로를 "로우코드/노코드와 처음부터 직접 만들기 사이의 적절한 지점"이라고 소개합니다.

## 어떤 문제를 푸나

관리자 페이지, 대시보드, 사내 도구, B2B 앱은 대부분 비슷한 일을 합니다. 목록을 보여 주고, 페이지를 넘기고, 정렬·필터를 걸고, 폼으로 생성·수정하고, 삭제 전에 확인하고, 로그인과 권한을 확인합니다.

이걸 매번 React로 처음부터 만들면 다음 문제가 생깁니다.

- 페이지네이션, 정렬, 필터 상태를 URL과 맞추는 코드, 저장 후 목록 캐시를 새로 고치는 코드가 화면마다 반복됩니다.
- 인증 토큰 처리, 401 응답 시 로그아웃, 버튼별 권한 처리가 곳곳에 흩어집니다.
- 반대로 Retool, Appsmith 같은 로우코드 도구를 쓰면 빨리 만들 수 있지만, 디자인과 동작을 세밀하게 통제하기 어렵고 일반 React 코드베이스와 섞기 어렵습니다.

Refine은 이 사이를 노립니다. **비즈니스 로직(데이터, 인증, 권한, 라우팅)은 프레임워크가 맡고, UI는 일반 React 코드로 남겨 두는** 방식입니다. 결과물은 평범한 React 앱이므로 Git, 코드 리뷰, 테스트, 배포 파이프라인을 그대로 씁니다.

## 핵심 개념

### 헤드리스(Headless)

**헤드리스**는 "로직만 제공하고 화면(head)은 제공하지 않는다"는 뜻입니다. `@refinedev/core`의 `useTable`은 데이터, 현재 페이지, 정렬 상태, 이를 바꾸는 함수만 돌려줍니다. 그걸 `<table>`로 그릴지, Ant Design `Table`로 그릴지, shadcn/ui로 그릴지는 개발자가 정합니다.

그렇다고 UI를 전부 직접 만들 필요는 없습니다. 공식 통합 패키지가 있습니다.

| UI 통합 | 패키지 | 성격 |
| --- | --- | --- |
| Ant Design | `@refinedev/antd` | 컴포넌트·훅 제공 (`tableProps`, `formProps` 등) |
| Material UI | `@refinedev/mui` | `useDataGrid` 등 MUI DataGrid 연동 |
| Mantine | `@refinedev/mantine` | 컴포넌트·훅 제공 |
| Chakra UI | `@refinedev/chakra-ui` | 컴포넌트·훅 제공 |
| shadcn/ui | 레지스트리(`ui.refine.dev`) | 패키지가 아니라 소스 코드를 프로젝트에 복사 |
| Tailwind 등 직접 구현 | `@refinedev/core`만 사용 | 완전 헤드리스 |

### 프로바이더(Provider)

Refine의 기능은 `<Refine>` 컴포넌트에 넘기는 **프로바이더** 객체로 연결됩니다. 프로바이더는 "이 기능이 필요할 때 호출할 함수 묶음"입니다.

| 프로바이더 | 역할 |
| --- | --- |
| `dataProvider` | API와 통신 (`getList`, `getOne`, `create`, `update`, `deleteOne` 등) |
| `authProvider` | 로그인, 로그아웃, 인증 확인, 오류 처리, 사용자 정보 |
| `accessControlProvider` | "이 사용자가 이 리소스에 이 동작을 해도 되나?" 판단 (`can`) |
| `routerProvider` | React Router, Next.js, Remix 등 라우터 연결 |
| `notificationProvider` | 저장 성공·실패 알림 표시 |
| `i18nProvider` | 다국어 번역 |
| `liveProvider` | 실시간 업데이트 구독 |
| `auditLogProvider` | 변경 이력(감사 로그) 기록 |

### 리소스(Resource)

**리소스**는 API의 엔티티(예: `posts`, `products`)와 그 화면 경로를 묶은 선언입니다. 리소스를 등록해 두면 훅이 현재 URL을 보고 어떤 리소스, 어떤 동작(list/create/edit/show)인지 추론하고, 저장 후 어디로 이동할지, 메뉴에 무엇을 띄울지도 정합니다.

```tsx
resources={[
  {
    name: "products",
    list: "/products",
    create: "/products/create",
    edit: "/products/edit/:id",
    show: "/products/show/:id",
    meta: { canDelete: true },
  },
]}
```

### 훅(Hooks)

데이터 훅은 TanStack Query(구 React Query) v5 위에 만들어져 캐싱, 재시도, 무효화(invalidation)를 그대로 씁니다.

| 분류 | 대표 훅 |
| --- | --- |
| 조회 | `useList`, `useOne`, `useMany`, `useShow`, `useInfiniteList`, `useCustom` |
| 변경 | `useCreate`, `useUpdate`, `useDelete`, `*Many` 계열, `useCustomMutation` |
| 화면 조합 | `useTable`, `useForm`, `useSelect` |
| 인증 | `useLogin`, `useLogout`, `useIsAuthenticated`, `useGetIdentity`, `usePermissions`, `useOnError` |
| 권한 | `useCan`, `<CanAccess>` |
| 라우팅 | `useGo`, `useResourceParams` |

v5에서 반환 형태가 정리되었습니다. 조회 훅은 정규화된 데이터를 `result`에, 쿼리 상태를 `query`에 담고, 변경 훅은 상태를 `mutation`에 담습니다. 예를 들어 `const { result, query } = useList(...)`처럼 씁니다.

## 동작 원리

```
  Component
     |  useTable({ resource: "products" })
     v
  Refine hooks  (pagination/sort/filter state)
     |  builds query key
     v
  TanStack Query  (cache, retry, invalidate)
     |  calls
     v
  dataProvider.getList({ resource, pagination,
                         sorters, filters, meta })
     |  HTTP
     v
  Your API  ->  { data, total }
```

1. 컴포넌트가 `useTable`을 호출하면 Refine이 페이지·정렬·필터 상태를 관리하고, 이 값들로 쿼리 키를 만듭니다.
2. TanStack Query가 캐시를 확인하고, 없으면 `dataProvider.getList`를 호출합니다.
3. 데이터 프로바이더가 실제 HTTP 요청을 만들고 `{ data, total }`을 돌려줍니다.
4. `useForm`으로 저장하면 `useCreate`/`useUpdate`가 호출되고, 성공 후 관련 쿼리(기본: 목록과 상세)를 무효화해 화면이 새 데이터로 갱신됩니다. 그다음 `redirect` 설정에 따라 목록 등으로 이동합니다.
5. 요청이 실패하면 `authProvider.onError`가 자동으로 호출되어 401일 때 로그아웃 같은 처리를 한곳에서 할 수 있습니다.

데이터 프로바이더 인터페이스에서 필수 메서드는 `getList`, `getOne`, `create`, `update`, `deleteOne`, `getApiUrl`이고, `getMany`, `createMany`, `updateMany`, `deleteMany`, `custom`은 선택입니다. `getMany`가 없으면 `getOne`을 여러 번 호출하는 방식으로 대체됩니다.

여러 API를 동시에 쓸 때는 객체로 넘기고 `default` 키를 반드시 둡니다.

{% raw %}
```tsx
<Refine
  dataProvider={{
    default: dataProvider(API_URL),
    fineFoods: dataProvider(FINE_FOODS_API_URL),
  }}
  resources={[
    { name: "orders", meta: { dataProviderName: "fineFoods" } },
  ]}
/>
```
{% endraw %}

## 주요 기능

- **15개 이상의 백엔드 커넥터:** REST(`@refinedev/simple-rest`), GraphQL, NestJS CRUD, Nestjs-Query, Strapi, Supabase, Hasura, Appwrite, Airtable, Medusa 등 공식 패키지가 있고, README는 Firebase, Sanity, Directus 연동도 언급합니다.
- **라우터 무관:** React Router(`@refinedev/react-router`), Next.js(`@refinedev/nextjs-router`), Remix(`@refinedev/remix-router`)용 라우터 프로바이더가 있습니다. Next.js·Remix와 함께 쓰면 SSR(서버 사이드 렌더링)도 됩니다.
- **인증과 접근 제어:** `authProvider`로 로그인 흐름을, `accessControlProvider`로 RBAC(역할 기반)·ABAC(속성 기반) 권한을 붙입니다. 문서는 Casbin, CASL, Cerbos, AccessControl.js 연동을 예로 듭니다.
- **폼 편의 기능:** 생성·수정·복제(`clone`) 동작, 저장 후 이동, 낙관적 업데이트(`mutationMode: "optimistic"`), 실행 취소 가능한 저장(`undoable`), 자동 저장(`autoSave`)을 지원합니다. React Hook Form 연동 패키지(`@refinedev/react-hook-form`)도 있습니다.
- **테이블:** 코어 `useTable` 외에 TanStack Table 연동(`@refinedev/react-table`), Ant Design `tableProps`, MUI `useDataGrid`가 있습니다. `syncWithLocation`을 켜면 페이지·정렬·필터가 URL 쿼리에 저장됩니다.
- **Inferencer:** API 응답 구조를 보고 List/Show/Create/Edit 화면 코드를 자동 생성합니다. 문서는 **실험적 패키지이며 개발 환경용이지 운영용이 아니라고** 명시합니다. 생성된 코드를 복사해 다듬는 출발점으로 쓰는 도구입니다.
- **실시간·감사 로그·다국어·알림:** `liveProvider`(예: `@refinedev/ably`), `auditLogProvider`, `i18nProvider`, `notificationProvider`를 같은 방식으로 붙입니다.
- **CLI와 Devtools:** `npm run refine` 명령으로 리소스·프로바이더 스캐폴딩, 컴포넌트 스위즐(swizzle, 라이브러리 컴포넌트를 내 코드로 꺼내 수정), 패키지 업데이트를 합니다.
- **Enterprise Edition:** 멀티 테넌시, Okta 연동 등은 유료 Enterprise Edition에 있고, 비공개 npm 레지스트리(`registry.refine.dev`)로 배포됩니다. 가격은 공개 문서에서 확인하지 못했습니다.
- **AI 에이전트:** README는 Refine Core 위에서 동작하는 자체 AI 에이전트로 프로젝트를 만들어 볼 수 있다고 안내합니다. 이 글에서는 다루지 않습니다.

Ant Design 통합을 쓰면 헤드리스 훅이 UI 컴포넌트용 props로 변환되어 코드가 매우 짧아집니다(공식 문서 예시).

```tsx
import { useTable } from "@refinedev/antd";
import { Table } from "antd";

export const ProductList = () => {
  const { tableProps } = useTable<IProduct>();

  return (
    <Table {...tableProps} rowKey="id">
      <Table.Column dataIndex="id" title="ID" />
      <Table.Column dataIndex="name" title="Name" />
      <Table.Column dataIndex="price" title="Price" />
    </Table>
  );
};
```

## 설치와 시작

### 요구 사항

- Node.js 20 이상(패키지의 `engines` 기준)
- React 18 또는 19
- TanStack Query v5 (`@tanstack/react-query` 5.x, 코어의 peer dependency)
- React Router를 쓴다면 v7 (`react-router` ^7.0.2)

### 스캐폴더로 시작하기

가장 권장되는 방법은 CLI 스캐폴더입니다. 실행하면 프레임워크(Vite, Next.js, Remix), UI 라이브러리, 백엔드, 인증 방식 등을 차례로 묻습니다.

```bash
npm create refine-app@latest my-refine-app
cd my-refine-app
npm run dev
```

shadcn/ui 조합은 프리셋으로 바로 만들 수 있습니다.

```bash
npm create refine-app@latest my-app -- --preset vite-shadcn
```

브라우저에서 같은 옵션을 고르고 미리 본 뒤 내려받는 [브라우저 스캐폴더](https://refine.dev/?playground=true)도 있습니다.

### 기존 React 프로젝트에 넣기

헤드리스 코어와 REST 데이터 프로바이더, React Router 연동만 설치하면 됩니다.

```bash
npm i @refinedev/core @refinedev/simple-rest @refinedev/react-router \
  @tanstack/react-query react-router
```

### CLI 명령

스캐폴더로 만든 프로젝트에는 `refine` 스크립트가 들어 있습니다.

```bash
npm run refine dev                    # 프레임워크를 감지해 개발 서버 실행
npm run refine add resource           # 리소스 화면 생성
npm run refine add provider auth      # authProvider 뼈대 생성
npm run refine swizzle                # 라이브러리 컴포넌트를 내 코드로 꺼내기
npm run refine check-updates          # 업데이트 확인
npm run refine update                 # 패키지 업데이트
```

### 예제 1: 헤드리스 CRUD 앱의 뼈대 (REST + React Router)

`<Refine>`에 데이터 프로바이더, 라우터 프로바이더, 리소스를 등록하고 라우트를 연결합니다.

```tsx
// src/App.tsx
import { Refine } from "@refinedev/core";
import dataProvider from "@refinedev/simple-rest";
import routerProvider from "@refinedev/react-router";
import { BrowserRouter, Routes, Route, Navigate } from "react-router";

import { ProductList } from "./pages/products/list";
import { ProductCreate } from "./pages/products/create";
import { ProductEdit } from "./pages/products/edit";

const API_URL = "https://api.fake-rest.refine.dev";

export default function App() {
  return (
    <BrowserRouter>
      <Refine
        dataProvider={dataProvider(API_URL)}
        routerProvider={routerProvider}
        resources={[
          {
            name: "products",
            list: "/products",
            create: "/products/create",
            edit: "/products/edit/:id",
          },
        ]}
        options={{ syncWithLocation: true }}
      >
        <Routes>
          <Route index element={<Navigate to="/products" />} />
          <Route path="/products">
            <Route index element={<ProductList />} />
            <Route path="create" element={<ProductCreate />} />
            <Route path="edit/:id" element={<ProductEdit />} />
          </Route>
        </Routes>
      </Refine>
    </BrowserRouter>
  );
}
```

`syncWithLocation: true`를 주면 목록 화면의 페이지·정렬·필터가 URL에 반영되어 새로 고침이나 링크 공유 후에도 같은 상태가 유지됩니다.

목록 화면은 `useTable`로 만듭니다. 리소스는 현재 URL(`/products`)에서 추론되므로 생략해도 됩니다.

```tsx
// src/pages/products/list.tsx
import { useTable, useDelete, useGo, HttpError } from "@refinedev/core";

interface IProduct {
  id: number;
  name: string;
  material: string;
  price: string;
}

export const ProductList = () => {
  const {
    result,
    tableQuery,
    currentPage,
    setCurrentPage,
    pageCount,
    setFilters,
  } = useTable<IProduct, HttpError>({
    pagination: { pageSize: 10 },
    sorters: { initial: [{ field: "id", order: "desc" }] },
  });
  const { mutate: deleteProduct } = useDelete();
  const go = useGo();

  if (tableQuery?.isLoading) return <div>Loading...</div>;

  return (
    <div>
      <button onClick={() => go({ to: "/products/create" })}>
        새 상품
      </button>
      <input
        placeholder="이름 검색"
        onChange={(e) =>
          setFilters([
            { field: "name", operator: "contains", value: e.target.value },
          ])
        }
      />
      <table>
        <thead>
          <tr><th>ID</th><th>이름</th><th>소재</th><th /></tr>
        </thead>
        <tbody>
          {result.data.map((p) => (
            <tr key={p.id}>
              <td>{p.id}</td>
              <td>{p.name}</td>
              <td>{p.material}</td>
              <td>
                <button onClick={() => go({ to: `/products/edit/${p.id}` })}>
                  수정
                </button>
                <button
                  onClick={() => {
                    if (confirm("삭제할까요?")) {
                      deleteProduct({ resource: "products", id: p.id });
                    }
                  }}
                >
                  삭제
                </button>
              </td>
            </tr>
          ))}
        </tbody>
      </table>
      <button
        disabled={currentPage <= 1}
        onClick={() => setCurrentPage(currentPage - 1)}
      >
        이전
      </button>
      <span> {currentPage} / {pageCount} </span>
      <button
        disabled={currentPage >= pageCount}
        onClick={() => setCurrentPage(currentPage + 1)}
      >
        다음
      </button>
    </div>
  );
};
```

`@refinedev/simple-rest`는 이 상태를 다음과 같은 요청으로 바꿉니다(패키지 소스 기준, 검색어가 chair일 때). `contains`는 `_like`, `ne`/`gte`/`lte`는 `_ne`/`_gte`/`_lte` 접미사로, `eq`는 `필드=값`으로 바뀝니다.

```
GET /products?_end=10&_order=desc&_sort=id&_start=0&name_like=chair
```

전체 개수는 응답 헤더 `x-total-count`에서 읽고, 없으면 받은 배열 길이를 씁니다.

### 예제 2: 생성·수정 폼 (useForm)

헤드리스 `useForm`은 `onFinish`만 주고 폼 상태는 맡기지 않습니다. 여기서는 단순하게 `useState`로 관리합니다.

```tsx
// src/pages/products/create.tsx
import { useState } from "react";
import { useForm, HttpError } from "@refinedev/core";

type FormValues = { name: string; material: string };

export const ProductCreate = () => {
  const { onFinish, mutation } = useForm<any, HttpError, FormValues>({
    action: "create",
    redirect: "list", // 저장 후 목록으로 (기본값도 list)
  });
  const [values, setValues] = useState<FormValues>({ name: "", material: "" });

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();
        onFinish(values);
      }}
    >
      <input
        placeholder="이름"
        value={values.name}
        onChange={(e) => setValues({ ...values, name: e.target.value })}
      />
      <input
        placeholder="소재"
        value={values.material}
        onChange={(e) => setValues({ ...values, material: e.target.value })}
      />
      <button type="submit" disabled={mutation.isPending}>저장</button>
    </form>
  );
};
```

수정 화면은 `action: "edit"`이면 URL의 `:id`로 기존 데이터를 먼저 불러옵니다. 불러온 값은 `query`에 들어 있습니다.

```tsx
// src/pages/products/edit.tsx
import { useEffect, useState } from "react";
import { useForm, HttpError } from "@refinedev/core";

type FormValues = { name: string; material: string };

export const ProductEdit = () => {
  const { onFinish, query, formLoading } = useForm<any, HttpError, FormValues>({
    action: "edit",
    mutationMode: "optimistic", // 서버 응답 전에 화면 먼저 갱신
  });
  const record = query?.data?.data;
  const [values, setValues] = useState<FormValues>({ name: "", material: "" });

  useEffect(() => {
    if (record) setValues({ name: record.name, material: record.material });
  }, [record]);

  if (formLoading) return <div>Loading...</div>;

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();
        onFinish(values);
      }}
    >
      <input
        value={values.name}
        onChange={(e) => setValues({ ...values, name: e.target.value })}
      />
      <input
        value={values.material}
        onChange={(e) => setValues({ ...values, material: e.target.value })}
      />
      <button type="submit">수정</button>
    </form>
  );
};
```

저장이 끝나면 `useForm`이 목록·상세 캐시를 무효화하므로 목록으로 돌아갔을 때 따로 새로 고칠 필요가 없습니다. 실제 프로젝트에서는 검증이 필요하므로 `@refinedev/react-hook-form`이나 UI 통합 패키지의 `useForm`(`formProps`, `saveButtonProps`)을 쓰는 편이 편합니다.

### 예제 3: JWT 로그인과 보호된 라우트

`authProvider`를 만들고, 같은 토큰을 모든 API 요청에 붙입니다. `@refinedev/simple-rest`의 `dataProvider`는 두 번째 인자로 axios 인스턴스를 받으므로 인터셉터로 헤더를 넣을 수 있습니다.

```tsx
// src/providers.ts
import axios from "axios";
import type { AuthProvider } from "@refinedev/core";
import dataProvider from "@refinedev/simple-rest";

const API_URL = "https://api.example.com";
const TOKEN_KEY = "access_token";

const http = axios.create();
http.interceptors.request.use((config) => {
  const token = localStorage.getItem(TOKEN_KEY);
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

export const appDataProvider = dataProvider(API_URL, http);

export const authProvider: AuthProvider = {
  login: async ({ email, password }) => {
    try {
      const { data } = await axios.post(`${API_URL}/auth/login`, {
        email,
        password,
      });
      localStorage.setItem(TOKEN_KEY, data.accessToken);
      return { success: true, redirectTo: "/products" };
    } catch {
      return {
        success: false,
        error: { name: "LoginError", message: "이메일 또는 비밀번호 오류" },
      };
    }
  },
  logout: async () => {
    localStorage.removeItem(TOKEN_KEY);
    return { success: true, redirectTo: "/login" };
  },
  check: async () => {
    return localStorage.getItem(TOKEN_KEY)
      ? { authenticated: true }
      : { authenticated: false, redirectTo: "/login", logout: true };
  },
  onError: async (error) => {
    if (error?.status === 401 || error?.status === 403) {
      return { logout: true, redirectTo: "/login", error };
    }
    return {};
  },
  getIdentity: async () => {
    const { data } = await http.get(`${API_URL}/auth/me`);
    return data;
  },
};
```

라우트는 `<Authenticated>`로 감쌉니다. 로그인 페이지는 이미 로그인한 사용자를 목록으로 보내고, 나머지 페이지는 로그인하지 않은 사용자를 `/login`으로 보냅니다. 같은 레벨에 `<Authenticated>`를 여러 번 쓸 때는 문서가 서로 다른 `key`를 반드시 주라고 안내합니다.

```tsx
// src/App.tsx (라우트 부분)
import { Refine, Authenticated } from "@refinedev/core";
import routerProvider, { NavigateToResource } from "@refinedev/react-router";
import { BrowserRouter, Routes, Route, Outlet } from "react-router";
import { appDataProvider, authProvider } from "./providers";
import { LoginPage } from "./pages/login";
import { ProductList } from "./pages/products/list";

export default function App() {
  return (
    <BrowserRouter>
      <Refine
        dataProvider={appDataProvider}
        authProvider={authProvider}
        routerProvider={routerProvider}
        resources={[{ name: "products", list: "/products" }]}
      >
        <Routes>
          <Route
            element={
              <Authenticated key="public" fallback={<Outlet />}>
                <NavigateToResource resource="products" />
              </Authenticated>
            }
          >
            <Route path="/login" element={<LoginPage />} />
          </Route>
          <Route
            element={
              <Authenticated key="private" redirectOnFail="/login">
                <Outlet />
              </Authenticated>
            }
          >
            <Route path="/products" element={<ProductList />} />
          </Route>
        </Routes>
      </Refine>
    </BrowserRouter>
  );
}
```

로그인 화면에서는 `useLogin`을 씁니다.

```tsx
// src/pages/login.tsx
import { useState } from "react";
import { useLogin } from "@refinedev/core";

export const LoginPage = () => {
  const { mutate: login, isPending } = useLogin();
  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();
        login({ email, password });
      }}
    >
      <input value={email} onChange={(e) => setEmail(e.target.value)} />
      <input
        type="password"
        value={password}
        onChange={(e) => setPassword(e.target.value)}
      />
      <button disabled={isPending}>로그인</button>
    </form>
  );
};
```

UI 통합 패키지를 쓴다면 로그인·회원가입·비밀번호 찾기 화면을 `<AuthPage type="login" />` 한 줄로 대신할 수 있습니다.

### 예제 4: 역할 기반 권한 (accessControlProvider + CanAccess)

`admin`은 모든 동작, `editor`는 삭제를 제외한 동작, 그 밖의 사용자는 조회만 허용하는 예시입니다. 역할은 `authProvider.getPermissions`나 토큰에서 읽는다고 가정합니다.

```tsx
// src/accessControl.ts
import type { AccessControlProvider } from "@refinedev/core";

const getRole = () => localStorage.getItem("role") ?? "viewer";

export const accessControlProvider: AccessControlProvider = {
  can: async ({ resource, action }) => {
    const role = getRole();

    if (role === "admin") return { can: true };

    if (role === "editor") {
      return action === "delete"
        ? { can: false, reason: "편집자는 삭제할 수 없습니다" }
        : { can: true };
    }

    // viewer
    if (action === "list" || action === "show") return { can: true };
    return { can: false, reason: `${resource}: 조회 권한만 있습니다` };
  },
  options: {
    buttons: { enableAccessControl: true, hideIfUnauthorized: false },
  },
};
```

`<Refine accessControlProvider={accessControlProvider}>`로 넘기면 UI 통합 패키지의 Edit/Delete 버튼이 자동으로 비활성화되고 `reason`이 툴팁으로 뜹니다. 다만 문서가 강조하듯 **프로바이더를 넘기는 것만으로는 라우트가 막히지 않습니다.** 페이지와 버튼은 `<CanAccess>`로 감싸야 합니다.

```tsx
import { CanAccess } from "@refinedev/core";

// 라우트 전체 보호: 현재 경로에서 resource/action을 추론
<Route
  path="/products/edit/:id"
  element={
    <CanAccess fallback={<div>권한이 없습니다</div>}>
      <ProductEdit />
    </CanAccess>
  }
/>

// 특정 버튼만 보호
<CanAccess resource="products" action="delete">
  <button>삭제</button>
</CanAccess>
```

`can` 함수는 브라우저에서 실행되므로 화면 제어용입니다. 실제 보안은 서버 API에서도 같은 규칙으로 검사해야 합니다.

### 예제 5: 사내 API 형식에 맞춘 커스텀 데이터 프로바이더

사내 API가 `?page=1&size=20&sort=id,desc` 형식을 받고 `{ items: [...], totalCount: 123 }`을 돌려준다고 가정합니다. 필수 메서드만 구현하면 모든 훅이 이 API로 동작합니다.

```tsx
// src/dataProvider.ts
import type { DataProvider } from "@refinedev/core";

const API_URL = "https://internal.example.com/api";

async function request(url: string, init?: RequestInit) {
  const res = await fetch(url, {
    ...init,
    headers: { "Content-Type": "application/json", ...init?.headers },
  });
  if (!res.ok) {
    // statusCode를 넣어 주면 onError와 알림에서 활용 가능
    throw { message: res.statusText, statusCode: res.status };
  }
  return res.status === 204 ? null : res.json();
}

export const internalDataProvider: DataProvider = {
  getList: async ({ resource, pagination, sorters, filters }) => {
    const { currentPage = 1, pageSize = 10, mode = "server" } =
      pagination ?? {};
    const params = new URLSearchParams();

    if (mode === "server") {
      params.set("page", String(currentPage));
      params.set("size", String(pageSize));
    }
    sorters?.forEach((s) => params.append("sort", `${s.field},${s.order}`));
    filters?.forEach((f) => {
      if ("field" in f && f.operator === "eq") {
        params.set(f.field, String(f.value));
      }
    });

    const body = await request(`${API_URL}/${resource}?${params}`);
    return { data: body.items, total: body.totalCount };
  },

  getOne: async ({ resource, id }) => ({
    data: await request(`${API_URL}/${resource}/${id}`),
  }),

  create: async ({ resource, variables }) => ({
    data: await request(`${API_URL}/${resource}`, {
      method: "POST",
      body: JSON.stringify(variables),
    }),
  }),

  update: async ({ resource, id, variables }) => ({
    data: await request(`${API_URL}/${resource}/${id}`, {
      method: "PUT",
      body: JSON.stringify(variables),
    }),
  }),

  deleteOne: async ({ resource, id }) => {
    await request(`${API_URL}/${resource}/${id}`, { method: "DELETE" });
    return { data: { id } as any };
  },

  getApiUrl: () => API_URL,
};
```

처음부터 쓰기보다 `npm run refine swizzle`로 `@refinedev/simple-rest` 소스를 프로젝트에 꺼낸 뒤 고치는 방법도 문서에서 안내합니다. 필터 연산자(`contains`, `in`, `between` 등)를 어디까지 지원할지는 API에 맞춰 정하면 됩니다.

## 실무 팁 & 자주 겪는 문제

| 증상 | 원인과 해결 |
| --- | --- |
| 목록의 전체 페이지 수가 이상함(항상 1페이지) | simple-rest는 `x-total-count` 헤더로 전체 개수를 읽습니다. API가 다른 출처(origin)라면 서버가 `Access-Control-Expose-Headers: x-total-count`를 보내야 브라우저에서 읽힙니다. 없으면 받은 배열 길이를 total로 씁니다. |
| simple-rest에서 `or`/`and` 필터 오류 | 이 프로바이더는 조건부 필터(`or`, `and`)를 지원하지 않고 예외를 던집니다. 커스텀 프로바이더를 쓰거나 swizzle해서 고칩니다. |
| v4 예제 코드가 v5에서 타입 오류 | v5에서 `current`→`currentPage`, `setCurrent`→`setCurrentPage`, `queryResult`→`query`, `tableQueryResult`→`tableQuery`, `metaData`→`meta`, `sort`→`sorters`, `hasPagination: false`→`pagination: { mode: "off" }`로 바뀌었습니다. 블로그·예제 중 v4 문법이 많으니 버전을 꼭 확인합니다. |
| v4에서 v5로 올리기 | 먼저 4.x 최신으로 맞춘 뒤 `npx @refinedev/codemod@latest refine4-to-refine5`를 실행합니다. 복잡한 구조 분해나 커스텀 래퍼는 코드모드가 놓치므로 직접 검토합니다. TanStack Query도 v5로 올려야 합니다. |
| `useNavigation`, `useResource`를 못 찾음 | v5에서 각각 `useGo`/`useBack`, `useResourceParams`로 대체되었습니다. |
| 로그인 후 화면이 깜빡이거나 잘못된 화면이 잠깐 보임 | 같은 레벨의 `<Authenticated>`에 서로 다른 `key`를 줍니다. |
| 권한 설정을 했는데 URL로 직접 들어가면 열림 | `accessControlProvider`만으로는 강제되지 않습니다. 라우트를 `<CanAccess>`로 감쌉니다. |
| Inferencer 화면을 그대로 배포 | 개발용 실험 패키지입니다. 생성된 코드를 복사해 실제 컴포넌트로 바꿉니다. |
| 401 처리 코드가 화면마다 흩어짐 | `authProvider.onError`에서 `{ logout: true, redirectTo: "/login" }`을 돌려주면 모든 데이터 훅 오류에 일괄 적용됩니다. |

추가로 알아 두면 좋은 점입니다.

- 리소스의 `meta`에는 `label`, `icon`, `canDelete`, `parent`, `dataProviderName` 같은 값을 넣어 메뉴와 버튼 동작을 조정합니다(v4의 `options`가 v5에서 `meta`로 바뀌었습니다).
- `useForm`의 기본 무효화 범위는 create/clone이 `list`·`many`, edit가 `list`·`many`·`detail`입니다. 연관 리소스까지 갱신하려면 `useInvalidate`를 직접 호출합니다.
- 전역 기본값(`mutationMode`, `redirect`, `syncWithLocation` 등)은 `<Refine options={...}>`에서 한 번에 정할 수 있습니다.
- Community Edition은 월 단위 릴리스 주기를 따른다고 문서에 적혀 있습니다. 패키지마다 버전이 따로 올라가므로 `npm run refine check-updates`로 함께 확인합니다.

## 비슷한 도구와 비교

Refine 열은 공식 문서 기준이고, 다른 도구 열은 일반적으로 알려진 내용이라 세부 기능과 요금제는 버전에 따라 다를 수 있습니다.

| 항목 | Refine | React-Admin | Appsmith | Retool | Next.js 직접 구현 |
| --- | --- | --- | --- | --- | --- |
| 형태 | React 프레임워크(코드) | React 프레임워크(코드) | 로우코드 플랫폼 | 로우코드 SaaS | 웹 프레임워크 |
| 라이선스 | MIT (+유료 EE) | MIT (+유료 Enterprise) | Apache 2.0 (+유료 에디션) | 상용 | MIT |
| UI | 헤드리스, Antd/MUI/Mantine/Chakra/shadcn 통합 | Material UI 중심 | 내장 위젯 | 내장 컴포넌트 | 자유 |
| 데이터 연결 | dataProvider 패턴 | dataProvider 패턴 | 쿼리/데이터소스 GUI | 쿼리/리소스 GUI | 직접 작성 |
| 셀프 호스팅 | 일반 정적/Node 배포 | 일반 정적/Node 배포 | Docker 등 | 유료 플랜에서 가능 | 자유 |
| 학습 대상 | React 개발자 | React 개발자 | 개발자·준개발자 | 개발자·준개발자 | React 개발자 |
| 커스터마이징 | 매우 높음 | 높음 | 중간(JS 확장) | 중간(JS 확장) | 무제한 |

대략적으로 정리하면 이렇습니다.

- **React-Admin:** 개념(데이터 프로바이더, 리소스)이 Refine과 매우 비슷한 선배 격 프레임워크입니다. Material UI 기반 완성형 컴포넌트가 풍부해 MUI를 쓴다면 빠르게 만들 수 있습니다. Refine은 UI 라이브러리를 고를 수 있고 헤드리스로 쓸 수 있다는 점이 다릅니다.
- **Appsmith / Retool:** 화면을 드래그해서 만드는 로우코드 도구입니다. 비개발자와 함께 빠르게 내부 도구를 만들 때 유리하지만, 결과물이 일반 React 코드베이스가 아니어서 세밀한 UX나 기존 디자인 시스템 적용에는 한계가 있습니다.
- **Next.js 직접 구현:** 가장 자유롭지만 테이블 상태, 폼 저장 흐름, 캐시 무효화, 인증·권한을 모두 직접 만들어야 합니다. Refine은 Next.js 위에서도 동작하므로 "둘 중 하나"보다는 "Next.js에 Refine을 얹을지"의 문제에 가깝습니다.

## 장점과 한계

**장점**

- CRUD 앱의 반복 작업(페이지네이션, 정렬, 필터, 저장 후 캐시 갱신, 리다이렉트)을 훅 하나로 처리합니다.
- 헤드리스 구조라 기존 디자인 시스템이나 Tailwind/shadcn과 자연스럽게 섞입니다.
- 데이터·인증·권한·라우팅이 프로바이더로 분리되어, 백엔드나 라우터를 바꿔도 화면 코드는 대부분 그대로입니다.
- TanStack Query 위에 있어 캐싱, 재시도, 낙관적 업데이트를 검증된 방식으로 씁니다.
- MIT 라이선스이고 결과물이 평범한 React 앱이라 벤더 종속이 적습니다.
- Next.js·Remix와 함께 SSR이 필요한 고객용 화면에도 쓸 수 있습니다.

**한계**

- React와 TanStack Query를 모르면 학습 곡선이 있습니다. 로우코드 도구처럼 비개발자가 만들 수는 없습니다.
- v3→v4→v5로 오면서 API 이름이 여러 번 바뀌어, 인터넷의 예제·블로그 상당수가 현재 버전과 맞지 않습니다. 공식 문서 안에서도 일부 예시는 예전 반환 형태를 쓰고 있어 주의가 필요합니다.
- 패키지가 잘게 나뉘어(코어, UI, 라우터, 데이터 프로바이더 등) 버전 조합을 맞추는 관리 부담이 있습니다.
- simple-rest 같은 기본 프로바이더는 기능이 단순해 실제 사내 API에는 결국 커스텀 프로바이더가 필요한 경우가 많습니다.
- 멀티 테넌시, Okta 같은 일부 기업용 기능은 유료 Enterprise Edition에 있습니다.
- Inferencer는 실험 단계이며 운영용이 아닙니다.

## 이런 분께 추천

- React로 관리자 페이지, 백오피스, 사내 도구를 자주 만드는 팀
- 이미 있는 디자인 시스템(또는 shadcn/ui, Tailwind)으로 내부 도구를 만들고 싶은 팀
- 로우코드 도구의 한계(디자인, 코드 리뷰, 테스트, 배포)에 부딪힌 팀
- REST, GraphQL, Supabase, Strapi 등 여러 백엔드를 같은 패턴으로 다루고 싶은 분
- 인증·권한·감사 로그 같은 엔터프라이즈 요구 사항을 일관된 구조로 붙이고 싶은 분

## 이런 경우엔 다른 도구

- **개발자가 아닌 운영팀이 직접 화면을 만들어야 한다면** Appsmith, Retool 같은 로우코드 도구가 맞습니다.
- **Material UI로 완성형 관리자 화면을 최대한 빨리 띄우고 싶다면** React-Admin의 완성형 컴포넌트가 더 빠를 수 있습니다.
- **CRUD가 거의 없는 마케팅 사이트나 콘텐츠 중심 서비스라면** Refine의 추상화가 오히려 부담입니다. Next.js나 Astro 같은 일반 프레임워크로 충분합니다.
- **DB 테이블을 그대로 보여 주는 관리 화면이면 충분하다면** Django Admin, Directus 같은 자동 생성형 도구가 더 적은 코드로 끝납니다.

# [오픈소스 소개] Files: Windows를 위한 현대적인 오픈소스 파일 관리자

- **저장소:** [files-community/Files](https://github.com/files-community/Files) · [files.community](https://files.community)
- **라이선스:** MIT
- **언어:** C#
- **현황 (2026-10-20 기준):** GitHub 스타 약 4.6만 개, 최신 릴리스 v4.3 (10월 11일)

## 한 줄 요약

**Windows 기본 탐색기(File Explorer)를 대신해 쓸 수 있는 커뮤니티 주도 파일 관리자**입니다. 탭, 분할 화면(Dual pane), 파일 태그, Git 연동, 명령 팔레트처럼 탐색기에 없거나 약한 기능을 깔끔한 Windows 11 스타일 UI에 담았습니다. "Windows 최고의 파일 관리자"를 목표로 GitHub에서 공개적으로 개발하고 있습니다.

![Files 스크린샷](https://raw.githubusercontent.com/files-community/Files/main/assets/FilesScreenshot.png)

## 어떤 문제를 푸나

Windows 탐색기는 오랫동안 크게 바뀌지 않았습니다. 일상적인 파일 작업은 충분하지만, 파일을 많이 다루는 사람에게는 아쉬운 점이 쌓입니다.

- 두 폴더를 나란히 놓고 비교하거나 옮기려면 창을 두 개 띄워 배치해야 합니다.
- 프로젝트별, 상태별로 파일을 묶어 두는 **태그** 같은 분류 수단이 없습니다.
- 자주 쓰는 동작에 단축키를 새로 붙이거나 바꾸기 어렵습니다.
- 개발자라면 폴더가 Git 저장소인지, 지금 어느 브랜치인지 탐색기에서 바로 알 수 없습니다.

Files는 이런 부분을 채우면서도 탐색기와 비슷한 사용감을 유지하는 쪽을 택했습니다. 처음 써도 낯설지 않지만, 익숙해질수록 손이 빨라지는 도구입니다.

## 핵심 개념

Files를 잘 쓰려면 몇 가지 용어를 먼저 알아두면 좋습니다.

| 용어 | 설명 |
|---|---|
| **탭(Tab)** | 한 창 안에서 여러 폴더를 동시에 여는 단위입니다. 탭을 떼어내 새 창으로 만들 수도 있습니다. |
| **창 분할(Pane)** | 한 탭 안에서 두 위치를 나란히 보는 기능입니다. 공식 문서에서는 Dual pane이라고 부릅니다. |
| **옴니바(Omnibar)** | 경로 표시(브레드크럼), 경로 직접 입력, 검색, 명령 팔레트를 하나로 합친 상단 입력창입니다. |
| **액션(Action)** | 복사, 압축, 탭 열기 같은 모든 명령의 단위입니다. 150개 이상 있고, 각각 단축키를 지정할 수 있습니다. |
| **명령 팔레트(Command Palette)** | 액션을 이름으로 검색해 실행하는 창입니다. VS Code의 명령 팔레트와 같은 개념입니다. |
| **Info Pane** | 오른쪽에 열리는 정보 영역으로, 상세 정보(Details) 탭과 미리보기(Preview) 탭이 있습니다. |
| **태그(Tag)** | 파일과 폴더에 붙이는 색상 라벨입니다. NTFS의 대체 데이터 스트림(ADS)에 저장됩니다. |

특히 **액션** 개념이 중요합니다. 메뉴에 보이는 기능도, 메뉴에 없는 고급 기능도 모두 액션이고, 명령 팔레트에서 찾아 실행하거나 설정에서 단축키를 붙일 수 있습니다.

## 주요 기능

### 1. 멀티태스킹: 탭과 분할 화면

**탭**

- `Ctrl` + `T` 또는 제목 표시줄의 `+` 버튼으로 새 탭을 엽니다.
- 폴더를 마우스 가운데 버튼으로 클릭하거나, 우클릭 메뉴의 "새 탭에서 열기"로 새 탭에 엽니다. 사이드바 항목은 `Ctrl`을 누른 채 클릭하면 새 탭에 열립니다.
- 탭을 끌어내면 새 창이 되고, 창 사이에 탭을 옮길 수도 있습니다.
- 파일을 다른 탭 위로 끌고 가 잠시 멈추면 그 탭으로 전환되어 바로 놓을 수 있습니다.

**분할 화면(Dual pane)**

- 왼쪽 위 **Actions** 버튼에서 두 번째 창(pane)을 추가하고 배치 방향을 고릅니다.
- 탭을 현재 파일 영역으로 끌어다 놓아도 분할됩니다. 좌우 가장자리에 놓으면 세로 분할, 위아래에 놓으면 가로 분할입니다.
- 폴더 우클릭 메뉴에서 "새 창(pane)에서 열기"를 고를 수 있습니다.
- 설정의 General 페이지에서 "새 탭을 항상 분할 화면으로 열기"를 켤 수 있고, 기본 분할 방향도 정할 수 있습니다(기본값은 꺼짐).

### 2. 파일 태그

- 우클릭 메뉴의 "Edit tags", Info Pane의 상세 정보, 툴바 버튼, 사이드바의 태그로 끌어다 놓기 등 여러 방법으로 태그를 붙입니다. 여러 항목에 한 번에 붙일 수도 있습니다.
- 사이드바에서 태그를 클릭하면 그 태그가 붙은 항목을 전체 검색합니다.
- 검색창에 `tag:Photos`처럼 입력해 찾을 수 있고, `tag:Photos,Important`처럼 쉼표로 여러 태그를 함께 검색합니다.
- Details 레이아웃의 태그 열, 홈 화면의 Tags 위젯으로도 확인할 수 있습니다.
- 태그 이름과 색상은 설정의 Tags 페이지에서 만들고 고치고 지웁니다. 태그를 지우면 그 태그가 붙은 모든 항목에서 빠지지만, 파일 자체는 삭제되지 않습니다.

태그는 데이터베이스가 아니라 **NTFS 대체 데이터 스트림**에 저장됩니다. 그래서 Files 밖에서 파일을 옮겨도 태그가 따라갑니다. 대신 NTFS가 아닌 드라이브에서는 동작하지 않고, 일부 클라우드 저장소에서도 동작하지 않을 수 있습니다.

### 3. 명령 팔레트와 단축키 커스터마이징

- `Ctrl` + `Shift` + `P`로 명령 팔레트를 엽니다. 150개 이상의 액션을 이름으로 검색하고, 현재 지정된 단축키도 함께 보여줍니다.
- 설정 > **Actions**에서 기존 단축키를 바꾸거나 지우고, 단축키가 없는 액션에 새 단축키를 붙일 수 있습니다. "Restore defaults"로 기본값 복원도 됩니다.
- 아직 액션에 사용자 정의 인자를 넘기는 기능은 지원하지 않습니다(공식 문서에 향후 검토 중이라고 적혀 있습니다).

### 4. 옴니바와 검색

- 기본은 브레드크럼(경로 조각) 표시이고, 각 단계의 꺾쇠를 눌러 하위 폴더로 바로 이동합니다.
- 빈 곳을 클릭하거나 `Ctrl` + `L`(또는 `Alt` + `D`)을 누르면 경로를 직접 편집하는 모드가 됩니다. 전체 경로가 자동 선택되어 복사나 덮어쓰기가 쉽습니다.
- `Ctrl` + `F`로 검색 모드로 바뀝니다. 제안 목록이 뜨고, `Enter`를 누르면 전체 검색 결과 페이지가 열립니다.
- 설정 화면에서는 검색 모드가 설정 항목 검색으로 바뀌어, 원하는 설정으로 바로 이동할 수 있습니다.

### 5. 레이아웃과 정렬

- 레이아웃은 Details, List, Cards, Grid, Columns 다섯 가지이고, 폴더 내용에 맞춰 자동으로 고르는 **Adaptive** 옵션이 있습니다.
- `Ctrl` + `Shift` + `1`~`6`으로 각 레이아웃(6은 Adaptive)을 바로 전환합니다.
- 기본적으로 레이아웃은 폴더별로 기억됩니다. "모든 폴더에서 레이아웃과 정렬 동기화" 설정을 켜면 한 곳의 변경이 전체에 적용됩니다.
- 이름, 수정 날짜, 만든 날짜, 크기, 유형, 태그로 정렬과 그룹화가 가능하고, 날짜 그룹은 연/월/일 단위를 고를 수 있습니다.

### 6. Git 연동

Git 저장소 폴더를 열면 개발자에게 유용한 정보가 자동으로 나타납니다.

- 상태 표시줄(Status Bar)에 현재 브랜치 이름과 로컬/원격 커밋 수가 보입니다.
- 브랜치 이름을 클릭해 브랜치를 만들거나 전환(checkout)합니다.
- 커밋 수를 클릭해 push, pull을 실행합니다. 진행 상황은 Status Center에 표시되고, 실패하면 Git의 실제 오류 메시지를 보여줍니다.
- Details 레이아웃에 Git 상태, 마지막 커밋, 커밋 해시, 작성자 열을 켤 수 있습니다.
- 상태 표시줄에서 현재 폴더를 지정한 IDE(기본은 VS Code)로 엽니다.
- 브라우저의 GitHub 저장소 URL을 Files로 끌어다 놓으면 Clone이 시작됩니다.
- GitHub에 연결하면 원격 저장소로 push와 sync를 할 수 있고, 인증이 필요할 때 안내가 표시됩니다.

v4.3에서는 SSH로 클론한 저장소에서도 Git 작업이 동작하도록 개선되었습니다.

### 7. 압축 파일

명령 팔레트 액션으로 다음 작업을 지원합니다.

- 압축 만들기: 일반 압축 대화상자, 7z로 바로 압축, zip으로 바로 압축
- 압축 풀기: 대화상자(`Ctrl` + `E`), 현재 폴더에 풀기, 새 폴더에 풀기
- **Smart extract**(`Ctrl` + `Shift` + `E`): 압축 파일 내용을 보고 풀 방식을 자동으로 고릅니다.

### 8. 미리보기

- Info Pane의 Preview 탭에서 선택한 파일을 미리 봅니다.
- **QuickLook**, **SeerPro**, **PowerToys Peek** 중 하나가 설치되어 있으면 파일을 선택하고 `Space`를 눌러 macOS의 훑어보기처럼 팝업 미리보기를 띄울 수 있습니다. 별도 설정은 필요 없습니다.

### 9. 사이드바, 클라우드, 네트워크

- 사이드바는 Home, Pinned, Libraries, Drives, Cloud Drives, Network, WSL, Tags 섹션으로 나뉩니다. 쓰지 않는 섹션은 헤더 우클릭으로 숨깁니다.
- OneDrive, Google Drive, iCloud, Dropbox, Box, Nextcloud, Proton Drive 등 20개 이상의 클라우드 클라이언트를 감지해 사이드바에 보여줍니다. 해당 클라이언트가 설치되어 실행 중이어야 합니다.
- 주소창에 `ftp://서버:포트` 또는 `ftps://서버:포트`를 입력하면 FTP/FTPS 서버에 접속합니다. **SFTP는 아직 지원하지 않습니다.**
- WSL에 설치한 리눅스 배포판도 사이드바에서 바로 열 수 있습니다.

### 10. 터미널과 기타 통합

- `Ctrl` + `` ` ``로 현재 폴더를 터미널에서 열고, `Ctrl` + `Shift` + `` ` ``로 관리자 권한 터미널을 엽니다. Windows 기본 터미널 설정을 따르며, Windows Terminal이 기본이면 선택한 폴더마다 탭으로 열립니다.
- 검색 도구 **Listary**와 연동하면 Listary 검색 결과에서 폴더를 Files로 바로 열 수 있습니다.

### 11. 테마와 모양

- 라이트/다크/시스템 기본 테마, Mica·Mica Alt(Windows 11 전용)·Acrylic 배경 효과를 고릅니다.
- 배경색과 배경 이미지(GIF 포함), 앱 글꼴을 바꿀 수 있습니다.
- 설정 파일을 직접 편집하면 주소창, 툴바, 사이드바, 파일 영역의 배경색을 따로 지정할 수 있습니다. 공식 문서에 Glass, Finder, Nord, Dracula 예시 테마 값이 나와 있습니다.
- 폴더의 `desktop.ini`에 설정을 넣어 **폴더별 배경 이미지**를 지정할 수도 있습니다.
- 툴바 버튼을 추가, 제거, 재배치하는 툴바 커스터마이징을 지원합니다.

## 설치와 시작

### 시스템 요구 사항

앱 패키지 매니페스트 기준으로 **Windows 10 빌드 19041(버전 2004) 이상의 데스크톱**에서 동작합니다. x64와 ARM64를 지원합니다. 설치에는 **Windows Update와 전송 최적화(Delivery Optimization) 서비스**가 켜져 있어야 합니다.

### 설치 방법 비교

| 방법 | 비용 | 특징 |
|---|---|---|
| Microsoft Store | 유료 | 개발 후원 성격. 가장 권장되는 방법 |
| 클래식 설치 파일 | 무료 | Store 버전과 **같은 기능**, 자동 업데이트 지원 |
| PowerShell | 무료 | 클래식 설치 파일을 명령으로 설치 |
| WinGet / Chocolatey / Scoop | 무료 | 제3자가 관리하는 패키지 |
| 오프라인 설치 | 무료 | 의존성 패키지를 순서대로 직접 설치 |

Store 버전과 클래식 버전은 기능 차이가 없습니다. 공식 다운로드 페이지는 "Store 구매가 개발을 지원하는 가장 좋은 방법"이라고 안내하며, 무료 버전을 쓴다면 GitHub 후원을 권합니다. 가격은 Store에서 지역별로 다를 수 있으니 직접 확인하세요.

### 명령으로 설치하기

PowerShell(관리자 권한, **Windows PowerShell 기본 버전**. PowerShell 7에서는 동작하지 않음):

```powershell
Add-AppxPackage -AppInstallerFile https://cdn.files.community/files/stable/Files.Package.appinstaller
```

WinGet:

```powershell
winget install -e --id FilesCommunity.Files
```

Chocolatey:

```powershell
choco install files
```

Scoop:

```powershell
scoop install nonportable/files-np
```

### 프리뷰 버전

프리뷰(Preview) 버전은 안정 버전과 **함께 설치**할 수 있어 새 기능을 먼저 써볼 수 있습니다. WinGet이라면 `FilesCommunity.FilesPreview`, Chocolatey라면 `filespreview`를 설치합니다.

### 업데이트

앱을 열 때와 실행 중에 주기적으로 업데이트를 확인하고, 새 버전이 있으면 툴바에 표시합니다. 업데이트를 설치하면 Files가 자동으로 재시작되니 작업 중인 내용을 먼저 정리하세요.

## 실전 활용 시나리오

### 시나리오 1: 탭과 분할 화면으로 정리 작업하기

다운로드 폴더에 쌓인 파일을 프로젝트 폴더로 옮기는 상황입니다.

1. `Ctrl` + `T`로 새 탭을 열고 다운로드 폴더로 갑니다.
2. `Alt` + `Shift` + `V`로 세로 분할합니다(가로 분할은 `Alt` + `Shift` + `H`).
3. 오른쪽 창에서 프로젝트 폴더로 이동합니다. `Ctrl` + `Shift` + `→`로 두 창 사이 포커스를 옮길 수 있습니다.
4. 왼쪽에서 파일을 골라 오른쪽으로 끌어다 놓습니다.
5. 다 끝나면 `Ctrl` + `Alt` + `W`로 활성 창을 닫습니다.

이 작업을 자주 한다면 설정 > General에서 "새 탭을 분할 화면으로 열기"를 켜 두면 편합니다. 실수로 탭을 닫았다면 `Ctrl` + `Shift` + `T`로 복구합니다.

### 시나리오 2: 태그로 진행 상태 관리하기

여러 폴더에 흩어진 문서를 "검토 필요", "완료" 상태로 관리하는 방법입니다.

1. `Ctrl` + `,`로 설정을 열고 **Tags** 페이지에서 "검토 필요", "완료" 태그를 만들고 색을 정합니다.
2. 문서를 여러 개 선택해 우클릭 > **Edit tags**에서 "검토 필요"를 켭니다. 사이드바의 태그 위로 끌어다 놓아도 됩니다.
3. 사이드바에서 "검토 필요" 태그를 클릭하면 어느 폴더에 있든 해당 문서가 모두 모입니다.
4. 검토가 끝난 문서는 태그를 바꿉니다. 태그를 모두 지우려면 우클릭 > Edit tags > **Remove tags**를 씁니다.
5. 다른 PC에서도 같은 태그 목록을 쓰려면 설정 > Advanced > **Export**로 내보내고 다른 PC에서 **Import** 합니다.

내보낸 설정의 `filetags` 파일에는 태그 정의(GUID)만 있고, 어떤 파일에 태그가 붙었는지는 들어 있지 않습니다. 태그 자체는 파일의 대체 데이터 스트림에 있으므로, NTFS 드라이브 사이에서 파일을 옮기면 함께 따라갑니다.

### 시나리오 3: Files를 기본 파일 관리자로 설정하기

Windows는 공식적으로 기본 파일 관리자 변경을 허용하지 않습니다. Files는 **실험적 기능**으로 우회 방법을 제공합니다.

1. 설정 > **Advanced** > Experimental feature flags로 갑니다.
2. "Set Files as the default file manager"를 켭니다.
3. 이후 `Win` + `E`, 다른 앱에서 폴더 열기 같은 동작이 Files로 연결됩니다.

이 기능은 **레지스트리를 수정**해 탐색기 호출을 가로챕니다. 공식 문서는 문제가 생길 수 있으니 **켜기 전에 레지스트리를 백업**하라고 강하게 권합니다. 같은 페이지의 "Windows 시작 시 Files 실행", "창을 닫아도 백그라운드 유지" 옵션을 함께 켜면 탐색기처럼 바로 뜨는 느낌에 가까워집니다.

### 시나리오 4: 개발 폴더에서 Git과 터미널 함께 쓰기

1. 저장소 폴더를 열면 상태 표시줄에 브랜치와 커밋 수가 나타납니다.
2. 브랜치 이름을 클릭해 작업 브랜치를 새로 만들거나 전환합니다.
3. Details 레이아웃(`Ctrl` + `Shift` + `1`)에서 열 머리글을 우클릭해 Git 상태, 마지막 커밋 열을 켭니다. 어떤 파일이 바뀌었는지 한눈에 보입니다.
4. 명령이 필요하면 `Ctrl` + `` ` ``로 그 폴더에서 터미널을 엽니다.
5. 코드 편집은 상태 표시줄의 IDE 열기 버튼으로 VS Code를 띄웁니다.
6. 작업 후 커밋 수를 클릭해 push 합니다.

커밋 자체는 Files 문서에 나와 있지 않으므로, 커밋은 터미널이나 IDE에서 하고 브랜치 전환, push/pull, 상태 확인을 Files에서 하는 식으로 나누어 쓰면 좋습니다.

## 실무 팁 & 자주 겪는 문제

**설치가 안 될 때**

- "Cannot open app package" 메시지가 나오면 Windows의 **App Installer** 구성 요소가 오래된 것입니다. Microsoft Store에서 업데이트하세요.
- AtlasOS, ReviOS 같은 수정된 Windows나 "디블로트" 스크립트를 돌린 환경은 공식 지원 대상이 아닙니다. 서비스(services.msc)에서 Windows Update와 Delivery Optimization의 시작 유형을 "수동"으로 바꾸고 서비스를 시작한 뒤 다시 설치해 보라고 안내합니다.

**명령줄에서 열기**

`files-stable.exe "C:\Users\이름\Documents"`처럼 실행하면 해당 폴더로 Files가 열립니다. 프리뷰는 `files-preview.exe`입니다.

**메모리 사용량이 높을 때**

탭을 많이 열거나 여러 위치를 오가면 메모리 사용이 늘어나고, 잠시 그대로 두면 다시 줄어든다고 공식 FAQ는 설명합니다. v4.3에서 시작 속도, 탐색 속도, 메모리 사용이 함께 개선되었습니다. 폴더 크기 계산 옵션은 CPU 사용량을 크게 늘릴 수 있으니 필요할 때만 켜세요.

**탐색기 우클릭 메뉴가 그립다면**

Files는 자체 컨텍스트 메뉴를 씁니다. 공식 FAQ는 탐색기 메뉴를 그대로 가져오면 레이아웃 변경, 붙여넣기 같은 항목이 Files에서 동작하지 않아 좋은 경험이 아니라고 설명합니다. 셸 확장(다른 앱이 추가한 메뉴)은 기본적으로 하위 메뉴로 묶여 있고, General 설정에서 풀어 놓을 수 있습니다.

**버그 리포트용 로그**

설정 > About > **Open log location**에서 로그 폴더를 엽니다. 로그에는 사용자 이름과 파일 경로가 가려져 있어 이슈에 첨부해도 됩니다. 앱이 안 뜨면 `%LocalAppData%\Packages\` 아래 Files 패키지 폴더의 `LocalState`에서 찾습니다.

**설정 파일 직접 편집**

설정 > Advanced > Edit settings file로 여는데, 편집 전에 시스템 트레이 아이콘에서 **Quit**으로 Files를 완전히 종료해야 합니다.

**Flatten folder 주의**

중첩 폴더 안의 모든 항목을 상위로 끌어올리는 기능인데, 공식 문서도 되돌릴 수 없으니 권장하지 않는다고 경고합니다.

## 장점과 한계

**장점**

- 오픈소스이고, 클래식 설치 파일은 무료이면서 Store 버전과 기능이 같습니다.
- 탭, 분할 화면, 태그, 명령 팔레트로 멀티태스킹이 확실히 편해집니다.
- 150개 이상의 액션에 단축키를 자유롭게 붙일 수 있습니다.
- Git 상태, WSL, 클라우드 드라이브, 터미널 연동으로 개발자 친화적입니다.
- 40개 이상 언어를 지원하고 한국어 UI도 쓸 수 있습니다.
- 커뮤니티가 활발해 업데이트가 잦습니다.

**한계**

- **Windows 전용**입니다.
- 기본 파일 관리자 지정은 레지스트리를 건드리는 실험적 기능입니다.
- 태그는 NTFS에서만 동작하고 일부 클라우드 저장소와 호환되지 않을 수 있습니다.
- SFTP를 지원하지 않습니다.
- 탐색기 우클릭 메뉴를 그대로 쓰지 않아, 특정 셸 확장 동작이 다를 수 있습니다.
- Details 레이아웃의 열 순서 변경은 아직 지원하지 않습니다.
- 수정된 Windows 환경은 공식 지원 대상이 아닙니다.

## 이런 분께 추천

- 탐색기 창을 여러 개 띄워 놓고 정리하는 일이 잦은 분
- 폴더 구조와 상관없이 태그로 파일을 분류하고 싶은 분
- Git 저장소를 많이 다루는 개발자
- VS Code처럼 키보드와 명령 팔레트 중심으로 일하는 분
- 비용 부담 없이 탐색기보다 나은 파일 관리자를 찾는 분

**이런 경우엔 다른 도구를 고려하세요**

- macOS나 Linux에서도 같은 도구를 써야 한다면 Files는 맞지 않습니다.
- 파일 작업을 스크립트로 자동화하거나 아주 세밀하게 커스터마이징해야 한다면 Directory Opus 같은 상용 도구가 더 적합할 수 있습니다.
- SFTP로 서버 파일을 자주 다룬다면 WinSCP 같은 전용 도구를 함께 쓰는 편이 낫습니다.
- 회사 정책상 레지스트리 수정이나 Store 앱 설치가 막혀 있다면 도입 전에 확인이 필요합니다.

# [오픈소스 소개] DevToys: 개발자를 위한 오프라인 만능 유틸리티 모음

- **저장소:** [DevToys-app/DevToys](https://github.com/DevToys-app/DevToys) · [devtoys.app](https://devtoys.app/) · [문서(SDK)](https://devtoys.app/doc)
- **라이선스:** MIT
- **언어:** C# (.NET)
- **현황 (2026-10-20 기준):** GitHub 스타 약 3.2만 개(32,086), GitHub에서 "정식(non-prerelease)"으로 표시된 최신 릴리스는 v1.0.13.0 (2023년 7월). 다만 공식 사이트가 기본으로 배포하는 버전은 GitHub에서 프리릴리스로 표시된 **v2.0.9.0 (2026년 1월)** 입니다. 자세한 내용은 아래 "현재 상태" 참고.

## 한 줄 요약

**JSON 포맷팅, Base64 인코딩, JWT 디코딩, 해시 계산, 정규식 테스트처럼 개발 중 자주 하는 자잘한 변환 작업을 내 컴퓨터 안에서 처리해 주는 데스크톱 앱**입니다. 스스로를 "개발자를 위한 스위스 아미 나이프"라고 소개합니다. 2.0부터 Windows, macOS, Linux를 모두 지원하고, 확장(extension)과 별도의 CLI 앱도 생겼습니다.

## 어떤 문제를 푸나

"이 JWT 안에 뭐가 들었지?", "이 Base64 문자열을 풀어 보자", "JSON이 한 줄로 붙어 있어서 못 읽겠다" 같은 순간에 많은 사람이 검색창에 "base64 decode online"을 칩니다. 편하지만 문제가 있습니다.

- **보안:** 토큰, API 응답, 고객 데이터를 출처를 알 수 없는 웹사이트에 붙여 넣게 됩니다. 사이트가 입력을 서버로 보내는지 사용자는 알기 어렵습니다.
- **분산:** 도구마다 사이트가 달라서 북마크가 늘어나고, 광고와 팝업을 매번 헤쳐 나가야 합니다.
- **오프라인 불가:** 네트워크가 막힌 환경에서는 쓸 수 없습니다.

DevToys README는 이 점을 직접 언급합니다. "텍스트를 디코딩하거나 이미지를 압축하려고 신뢰할 수 없는 웹사이트를 여러 개 쓸 필요가 없다"는 것이 출발점입니다. 공식 사이트도 "30 default offline tools"라는 표현으로 오프라인 동작을 강조합니다.

## 핵심 개념

| 용어 | 설명 |
|---|---|
| **도구(Tool)** | JSON Formatter, JWT Encoder/Decoder처럼 한 가지 일을 하는 화면 하나입니다. 2.0에는 기본 도구가 30개 있습니다. |
| **그룹(Group)** | 도구를 묶는 카테고리입니다. Converters, Encoders/Decoders, Formatters, Generators, Graphic, Testers, Text가 있습니다. |
| **Smart Detection** | 클립보드 내용을 분석해 어울리는 도구를 추천하는 기능입니다. 추천된 도구는 사이드바에 전구 아이콘으로 표시됩니다. |
| **확장(Extension)** | 서드파티가 만든 추가 도구입니다. NuGet 패키지(`.nupkg`) 형태로 배포되고 앱 안의 확장 관리자에서 설치합니다. |
| **DevToys CLI** | GUI 앱과 별도로 설치하는 명령줄 앱입니다. 서버나 CI처럼 GUI가 없는 환경에서 같은 도구를 쓰게 해 줍니다. |
| **SDK (`DevToys.Api`)** | 확장을 만들 때 쓰는 .NET 라이브러리입니다. NuGet에서 받습니다. |

## 현재 상태: 1.x와 2.0

DevToys의 버전 상황은 조금 헷갈리니 먼저 정리합니다.

- **1.x (Windows 전용):** 처음 유명해진 버전입니다. Windows 앱으로 Microsoft Store 등을 통해 배포됐고, GitHub의 마지막 1.x 릴리스는 **v1.0.13.0 (2023-07-25)** 입니다. macOS에는 별도 커뮤니티 프로젝트인 DevToysMac이 있었습니다(README의 Special Thanks에 언급).
- **2.0 (크로스 플랫폼):** 2024년 6월 v2.0.1.0부터 2026년 1월 v2.0.9.0까지 9번 릴리스됐습니다. **GitHub에서는 전부 "프리릴리스(pre-release)"로 표시**돼 있습니다. 확장 개발 문서에도 "As of DevToys 2.0 preview"라는 표현이 남아 있습니다.
- **그런데 공식 사이트는 2.0을 기본으로 배포합니다.** devtoys.app 메인 버튼은 "Get DevToys 2.0"이고, 다운로드 페이지의 모든 링크는 v2.0.9.0을 가리킵니다. README도 "DevToys 2.0 comes with 30 default tools"로 2.0 기준으로 쓰여 있습니다.

정리하면, **실사용 기준 최신은 2.0이지만 GitHub 라벨상으로는 아직 프리뷰**인 셈입니다. 이 글은 2.0을 기준으로 설명합니다.

개발 속도도 짚어 둘 필요가 있습니다. v2.0.8.0(2024-11)과 v2.0.9.0(2026-01) 사이에 1년 넘는 간격이 있었고, v2.0.9.0의 주요 변경은 확장 설치 관련 취약점 수정, 번역 개선, 신규 확장 소개였습니다. 저장소에는 2026년 9월에도 macOS/Linux의 Text Comparer 버그 수정 같은 커밋이 있어 유지보수는 이어지고 있지만, 빠르게 새 기능이 쏟아지는 단계는 아닙니다.

## 동작 원리

2.0은 하나의 C# 코드베이스로 세 운영체제를 지원하도록 다시 만들어졌습니다. v2.0.1.0 릴리스 노트에 따르면 UI는 Blazor 기반이며, Windows에서는 WPF Blazor, macOS에서는 MAUI Blazor를 쓰도록 정리됐고 이후 Linux 지원이 추가됐습니다. 텍스트 편집 영역에는 VS Code와 같은 Monaco Editor가 들어갑니다.

```
 +------------------------------------------+
 | DevToys app (Win / macOS / Linux)        |
 |  Blazor UI + Monaco editor               |
 |                                          |
 |  Clipboard --> Data type detectors       |
 |                  |                       |
 |                  v                       |
 |  Suggested tools (light bulb)            |
 |                                          |
 |  Built-in tools   Extensions (.nupkg)    |
 |  (30 default)     loaded via MEF         |
 +------------------------------------------+
 +------------------------------------------+
 | DevToys CLI (separate app)               |
 |  same tools as commands: base64, uuid... |
 +------------------------------------------+
```

### 도구와 확장은 같은 구조

기본 도구는 [DevToys.Tools](https://github.com/DevToys-app/DevToys.Tools) 저장소에 따로 있고, 확장과 같은 방식으로 만들어져 있습니다. 각 도구는 `IGuiTool`(GUI 화면) 또는 `ICommandLineTool`(CLI 명령) 인터페이스를 구현하고, .NET의 **MEF**(Managed Extensibility Framework, 실행 시점에 어셈블리를 읽어 특정 인터페이스 구현체를 찾아 붙이는 플러그인 프레임워크)의 `[Export]` 속성으로 앱에 노출됩니다. 그래서 확장을 설치하면 기본 도구와 똑같이 사이드바와 CLI에 나타납니다.

### Smart Detection의 동작

공식 문서의 설명을 정리하면 다음과 같습니다.

1. 클립보드 데이터가 먼저 텍스트, 이미지, 파일 감지기로 들어갑니다.
2. 결과는 더 구체적인 감지기로 이어집니다. 예를 들어 텍스트는 JSON 감지기 등으로, 파일 목록은 단일 파일, 다시 HTML 파일이나 이미지 파일 감지기로 넘어가는 상속 구조입니다.
3. 각 도구는 받고 싶은 데이터 타입을 등록해 둡니다. 맞는 타입이 감지되면 그 도구에 전구 아이콘이 붙습니다.
4. 추천된 도구를 누르면 클립보드 내용이 입력으로 자동으로 들어갑니다.
5. 일부 도구는 읽기 전용 출력 상자 옆에도 전구 아이콘이 있어서, 출력을 다른 도구의 입력으로 넘길 수 있습니다. 문서의 예시는 "JSON 포맷팅, Base64 변환, QR 코드 생성"을 연달아 하는 것입니다.

감지기 하나는 2초 안에 끝나야 하며 그렇지 않으면 취소됩니다. Smart Detection은 앱 설정에서 켜고 끌 수 있습니다.

### 확장 생태계

- 앱 안의 **Manage extensions** 화면에서 `.nupkg`를 설치합니다. 설치 시 패키지(사실상 ZIP)를 폴더에 풀고, `.nuspec` 정보로 제목, 설명, 버전을 표시합니다.
- v2.0.9.0 릴리스 노트 기준으로 확장 관리자를 통해 받을 수 있는 확장은 **총 44개**입니다. 예시로 `JSON to Python`, `Msgpack`, `C# to TypeScript`, `CodeFormatter`, `UUID Hyphen Formatter`, 이전 릴리스의 `Semver Calculator`, `ULID Generator`, `Text Delimiter` 등이 소개됐습니다.
- 공식 문서는 확장을 nuget.org에 `devtoys-app` 태그로 올리기를 권장합니다. 사내 NuGet 피드나 GitHub 배포도 가능합니다.
- 설치 위치는 운영체제별로 다음과 같습니다.

| OS | 확장 설치 경로 | 로그 경로 |
|---|---|---|
| Windows | `%LocalAppData%/DevToys/Plugins/` | `%LocalAppData%/DevToys/Logs/` |
| macOS | `~/Library/com.devtoys/Plugins/` | `~/Library/Caches/com.devtoys/Logs/` |
| Linux | `~/.local/share/devtoys/Plugins/` (`XDG_DATA_HOME` 따름) | `~/.local/share/devtoys/Logs/` |

### DevToys CLI

GUI 앱과 **별도로 설치**하는 명령줄 앱입니다. 공식 문서는 GUI가 없는 서버나 CI(지속적 통합) 환경을 용도로 듭니다. 실행 파일 이름은 Windows에서 `DevToys.CLI.exe`, Linux에서는 보통 `/usr/bin/devtoys.cli`입니다. `--help`로 명령과 옵션 설명을 볼 수 있습니다.

DevToys.Tools 소스를 보면 상당수 기본 도구가 CLI 명령도 함께 제공합니다. 몇 가지 명령 이름과 별칭(alias)을 소스에서 확인한 대로 옮기면 다음과 같습니다.

| 명령 (별칭) | 하는 일 | 주요 옵션 |
|---|---|---|
| `base64` (`b64`) | Base64 인코딩/디코딩 | `-i` 입력(문자열 또는 파일), `-c Encode\|Decode`, `-e` 인코딩, `-o` 출력 파일 |
| `url` | URL 인코딩/디코딩 | `-i`, `-c Encode\|Decode` |
| `JsonFormatter` (`Jsonf`) | JSON 포맷팅 | `-i`, `--indentation TwoSpaces\|FourSpaces\|OneTab\|Minified`, `--sortProperties`, `-o` |
| `jsonToYaml` | JSON과 YAML 상호 변환 | `-i`, `-c JsonToYaml\|YamlToJson`, `--indentation`, `-o` |
| `checksum` (`hash`) | 해시 계산, 체크섬 검증 | `-i`, `-a` 알고리즘(기본 MD5), `-m` HMAC 키, `-c` 비교할 체크섬, `-u` 대문자 |
| `uuid` (`guid`) | UUID 생성 | `-v` 버전, `-h` 하이픈, `-u` 대문자 |

입력 옵션 `-i`는 상당수가 "파일 경로 또는 문자열"을 모두 받습니다. 경로에 실제 파일이 있으면 파일로, 없으면 문자열로 처리하는 방식입니다(문서의 `OneOf<FileInfo, string>` 설명). 명령이 성공하면 `0`, 실패하면 `-1`을 반환하는 것이 문서가 안내하는 관례입니다.

### 개인정보와 오프라인

- 개인정보 처리방침(PRIVACY-POLICY.md)은 개인 식별 정보를 요구하거나 보관하지 않는다고 밝힙니다. 사용 데이터(오류 메시지, 성능 지표 등)는 **개발자에게 전송되지 않고** 설정 화면의 "Logs" 섹션에 표시된다고 적혀 있습니다.
- 로그 문서에 따르면 로그는 로컬에만 저장되고 인터넷으로 업로드하지 않습니다. 실행할 때마다 새 로그 파일이 생기고, 2일이 지난 로그는 시작 시 삭제됩니다.
- **단, 확장은 예외입니다.** 공식 문서는 서드파티 확장이 기존 도구 동작을 바꾸거나 허락 없이 컴퓨터에 접근하고 데이터를 인터넷으로 보낼 수 있다고 강하게 경고합니다. 신뢰하는 확장만 설치하고, 필요하면 Wireshark, Little Snitch, Fiddler 같은 도구로 네트워크 활동을 감시하라고 안내합니다. 또 수동 확장 설치를 완전히 막을 방법은 현재 없다고 명시합니다.

## 설치와 시작

공식 다운로드 페이지(v2.0.9.0 기준)에 나온 방법입니다.

### Windows

```powershell
# WinGet
winget install DevToys-app.DevToys
```

- **Microsoft Store:** 자동 설치, 자동 업데이트
- **설치 파일(.exe):** `devtoys_win_x64.exe`, `devtoys_win_x86.exe`, `devtoys_win_arm64.exe`
- **포터블 ZIP:** 아키텍처별 `_portable.zip`
- Chocolatey는 "COMING SOON"으로 표시돼 있습니다.

### macOS

```bash
brew install --cask devtoys
```

- 또는 앱 번들 ZIP: Intel은 `devtoys_osx_x64.zip`, Apple Silicon은 `devtoys_osx_arm64.zip`

### Linux (Debian/Ubuntu)

- `.deb` 패키지: `devtoys_linux_x64.deb`, `devtoys_linux_arm.deb` (ARM64)
- 포터블 ZIP: `devtoys_linux_*_portable.zip`
- `apt` 저장소는 "COMING SOON"으로 표시돼 있습니다.

```bash
# 예: GitHub 릴리스에서 받은 .deb 설치
sudo apt install ./devtoys_linux_x64.deb
```

`apt install ./파일.deb`는 데비안 계열의 일반적인 로컬 패키지 설치 방법입니다. 다운로드 페이지는 Debian/Ubuntu만 명시하며, AppImage, Flatpak, RPM 같은 다른 형식은 공식 다운로드 페이지에서 확인하지 못했습니다.

### DevToys CLI

| OS | 형식 |
|---|---|
| Windows | 포터블 ZIP, .NET 미포함 ZIP(.NET 8.0 필요). WinGet/Chocolatey는 준비 중 |
| macOS | 포터블 ZIP, .NET 미포함 ZIP(.NET 8.0 필요). Homebrew는 준비 중 |
| Linux | `.deb`(`devtoys.cli_linux_x64.deb` 등), 포터블 ZIP, .NET 미포함 ZIP |

"포터블"은 .NET 런타임이 포함된 버전, ".NET 미포함"은 이미 .NET 8.0이 설치된 환경용 가벼운 버전입니다.

## 실전 활용 시나리오

### 1. JWT 내용 안전하게 확인하기

API 응답에서 받은 토큰의 만료 시간이나 클레임을 확인하는 상황입니다.

1. 토큰 문자열을 복사합니다.
2. DevToys를 엽니다. Smart Detection이 켜져 있으면 사이드바의 JWT Encoder/Decoder에 전구 아이콘이 붙습니다.
3. 그 도구를 누르면 토큰이 자동으로 입력되고 헤더와 페이로드가 펼쳐집니다.
4. `exp` 같은 타임스탬프 값을 복사해 Date Converter로 넘기면 사람이 읽을 수 있는 날짜로 바꿀 수 있습니다.

운영 환경 토큰을 외부 웹사이트에 붙여 넣지 않아도 된다는 점이 가장 큰 이점입니다.

### 2. 도구 체이닝: JSON 정리 후 Base64, 다시 QR 코드

공식 문서가 Smart Detection 예시로 든 흐름입니다.

1. 한 줄로 붙은 JSON을 복사하고 JSON Formatter에 넣어 정리합니다.
2. 출력 상자 옆 전구 아이콘으로 결과를 Base64 Text Encoder로 넘깁니다.
3. 다시 그 출력을 QR Code 도구로 넘겨 QR 이미지를 만듭니다.

모바일 기기에 설정값을 옮기거나 테스트용 QR을 만들 때 복사/붙여넣기를 반복하지 않아도 됩니다.

### 3. CI에서 DevToys CLI 쓰기

빌드 산출물의 체크섬을 확인하거나 설정 파일을 변환하는 예입니다. 명령과 옵션 이름은 DevToys.Tools 소스에서 확인한 것입니다. Linux 기준 실행 파일 이름(`devtoys.cli`)은 설치 방식에 따라 다를 수 있으니 `--help`로 먼저 확인하세요.

```bash
# 사용 가능한 명령 목록
devtoys.cli --help

# Base64 인코딩 / 디코딩
devtoys.cli base64 -i "hello world"
devtoys.cli b64 -i "aGVsbG8gd29ybGQ=" -c Decode

# JSON 파일을 4칸 들여쓰기로 정리해서 파일로 저장
devtoys.cli JsonFormatter -i ./response.json --indentation FourSpaces -o ./pretty.json

# YAML을 JSON으로 변환
devtoys.cli jsonToYaml -i ./config.yaml -c YamlToJson -o ./config.json

# UUID 생성
devtoys.cli uuid

# 파일 해시 계산 (기본 알고리즘은 MD5)
devtoys.cli checksum -i ./artifact.zip -a Sha256
```

마지막 줄의 `Sha256` 값은 소스의 `HashAlgorithmType` 열거형 이름을 따른 것입니다. 실제로 허용되는 값 목록은 `devtoys.cli checksum --help`로 확인하는 것이 안전합니다. 솔직히 말하면 CI에서는 `base64`, `sha256sum`, `jq`, `yq` 같은 표준 도구가 이미 있는 경우가 많습니다. DevToys CLI는 GUI에서 쓰던 도구와 같은 동작을 그대로 쓰고 싶거나, 사내에서 만든 DevToys 확장을 CLI로도 돌리고 싶을 때 의미가 커집니다.

### 4. 팀 전용 도구를 확장으로 만들기

사내 전용 ID 형식 디코딩, 사내 로그 포맷 파싱처럼 공개 도구에 없는 기능이 필요할 때입니다. 공식 Getting Started 문서의 흐름은 다음과 같습니다.

1. .NET 8.0 이상 **Class Library** 프로젝트를 만듭니다.
2. SDK를 추가합니다.

   ```bash
   dotnet add package DevToys.Api --version VERSION_NUMBER
   ```

3. 지역화 문자열을 담을 `.resx` 파일, 리소스 위치를 알려 주는 `IResourceAssemblyIdentifier` 구현, 그리고 실제 도구인 `IGuiTool` 구현을 만듭니다.

   ```csharp
   [Export(typeof(IGuiTool))]
   [Name("MyExtension")]
   [ToolDisplayInformation(
       IconFontName = "FluentSystemIcons",
       IconGlyph = '',
       GroupName = PredefinedCommonToolGroupNames.Converters,
       ResourceManagerAssemblyIdentifier = nameof(MyResourceAssemblyIdentifier),
       ResourceManagerBaseName = "MyExtension.MyExtension",
       ShortDisplayTitleResourceName = nameof(MyExtension.ShortDisplayTitle),
       LongDisplayTitleResourceName = nameof(MyExtension.LongDisplayTitle),
       DescriptionResourceName = nameof(MyExtension.Description),
       AccessibleNameResourceName = nameof(MyExtension.AccessibleName))]
   internal sealed class MyExtensionGui : IGuiTool
   {
       public UIToolView View => new(
           Label().Style(UILabelStyle.BodyStrong)
                  .Text(MyExtension.HelloWorldLabel));

       public void OnDataReceived(string dataTypeName, object? parsedData)
       {
       }
   }
   ```

4. 디버깅용으로 `DevToysGuiDebugEntryPoint`, `DevToysCliDebugEntryPoint` 환경 변수에 설치된 DevToys 실행 파일 경로를 지정합니다.
5. `.csproj`에 패키지 정보(`IsPackable`, `Version`, `PackageTags`에 `devtoys-app` 등)를 넣고 `dotnet pack`으로 `.nupkg`를 만듭니다.
6. 사내 NuGet 피드나 공유 폴더에 올리고, 팀원은 Manage extensions에서 설치합니다.

공식 문서는 릴리스 빌드에서 **트리밍(trimming)과 Native AOT를 피하라**고 권합니다. 확장을 리플렉션으로 찾기 때문에 이 최적화가 컴포넌트 탐색을 깨뜨릴 수 있습니다. 또 `[Name]` 값은 다른 확장과 겹치지 않게 충분히 고유하게 지으라고 강조합니다.

### 5. 정규식과 diff를 오프라인으로

1. 로그에서 패턴을 뽑을 정규식을 RegEx Tester에서 실제 샘플 로그와 함께 다듬습니다.
2. 설정 파일 두 버전을 Text Comparer에 넣어 차이를 확인합니다.
3. 두 목록(예: 배포 전후 서버 목록)의 교집합과 차집합은 List Compare로 봅니다.

모두 로컬에서 처리되므로 사내 설정이나 로그를 외부로 보내지 않습니다.

## 실무 팁 & 자주 겪는 문제

- **GitHub 릴리스 페이지에서 "Latest"가 1.0.13.0으로 보일 때:** 2.0 계열이 전부 프리릴리스로 표시되어 생기는 현상입니다. 공식 사이트 다운로드 페이지는 v2.0.9.0을 안내합니다. 크로스 플랫폼, 확장, CLI가 필요하면 2.0을 받으세요.
- **Smart Detection이 거슬릴 때:** 클립보드를 볼 때마다 추천이 뜨는 것이 불편하거나 민감한 데이터를 자주 복사한다면 설정에서 끌 수 있습니다.
- **확장 설치 전 확인:** 공식 문서가 직접 경고하듯 확장은 앱과 같은 권한으로 실행됩니다. 소스가 공개된 확장인지, 누가 배포하는지 확인하세요. v2.0.9.0에서 확장 설치 관련 취약점(경로 조작 계열, CWE-22/23)이 수정됐으니 이전 버전이라면 업데이트를 권합니다.
- **확장을 강제로 지우거나 점검할 때:** 위 표의 `Plugins` 폴더에서 직접 확인할 수 있습니다.
- **문제 보고 전에:** `Logs` 폴더의 최근 로그 파일(`log-yyyymmddThhmmss.txt` 형식)을 확인하세요. 2일이 지나면 자동 삭제되므로 문제가 생긴 직후에 확보해야 합니다.
- **macOS 단축키 문제:** v2.0.5.0에서 macOS의 `Cmd+C`/`Cmd+V`/`Cmd+X`가 안 되던 문제가 수정됐습니다. 오래된 2.0 빌드를 쓰고 있다면 업데이트하세요.
- **Linux에서 빈 창이 뜰 때:** v2.0.8.0에서 Linux 시작 시 빈 창이 뜨는 문제가 수정됐고, 2026년 9월 커밋에도 Linux WebView 관련 수정이 있습니다. 증상이 있으면 최신 빌드나 이슈 트래커를 확인하세요.
- **CLI가 .NET 오류를 낼 때:** ".NET 미포함" ZIP을 받았다면 .NET 8.0 런타임이 필요합니다. 런타임 설치가 번거로우면 포터블 버전을 받으세요.
- **확장 자동 업데이트:** 공개 문서(2.0 preview 시점 작성)에는 확장 새 버전을 자동으로 확인하지 않는다고 적혀 있습니다. 이후 릴리스 노트에 "확장 업데이트 확인 문제 수정" 항목이 있어 현재는 동작이 달라졌을 수 있습니다.

## 비슷한 도구와 비교

아래 비교는 필자의 일반적인 지식을 바탕으로 한 것이며, 각 도구의 세부 기능은 버전에 따라 다를 수 있으니 공식 문서로 확인하세요.

| 항목 | DevToys 2.0 | IT-Tools | CyberChef | Boop | 일반 온라인 변환 사이트 |
|---|---|---|---|---|---|
| 형태 | 데스크톱 앱 + CLI | 웹 앱 (셀프 호스팅 가능) | 웹 앱 (단일 HTML로도 실행 가능) | macOS 앱 | 웹사이트 |
| 플랫폼 | Windows, macOS, Linux | 브라우저 | 브라우저 | macOS | 브라우저 |
| 데이터 처리 위치 | 로컬 | 브라우저 (자체 호스팅 시 사내) | 브라우저 | 로컬 | 사이트마다 다름 (서버 전송 가능) |
| 강점 | Smart Detection, 도구 체이닝, 네이티브 앱 | 도구 개수가 많고 Docker로 배포 쉬움 | "레시피"로 수십 단계 변환 조합, 보안 분석에 강함 | 스크립트(JS)로 텍스트 변환 확장 | 설치 불필요 |
| 확장 방식 | NuGet 기반 C# SDK | 소스 수정 | 소스 수정 | JavaScript 스크립트 | 없음 |
| CLI | 있음 (별도 앱) | 없음 | 없음 (Node API는 별도) | 없음 | 없음 |

- **IT-Tools**는 브라우저에서 동작하는 개발자 도구 모음입니다. Docker로 팀 서버에 한 번 띄우면 모두가 설치 없이 쓸 수 있다는 것이 장점입니다.
- **CyberChef**는 영국 GCHQ가 공개한 도구로, 인코딩, 암호, 압축, 데이터 추출 작업을 "레시피"로 연결하는 데 특화돼 있습니다. 보안 분석이나 복잡한 다단계 변환에서는 DevToys보다 훨씬 강력합니다.
- **Boop**은 macOS용 가벼운 텍스트 변환 앱으로, 스크립트를 직접 추가하기 쉽습니다. 텍스트 위주라면 충분히 좋은 대안입니다.
- **온라인 변환 사이트**는 가장 쉽지만, 민감한 데이터를 넣기 전에 처리 위치를 확인하기 어렵다는 점이 DevToys가 등장한 이유이기도 합니다.

## 장점과 한계

**장점**

- 자주 쓰는 30개 도구가 하나의 깔끔한 앱에 모여 있습니다.
- 기본 도구는 로컬에서 처리되고, 로그도 외부로 보내지 않는다고 문서에 명시돼 있습니다.
- Smart Detection과 도구 체이닝으로 복사/붙여넣기 횟수가 줄어듭니다.
- 2.0부터 Windows, macOS, Linux를 모두 지원합니다.
- C# SDK와 NuGet 배포로 사내 전용 도구를 만들어 배포할 수 있고, 같은 도구를 CLI로도 노출할 수 있습니다.
- MIT 라이선스입니다.

**한계**

- **버전 상태가 애매합니다.** 2.0이 공식 사이트의 기본 배포 버전이지만 GitHub에서는 여전히 프리릴리스입니다. 사내 도입 정책이 "정식 릴리스만"이라면 걸릴 수 있습니다.
- **개발 속도가 느려졌습니다.** v2.0.8.0 이후 다음 릴리스까지 1년 넘게 걸렸고, 2026년 1월 이후 새 릴리스는 없습니다(2026-10-20 기준).
- 웹 도구와 달리 설치가 필요합니다. 팀 전체가 같은 도구를 쓰게 하려면 각자 설치해야 합니다.
- 확장은 앱과 같은 권한으로 동작하며, 설치를 완전히 막을 방법이 없다고 문서가 인정합니다. 보안 정책이 엄격한 조직은 확장 사용 규칙을 따로 정해야 합니다.
- Linux 패키지는 Debian/Ubuntu용 `.deb`와 ZIP만 공식 안내되고, apt 저장소는 아직 준비 중입니다.
- CLI의 명령 이름 표기가 `base64`, `JsonFormatter`, `jsonToYaml`처럼 일관되지 않아 `--help`를 자주 보게 됩니다.

## 이런 분께 추천

- JSON, JWT, Base64, 해시, 정규식을 매일 다루는 백엔드/프론트엔드 개발자
- 업무 데이터를 외부 변환 사이트에 붙여 넣는 것이 꺼려지는 분
- Windows, macOS, Linux를 오가며 같은 도구를 쓰고 싶은 분
- 사내 전용 변환/디코딩 도구를 C#으로 만들어 팀에 배포하고 싶은 .NET 개발자

## 이런 경우엔 다른 도구

- 설치 없이 팀 전체가 브라우저로 쓰게 하고 싶다면: **IT-Tools**를 사내 서버에 셀프 호스팅
- 여러 단계의 인코딩, 암호화, 데이터 추출을 조합하는 보안 분석 작업이라면: **CyberChef**
- macOS에서 가벼운 텍스트 변환만 필요하고 JS로 직접 확장하고 싶다면: **Boop**
- CI 스크립트에서 단순 변환만 한다면: `base64`, `sha256sum`, `jq`, `yq` 같은 **표준 CLI 도구**
- 정식 릴리스와 빠른 업데이트 주기가 중요한 환경이라면: 대안 도구들의 활동성과 릴리스 정책을 함께 비교해 보세요.

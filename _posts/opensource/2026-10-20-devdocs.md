# [오픈소스 소개] DevDocs: 여러 API 문서를 한곳에서 빠르게 검색하는 문서 브라우저

- **저장소:** [freeCodeCamp/devdocs](https://github.com/freeCodeCamp/devdocs) · [devdocs.io](https://devdocs.io) · [사용 도움말](https://devdocs.io/help)
- **라이선스:** MPL 2.0 (Mozilla Public License 2.0)
- **언어:** Ruby (스크레이퍼, 서버) + JavaScript (웹 앱)
- **현황 (2026-10-20 기준):** GitHub 스타 약 4만 개(39,561), GitHub 릴리스는 따로 내지 않음 (호스팅 버전 devdocs.io와 `main` 브랜치가 사실상 최신), 저장소는 꾸준히 커밋 중

## 한 줄 요약

**HTML, CSS, JavaScript부터 Python, Rust, Kubernetes까지 수많은 공식 레퍼런스 문서를 한 화면에 모아, 즉시 검색과 오프라인 열람을 제공하는 웹 앱**입니다. 원래 Thibaut Courouble이 만들었고 지금은 freeCodeCamp가 운영합니다. 대부분의 사람은 설치 없이 [devdocs.io](https://devdocs.io)에 접속해 바로 쓰면 됩니다.

## 어떤 문제를 푸나

개발 중에 "이 함수 인자 순서가 뭐였지?" 같은 질문은 하루에도 수십 번 생깁니다. 보통은 검색 엔진에 묻거나 각 프로젝트의 공식 문서 사이트를 엽니다. 이 과정에는 자잘한 비용이 쌓입니다.

- 검색 결과에서 공식 문서보다 블로그, Q&A, 광고 페이지가 먼저 나오기도 합니다.
- 문서 사이트마다 레이아웃, 검색창 위치, 버전 선택 방식이 달라서 매번 눈이 적응해야 합니다.
- 비행기, 지하철, 사내 폐쇄망처럼 인터넷이 불안정하면 문서를 볼 수 없습니다.
- 문서 사이트가 무거우면 페이지 하나 여는 데도 시간이 걸립니다.

DevDocs는 이 문제를 "레퍼런스 문서만 모아서 같은 디자인으로 정리하고, 이름 기반 검색을 아주 빠르게 만든다"는 방식으로 풉니다. README의 비전(Vision) 항목은 목표를 이렇게 정리합니다. 로딩 시간을 최소화하고, 검색 결과의 품질과 속도를 높이고, 완전히 오프라인에서 동작하고, 키보드만으로 모든 조작이 가능하고, 문서마다 다른 디자인 때문에 생기는 "컨텍스트 전환"을 줄이는 것입니다.

반대로 DevDocs가 **하지 않는 것**도 분명합니다. README는 DevDocs가 프로그래밍 가이드도, 검색 엔진도 아니라고 말합니다. 튜토리얼이나 가이드처럼 "짧고 뻔한 이름으로 식별되지 않는 콘텐츠"는 범위 밖이고, 전문(full-text) 검색 엔진과 경쟁할 생각도 없다고 명시합니다.

## 핵심 개념

| 용어 | 설명 |
|---|---|
| **문서(Documentation)** | `JavaScript`, `CSS`, `Python 3.13`처럼 DevDocs가 수집해 둔 하나의 문서 세트입니다. 버전별로 따로 존재하기도 합니다. |
| **활성화(Enable)** | 내가 쓸 문서를 고르는 동작입니다. 활성화한 문서만 검색과 사이드바에 나타납니다. |
| **엔트리(Entry)** | 검색 대상이 되는 항목 하나입니다. 이름, 타입(분류), 경로로 구성됩니다. 예를 들어 `Array.prototype.map`이 하나의 엔트리입니다. |
| **인덱스(Index)** | 문서 하나의 엔트리 목록을 담은 JSON 파일입니다. 검색과 사이드바는 이 인덱스를 씁니다. |
| **오프라인 설치(Install)** | 문서의 모든 페이지를 브라우저 저장소(IndexedDB)에 내려받아 두는 동작입니다. |
| **스크레이퍼(Scraper)** | 원본 문서 사이트를 크롤링해서 DevDocs용 HTML 조각과 인덱스를 만드는 Ruby 코드입니다. |
| **필터(Filter)** | 스크레이퍼가 가져온 각 페이지를 정리하는 처리 단계입니다. 불필요한 마크업 제거, 링크 정리, 메타데이터 추출 등을 맡습니다. |

DevDocs를 이해하는 핵심은 **"메타데이터가 뼈대"**라는 점입니다. README는 각 콘텐츠가 고유하고 짧고 뻔한 문자열로 식별된다고 설명합니다. 그래서 검색은 본문 전체가 아니라 엔트리 이름을 대상으로 하고, 그 덕분에 매우 빠릅니다.

## 동작 원리

DevDocs는 크게 두 부분으로 나뉩니다. 문서를 미리 만들어 두는 **Ruby 스크레이퍼**와, 그 결과물을 브라우저에서 보여 주는 **JavaScript 앱**입니다. 앱은 작은 Sinatra(Ruby 웹 프레임워크) 서버가 서빙합니다.

```
 [Source docs site]
        |
        v  (UrlScraper / FileScraper)
 +---------------------------+
 | Filters (HTML::Pipeline)  |
 |  clean HTML, fix links,   |
 |  extract entries          |
 +---------------------------+
        |
        v
 HTML partials + index.json + db.json
        |
        v  (served by Sinatra app)
 +---------------------------+
 | Browser app (JS)          |
 |  search over index        |
 |  pages in IndexedDB       |
 |  app shell via SW cache   |
 +---------------------------+
```

### 1. 스크레이퍼: 원본 문서를 정규화된 HTML로

스크레이퍼는 루트 URL에서 시작해 규칙에 맞는 링크를 재귀적으로 따라가며 페이지를 복사합니다. 종류는 두 가지입니다.

- **`UrlScraper`:** HTTP로 원본 사이트에서 직접 내려받습니다.
- **`FileScraper`:** 로컬 파일 시스템에 받아 둔 문서를 읽습니다. 페이지가 수백 개를 넘고 다운로드 가능한 문서라면 이쪽을 권장합니다. 개발 속도도 빠르고 원본 사이트에 부담도 주지 않기 때문입니다.

HTTP 요청은 Typhoeus, HTML 파싱은 Nokogiri, 필터 체인은 HTML::Pipeline 라이브러리가 맡습니다. 응답은 200 상태 코드이면서 HTML이고, 리다이렉트 후 최종 URL이 `base_url` 안에 있어야 처리됩니다.

가져온 각 문서에는 README에 나열된 다음과 같은 변형이 적용됩니다.

- `<html>`, `<head>` 같은 문서 구조, 주석, 빈 노드, 스크립트와 스타일시트 제거
- 외부 URL은 완전한 주소로, 내부(수집 대상) URL은 상대 경로로 변환
- 제목과 원본 문서 링크 추가
- [Prism](https://prismjs.com/)으로 구문 강조, [KaTeX](https://katex.org/)로 수식을 MathML로 변환
- 이미지를 내려받아 data URI로 넣고 WebP로 재인코딩

마지막 결과물은 정규화된 HTML 조각들과 JSON 파일 두 개(인덱스, 오프라인용 데이터)입니다. 여기에 현재 사용 가능한 문서 목록과 버전, 갱신일을 담은 **매니페스트** JSON이 따로 만들어집니다.

### 2. 웹 앱: 전부 클라이언트에서

앱은 **전부 클라이언트 사이드 JavaScript**입니다. 페이지 내용을 XHR로 받아 메인 프레임에 직접 넣는 구조라서 몇 가지 설계가 따라옵니다.

- 원본 문서의 스크립트와 스타일시트를 거의 다 걷어냅니다. 메인 프레임을 오염시키지 않기 위해서입니다.
- 모든 CSS 클래스 이름 앞에 밑줄(`_`)을 붙여 충돌을 막습니다.
- 사용자가 문서를 직접 골라 활성화하게 해서 메모리 사용량을 관리합니다.
- 검색 알고리즘은 일부러 단순하게 유지합니다. 10만 개 문자열을 검색해도 빨라야 하기 때문입니다.

앱은 import map으로 해석되는 ES 모듈 형태로 서빙되며, 이것 때문에 브라우저 요구 사항이 높습니다. README 기준으로 최신 Firefox, Chrome, Opera, 그리고 Safari 16.4+, Edge 89+, iOS 16.4+가 필요합니다.

### 3. 오프라인: IndexedDB + 서비스 워커

앱의 오프라인 페이지(`/offline`)에 있는 Q&A가 원리를 직접 설명합니다.

- 문서의 각 페이지는 **IndexedDB**(브라우저 내장 키-값 데이터베이스)에 키-값 쌍으로 저장됩니다. 다운로드 자체는 문서당 파일 하나로 받습니다.
- 인덱스 파일도 IndexedDB에 캐시됩니다.
- 앱 자체(HTML, JS, CSS)는 **서비스 워커**(Service Worker, 네트워크 요청을 가로채 캐시로 응답할 수 있는 브라우저 백그라운드 스크립트)가 캐시합니다. 부팅 속도를 위해 `localStorage`도 함께 씁니다.

그래서 서비스 워커가 동작하는 브라우저라면, 오프라인 상태에서 새 탭을 열고 devdocs.io에 접속해도 온라인처럼 동작합니다. 단, 쓰려는 문서를 미리 설치해 두어야 합니다.

## 주요 기능

### 문서 관리

- 설정(Preferences, `/settings`)에서 문서를 켜고 끕니다. 검색창에 문서 이름을 쳐서 결과의 "Enable" 링크로 바로 켤 수도 있습니다.
- 처음에는 CSS, DOM, HTML, HTTP, JavaScript 다섯 가지가 기본으로 켜져 있습니다(`lib/app.rb`의 `default_docs`).
- 공식 도움말은 **실제로 쓸 문서만 켜라**고 권합니다. 켠 문서가 적을수록 검색이 빠르고 결과가 깔끔합니다.
- `lib/docs/scrapers` 디렉터리에는 2026-10-20 기준 230개가 넘는 스크레이퍼 항목이 있습니다. 문서 하나에 여러 버전이 있는 경우도 많아서, 실제로 고를 수 있는 문서 세트는 그보다 많습니다.

### 검색

공식 도움말(`?` 키로 열림)에 적힌 검색 규칙입니다.

- 대소문자를 구분하지 않고 공백을 무시합니다.
- **퍼지 매칭**(fuzzy matching, 글자가 순서대로만 들어 있으면 중간이 빠져도 찾아 주는 방식)을 지원합니다. 도움말의 예시로 `bgcp`를 치면 `background-clip`이 나옵니다.
- **단일 문서 검색:** 문서 이름이나 약어를 치고 `Tab`(모바일은 `Space`)을 누르면 그 문서로 범위가 좁혀집니다. 예를 들어 `js` + `Tab` 후 `date`를 입력합니다. 범위를 해제하려면 검색창을 비우고 `Backspace`나 `Esc`를 누릅니다.
- **별칭(alias):** 자주 쓰는 약어가 정의돼 있습니다. 일부만 옮기면 다음과 같습니다(`lib/docs.rb`의 `aliases`).

| 문서 | 별칭 | 문서 | 별칭 |
|---|---|---|---|
| javascript | `js` | typescript | `ts` |
| python | `py` | ruby | `rb` |
| rust | `rs` | postgresql | `pg` |
| kubernetes | `k8s` | nginx | `ngx` |
| numpy | `np` | pandas | `pd` |
| openjdk | `java` | cpp | `c++` |
| angular | `ng` | markdown | `md` |

### URL로 검색 미리 채우기

`devdocs.io/#q=keyword` 형태로 접속하면 `#q=` 뒤의 문자열이 검색어로 들어갑니다. 특정 문서만 검색하려면 문서 이름(또는 약어)과 공백을 앞에 붙입니다. 예: `devdocs.io/#q=js date`. 이 기능은 **활성화된 문서에만** 적용됩니다.

### 주소창 검색 엔진 등록 (OpenSearch)

DevDocs는 OpenSearch(웹사이트가 브라우저에 검색 엔진으로 등록되도록 하는 표준)를 지원합니다.

- **Chrome:** 자동으로 설정됩니다. 주소창에서 devdocs.io가 자동 완성될 때 `Tab`을 누르면 됩니다. 키워드를 바꾸려면 설정의 "검색엔진 관리"에서 지정합니다.
- **Firefox:** 주소창의 `•••` 메뉴에서 "검색 엔진 추가"를 선택한 뒤, 환경 설정에서 키워드를 붙입니다.

### 키보드 단축키

앱 내 도움말 페이지에 정리된 단축키 중 자주 쓰는 것들입니다. macOS에서는 표의 `ctrl`이 `cmd`로, "뒤로/앞으로"의 `alt`도 `cmd`로 바뀝니다.

| 동작 | 단축키 |
|---|---|
| 사이드바 선택 이동 | `↓` `↑` |
| 하위 목록 펼치기/접기 | `→` `←` |
| 선택 항목 열기 / 새 탭으로 열기 | `enter` / `ctrl + enter` |
| 선택을 옮기면서 바로 열기 | `ctrl + shift + ↓` / `↑` |
| 현재 페이지를 사이드바에서 찾기 | `alt + r` |
| 뒤로 / 앞으로 | `alt + ←` / `alt + →` |
| 맨 위 / 맨 아래로 스크롤 | `ctrl + ↑` / `ctrl + ↓` |
| 본문의 첫 링크에 포커스 | `alt + f` |
| 환경 설정 열기 | `ctrl + ,` |
| 검색창 비우기 / UI 초기화 | `esc` |
| 도움말 보기 | `?` |
| 원본 페이지 URL 복사 / 원본 페이지 열기 | `alt + c` / `alt + o` |
| Google / Stack Overflow / DuckDuckGo에서 검색 | `alt + g` / `alt + s` / `alt + d` |

또 하나 알아 두면 좋은 팁이 있습니다. 커서가 검색창에 없을 때 `/`를 누르거나 그냥 타이핑을 시작하면 검색창으로 포커스가 돌아갑니다. README의 치트시트에는 `Ctrl + K`로 검색창에 포커스하기, `Shift + S`로 사이드바 토글 같은 항목도 함께 나옵니다.

### 오프라인 관리 화면

`/offline` 페이지에서 할 수 있는 일입니다.

- 문서별 크기와 상태를 보고 개별 설치/업데이트/삭제
- "Install all", "Update all", "Uninstall all"로 일괄 처리
- "활성화한 문서를 자동으로 오프라인 설치" 옵션 (대역폭 걱정이 없을 때만 켜라는 안내가 붙어 있습니다)
- "오프라인 문서 업데이트 자동 설치" 옵션
- **Export all / Import:** 설치한 문서를 파일로 내보내고 다른 컴퓨터에서 가져올 수 있습니다. 다만 가져오는 컴퓨터도 앱 자체를 캐시하려면 한 번은 온라인으로 DevDocs를 열어야 합니다.
- **영구 저장소(persistent storage) 요청:** 브라우저는 디스크가 부족하고 한동안 쓰지 않은 사이트의 데이터를 지울 수 있습니다. 이 페이지의 "Enable persistent storage" 버튼으로 이를 막도록 요청할 수 있습니다.

### 기타

- 다크 테마, 모바일 버전을 지원합니다.
- 각 페이지 하단에 원본 문서 링크와 저작권/라이선스 정보가 붙습니다. 수집된 문서들의 라이선스 목록은 [About 페이지](https://devdocs.io/about)에 표로 정리돼 있습니다.

## 설치와 시작

### 그냥 쓰기 (권장)

README는 기여할 생각이 없다면 호스팅 버전 [devdocs.io](https://devdocs.io)를 쓰라고 권합니다. 항상 최신이고 별도 설정 없이 오프라인으로 동작합니다.

1. devdocs.io에 접속합니다.
2. 왼쪽 아래 설정(Preferences)에서 자주 쓰는 문서와 버전을 켭니다.
3. `/offline`에서 필요한 문서를 설치합니다.
4. 주소창 검색 엔진으로 등록해 둡니다.

### Docker로 직접 띄우기

사내망이나 개인 서버에 두고 싶다면 README의 Docker 명령이 가장 간단합니다.

```bash
docker run --name devdocs -d -p 9292:9292 ghcr.io/freecodecamp/devdocs:latest
```

`localhost:9292`에서 열립니다. 이미지는 두 가지입니다.

- `ghcr.io/freecodecamp/devdocs:latest`: 표준 이미지
- `ghcr.io/freecodecamp/devdocs:latest-alpine`: Alpine 기반의 더 작은 이미지

README에 따르면 이미지는 최신 문서를 포함해 **매월 자동으로 다시 빌드**됩니다. 직접 빌드하려면 다음과 같습니다.

```bash
git clone https://github.com/freeCodeCamp/devdocs.git && cd devdocs
docker build -t devdocs .
docker run --name devdocs -d -p 9292:9292 devdocs
```

### 수동 설치 (개발용)

README 기준 요구 사항은 `Gemfile`에 정의된 Ruby 버전(문서 작성 시점 README는 Ruby 4.0.7로 표기), libcurl, bsdtar(Debian/Alpine은 `libarchive-tools` 패키지), 그리고 ExecJS가 지원하는 JavaScript 런타임(Linux는 Node.js)입니다.

```bash
git clone https://github.com/freeCodeCamp/devdocs.git && cd devdocs
gem install bundler
bundle install
bundle exec thor docs:download --default
bundle exec rackup
```

브라우저에서 `localhost:9292`를 열면 됩니다. 첫 요청은 에셋 컴파일 때문에 몇 초 걸립니다.

`thor docs:download`는 DevDocs 서버에서 **미리 생성된 문서**를 내려받는 명령입니다. 직접 스크레이핑할 필요가 없습니다.

```bash
bundle exec thor docs:list                 # 받을 수 있는 문서와 버전 목록
bundle exec thor docs:download html css    # 특정 문서만
bundle exec thor docs:download --default   # 기본 문서 세트
bundle exec thor docs:download --installed # 이미 받은 문서 모두 업데이트
bundle exec thor docs:download --all       # 전체 문서
```

코드 업데이트 방법은 README에 명시된 대로 `git pull origin main`과 `thor docs:download --installed` 조합뿐입니다. 별도의 업데이트 메커니즘은 없습니다.

## 실전 활용 시나리오

### 1. 주소창 한 번으로 레퍼런스 찾기

가장 효과가 큰 설정입니다.

1. Chrome에서 devdocs.io를 한 번 방문합니다.
2. 설정, 검색엔진 관리에서 DevDocs 항목의 단축어를 `dd`처럼 짧게 바꿉니다.
3. 이제 주소창에 `dd` + `Tab` 후 `flex-basis`를 치면 바로 결과로 갑니다.

검색 엔진 등록이 어려운 환경이라면 북마크에 `https://devdocs.io/#q=%s`를 키워드 북마크로 만들어도 같은 효과를 낼 수 있습니다. `#q=` 동작은 공식 문서에 있지만, `%s` 키워드 북마크는 브라우저 기능이니 브라우저별로 지원 여부를 확인하세요.

### 2. 비행기, 폐쇄망 대비 오프라인 세팅

1. 출발 전에 설정에서 프로젝트에 필요한 문서만 켭니다. 예: `Python 3.x`, `Django`, `PostgreSQL`, `Docker`.
2. `/offline`에서 "Install all"을 누릅니다.
3. 같은 페이지에서 "Enable persistent storage"를 눌러 브라우저가 데이터를 지우지 않게 요청합니다.
4. 네트워크를 끄고 새 탭에서 devdocs.io를 열어 실제로 동작하는지 확인합니다.

팀원 여러 명이 같은 문서 세트를 써야 한다면 "Export all"로 파일을 만들어 공유하고, 각자 "Import"로 가져오면 다운로드를 반복하지 않아도 됩니다.

### 3. 사내망에 DevDocs 미러 띄우기

외부 인터넷이 막힌 개발망에서 쓰는 경우입니다.

```bash
# 인터넷이 되는 곳에서 이미지 받기
docker pull ghcr.io/freecodecamp/devdocs:latest-alpine
docker save ghcr.io/freecodecamp/devdocs:latest-alpine -o devdocs.tar

# 폐쇄망 서버로 옮긴 뒤
docker load -i devdocs.tar
docker run --name devdocs -d --restart unless-stopped \
  -p 9292:9292 ghcr.io/freecodecamp/devdocs:latest-alpine
```

`docker save`/`docker load`, `--restart`는 Docker 자체 기능입니다. 이미지가 매월 갱신되므로 문서를 최신으로 유지하려면 주기적으로 새 이미지를 받아 교체하면 됩니다. 이렇게 띄운 인스턴스가 브라우저 오프라인 기능까지 쓸 수 있는지는 배포 환경(HTTPS 여부, 서비스 워커 설정)에 따라 다릅니다. 앱 코드상 서비스 워커는 production 환경이거나 `ENABLE_SERVICE_WORKER=true`일 때만 켜지고, 브라우저는 보통 HTTPS나 localhost에서만 서비스 워커를 허용합니다.

### 4. 에디터와 연결하기

README의 "Related Projects" 표에는 커뮤니티가 만든 연동 도구가 정리돼 있습니다. Alfred, Raycast 확장, VS Code 확장, Vim/Neovim 플러그인, Emacs 패키지, 터미널 뷰어(`dedoc`) 등이 있습니다. 대부분은 결국 `devdocs.io/#q=...` 같은 URL을 열거나 DevDocs 데이터를 읽는 방식입니다. 공식 프로젝트가 아니므로 유지 상태는 각 저장소에서 확인하세요.

### 5. 새 문서 추가하기 (스크레이퍼 작성)

원하는 문서가 없다면 직접 추가할 수 있습니다. 공식 가이드([adding-docs.md](https://github.com/freeCodeCamp/devdocs/blob/main/docs/adding-docs.md))의 흐름을 요약하면 다음과 같습니다.

1. `lib/docs/scrapers/my_doc.rb`에 `Docs::UrlScraper` 또는 `Docs::FileScraper`의 하위 클래스를 만듭니다. 클래스 이름은 파일 이름의 PascalCase(`my_doc` → `MyDoc`)입니다.
2. `thor docs:list`에 나오는지 확인합니다.
3. `lib/docs/filters/my_doc/`에 최소 두 개의 필터를 만듭니다. HTML을 정리하는 `CleanHtml`과, 엔트리(이름, 타입, 경로)를 뽑는 `Entries`입니다.
4. `thor docs:page my_doc 경로`로 한 페이지만 먼저 확인합니다.
5. `thor docs:generate my_doc --force`로 전체를 생성합니다. `--verbose`, `--debug`로 무엇이 생성되고 어떤 URL이 큐에 들어가는지 볼 수 있습니다.
6. 서버를 띄워 문서를 켜고 결과를 확인하며 반복합니다.
7. 아이콘(16x16, 32x32), 저작권 정보(`options[:attribution]`), 최신 버전 확인 메서드(`get_latest_version`)를 채웁니다.

실제 저장소의 Axios 스크레이퍼는 아래처럼 짧습니다(`links` 일부 생략).

```ruby
module Docs
  class Axios < UrlScraper
    self.type = 'simple'
    self.release = '1.15.0'
    self.base_url = "https://axios-http.com/docs/"
    self.initial_paths = %w(index intro)
    options[:skip] = %w(sponsor)

    html_filters.push 'axios/entries', 'axios/clean_html'

    options[:attribution] = <<-HTML
      &copy; 2020-present John Jakob "Jake" Sarjeant<br>
      Licensed under the MIT License.
    HTML

    def get_latest_version(opts)
      get_latest_github_release('axios', 'axios', opts)
    end
  end
end
```

엔트리 필터는 페이지마다 이름과 타입을 돌려주는 메서드 두 개면 충분합니다.

```ruby
module Docs
  class Axios
    class EntriesFilter < Docs::EntriesFilter
      def get_name
        at_css('h1').content
      end

      def get_type
        'axios'
      end
    end
  end
end
```

`UrlScraper`는 받아 온 응답을 `tmp/cache/[slug]`에 HAR 형식 JSON으로 캐시합니다. 그래서 필터를 고치고 다시 생성해도 원본 사이트에 요청을 반복하지 않습니다. 원본 사이트의 변경을 반영하려면 `thor docs:clean`으로 캐시를 비워야 합니다.

## 실무 팁 & 자주 겪는 문제

- **검색 결과가 너무 많거나 엉뚱할 때:** 쓰지 않는 문서를 끄세요. 공식 도움말도 "실제로 쓸 문서만 켜라"고 권합니다. 특정 문서 안에서만 찾고 싶다면 `py` + `Tab`처럼 범위를 좁힙니다.
- **`#q=` URL이나 주소창 검색이 안 될 때:** 이 기능은 활성화된 문서에만 동작합니다. 해당 문서가 켜져 있는지 먼저 확인하세요.
- **오프라인인데 페이지가 안 열릴 때:** 문서를 "켜기"만 하고 "설치"는 안 한 경우가 많습니다. `/offline`에서 상태가 설치됨인지 확인하세요. 브라우저가 디스크 부족으로 데이터를 지웠을 수도 있으니 영구 저장소를 요청해 두는 편이 안전합니다.
- **오프라인 문서를 업데이트하지 않으면:** 공식 Q&A에 따르면 검색과 사이드바 데이터는 다른 캐시 방식으로 자동 갱신되기 때문에, 설치된 본문이 오래되면 일부 페이지가 누락되거나 깨질 수 있습니다. 자동 업데이트 옵션을 켜 두는 것을 권합니다.
- **앱이 이상하게 동작할 때:** `/offline` 페이지 Q&A의 "How do I uninstall/reset the app?" 항목에 앱 초기화 링크가 있습니다.
- **셀프 호스팅에서 오프라인이 안 될 때:** 개발 모드에서는 서비스 워커가 꺼져 있습니다. `ENABLE_SERVICE_WORKER=true` 환경 변수가 필요하다고 앱 안내 문구에 나옵니다.
- **Ruby 버전이 여러 개 설치된 환경:** README는 모든 `thor` 명령을 `bundle exec`로 실행하라고 안내합니다.
- **문서 버전 확인:** 같은 라이브러리라도 여러 버전이 따로 있습니다. 설정에서 내가 쓰는 버전을 골라 켜야 합니다.
- **개인정보 관점:** 검색과 문서 렌더링은 브라우저 안에서 처리됩니다. 설정 화면에는 "Enable tracking cookies" 체크박스가 있고, 켜면 Google Analytics와 Gauges가 익명 트래픽 정보를 수집한다고 적혀 있습니다. 원치 않으면 꺼 두세요. 앱 설정 코드에는 오류 보고용 Sentry 설정 항목도 있습니다. 외부 서비스로 나가는 요청 자체가 부담스러운 환경이라면 셀프 호스팅이 가장 확실합니다.

## 비슷한 도구와 비교

아래 비교는 필자의 일반적인 경험과 각 제품의 공개 정보를 바탕으로 한 것이며, 세부 기능은 버전에 따라 다를 수 있습니다.

| 항목 | DevDocs | Dash (macOS) | Zeal | 각 공식 사이트 직접 (예: MDN) | AI 챗봇 |
|---|---|---|---|---|---|
| 형태 | 웹 앱 (셀프 호스팅 가능) | 네이티브 앱 | 네이티브 앱 (Windows/Linux) | 웹사이트 | 웹/앱 |
| 가격 | 무료, 오픈소스(MPL 2.0) | 유료(평가판 있음) | 무료, 오픈소스 | 무료 | 무료~유료 |
| 오프라인 | 브라우저 저장소에 설치 | 문서 세트(docset) 다운로드 | Dash docset 형식 사용 | 대체로 불가 | 불가(로컬 모델 제외) |
| 검색 | 이름 기반 퍼지 검색, 매우 빠름 | 이름 기반, 에디터 연동 강함 | 이름 기반 | 사이트별 검색 품질 상이 | 자연어 질문 |
| 문서 디자인 | 모든 문서 통일 | 원본에 가까움 | 원본에 가까움 | 원본 그대로 | 요약/재구성 |
| 정확성 | 원본 레퍼런스 그대로 | 원본 그대로 | 원본 그대로 | 원본 | 틀릴 수 있음, 검증 필요 |
| 튜토리얼/가이드 | 범위 밖 | 일부 포함 | 일부 포함 | 풍부 | 풍부 |

- **Dash**는 macOS에서 에디터, 스니펫 관리, 다양한 docset과의 연동이 강점인 상용 앱입니다. macOS 사용자이고 IDE 연동을 중시하면 좋은 선택입니다.
- **Zeal**은 Dash의 docset을 쓰는 오픈소스 데스크톱 앱입니다. 브라우저 밖에서 네이티브 창으로 보고 싶을 때 적합합니다.
- **공식 사이트 직접**은 튜토리얼, 예제, 호환성 표처럼 DevDocs가 일부러 빼 둔 맥락까지 볼 수 있습니다. 개념을 처음 배울 때는 원본 사이트가 낫습니다.
- **AI 챗봇**은 "어떻게 하지?" 같은 열린 질문에 강하지만, 인자 순서나 반환 타입처럼 정확해야 하는 정보는 결국 레퍼런스로 확인해야 합니다. DevDocs는 그 확인 단계를 빠르게 해 주는 도구로 함께 쓰기 좋습니다.

## 장점과 한계

**장점**

- 설치 없이 브라우저만 있으면 됩니다. 계정도 필요 없습니다.
- 이름 기반 퍼지 검색이 매우 빠르고, 키보드만으로 거의 모든 조작이 가능합니다.
- 수백 종의 문서가 같은 디자인으로 정리돼 있어 문서 사이를 오갈 때 피로가 적습니다.
- 오프라인 설치, 내보내기/가져오기, 영구 저장소 요청까지 오프라인 지원이 탄탄합니다.
- Docker 이미지 한 줄로 셀프 호스팅할 수 있고, 이미지가 매월 갱신됩니다.
- 스크레이퍼 구조가 문서화돼 있어서 원하는 문서를 직접 추가하는 길이 열려 있습니다.

**한계**

- **레퍼런스 전용입니다.** 튜토리얼, 가이드, 블로그 성격의 콘텐츠는 의도적으로 제외됩니다.
- **본문 전문 검색이 아닙니다.** 엔트리 이름을 모르면 원하는 내용을 찾기 어렵습니다.
- 원본 사이트가 개편되면 스크레이퍼가 깨지거나 업데이트가 늦을 수 있습니다. 문서별 최신성은 일정하지 않습니다.
- 정식 릴리스나 버전 번호가 없습니다. 셀프 호스팅은 `git pull`이나 새 Docker 이미지로 갱신해야 합니다.
- README 상단에 "메인테이너를 찾고 있다"는 공지가 있습니다. 커밋은 꾸준하지만 유지 인력이 넉넉하지는 않다는 신호로 볼 수 있습니다.
- 브라우저 요구 사항이 높아 오래된 브라우저에서는 동작하지 않습니다.
- 오프라인 데이터가 브라우저 저장소에 있어서, 브라우저 데이터 삭제나 저장소 정리 정책의 영향을 받습니다.

## 이런 분께 추천

- 여러 언어와 프레임워크를 오가며 API 레퍼런스를 자주 찾는 개발자
- 키보드 중심으로 빠르게 일하는 것을 좋아하는 분
- 출장, 이동 중, 폐쇄망 등 인터넷이 불안정한 환경에서 개발하는 분
- 사내 개발망에 문서 미러를 가볍게 두고 싶은 인프라 담당자
- 좋아하는 라이브러리의 문서를 직접 추가해 오픈소스에 기여하고 싶은 분 (Ruby 경험이 있으면 수월합니다)

## 이런 경우엔 다른 도구

- 개념 설명, 튜토리얼, 예제 중심으로 처음 배우는 중이라면: 각 프로젝트의 **공식 사이트**
- macOS에서 IDE와 깊게 연동되는 네이티브 문서 앱이 필요하다면: **Dash**
- 브라우저 밖에서 네이티브 창으로 오프라인 문서를 보고 싶다면: **Zeal**
- 본문 내용까지 전문 검색해야 한다면: 검색 엔진이나 사이트 자체 검색
- "이 상황에서 어떻게 구현하지?" 같은 열린 질문이라면: AI 챗봇에 묻고, 답의 세부는 DevDocs로 확인

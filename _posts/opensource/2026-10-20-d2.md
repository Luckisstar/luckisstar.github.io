# [오픈소스 소개] D2: 텍스트로 그리는 현대적인 다이어그램 언어

- **저장소:** [d2lang/d2](https://github.com/d2lang/d2) · [d2lang.com](https://d2lang.com) · [문서(Tour)](https://d2lang.com/tour/intro) · [Playground](https://play.d2lang.com)
- **라이선스:** MPL 2.0
- **언어:** Go
- **현황 (2026-10-20 기준):** GitHub 스타 약 2.6만 개, 최신 릴리스 v0.9.0 (2026년 9월 7일)

## 한 줄 요약

**`x -> y` 같은 짧은 텍스트를 쓰면 배치와 선 연결은 레이아웃 엔진이 알아서 해 주는 "텍스트-다이어그램(text-to-diagram)" 언어**입니다. 아키텍처 그림, 시퀀스 다이어그램, ERD를 코드처럼 Git에 넣고 리뷰할 수 있고, 테마와 손그림 스타일, 애니메이션, 여러 장짜리 다이어그램까지 CLI 하나로 SVG·PNG·PDF·PPTX·GIF로 뽑아냅니다.

## 어떤 문제를 푸나

팀에서 다이어그램을 관리하다 보면 이런 일이 반복됩니다.

- draw.io나 PPT로 그린 그림은 **원본 파일이 어디 있는지 모르고**, 누가 무엇을 바꿨는지 diff로 볼 수 없습니다.
- 박스 하나 추가하면 **나머지 박스와 화살표를 손으로 다시 정렬**해야 합니다.
- 코드는 바뀌었는데 문서의 그림은 몇 달 전 상태로 남습니다.

텍스트로 다이어그램을 정의하면 이 문제가 상당 부분 사라집니다. 원본이 텍스트라 PR에서 변경점이 보이고, 위치는 레이아웃 엔진이 계산하므로 노드를 추가해도 다시 그릴 필요가 없습니다. Mermaid, PlantUML, Graphviz가 같은 문제를 푸는 선배 도구인데, D2는 여기에 **읽기 쉬운 문법, 보기 좋은 기본 결과물, 여러 레이아웃 엔진 선택, 다중 보드(composition)** 를 더한 것이 특징입니다.

```d2
x -> y -> z
```

이 한 줄이 세 개의 박스와 두 개의 화살표가 됩니다.

## 핵심 개념

D2 문법은 몇 가지 개념만 알면 대부분을 읽을 수 있습니다.

| 개념 | 문법 예 | 설명 |
|---|---|---|
| 셰이프(shape) | `server` | 이름만 쓰면 사각형 노드가 생깁니다. 이 이름이 **키(key)** 입니다 |
| 라벨 | `pg: PostgreSQL` | 키는 `pg`, 화면에 보이는 글자는 `PostgreSQL` |
| 셰이프 종류 | `pg.shape: cylinder` | `circle`, `cloud`, `person`, `queue`, `page`, `hexagon` 등 |
| 연결(connection) | `a -> b: label` | `--`, `->`, `<-`, `<->` 네 가지 |
| 컨테이너 | `aws: { api; db }` | 중괄호 안에 노드를 넣으면 그룹 박스가 됩니다 |
| 경로 참조 | `aws.api -> aws.db` | 점(`.`)으로 컨테이너 안의 노드를 가리킵니다 |
| 부모 참조 | `_.other` | 컨테이너 안에서 바깥 노드를 가리킬 때 `_` 사용 |
| 스타일 | `style.fill: "#E3F2FD"` | 색, 테두리, 그림자, 점선 등 |
| 주석 | `# comment` | `#` 뒤는 주석 |

몇 가지 규칙이 초보자를 자주 헷갈리게 합니다.

- **연결은 라벨이 아니라 키를 참조합니다.** `be: Backend` 로 정의했다면 `be -> fe` 로 써야 합니다. `Backend -> Frontend` 라고 쓰면 새 노드가 두 개 더 생깁니다.
- **키는 대소문자를 구분하지 않습니다.** `postgresql` 과 `postgreSQL` 은 같은 노드입니다.
- **같은 연결을 두 번 쓰면 덮어쓰지 않고 두 번째 화살표가 추가됩니다.** 특정 연결을 나중에 수정하려면 `(x -> y)[0].style.stroke: red` 처럼 인덱스로 참조합니다.
- 한 줄에 여러 노드를 정의할 때는 세미콜론을 씁니다. `SQLite; Cassandra`
- 하이픈 하나(`a-shape`)는 연결이 아니라 이름의 일부입니다. `a--shape` 는 연결입니다.

### 보드와 컴포지션

지금까지의 다이어그램은 모두 "루트 보드" 한 장입니다. D2는 한 파일에 여러 장의 보드를 정의할 수 있고, 이를 **컴포지션(composition)** 이라고 부릅니다. 보드를 만드는 키워드는 세 가지이며 상속 규칙이 다릅니다.

| 키워드 | 상속 | 용도 |
|---|---|---|
| `layers` | 아무것도 상속하지 않는 새 보드 | 추상화 단계별 상세도 (클릭해서 들어가기) |
| `scenarios` | 기반 레이어를 상속 | 같은 그림의 다른 상황 (평상시 vs 장애 시) |
| `steps` | 바로 앞 단계를 상속 | 순서대로 쌓아 가는 설명, 발표용 애니메이션 |

### 변수, 클래스, 임포트

- **`vars` 와 `${name}`:** 반복되는 값을 변수로 뺍니다. 작은따옴표 문자열 안에서는 치환되지 않습니다.
- **`classes`:** 스타일 묶음을 정의하고 `class: 이름` 으로 적용합니다. 배열로 여러 개를 주면 왼쪽부터 차례로 적용됩니다.
- **`@파일` 임포트:** `a: @x` 는 `x.d2` 전체를 `a` 의 값으로, `...@x` 는 현재 맵에 펼쳐 넣습니다. 경로는 실행 위치가 아니라 **파일 기준 상대 경로**입니다.
- **`vars.d2-config`:** 레이아웃 엔진, 테마, 스케치 여부 같은 렌더 설정을 파일 안에 적어 둘 수 있습니다. 단, CLI 플래그와 환경 변수가 우선합니다.

## 동작 원리

`d2` CLI는 크게 세 단계로 동작합니다.

```
 in.d2 (text)
     │
     ▼
 ┌──────────────┐  parse, compile
 │  Compiler    │  vars, imports, globs, classes
 └──────┬───────┘
        ▼
 ┌──────────────┐  dagre (default)
 │ Layout engine│  elk / tala
 └──────┬───────┘  + sequence, grid layouts
        ▼
 ┌──────────────┐  themes, sketch
 │  Renderer    │  SVG/PNG/PDF/PPTX/GIF/TXT
 └──────────────┘
```

1. **컴파일:** 텍스트를 파싱해 그래프(노드, 연결, 스타일)로 만듭니다. 파서는 망가진 파일에서도 오류를 여러 개 한꺼번에 보고하도록 설계되어 있습니다.
2. **레이아웃:** 각 노드의 좌표와 선 경로를 계산합니다. 엔진을 바꾸면 같은 소스에서 전혀 다른 배치가 나옵니다. 시퀀스 다이어그램과 그리드는 별도의 전용 레이아웃이 처리합니다.
3. **렌더링:** 테마 색과 폰트를 입혀 결과 파일을 씁니다.

### 레이아웃 엔진 세 가지

README와 `d2 layout` 출력 기준으로 v0.9.0에는 세 엔진이 모두 기본 포함(bundled)되어 있습니다.

| 엔진 | 특징 |
|---|---|
| **dagre** (기본값) | Graphviz DOT 알고리즘 계열의 계층형 레이아웃. 빠르고 무난합니다. v0.9.0 README 기준으로 Dagre를 Go로 옮긴 Dagro를 씁니다 |
| **ELK** | 방향성 있는 노드-링크 그림과 포트(port) 연결에 강합니다. Go 포트(elk-go)가 포함되어 있습니다 |
| **TALA** | Terrastruct가 소프트웨어 아키텍처 다이어그램용으로 만든 엔진. 직교(orthogonal) 배치, 대칭 선호, 컨테이너 친화적 |

**TALA는 원래 별도 설치와 유료 라이선스 키가 필요한 독점 엔진이었습니다.** 그런데 v0.9.0 릴리스 노트에 "TALA is now open source and bundled with D2 ... No separate plugin installation or license key is required." 라고 명시되었습니다. 이전 버전 기준으로 작성된 블로그 글이나 비교표에는 "TALA는 유료"라고 나와 있을 수 있으니 버전을 확인하세요.

엔진에 따라 지원 기능이 다릅니다. 레이아웃 문서가 정리한 내용은 이렇습니다.

- `near` 를 **다른 객체**로 지정하는 것은 TALA만 됩니다. `top-center` 같은 상수 위치는 모든 엔진에서 됩니다.
- 컨테이너의 `width`, `height` 는 TALA와 ELK에서 동작합니다.
- `top`, `left` 로 위치를 고정하는 기능은 TALA 전용입니다.
- 컨테이너별 `direction` 은 TALA 전용이고, 다른 엔진은 전역 방향만 지원합니다.
- 컨테이너에서 자기 자식으로 가는 연결은 dagre에서 동작하지 않습니다.
- `sql_table` 의 외래 키 화살표가 **정확한 행(row)** 을 가리키는 것은 ELK와 TALA입니다.

TALA의 단점으로 문서는 "무작위성이 있어 라벨 하나만 바꿔도 배치가 크게 달라질 수 있다"를 꼽습니다. v0.9.0에서는 `--tala-seeds` 로 시도할 시드를 지정할 수 있게 되었습니다.

## 주요 기능

### 다양한 셰이프와 특수 다이어그램

- 기본 셰이프: `rectangle`, `square`, `circle`, `oval`, `diamond`, `cylinder`, `queue`, `page`, `hexagon`, `cloud`, `person`, `parallelogram` 등
- **`sql_table`:** 각 키가 컬럼, 값이 타입, `constraint` 로 `primary_key`(PK), `foreign_key`(FK), `unique`(UNQ) 표기
- **`class`:** UML 클래스. `(` 가 들어간 키는 메서드, `+ - #` 접두사로 public/private/protected
- **`sequence_diagram`:** 별도 문법 없이 같은 D2 문법으로 시퀀스 다이어그램. 단, 이 안에서만 **정의 순서가 곧 표시 순서**입니다
- **그리드:** `grid-rows`, `grid-columns` 로 표 형태 배치
- `shape: image` 로 아이콘만 단독 노드로 쓰기, `shape: text` 로 텍스트만 배치

### 텍스트, 코드, 수식

블록 문자열 `|md ... |` 로 마크다운을, `|go ... |` 처럼 언어 이름을 주면 문법 강조된 코드를, `|latex ... |` 로 수식을 넣습니다. 수식은 MathJax 기반이라 수학 표기용이며 일반 LaTeX 문서 서식은 지원하지 않습니다. 한국어, 일본어, 이모지도 라벨에 그대로 쓸 수 있습니다.

### 아이콘과 위치

- `icon: https://...` 로 어떤 URL 이미지든 붙일 수 있고, CLI에서는 `icon: ./cat.png` 같은 로컬 파일도 됩니다. 아키텍처용 무료 아이콘 모음이 [icons.d2lang.com](https://icons.d2lang.com) 에 있습니다.
- `near: top-center` 처럼 제목, 범례, 설명 박스를 다이어그램 가장자리에 고정합니다.
- `label.near`, `icon.near` 로 라벨과 아이콘 위치를 조정하고, `outside-` 접두사로 셰이프 바깥에 둘 수도 있습니다.
- `direction: right` 로 흐름 방향(`up`, `down`, `right`, `left`)을 정합니다.

### 스타일, 테마, 스케치

- `style` 키워드: `fill`, `stroke`, `stroke-width`, `stroke-dash`, `border-radius`, `shadow`, `3d`, `multiple`, `double-border`, `opacity`, `font-size`, `font-color`, `bold`, `italic`, `underline`, `text-transform`, `animated`, `fill-pattern` 등
- 테마: `d2 themes` 로 목록 확인. `Terminal`(300), `C4`(303) 처럼 색 이상을 바꾸는 특수 테마도 있습니다
- 다크 모드: `--dark-theme 200` 을 주면 보는 사람의 시스템 설정이 다크일 때 다른 테마로 바뀌는 SVG가 됩니다
- `theme-overrides` 로 기존 테마의 색 코드만 바꿀 수 있습니다
- `--sketch` 로 손으로 그린 듯한 스타일(내부적으로 Rough.js 포트 사용)

### 인터랙티브 요소

- `tooltip:` 은 마우스를 올리면 보이는 설명, `link:` 는 클릭하면 이동하는 링크입니다. 레이어 이름(`layers.detail`)을 링크로 걸면 상세 보드로 들어가는 구조를 만들 수 있습니다.
- PNG처럼 인터랙션이 없는 형식으로 내보내면 툴팁과 링크가 번호로 바뀌고 부록(appendix)이 붙습니다.

### 내보내기 형식

| 형식 | 명령 | 메모 |
|---|---|---|
| SVG | `d2 in.d2 out.svg` | 기본값. 출력을 생략하면 `in.svg` |
| PNG | `d2 in.d2 out.png` | v0.9.0부터 내장 렌더러, 외부 브라우저 불필요 |
| PDF | `d2 in.d2 out.pdf` | 링크는 클릭 가능, 애니메이션은 안 됨 |
| PPTX | `d2 in.d2 out.pptx` | 여러 보드를 슬라이드로 |
| GIF | `d2 in.d2 out.gif` | 짧은 scenario/steps 반복 재생용 |
| ASCII | `d2 in.d2 out.txt` | 0.7.1부터 베타. ELK/TALA로만 렌더 |
| stdout | `d2 - -` | `--stdout-format=png` 등으로 형식 지정 |

### 도구와 연동

- `d2 fmt` 자동 포매터, `d2 fmt --check` 로 CI 검사, `d2 validate` 로 문법 검증
- `d2 play in.d2` 로 온라인 Playground에서 열기
- 공식 플러그인: VS Code 확장, Vim 확장, Obsidian 플러그인
- README에 나열된 커뮤니티 플러그인: MkDocs, VitePress, Remark/Rehype, mdBook, Pandoc 필터, Goldmark, Confluence, Zed, Emacs, Logseq, Postgres 스키마에서 ERD 생성 등
- **Go 라이브러리:** Go 프로그램 안에서 다이어그램 생성 (`docs/examples/lib`)
- **D2.js:** `npm install @d2lang/d2` 로 브라우저와 Node에서 WebAssembly로 실행. Playground가 이것으로 만들어졌습니다

## 설치와 시작

공식 설치 스크립트가 가장 간단합니다. 패키지 매니저가 있으면 그것을 쓰도록 알아서 판단하며, `--dry-run` 으로 실행할 명령을 먼저 볼 수 있습니다.

```bash
# 무엇을 할지 먼저 확인
curl -fsSL https://d2lang.com/install.sh | sh -s -- --dry-run
# 실제 설치
curl -fsSL https://d2lang.com/install.sh | sh -s --
d2 --version
```

다른 방법도 있습니다.

```bash
brew install d2                              # macOS (macOS 13 이상)
go install github.com/d2lang/d2@latest       # Go 소스 설치 (man 페이지 미포함)
scoop install main/d2                        # Windows
choco install d2                             # Windows
```

Docker 이미지는 `d2lang/d2` 입니다(이전 이름 `terrastruct/d2` 는 호환용 미러).

```bash
docker run --rm -it -u "$(id -u):$(id -g)" -v "$PWD:/home/debian/src" \
  -p 127.0.0.1:8080:8080 d2lang/d2:v0.9.0 --watch helloworld.d2
```

설치가 끝나면 감시 모드로 시작해 보세요.

```bash
echo 'x -> y -> z' > in.d2
d2 --watch in.d2 out.svg
```

브라우저 창이 열리고, `in.d2` 를 저장할 때마다 그림이 자동으로 새로고침됩니다. 브라우저를 띄우지 않으려면 `--browser 0` 을 줍니다.

FAQ에 따르면 D2는 설치 후 텔레메트리를 수집하지 않고, 주기적인 버전 업데이트 확인 외에는 인터넷 연결을 쓰지 않습니다. 브라우저 없이 서버 측에서만 실행할 수도 있습니다.

## 실전 예제

아래 예제는 모두 v0.9.0 바이너리로 렌더링이 성공하는 것을 확인했습니다.

### 예제 1. 시스템 아키텍처 다이어그램

컨테이너, 클래스, 아이콘, 제목, 셰이프 종류를 한 번에 쓰는 예입니다.

```d2
vars: {
```

포인트는 이렇습니다.

- `vars.d2-config` 에 엔진과 테마를 적어 두면 팀원 누가 렌더해도 같은 설정이 됩니다.
- `style.multiple: true` 는 여러 인스턴스를 겹친 박스로 표현합니다.
- `mail` 은 연결에서 먼저 등장하고 뒤에서 라벨과 셰이프를 붙였습니다. D2에서는 선언 순서가 상관없습니다(시퀀스 다이어그램 제외).

### 예제 2. 로그인 시퀀스 다이어그램

```d2
shape: sequence_diagram

browser: Browser
api: API
auth: Auth Server
db: DB

browser -> api: POST /login
api -> auth: verify credentials
auth -> db: SELECT user
db -> auth: row
auth -> api: token

success: {
  api -> browser: 200 OK + cookie
}
failure: {
  api -> browser: 401 Unauthorized
}

api."Token expires in 1h"
```

- 액터(participant)를 맨 위에 먼저 선언하면 그 순서대로 왼쪽부터 배치됩니다.
- `success`, `failure` 처럼 아무것과도 연결되지 않은 컨테이너는 **그룹(fragment)** 이 됩니다. 그룹 안에서 참조하는 액터는 최상위에 미리 선언되어 있어야 합니다.
- 연결이 없는 하위 객체 `api."..."` 는 **노트**가 됩니다.
- `alice.t1 -> bob` 처럼 액터의 하위 객체에서 연결하면 활성 구간(span, activation bar)이 됩니다.

### 예제 3. ERD (sql_table)

```d2
direction: right

users: {
  shape: sql_table
  id: bigint {constraint: primary_key}
  email: varchar(255) {constraint: unique}
  created_at: timestamptz
}

orders: {
  shape: sql_table
  id: bigint {constraint: primary_key}
  user_id: bigint {constraint: foreign_key}
  total: numeric(10,2)
  status: varchar(20)
}

order_items: {
  shape: sql_table
  id: bigint {constraint: primary_key}
  order_id: bigint {constraint: foreign_key}
  product_id: bigint {constraint: foreign_key}
  qty: int
}

products: {
  shape: sql_table
  id: bigint {constraint: primary_key}
  name: text
  price: numeric(10,2)
}

orders.user_id -> users.id
order_items.order_id -> orders.id
order_items.product_id -> products.id
```

```bash
d2 --layout=elk erd.d2 erd.svg    # 화살표가 정확한 컬럼 행을 가리킴
```

`label`, `shape` 처럼 예약어와 같은 컬럼 이름은 `"label": string` 처럼 따옴표로 감쌉니다. 손으로 쓰기 번거롭다면 README에 있는 Postgres 스키마 가져오기 같은 커뮤니티 도구를 검토해 볼 수 있습니다.

그리고 GitHub Actions에서 포맷 검사와 렌더를 돌립니다. 아래 워크플로는 예시이며, 공식 D2 액션이 아니라 설치 스크립트를 직접 실행하는 방식입니다.

```yaml
# .github/workflows/diagrams.yml
name: diagrams
on:
  pull_request:
    paths: ["docs/diagrams/**.d2"]

jobs:
  render:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install D2
        run: curl -fsSL https://d2lang.com/install.sh | sh -s --
      - name: Check format
        run: d2 fmt --check docs/diagrams/*.d2
      - name: Render
        run: |
          for f in docs/diagrams/*.d2; do
            d2 "$f" "${f%.d2}.svg"
          done
      - uses: actions/upload-artifact@v4
        with:
          name: diagrams
          path: docs/diagrams/*.svg
```

man 페이지가 강조하는 주의점이 있습니다. **렌더 중 오류가 나도 D2는 부분 결과 파일을 쓸 수 있으므로, 성공 여부는 출력 파일 존재가 아니라 종료 코드로 판단해야 합니다.** 위처럼 `run` 단계에 그대로 두면 실패 시 단계가 실패합니다.

## 실무 팁 & 자주 겪는 문제

- **"노드가 두 개씩 생겨요."** 연결에서 라벨을 썼기 때문입니다. 연결은 항상 키로 겁니다.
- **"화살표 순서대로 그려지지 않아요."** 일반 다이어그램에는 순서 개념이 없습니다. 순서가 중요하면 `sequence_diagram` 을 쓰고, 흐름 방향은 `direction` 으로 잡습니다.
- **배치가 마음에 안 들면 엔진부터 바꿔 봅니다.** `--layout=elk`, `--layout=tala` 를 번갈아 렌더해 보는 것이 위치를 손으로 조정하는 것보다 빠릅니다. 엔진별 옵션은 `d2 layout elk` 처럼 확인합니다.
- **TALA 결과가 매번 크게 바뀌면** 시드를 고정하거나(`--tala-seeds`) 다른 엔진을 고려합니다.
- **여러 보드가 있는 파일을 SVG로 내보내면** `--animate-interval` 이 없을 때 결과가 디렉터리(`out/index.svg` 등)로 나옵니다. 루트 보드만 원하면 `--target=''`, 특정 레이어와 하위 보드는 `--target='layers.x.*'` 를 씁니다.
- **한 페이지에 같은 다이어그램을 여러 번 넣으면** SVG ID가 충돌할 수 있습니다. `--salt` 로 고유 ID를 만듭니다.
- **HTML에 SVG를 직접 삽입할 때는** `--no-xml-tag` 로 XML 선언을 뺍니다.
- **다크 모드 테마와 직접 지정한 색은 섞이면 어색합니다.** man 페이지도 `--dark-theme` 사용 시 D2 코드의 명시적 스타일이 그대로 적용되어 예상과 다를 수 있다고 경고합니다. 색은 가능하면 테마와 `theme-overrides` 로 관리합니다.
- **큰 다이어그램이 시간 초과되면** `--timeout` (기본 120초)을 늘립니다.
- **아이콘이 바뀌었는데 감시 모드에서 반영이 안 되면** `--img-cache=false` 를 줍니다.
- **URL에 `#` 이 들어가면** 따옴표로 감싸야 합니다. 그렇지 않으면 `#` 뒤가 주석으로 처리됩니다.
- **수식 줄바꿈이 안 되면** MathJax 제약입니다. 문서가 안내하는 `displaylines` 명령으로 우회합니다.
- **스타일이 반복되면** `classes` 와 `globs`(`*.style.fill: ...` 처럼 여러 객체에 한 번에 적용하는 패턴)로 줄입니다.

## 비슷한 도구와 비교

아래 비교는 각 도구의 일반적인 특성을 바탕으로 한 정리이며, 세부 기능은 버전에 따라 달라질 수 있습니다. D2 팀이 운영하는 비교 사이트 [text-to-diagram.com](https://text-to-diagram.com) 도 참고할 만합니다(작성 주체가 D2 쪽이라는 점은 감안하세요).

| 항목 | D2 | Mermaid | PlantUML | Graphviz | Excalidraw |
|---|---|---|---|---|---|
| 방식 | 텍스트 → 다이어그램 | 텍스트 → 다이어그램 | 텍스트 → 다이어그램 | 텍스트(DOT) → 그래프 | 손으로 그리는 화이트보드 |
| 구현 | Go 단일 바이너리, WASM | JavaScript | Java | C | 웹 앱 (React) |
| 레이아웃 엔진 선택 | dagre, ELK, TALA | 주로 dagre (일부 ELK) | 주로 Graphviz | dot, neato 등 여러 개 | 수동 배치 |
| 문서 플랫폼 기본 지원 | 플러그인 필요 | GitHub, GitLab 등 마크다운에서 바로 렌더 | 일부 위키/플러그인 | 다양한 도구가 내부적으로 사용 | 임베드/이미지 |
| 다이어그램 종류 | 일반, 시퀀스, ERD, UML 클래스, 그리드 | 매우 다양 (간트, 파이, 상태 등) | UML 전 범위에 강함 | 일반 그래프 | 자유 |
| 다중 보드/애니메이션 | layers, scenarios, steps | 제한적 | 제한적 | 없음 | 프레임 |
| 결과물 미관 | 테마 풍부, 스케치 모드 | 무난 | 다소 투박하다는 평이 많음 | 기능적 | 손그림 감성 |

간단히 정리하면 이렇습니다.

- GitHub README나 이슈에 바로 그림을 넣고 싶다면 별도 렌더 없이 동작하는 Mermaid가 편합니다.
- UML 다이어그램 종류를 폭넓게 그려야 한다면 PlantUML이 여전히 강합니다.
- 프로그램이 생성한 그래프를 자동 시각화한다면 Graphviz가 가볍고 검증되어 있습니다.
- 회의 중 빠르게 스케치하고 공동 편집한다면 Excalidraw가 맞습니다.
- 아키텍처 문서를 코드처럼 관리하면서 결과물 품질과 레이아웃 선택권, 발표용 다중 보드가 필요하다면 D2가 좋은 선택입니다.

## 장점과 한계

**장점**

- 문법이 짧고 읽기 쉽습니다. 시퀀스 다이어그램과 ERD도 같은 문법을 공유해서 새로 배울 것이 적습니다.
- 레이아웃 엔진을 바꿔 가며 결과를 고를 수 있고, v0.9.0부터 TALA까지 추가 비용 없이 포함됩니다.
- 테마, 다크 모드, 스케치 모드 덕분에 별다른 손질 없이 문서와 발표에 쓸 만한 결과가 나옵니다.
- layers, scenarios, steps로 한 파일에서 여러 장의 그림과 애니메이션을 관리합니다.
- 변수, 클래스, 임포트, 글롭으로 큰 다이어그램을 모듈화할 수 있습니다.
- Go 단일 바이너리라 설치가 쉽고, PNG/PDF/PPTX까지 외부 브라우저 없이 만듭니다. 텔레메트리도 없습니다.

**한계**

- **문서 플랫폼 기본 지원이 Mermaid보다 적습니다.** GitHub 마크다운에서 바로 렌더되지 않으므로 CI나 플러그인으로 이미지를 만들어야 합니다.
- **기능이 엔진마다 다릅니다.** `near` 객체 지정, 위치 고정, 컨테이너별 방향은 TALA 전용이라, 엔진을 바꾸면 결과가 깨질 수 있습니다.
- **배치를 세밀하게 통제하기 어렵습니다.** 자동 레이아웃 도구의 공통 한계입니다. 특정 위치를 정확히 원하면 수작업 도구가 낫습니다.
- **다이어그램 종류의 폭은 Mermaid, PlantUML보다 좁습니다.** 간트 차트, 파이 차트, 상태 머신 같은 전용 다이어그램이 필요하면 다른 도구가 편합니다.
- **아직 1.0 이전(0.x) 버전입니다.** 릴리스 사이에 동작이나 기본값이 바뀔 수 있으니 CI에서는 버전을 고정하는 편이 안전합니다.

## 이런 분께 추천

- 아키텍처 문서를 Git에 두고 PR로 리뷰하고 싶은 백엔드/플랫폼 엔지니어
- 설계 리뷰나 발표에서 "평상시 vs 장애 시", "1단계 → 3단계" 같은 흐름을 보여줘야 하는 분
- Mermaid 결과물의 배치나 디자인이 아쉬웠던 분
- 데이터 모델(ERD)과 서비스 구조를 같은 도구로 그리고 싶은 팀
- Go나 JavaScript 프로그램 안에서 다이어그램을 자동 생성하고 싶은 개발자

## 이런 경우엔 다른 도구

- GitHub/GitLab 마크다운 안에서 별도 빌드 없이 바로 보여야 한다면 Mermaid
- 시퀀스, 유스케이스, 컴포넌트, 배포 등 UML 표준 다이어그램을 폭넓게 써야 한다면 PlantUML
- 수천 개 노드의 그래프를 프로그램으로 생성해 빠르게 그려야 한다면 Graphviz
- 회의 중 즉석 스케치와 실시간 공동 편집이 목적이라면 Excalidraw
- 픽셀 단위로 배치를 직접 정해야 하는 포스터나 마케팅 그림이라면 Figma, draw.io 같은 수작업 도구

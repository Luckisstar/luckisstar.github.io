# [오픈소스 소개] Lapce: Rust로 만든 초고속 코드 에디터

- **저장소:** [lapce/lapce](https://github.com/lapce/lapce) · [lapce.dev](https://lapce.dev) · [문서](https://docs.lapce.dev/)
- **라이선스:** Apache 2.0
- **언어:** Rust
- **현황 (2026-10-20 기준):** GitHub 스타 약 3.9만 개, 최신 릴리스 v0.4.6 (2026년 1월)

## 한 줄 요약

**순수 Rust로 만든 GPU 렌더링 GUI 코드 에디터**입니다. LSP(언어 서버 프로토콜) 기반 코드 지능, Vim식 모달 편집, SSH 원격 개발, WASI 플러그인을 기본 기능으로 갖추고 "가볍고 빠른 VS Code"에 가까운 경험을 목표로 합니다. 이름은 "랩스(/læps/)"로 읽고, README는 "Lightning-fast And Powerful Code Editor"의 약자로 소개합니다.

## 어떤 문제를 푸나

에디터 선택에는 늘 절충이 있었습니다.

- **VS Code**는 기능과 확장이 풍부하지만 Electron(웹 기술 기반 데스크톱 런타임) 위에서 돌아가 메모리 사용량과 반응 속도에 불만이 생기기 쉽습니다.
- **Vim/Neovim**은 빠르고 키보드 중심이지만, GUI 수준의 세밀한 화면 표현에는 한계가 있습니다.

Lapce 저장소의 `docs/why-lapce.md`에는 만든 사람(dzhou121)의 동기가 꽤 구체적으로 적혀 있습니다. 오랜 Vim 사용자였던 그는 Neovim 외부 UI와 Xi-Editor 프런트엔드를 직접 만들어 보다가, VS Code의 원격 개발 기능을 써 보고 결정적인 문제를 발견합니다. Vim이나 Xi처럼 **편집 엔진이 백엔드에 있는 구조**에서는 백엔드를 원격 서버에 두면 키 입력 하나하나가 네트워크를 왕복해야 하므로 타이핑에 지연이 섞인다는 것입니다.

그래서 Lapce는 **편집 로직은 로컬 UI에 두고, 파일 시스템과 플러그인, 언어 서버는 "프록시"를 통해 원격에 둘 수 있는 구조**로 설계됐습니다. 빠른 로컬 편집감과 원격 개발을 동시에 잡으려는 것이 Lapce의 출발점입니다.

## 핵심 개념 / 동작 원리

### 구성 요소

| 구성 요소 | 역할 |
|---|---|
| **Rust** | 전체 코드베이스 언어. 저장소는 `lapce-app`, `lapce-core`, `lapce-proxy`, `lapce-rpc` 크레이트로 나뉩니다 |
| **[Floem](https://github.com/lapce/floem)** | Lapce 팀이 만든 Rust GUI 프레임워크. 프런트엔드(`lapce-app`)가 이 위에 만들어졌습니다 |
| **[wgpu](https://github.com/gfx-rs/wgpu)** | GPU 렌더링 라이브러리 |
| **Rope** | 긴 텍스트를 작은 조각의 트리로 나눠 저장하는 자료구조. Xi-Editor의 "Rope Science"를 바탕으로 큰 파일의 삽입/삭제를 빠르게 처리합니다 |
| **Tree-sitter** | 구문 분석기. 토큰화와 구문 강조를 담당합니다 |
| **LSP** | 자동 완성, 진단, 정의로 이동, 코드 액션 같은 기능을 언어 서버에서 받아옵니다 |
| **WASI 플러그인** | WebAssembly 시스템 인터페이스(WASI)로 컴파일된 플러그인. C, Rust, AssemblyScript 등으로 작성할 수 있습니다 |

### UI와 프록시의 분리

공식 문서의 Architecture 페이지와 `why-lapce.md`를 요약하면 구조는 다음과 같습니다.

```
 local machine           local or remote host
+-------------+  delta   +---------------+
| lapce-app   | -------> | lapce-proxy   |
| (Floem UI,  | <------- | file I/O,     |
|  editing)   |  content | plugin relay  |
+-------------+          +-------+-------+
                                 |
                      +----------+---------+
                      | WASI plugins / LSP |
                      +--------------------+
```

1. 파일을 열면 `lapce-app`이 `lapce-proxy`에 요청하고, 프록시가 디스크에서 읽어 내용을 돌려줍니다.
2. 키 입력과 편집은 **UI 쪽 버퍼에서 바로** 처리하고, 변경분(delta)만 프록시로 보내 동기화합니다.
3. 저장하면 UI가 저장 요청을 보내고 프록시가 디스크에 씁니다.
4. 플러그인과 LSP 서버는 프록시를 통해 UI와 통신합니다.

원격 개발 모드에서는 `lapce-proxy` 바이너리가 원격 호스트에서 실행됩니다. 그래서 타이핑은 로컬처럼 즉각적이고, 언어 서버와 빌드 도구는 원격 머신의 자원을 씁니다. 구문 강조 같은 작업은 별도 스레드에서 처리해 메인 스레드를 막지 않도록 설계했다고 설명합니다.

### 언어 지원이 들어오는 경로

- **구문 강조:** Tree-sitter 문법(grammar)으로 처리합니다. Rust, JSON, TOML 등 일부만 내장이고, 나머지 언어의 문법은 공유 라이브러리 형태로 `grammars` 데이터 디렉터리에 받아 씁니다. 기본적으로 시작할 때 지원 문법을 업데이트합니다.
- **코드 지능(LSP):** 언어 서버는 대개 **플러그인(volt)** 이 띄웁니다. 예를 들어 공식 `lapce-rust` 플러그인은 rust-analyzer로 Rust LSP를 제공합니다. 즉 "에디터 설치 → 언어별 플러그인 설치"가 기본 흐름입니다.

## 주요 기능

### 편집

- **명령 팔레트:** 모든 명령을 퍼지 검색으로 실행합니다. macOS `Cmd+Shift+P`, Linux/Windows `Ctrl+Shift+P`(또는 `F1`).
- **파일로 이동:** macOS `Cmd+P`, Linux/Windows `Ctrl+P`.
- **멀티 커서:** 다음 같은 항목 추가 `Ctrl+D`(macOS `Meta+D`), 모든 같은 항목 선택 `Ctrl+Shift+L`(macOS `Meta+Shift+L`), 위/아래 줄 커서 추가 `Ctrl+Alt+↑/↓`(macOS `Meta+Alt+↑/↓`), 선택 영역 줄 끝마다 커서 `Alt+Shift+I`, 마지막 커서 동작 취소 `Ctrl+U`(macOS `Meta+U`).
- **기본 설정에 들어 있는 편의 기능:** 스티키 헤더, 인레이 힌트, 에러 렌즈(진단 메시지를 줄 끝에 표시), 브레드크럼, 들여쓰기 가이드, 괄호 자동 닫기, 자동 저장 간격, 저장 시 포맷(기본 꺼짐) 등이 `defaults/settings.toml`에 정의돼 있습니다.

### 모달 편집 (Vim 모드)

- 첫 실행 화면의 `Enable modal editing`, 설정 패널, 또는 명령 팔레트의 `Enable Modal Editing`으로 켭니다. 설정 키는 `[core]`의 `modal`이며 기본값은 `false`입니다.
- 모달 모드에서는 상대 줄 번호가 기본으로 켜집니다(`modal-mode-relative-line-numbers = true`).
- 기본 키맵에서 확인되는 노멀 모드 키 예시: `gd`(정의로 이동), `gh`(호버 정보), `gf`(코드 액션), `/`(줄 검색 팔레트), `:`(명령 팔레트), `v`/`V`/`Ctrl+V`(비주얼 모드), `Ctrl+W v`(세로 분할), `n`/`N`(다음/이전 검색).
- 완전한 Vim 에뮬레이터라기보다 "Vim식 모달 편집"에 가깝습니다. 매크로나 Ex 명령 전반이 Vim과 같다고 기대하면 차이가 있을 수 있으니 직접 확인해 보는 것이 좋습니다.

### 코드 지능 (LSP)

- 자동 완성, 진단(문제 패널 `Ctrl+Shift+M`, macOS `Meta+Shift+M`), 코드 액션(`Ctrl+.`, macOS `Meta+.`), 정의로 이동(`F12`), 이름 바꾸기(`F2`), 문서 심볼(`Ctrl+Shift+O`), 워크스페이스 심볼(`Ctrl+T`) 등을 제공합니다.
- 0.4.3에서 "Find References"와 "Go To Implementation" 패널이 추가됐고, 개발 중인 다음 버전 변경 로그에는 LSP document highlight 지원이 올라와 있습니다.

### 원격 개발

- SSH로 원격 머신에 접속하면 **플러그인과 명령이 모두 원격에서 실행**됩니다. Windows에는 명령 팔레트에 `Connect to WSL Host` 명령도 있습니다.
- 릴리스에는 OS/아키텍처별 `lapce-proxy` 바이너리가 따로 올라옵니다. 접속 시 원격 호스트가 직접 프록시를 받고, 실패하면 로컬에서 받아 업로드합니다.

### 터미널, 테마, 플러그인

- **내장 터미널:** 워크스페이스에서 바로 명령을 실행합니다. `settings.toml`에 **터미널 프로필**(쉘 종류, 인자, 작업 디렉터리, 환경 변수)을 정의할 수 있고, 팔레트에서 `<` 접두어로 실행합니다(문서상 실험 기능).
- **테마:** 색 테마와 아이콘 테마를 명령 팔레트나 설정에서 바꿉니다. 테마도 플러그인처럼 확장 탭에서 설치합니다.
- **플러그인 레지스트리:** [plugins.lapce.dev](https://plugins.lapce.dev/)에서 배포됩니다. 플러그인 패널은 `Ctrl+Shift+X`(macOS `Meta+Shift+X`)입니다.

## 설치와 시작

### 설치

- **실행 파일:** [GitHub 릴리스 페이지](https://github.com/lapce/lapce/releases)에서 받습니다. v0.4.6 기준으로 macOS용 `.dmg`, Windows용 `.msi`와 포터블 `.zip`, Linux용 `tar.gz`(amd64/arm64), Debian/Ubuntu용 `.deb`, Fedora용 `.rpm`이 올라와 있습니다.
- **패키지 매니저:** 공식 문서(`docs/installing-with-package-manager.md`)는 [Repology 목록](https://repology.org/project/lapce/versions)과 함께 [Flatpak(Flathub)](https://flathub.org/apps/details/dev.lapce.lapce), [Scoop](https://scoop.sh/#/apps?q=lapce)을 안내합니다. 이 문서에 명령어가 직접 적혀 있는 것은 Fedora의 비공식 COPR 저장소뿐입니다.

```bash
# Fedora (비공식 COPR, 문서 기준 nightly 빌드)
sudo dnf copr enable titaniumtown/lapce
sudo dnf install lapce
```

Flatpak, Scoop, 각 배포판 패키지는 링크된 페이지에서 해당 패키지 관리자의 안내를 따르세요.

### 소스에서 빌드 (Linux 기준, 공식 문서)

```bash
# 1) rustup으로 최신 Rust 설치 후, 의존성 설치 (Ubuntu 예시)
sudo apt install clang libxkbcommon-x11-dev pkg-config libvulkan-dev libwayland-dev xorg-dev libxcb-shape0-dev libxcb-xfixes0-dev

# 2) 저장소 클론
git clone https://github.com/lapce/lapce.git ~/lapce
cd ~/lapce

# 3) 릴리스 프로필로 빌드 및 설치
cargo install --path . --bin lapce --profile release-lto --locked
```

빌드가 끝나면 `$HOME/.cargo/bin/lapce`에 실행 파일이 생깁니다. Fedora와 Void Linux용 의존성 목록도 같은 문서에 있습니다.

### 첫 실행

1. 상단 `Open Folder` 옆 화살표를 눌러 워크스페이스 메뉴를 열고 `Open Folder`로 프로젝트 폴더를 엽니다. `Open recent workspace`로 최근 작업 공간을 퍼지 검색할 수도 있습니다.
2. 명령 팔레트에서 `Install Lapce to PATH`를 실행해 두면 터미널에서 `lapce <PATH>`로 열 수 있습니다.
3. 오른쪽 위 톱니바퀴 아이콘에서 설정과 키보드 단축키를 엽니다(`Ctrl+,`, macOS `Cmd+,`).

## 실전 예제

### 1. LSP 플러그인을 설치해 언어 지원 켜기

Lapce를 설치한 직후에는 구문 강조만 되고 자동 완성이나 정의로 이동이 안 되는 경우가 많습니다. 언어별 플러그인을 설치해야 LSP가 붙습니다.

1. `Ctrl+Shift+X`(macOS `Meta+Shift+X`)로 플러그인 패널을 엽니다.
2. 언어 이름으로 검색해 설치합니다. 2026-10-20 기준 레지스트리 다운로드 상위권 언어 플러그인은 다음과 같습니다.

| 플러그인 | 제공 언어 / 서버 | 레지스트리 최종 갱신 |
|---|---|---|
| `lapce-rust` | Rust (rust-analyzer) | 2026-09 |
| `lapce-typescript` | TypeScript / JavaScript | 2022-11 |
| `lapce-python` | Python (python-lsp-server) | 2024-03 |
| `lapce-cpp-clangd` | C/C++ (clangd) | 2024-02 |
| `lapce-go` | Go (gopls) | 2023-01 |
| `lapce-toml` | TOML (taplo) | 2022-11 |

3. 플러그인 설정에서 언어 서버 경로 등을 조정합니다. 예를 들어 `lapce-rust`의 `volt.toml`에는 `serverPath`(비우면 번들된 rust-analyzer 사용), `checkOnSave`, `check.command` 같은 설정 항목이 정의돼 있습니다.
4. 플러그인은 `volt.toml`의 `[activation]` 조건으로 켜집니다. `lapce-rust`는 언어가 `rust`이거나 워크스페이스에 `Cargo.toml`이 있을 때 활성화됩니다.

플러그인마다 언어 서버를 함께 내려받는지, 시스템에 설치된 서버를 쓰는지가 다릅니다. 동작하지 않으면 플러그인 설명과 저장소를 확인하고, 필요하면 해당 언어 서버(gopls, clangd 등)를 직접 설치해 PATH에 두세요.

### 2. Vim 모드 켜기와 키 바인딩 바꾸기

가장 간단한 방법은 명령 팔레트에서 `Enable Modal Editing`을 실행하는 것입니다. 설정 파일로 고정하려면 명령 팔레트의 `Open Settings File`로 사용자 `settings.toml`을 열어 다음을 넣습니다.

```toml
[core]
modal = true

[editor]
modal-mode-relative-line-numbers = true
```

키 바인딩은 설정의 `Open Keyboard Shortcuts`에서 명령을 검색해 행을 클릭하고 원하는 키를 누르면 됩니다. 빈 상태로 저장하면 바인딩이 지워집니다. 파일로 관리하려면 `Open Keyboard Shortcuts File`로 `keymaps.toml`을 엽니다. 형식은 기본 키맵(`defaults/keymaps-*.toml`)과 같습니다.

```toml
# 노멀 모드에서 g d 로 정의로 이동 (기본 키맵에 있는 형식)
[[keymaps]]
key = "g d"
command = "goto_definition"
mode = "n"

# 모든 모드에서 F1 로 명령 팔레트
[[keymaps]]
key = "F1"
command = "palette.command"
```

`mode`는 `n`(노멀), `i`(삽입), `v`(비주얼) 등을 조합해 쓰고(`nv`처럼), `when`으로 포커스 조건(예: `!file_explorer_focus`)을 줄 수 있습니다.

### 3. SSH 원격 개발 연결

1. 원격 서버에 **SSH 키 인증**이 되어 있는지 먼저 확인합니다. 문서상 원격 개발은 키 인증에서만 동작합니다. 비밀번호 인증이 필요하면 터미널에서 `--wait` 옵션으로 Lapce를 실행해 stdin/stdout에 붙게 하라고 안내합니다.
2. 왼쪽 위 원격 아이콘을 누르거나 명령 팔레트에서 `Connect to SSH Host`를 실행합니다.
3. `user@host` 또는 `~/.ssh/config`에 정의한 `Host` 이름(별칭)을 입력합니다. `HostName`이 아니라 `Host`입니다.
4. 접속에 성공하면 원격에 `lapce-proxy`가 설치/실행되고 SSH 터널로 연결되며, 원격 아이콘이 초록색으로 바뀝니다.
5. 폴더를 엽니다. 문서에는 **최근 UI 재작성 때문에 원격에서 `Open folder`가 동작하지 않을 수 있으니, 내장 터미널에서 `lapce <PATH>`를 실행하라**는 경고가 있습니다. 개발 중인 다음 버전 변경 로그에는 "원격에서 폴더/파일 선택 구현"이 올라와 있어 이후 개선될 것으로 보입니다.

알아 둘 점: Lapce는 시스템의 OpenSSH(`ssh` 프로그램)를 그대로 호출하고, SSH 설정 파일이나 키를 직접 읽지 않습니다. 그래서 접속 입력창에는 `~/.ssh/config`의 호스트 목록이 아니라 **Lapce에서 접속한 적 있는 최근 기록**만 표시됩니다.

### 4. 설정 파일 커스터마이즈 (전역 + 프로젝트별)

설정은 세 단계로 겹쳐 적용됩니다(소스 코드 `lapce-app/src/config.rs` 기준).

1. 기본값: 저장소의 `defaults/settings.toml`
2. 사용자 설정: 설정 디렉터리의 `settings.toml` (`Open Settings File` / `Open Settings Directory` 명령으로 위치 확인)
3. 워크스페이스 설정: 프로젝트 루트의 `.lapce/settings.toml` (로컬 워크스페이스에만 적용)

기본 설정에 정의된 키를 바탕으로 한 예시입니다.

```toml
[core]
modal = true
color-theme = "Lapce Dark"
icon-theme = "Lapce Codicons"

[editor]
font-family = "JetBrains Mono"
font-size = 14
line-height = 1.5
tab-width = 4
format-on-save = true
autosave-interval = 0          # 0이면 자동 저장 끔
enable-inlay-hints = true
enable-error-lens = true
render-whitespace = "none"
bracket-pair-colorization = true

[terminal.default-profile]
macos   = "default"
linux   = "default"
windows = "pwsh"

[terminal.profiles.default]

[terminal.profiles.pwsh]
command = "pwsh"
```

팀 프로젝트라면 `tab-width`나 `format-on-save`처럼 프로젝트 성격에 맞는 값만 `.lapce/settings.toml`에 두고, 글꼴과 테마 같은 개인 취향은 사용자 설정에 두는 식으로 나누면 깔끔합니다. 테마 색을 설정 화면에서 조정한 뒤 `Export current settings to a theme file`로 테마 파일을 만들 수도 있습니다.

## 플러그인 개발 맛보기 (WASI)

- 플러그인은 WASI로 컴파일한 `.wasm` 파일과 매니페스트 `volt.toml`로 구성됩니다. Rust로 작성할 때는 공식 라이브러리 [lapce-plugin-rust](https://github.com/lapce/lapce-plugin-rust)를 씁니다.
- `volt.toml`에는 `name`, `version`, `author`, `display-name`, `description`, `wasm`, `icon`, `repository`, 활성화 조건 `[activation]`, 사용자 설정 항목 `[config."키"]` 등이 들어갑니다(`lapce-rust` 기준).
- LSP를 제공하는 플러그인은 확장 API나 `volt.toml`에서 처리할 문서 종류(`DocumentSelector`)를 정의해야 합니다.
- 테마 플러그인은 `wasm` 없이 `volt.toml`과 테마 파일만으로 만들 수 있습니다. 예시 저장소는 [lapce/atom-one](https://github.com/lapce/atom-one)입니다.
- 배포는 CLI 도구 `volts`로 합니다. plugins.lapce.dev에 GitHub로 로그인해 API 토큰을 만든 뒤 플러그인 폴더에서 실행합니다.

```bash
cargo install volts
volts publish
```

## 실무 팁 & 자주 겪는 문제

- **자동 완성이 안 될 때:** 대부분 언어 플러그인이 없거나 언어 서버를 못 찾는 경우입니다. 플러그인 설치 여부, 플러그인 설정의 서버 경로를 확인하고, `Open Log File` / `Open Logs Directory` 명령으로 로그를 보세요.
- **구문 강조가 이상할 때:** Rust, JSON, TOML 외 언어는 Tree-sitter 문법을 외부에서 받아옵니다. 오프라인 환경에서는 문법 다운로드가 안 되어 강조가 빠질 수 있습니다.
- **원격 접속 실패:** 먼저 일반 터미널에서 `ssh 호스트별칭`이 비밀번호 없이 붙는지 확인합니다. Lapce는 시스템 `ssh`를 그대로 쓰므로, 터미널에서 되면 Lapce에서도 될 가능성이 높습니다. 원격 서버가 외부로 나가지 못하면 로컬이 프록시를 받아 업로드하는 경로로 대체됩니다.
- **원격에서 폴더가 안 열릴 때:** 내장 터미널에서 `lapce <PATH>`를 실행합니다(공식 문서의 우회 방법).
- **프로젝트 설정이 원격에서 적용되지 않을 때:** 소스 코드상 `.lapce/settings.toml`은 로컬 워크스페이스에서만 읽습니다.
- **설정 위치를 모를 때:** `Open Settings Directory` 명령이 가장 빠릅니다. 설정, 키맵, 테마, 플러그인, 로그 위치는 OS 표준 디렉터리를 따릅니다.
- **nightly 빌드:** 정식 릴리스 간격이 길기 때문에 최신 수정을 원하면 릴리스 페이지의 `nightly` 태그(2026-10-09 갱신)를 쓸 수 있습니다. 대신 안정성은 낮다고 보는 것이 맞습니다.

## 비슷한 도구와 비교

| 항목 | Lapce | VS Code | Zed | Helix |
|---|---|---|---|---|
| 형태 | 네이티브 GUI | Electron GUI | 네이티브 GUI | 터미널(TUI) |
| 구현 언어 | Rust (Floem, wgpu) | TypeScript (Electron) | Rust (자체 GPU UI 프레임워크) | Rust |
| 편집 방식 | 일반 + Vim식 모달(토글) | 일반 (Vim은 확장으로) | 일반 + Vim 모드 | 모달 (선택 후 동작, Kakoune 계열) |
| LSP | 플러그인으로 연결 | 확장으로 연결 | 다수 언어 내장 + 확장 | 내장, 설정 파일로 서버 지정 |
| 확장 방식 | WASI 플러그인 | JS/TS 확장, 매우 큰 마켓플레이스 | WASM 확장 | 플러그인 시스템은 제한적(개발 진행 상황은 공식 문서 확인) |
| 원격 개발 | SSH, WSL 내장 | Remote 확장(SSH, 컨테이너, WSL) | SSH 원격 지원 | 원격 서버 터미널에서 직접 실행 |
| 협업/AI | 별도 기능 없음 | 확장 생태계로 풍부 | 실시간 협업, AI 기능 내장 | 없음 |
| 성숙도 | 0.x | 매우 성숙 | 빠르게 발전 중 | 1.0 이전이지만 정기 릴리스 |

비교표의 VS Code, Zed, Helix 항목은 각 프로젝트의 일반적으로 알려진 특징을 요약한 것이며, 세부 기능은 버전에 따라 바뀔 수 있으니 공식 문서로 확인하세요.

- **VS Code 대비:** Lapce는 더 가볍고 빠른 반응을 노리지만, 확장 생태계와 디버거, 노트북 같은 주변 기능은 VS Code가 압도적입니다.
- **Zed 대비:** 둘 다 Rust 네이티브 GUI 에디터라 지향점이 비슷합니다. Zed는 협업과 AI 기능, 활발한 릴리스로 주목받고 있고, Lapce는 WASI 플러그인과 SSH 프록시 구조가 특징입니다.
- **Helix 대비:** Helix는 터미널에서 돌아가는 모달 에디터라 SSH 세션 안에서 바로 쓰기 좋습니다. Lapce는 GUI와 Vim식 편집을 함께 원할 때 대안이 됩니다.

## 장점과 한계

**장점**

- Rust + GPU 렌더링 기반이라 시작과 반응이 가볍습니다.
- UI와 프록시를 분리한 구조 덕분에 원격 개발에서도 타이핑 지연이 적도록 설계됐습니다.
- 모달 편집이 "1급 기능"이라 설정 하나로 켜고 끌 수 있습니다.
- 설정과 키맵이 TOML 파일이라 버전 관리와 공유가 쉽고, 프로젝트별 `.lapce/settings.toml`도 지원합니다.
- Apache 2.0 라이선스이고, UI 프레임워크(Floem)까지 오픈소스입니다.

**한계**

- **아직 0.x입니다.** 최신 정식 릴리스는 v0.4.6이고, 문서에도 "최근 UI 재작성 때문에 원격에서 Open folder가 안 된다"는 식의 과도기 흔적이 남아 있습니다.
- **릴리스 간격이 길고 불규칙합니다.** v0.4.0(2024-04) → v0.4.1(2024-08) → v0.4.2(2024-08) → v0.4.3(2025-06) → v0.4.4(2025-08) → v0.4.5(2025-09) → v0.4.6(2026-01) 순서로, 2024년 8월부터 2025년 6월까지는 약 10개월 공백이 있었습니다. 최근 릴리스도 버그 수정과 패키징 변경 위주입니다. nightly는 꾸준히 갱신되고 있습니다(2026-10 기준).
- **플러그인 생태계가 작습니다.** 2026-10-20 기준 레지스트리 API가 보고하는 플러그인 수는 110개 수준이고, 다운로드 상위 언어 플러그인 중에도 TypeScript(2022-11), Go(2023-01), TOML(2022-11)처럼 몇 년째 갱신되지 않은 것이 많습니다. 공식 Rust 플러그인은 비교적 최근(2026-09)까지 갱신됐습니다.
- 문서(docs.lapce.dev)가 짧고 일부 화면 캡처가 2022년 기준이라, 세부 설정은 저장소의 `defaults/` 파일과 소스 코드를 직접 봐야 할 때가 많습니다.
- 디버거(DAP) 통합, 협업, AI 보조 같은 기능은 경쟁 에디터에 비해 제한적이거나 별도로 확인이 필요합니다.

## 이런 분께 추천 / 이런 경우엔 다른 도구

**추천**

- VS Code가 무겁게 느껴지고, 가벼운 네이티브 GUI 에디터를 써 보고 싶은 분
- Vim식 모달 편집을 GUI 에디터에서 기본 기능으로 쓰고 싶은 분
- 주력 언어가 Rust이고 rust-analyzer 기반 개발 환경을 가볍게 꾸리고 싶은 분
- Rust GUI(Floem), Rope 자료구조, WASI 플러그인 같은 에디터 내부 구조에 관심 있는 분, 또는 오픈소스 기여처를 찾는 분

**다른 도구가 나은 경우**

- 특정 언어의 디버거, 테스트 탐색기, 프레임워크 전용 확장이 꼭 필요하다면: **VS Code**
- Rust 네이티브 GUI 에디터를 원하지만 활발한 릴리스, 협업, AI 기능이 중요하다면: **Zed**
- 서버에 SSH로 들어가 터미널 안에서 바로 편집하는 일이 많다면: **Helix** 또는 **Neovim**
- 업무용 주력 에디터로 안정성과 장기 지원이 최우선이라면: 0.x라는 점을 고려해 보조 에디터로 먼저 써 보는 것을 권합니다.

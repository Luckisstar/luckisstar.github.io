# [오픈소스 소개] daily.dev: 개발자를 위한 개인화 뉴스 피드와 커뮤니티

- **저장소:** [dailydotdev/daily](https://github.com/dailydotdev/daily) · [daily.dev](https://daily.dev) · [문서](https://docs.daily.dev/intro/)
- **라이선스:** AGPL-3.0
- **언어:** JavaScript (이 저장소 기준. 실제 앱 코드는 TypeScript)
- **현황 (2026-10-20 기준):** GitHub 스타 약 2만 개, GitHub 릴리스 없음 (서비스형 제품. 크롬 확장 패키지 버전은 3.47.10)

## 한 줄 요약

**2,000개 이상의 기술 블로그, 뉴스, 릴리스 노트를 모아 내가 고른 태그와 읽은 기록에 맞춰 보여주는 개발자용 뉴스 피드**입니다. 브라우저 새 탭, 웹, 모바일 앱에서 쓸 수 있고, 댓글과 Squad(커뮤니티) 기능이 붙어 있습니다. 다만 이 글에서 소개하는 `dailydotdev/daily` 저장소는 코드가 아니라 **이슈·기능 제안·문서를 모으는 허브 저장소**라는 점을 먼저 알아두세요.

## 저장소 구조부터: 이 저장소에는 무엇이 있나

GitHub 스타 2만 개를 보고 들어가면 코드가 거의 없어 당황할 수 있습니다. README는 이 저장소를 "모든 프로젝트를 위한 중앙 장소(central place)"이며 "문서, 커뮤니티 아이디어, 제안 등"을 담는다고 설명합니다. 2026-10-20 기준으로 실제 내용은 이렇습니다.

| 경로 | 내용 |
|---|---|
| `README.md` | 제품 소개, FAQ, 관련 저장소 목록 |
| `.github/ISSUE_TEMPLATE/` | 버그 리포트, 기능 요청 양식 |
| `skills/`, `.claude/`, `.cursor/`, `.agents/` | AI 코딩 에이전트용 daily.dev 스킬(SKILL.md) |
| `.claude-plugin/` | Claude Code 플러그인 마켓플레이스 정의와 플러그인 코드 |
| `assets/` | README 이미지 |

GitHub가 언어를 JavaScript로 표시하는 이유도 이 플러그인 스크립트(`statusline.mjs` 등) 때문입니다. 기능 요청은 이 저장소의 Discussions에, 버그는 Issues에 올립니다.

실제 코드가 있는 저장소는 따로 있습니다.

```
 dailydotdev (GitHub org)
 ├── daily        hub: issues, ideas, skills
 ├── apps         frontend monorepo (AGPL-3.0)
 │   ├── packages/extension   Chrome/Edge
 │   ├── packages/webapp      Next.js
 │   └── packages/shared      UI, hooks
 ├── daily-scraper  page metadata fetcher
 ├── action-devcard GitHub Action (BSD-3)
 └── docs         product docs (archived)
```

- **[dailydotdev/apps](https://github.com/dailydotdev/apps):** 브라우저 확장과 웹 앱을 담은 모노레포입니다. Node, pnpm, Next.js, React, Tailwind CSS를 씁니다. README FAQ도 "프론트엔드 애플리케이션(확장과 웹 앱)은 dailydotdev/apps에 있다"고 안내합니다.
- **백엔드(API):** 과거 README에는 `daily-api` 를 Docker로 띄우는 로컬 실행 방법이 있었지만, 2026년 8월 커밋 "docs: remove obsolete public local setup" 에서 삭제되었습니다. 이 글을 쓰는 시점에 `github.com/dailydotdev/daily-api` 는 404를 반환해 공개 저장소로 확인되지 않습니다. `apps` 의 `docker-compose.yml` 은 여전히 `us.gcr.io/daily-ops/daily-api` 이미지를 참조하지만, 이를 외부에서 받을 수 있는지는 확인하지 못했습니다.
- **모바일:** `dailydotdev/android` 저장소가 공개되어 있습니다. iOS 앱 소스는 공개 저장소에서 찾지 못했습니다.

정리하면, **"오픈소스"라는 표현은 주로 프론트엔드(확장·웹 앱)에 해당**하고, 서비스 전체를 내 서버에 올리는 셀프 호스팅은 현재 공식적으로 안내되지 않습니다.

## 어떤 문제를 푸나

개발자가 기술 흐름을 따라가는 방법은 보통 이렇습니다.

- 여러 블로그와 뉴스레터를 구독한다: 양이 많아 다 못 읽고, 출처가 흩어져 있습니다.
- Hacker News나 Reddit을 본다: 모두에게 같은 목록이라 내 스택과 상관없는 글이 많습니다.
- RSS 리더를 쓴다: 좋은 출처를 직접 찾아 등록하고 관리해야 합니다.

daily.dev는 출처 관리를 서비스가 대신합니다. 운영팀이 검증한 2,000개 이상의 출처에서 글을 모으고, 사용자는 `#react`, `#kubernetes`, `#ai` 같은 **태그**만 고르면 됩니다. 이후에는 읽기, 추천(upvote), 북마크 기록을 바탕으로 피드가 조정됩니다. 새 탭을 열 때마다 피드가 보이므로 따로 사이트를 찾아갈 필요가 없다는 점이 핵심 아이디어입니다.

## 핵심 개념

| 용어 | 뜻 |
|---|---|
| **피드(Feed)** | 글 카드 목록. My Feed, Following, Popular, Most Upvoted, Best Discussions 등 여러 종류 |
| **태그(Tag)** | 글의 주제 분류. 팔로우하거나 차단(block)해 피드를 조정 |
| **소스(Source)** | 글을 내는 출처(블로그, 매체). 마찬가지로 팔로우·차단 가능 |
| **Squad** | 사용자가 만드는 개발자 커뮤니티. 글 공유, 투표(poll), 토론 |
| **Reputation** | 커뮤니티 활동으로 쌓이는 평판 점수. 일부 기능의 잠금 해제 조건 |
| **DevCard** | 읽은 글 수, 평판, 관심 태그 등을 요약한 공유용 카드 이미지 |
| **Plus** | 유료 구독. 광고 제거와 고급 기능 |

### 피드 종류

문서 기준으로 피드는 다음과 같습니다.

- **My Feed:** 고른 관심사에 맞춘 개인화 피드
- **Following:** 팔로우한 사용자, 소스, Squad의 글 (`/following`)
- **Popular:** 최근성, 고유 조회 수, 추천, 참여도를 반영한 인기 글
- **Most Upvoted:** 추천이 가장 많은 글. 기본 7일, 월·년 단위로 전환
- **Best Discussions:** 댓글 작성자의 평판, 댓글 최신성, 댓글 추천으로 고른 토론
- **Custom Feeds:** 특정 도구나 주제에 집중한 별도 피드(고급 설정은 Plus 기능)

## 동작 원리

daily.dev 자체는 중앙 서비스입니다. 사용자는 확장이나 웹 앱으로 같은 API에 접속합니다.

```
  2,000+ sources (blogs, news, releases)
              │ crawl, tag
              ▼
  ┌───────────────────────────┐
  │  daily.dev backend + API  │◀── votes, reads,
  │  ranking, personalization │    bookmarks
  └─────┬───────┬───────┬─────┘
        ▼       ▼       ▼
   extension  webapp  mobile    + public API / MCP
   (new tab)  (web)   (iOS/And)
```

1. **수집:** 등록된 소스에서 글을 가져와 태그와 메타데이터를 붙입니다. 공개된 `daily-scraper` 저장소는 "모든 웹페이지 정보를 가져오는" 도구로 소개되어 있습니다.
2. **개인화:** 팔로우·차단한 태그와 소스, 읽기·추천·북마크 기록을 바탕으로 피드를 구성합니다. 문서와 README가 설명하는 수준은 여기까지이고, 랭킹 알고리즘 세부는 공개 문서에 없습니다.
3. **커뮤니티 신호:** 추천과 댓글, 평판이 Popular, Best Discussions 같은 피드 순위에 반영됩니다.
4. **수익 모델:** README FAQ에 따르면 피드 안의 **명확히 표시된 네이티브 광고**로 운영되며, Plus 구독이 추가 수익원입니다. 데이터는 판매하지 않는다고 명시합니다.

### 개인정보와 권한

README FAQ는 확장 프로그램이 "새 탭 페이지만 바꾸며, 다른 사이트의 브라우징을 추적하거나 내용을 읽거나 스크립트를 주입하지 않는다"고 설명합니다. 다만 선택 기능인 **Companion 위젯**은 예외입니다. 문서에 따르면 이 위젯은 글 원문 페이지에서 바로 추천·댓글·북마크를 할 수 있게 하는 기능이고, 켤 때 **추가 권한을 요청**하며, "지금 보는 페이지가 피드에 있는 글인지 확인하기 위해" 그 권한이 필요하다고 합니다. 권한에 민감하다면 Companion은 켜지 않거나 설정에서 끄면 됩니다.

## 주요 기능

### 피드 개인화

- 온보딩에서 태그 카테고리를 고르고, 나중에 "My Feed" 메뉴에서 태그를 추가·삭제합니다.
- **콘텐츠 종류 필터:** Comparisons, Listicles, Memes, News, Opinions, Releases, Stories, Tutorials 등을 켜고 끌 수 있습니다.
- **언어 필터:** 피드 설정에서 콘텐츠 언어를 거릅니다.
- **차단:** 태그, 소스, 사용자를 차단할 수 있고, 차단 목록은 Feed Settings의 "Blocked Items" 에서 확인합니다.
- **Plus 전용:** 키워드 필터(특정 단어가 들어간 글 숨기기), Clickbait Shield(AI가 낚시성 제목을 내용에 맞게 다시 씀), 고급 커스텀 피드

### 북마크

- 카드, 글 페이지, Companion 위젯에서 북마크하면 로그인한 모든 기기에 동기화됩니다.
- 북마크한 글이 피드에 다시 나타나 읽으라고 알려주기도 합니다.
- **Public Mode** 를 켜면 북마크 목록을 공개 RSS로 내보낼 수 있습니다.
- 북마크 폴더(목록)로 정리하는 기능은 Plus 기능입니다.

### Squads

- 왼쪽 사이드바의 "New Squad" 로 만들고, 이름·핸들·이미지·설명을 정합니다.
- **Private Squad** 는 초대한 멤버만 내용을 보고, **Public Squad** 는 모든 개발자에게 열려 Squad 디렉터리에 노출됩니다. Public은 생성 시 카테고리(Languages, Web, AI, Career 등)를 골라야 합니다.
- 관리자(Admin)가 규칙, 게시글, 댓글, 멤버를 관리하고, 게시 권한을 모두에게 열지 모더레이터로 제한할지 정할 수 있습니다.
- 멤버는 글 공유, 투표 생성, 마크다운 게시글 작성을 할 수 있습니다.
- **Slack 연동:** Squad의 Manage > Integrations에서 연결하면 새 글이 올라올 때 Slack 채널에 알림이 갑니다. 사내 기술 공유 채널과 묶어 쓰기 좋습니다.

### 평판(Reputation)

문서 기준 점수 규칙은 다음과 같습니다. 처음 10점으로 시작하며 0 아래로 내려가지 않습니다.

| 활동 | 점수 |
|---|---|
| 내 글이 추천받음 / 비추천받음 | +10 / -10 |
| 내 댓글이 추천받음 / 비추천받음 | +50 / -50 |
| 내 글이 차단·삭제됨 | -100 |
| 내 신고로 글이 삭제됨 | +100 |
| 제안한 소스가 승인됨 | +200 |

중요한 조건이 있습니다. **평판 250점 이상인 사용자의 추천·비추천만 점수에 반영**됩니다. 250점이 넘으면 내 추천이 다른 사람 평판에 반영되고, 새 소스 제안과 "New Post" 로 직접 글 올리기가 가능해집니다. 평판이 높을수록 글과 댓글이 랭킹에서 우선된다고 문서는 설명합니다. 평판 조작은 점수 차감, 정지, 차단 대상입니다.

### DevCard

읽은 글 수, 평판, 팔로우한 소스와 태그, 가입한 Squad를 요약한 카드입니다. 프로필 메뉴의 DevCard 또는 `daily.dev/devcard` 에서 테마, 세로·가로 배치, 배경 이미지를 골라 생성합니다. 일부 테마는 평판에 따라 열립니다. GitHub 프로필 README나 X 헤더에 붙이는 용도로 많이 씁니다.

### 그 밖의 기능

- **검색:** 글, 태그, 소스, 토론 전체 검색
- **토론과 투표(Polls):** 글마다 댓글, Squad 안에서 투표
- **Pause New Tab:** 30분, 1시간, 2시간, 내일까지, 사용자 지정 시간 동안 새 탭 피드를 끄고 다른 URL을 보여줌. 집중 시간에 유용합니다
- **Reading streaks, Achievements, Quests:** 읽기 습관을 위한 게임 요소
- **Career Mode:** 구직 선호를 설정하면 채용 기회를 매칭해 주는 기능(문서상 Plus와 별개로 무료)
- **Organizations:** 회사가 Plus 좌석을 일괄 구매·관리

### 공개 API와 MCP 서버

개발자 입장에서 흥미로운 부분입니다. 모든 계정이 개인 액세스 토큰을 만들어 `https://api.daily.dev/public/v1` API로 피드, 검색, 북마크, 커스텀 피드를 JSON으로 다룰 수 있습니다. 같은 기능이 원격 MCP 서버(`https://api.daily.dev/mcp`)로도 제공되어 Claude Code, Cursor, Codex 같은 AI 에이전트에서 바로 쓸 수 있습니다.

- 무료 계정은 **월 200 요청**, Plus는 더 높은 한도(구체적 수치는 문서에 없음)
- 토큰은 `dda_` 로 시작하며 생성 시 한 번만 보여집니다
- MCP 호출도 같은 한도를 공유하고, 호출 한 번이 요청 한 번입니다
- MCP 서버는 문서상 베타입니다

참고로 Plus 소개 페이지에는 아직 "Public API" 가 Plus 혜택으로 적혀 있지만, 2026년 10월 커밋("drop the Plus requirement")과 API 설정 문서는 무료 계정도 토큰을 만들 수 있다고 안내합니다. 최신 안내는 API 문서 쪽을 기준으로 보세요.

## 설치와 시작

### 일반 사용자

1. **브라우저 확장 (권장):** [Chrome 웹 스토어](https://chromewebstore.google.com/detail/dailydev-where-developers/jlmpjdjjbgclbocgajdjefcidcncaied) 또는 [Edge 애드온](https://microsoftedge.microsoft.com/addons/detail/dailydev-the-homepage-/cbdhgldgiancdheindpekpcbkccpjaeb)에서 설치하고 새 탭을 엽니다.
2. **웹 앱:** [daily.dev](https://daily.dev) 에 접속합니다. Safari, Firefox, Brave, Opera, Vivaldi 사용자에게는 문서가 PWA(설치형 웹 앱) 사용을 권합니다.
3. **모바일:** [iOS](https://apps.apple.com/app/daily-dev/id6740634400), [Android](https://play.google.com/store/apps/details?id=dev.daily) 앱
4. 태그를 고르고 가입하면 북마크, 설정 동기화가 활성화됩니다.

Firefox 확장은 문서에 따르면 Mozilla 심사 이후 스토어에서 일시적으로 내려가 있는 상태입니다.

### 기여자: 확장 프로그램 로컬 빌드

`apps` README 기준 절차입니다. Node 버전은 `.nvmrc`, pnpm 버전은 `package.json` 에 고정되어 있습니다.

```bash
git clone https://github.com/dailydotdev/apps.git
cd apps
nvm use
corepack enable
corepack prepare pnpm@10.33.4 --activate
pnpm install

# 확장 개발 빌드 (변경 감시)
pnpm --filter extension dev
```

그다음 Chrome에서 `chrome://extensions/` 를 열고 개발자 모드를 켠 뒤, "압축해제된 확장 프로그램 로드" 로 `packages/extension/dist/chrome` 폴더를 선택합니다. 스토어에서 설치한 정식 확장과 충돌할 수 있으니 테스트 중에는 정식 확장을 꺼 두라고 README가 안내합니다.

웹 앱의 `.env` 는 사내 개발 도메인을 API 주소로 가리키고 있고, 공개 백엔드 로컬 실행 안내는 삭제되었습니다. 따라서 외부 기여자가 전체 스택을 로컬에서 재현하기는 쉽지 않다고 보는 것이 현실적입니다. UI 컴포넌트 작업은 `packages/storybook` 으로 백엔드 없이 진행할 수 있습니다.

## 활용 시나리오

### 시나리오 1. 팀 기술 공유 채널을 Squad로 운영하기

1. Private Squad를 만들고 팀원을 초대합니다.
2. 게시 권한은 모두에게 열어 두고, 기본 규칙에 "공유 시 한 줄 요약 필수" 같은 팀 규칙을 추가합니다.
3. Manage > Integrations에서 Slack을 연결하고 `#tech-share` 채널을 고릅니다. 비공개 채널이면 채널에서 `/invite @daily.dev` 를 먼저 실행합니다.
4. 팀원은 피드에서 좋은 글을 Squad로 공유하고, 토론은 글 아래 댓글에서 이어갑니다.

Slack에 링크만 쌓이는 것보다 글마다 토론이 붙고, 나중에 검색하기도 쉽습니다.

### 시나리오 2. 터미널에서 오늘의 글 확인하기 (공개 API)

[설정 > API](https://daily.dev/settings/api/) 에서 토큰을 만든 뒤, 문서의 첫 쿼리 예제를 그대로 실행해 봅니다.

```bash
export DAILY_DEV_TOKEN="dda_your_token_here"

# 내 For You 피드 5개
curl -s -H "Authorization: Bearer $DAILY_DEV_TOKEN" \
  "https://api.daily.dev/public/v1/feeds/foryou?limit=5" | jq .

# 이번 주 kubernetes 관련 글 검색
curl -s -H "Authorization: Bearer $DAILY_DEV_TOKEN" \
  "https://api.daily.dev/public/v1/search/posts?q=kubernetes&time=week&limit=10" | jq .
```

응답에 들어 있는 `cursor` 값을 다음 요청의 쿼리 파라미터로 넘기면 다음 페이지를 받습니다. 응답 필드 구조는 OpenAPI 스펙(`https://api.daily.dev/public/v1/docs/json`)에서 확인합니다. 무료 한도가 월 200회이므로 cron으로 자주 돌리는 용도에는 맞지 않습니다. 응답 헤더 `X-RateLimit-Remaining` 으로 남은 횟수를 확인할 수 있습니다.

토큰을 셸 설정 파일에 평문으로 두기 싫다면 macOS에서는 키체인에 넣고 꺼내 쓰면 됩니다(daily.dev 스킬 문서가 안내하는 방법).

```bash
security add-generic-password -a "$USER" -s "daily-dev-api" -w "dda_your_token"
export DAILY_DEV_TOKEN=$(security find-generic-password -a "$USER" -s "daily-dev-api" -w 2>/dev/null)
```

### 시나리오 3. AI 코딩 에이전트에 daily.dev 연결하기 (MCP)

LLM은 학습 시점 이후의 소식을 모릅니다. daily.dev MCP 서버를 붙이면 에이전트가 최신 개발 글을 검색해 참고할 수 있습니다.

```bash
# Claude Code
claude mcp add --transport http daily.dev https://api.daily.dev/mcp
# 이후 Claude Code 안에서 /mcp 실행해 로그인 (OAuth)

# Codex
codex mcp add daily-dev --url https://api.daily.dev/mcp
```

Cursor는 `.cursor/mcp.json` 에 다음을 추가합니다.

```json
{
  "mcpServers": {
    "daily.dev": {
      "url": "https://api.daily.dev/mcp"
    }
  }
}
```

OAuth 동의 화면에서 `write` 권한은 거절하고 읽기만 허용할 수 있고, 연결은 Settings > API > Connected apps에서 해제합니다. Claude Code 사용자라면 이 저장소 자체가 플러그인 마켓플레이스 역할도 합니다.

```
/plugin install daily.dev --marketplace dailydotdev/daily
```

이 플러그인은 스킬 외에 대기 중 상태줄에 daily.dev 헤드라인을 보여주는데, README에 따르면 어떤 헤드라인이 표시되었는지 익명 노출 데이터를 보냅니다. 원치 않으면 `DAILY_DEV_TELEMETRY=0` 으로 끕니다.

### 시나리오 4. GitHub 프로필에 DevCard 자동 갱신하기

공식 GitHub Action `dailydotdev/action-devcard` 를 쓰면 DevCard PNG를 주기적으로 저장소에 커밋할 수 있습니다. `user_id` 는 DevCard 이미지 URL에서 확인할 수 있고, 저장소 시크릿에 넣습니다. 아래는 README 예제에 스케줄 트리거를 붙인 것입니다.

{% raw %}
```yaml
# .github/workflows/devcard.yml (프로필 저장소에)
name: devcard
on:
  schedule:
    - cron: "0 0 * * *"
  workflow_dispatch:

jobs:
  devcard:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - name: devcard
        uses: dailydotdev/action-devcard@3.2.1
        with:
          user_id: ${{ secrets.USER_ID }}
          type: wide
          commit_filename: devcard.png
```
{% endraw %}

그리고 프로필 README에 `![DevCard](./devcard.png)` 를 넣으면 됩니다. `type` 은 `default`(세로)와 `wide`(가로) 중에서 고릅니다.

## 실무 팁 & 자주 겪는 문제

- **피드가 내 관심사와 안 맞으면** 태그를 추가하기보다 **관심 없는 태그와 소스를 차단**하는 편이 효과가 빠릅니다. 콘텐츠 종류 필터에서 Memes, Listicles를 끄는 것도 체감이 큽니다.
- **팔로우 태그를 너무 많이 고르면** 개인화의 의미가 줄어듭니다. 지금 쓰는 스택 위주로 시작해 조금씩 넓히세요.
- **새 탭이 집중을 방해하면** Pause New Tab으로 일정 시간 끄거나, 웹 앱을 북마크해 두고 필요할 때만 여는 방식도 있습니다.
- **회사 PC에서 확장 설치가 막혀 있으면** 웹 앱이나 PWA로 같은 계정을 씁니다. 북마크와 설정은 동기화됩니다.
- **Companion 위젯은 선택 기능입니다.** 추가 권한이 부담스럽다면 Customize > Preferences에서 끕니다.
- **평판 점수가 안 오르면** 추천을 준 사람의 평판이 250 미만이기 때문일 수 있습니다. 댓글 추천(+50)이 글 추천(+10)보다 비중이 큽니다.
- **API 토큰은 `api.daily.dev` 외의 곳으로 보내지 말고 커밋하지 마세요.** 만료 기간(30일, 90일, 1년, 무기한)을 정할 수 있으니 스크립트용은 짧게 잡습니다.
- **버그 제보는 `dailydotdev/daily` 이슈, 기능 아이디어는 Discussions** 에 올립니다. 비활성 이슈를 자동으로 닫는 워크플로가 있으니 재현 절차를 구체적으로 적는 것이 좋습니다.
- **코드 기여 시 CLA 서명이 필요합니다.** 기여 가이드에 따르면 PR 전에 관련 이슈로 먼저 논의하고, Angular 커밋 메시지 규칙을 따릅니다.

## 비슷한 도구와 비교

아래 비교 중 daily.dev 외의 도구에 대한 내용은 일반적으로 알려진 특성을 바탕으로 한 정리입니다.

| 항목 | daily.dev | Hacker News | Reddit (r/programming 등) | dev.to | Feedly |
|---|---|---|---|---|---|
| 성격 | 외부 글 모음 + 개인화 피드 + 커뮤니티 | 단일 공용 링크 순위 | 주제별 게시판 커뮤니티 | 플랫폼 안에서 글을 쓰는 블로그 커뮤니티 | 범용 RSS 리더 |
| 개인화 | 태그·소스·읽기 기록 기반 | 없음 (모두 같은 목록) | 구독한 서브레딧 단위 | 팔로우 태그 기반 | 직접 등록한 피드 |
| 출처 관리 | 서비스가 큐레이션 (2,000+) | 사용자 제출 | 사용자 제출 | 플랫폼 작성 글 | 사용자가 직접 |
| 토론 | 글별 댓글, Squad | 강함 (스레드 문화) | 강함 | 글별 댓글 | 거의 없음 (팀 기능 일부) |
| 접근 방식 | 새 탭 확장, 웹, 모바일 | 웹 | 웹, 앱 | 웹 | 웹, 앱 |
| 오픈소스 | 프론트엔드 공개 (AGPL) | 아님 | 아님 | Forem 엔진 공개 | 아님 |
| 수익 모델 | 광고 + Plus 구독 | 운영사(YC) 부속 | 광고 | 광고·후원 | 구독 |

README FAQ도 dev.to는 "플랫폼 안에서 글을 쓰는 블로깅 커뮤니티", Hacker News는 "모두에게 같은 하나의 순위 목록"이라고 구분하며, 많은 개발자가 함께 쓴다고 설명합니다. 실제로는 하나를 고르기보다, daily.dev로 넓게 훑고 HN·Reddit에서 깊은 토론을 보는 식으로 병행하는 경우가 많습니다.

## 장점과 한계

**장점**

- 출처를 직접 찾고 관리할 필요 없이 태그만 고르면 됩니다.
- 새 탭에 피드가 떠서 습관적으로 기술 소식을 접하게 됩니다.
- 확장, 웹, iOS, Android 사이에 북마크와 설정이 동기화됩니다.
- Squad와 Slack 연동으로 팀 지식 공유 채널로도 쓸 수 있습니다.
- 공개 API와 MCP 서버로 스크립트나 AI 에이전트에 연결할 수 있습니다.
- 핵심 기능은 무료이고, 프론트엔드 코드가 공개되어 확장이 무엇을 하는지 직접 확인할 수 있습니다.

**한계**

- **셀프 호스팅 대상이 아닙니다.** 백엔드 저장소가 현재 공개 상태로 확인되지 않고 로컬 전체 실행 안내도 삭제되었습니다. "오픈소스"라는 말에서 Mastodon처럼 직접 운영할 수 있는 서비스를 기대하면 맞지 않습니다.
- **`daily` 저장소는 코드가 아닙니다.** 스타 수에 비해 코드를 읽거나 기여할 거리는 `apps` 쪽에 있습니다.
- **광고 기반 서비스입니다.** 표시된 네이티브 광고가 피드에 섞이며, 광고 제거는 Plus입니다.
- **추천 로직이 블랙박스입니다.** 공개 문서는 피드 순위 요소를 개략적으로만 설명합니다.
- **새 탭 점유가 오히려 산만함이 될 수 있습니다.** 집중이 필요한 사람에게는 Pause 기능이나 웹 앱 사용이 낫습니다.
- **Firefox 확장이 현재 제공되지 않습니다**(문서 기준 일시 중단). Safari도 확장이 없어 PWA로 써야 합니다.
- **무료 API 한도(월 200회)가 작습니다.** 자동화에 본격적으로 쓰려면 Plus가 필요합니다.
- **주로 영어 콘텐츠입니다.** 언어 필터가 있지만 출처 대부분이 영어권입니다(문서에 언어 목록이 명시되어 있지 않아 한국어 출처 비중은 확인하지 못했습니다).

## 이런 분께 추천

- 여러 기술 블로그와 뉴스레터를 따로 챙기기 버거운 개발자
- 내 스택(예: React, Kubernetes, AI) 관련 소식만 걸러서 보고 싶은 분
- 팀 단위로 좋은 글을 공유하고 토론할 공간이 필요한 리드나 DevRel
- AI 에이전트에 최신 개발 소식 검색 도구를 붙이고 싶은 분
- 대규모 Next.js + 브라우저 확장 모노레포의 실제 구조를 보고 싶은 프론트엔드 개발자 (`apps` 저장소)

## 이런 경우엔 다른 도구

- 내가 고른 출처만 정확히 받아보고 싶다면 Feedly, Inoreader, Miniflux 같은 RSS 리더
- 셀프 호스팅 가능한 피드 리더가 필요하다면 FreshRSS, Miniflux
- 깊이 있는 스레드 토론이 목적이라면 Hacker News, Lobsters, Reddit
- 직접 글을 쓰고 독자를 모으고 싶다면 dev.to, Hashnode, 개인 블로그
- 사내 전용으로 외부 서비스 없이 운영해야 한다면 사내 RSS 리더나 Slack RSS 연동

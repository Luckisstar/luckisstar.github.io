# [기술 소개] Claude Duet: 백그라운드에서 일하고 행동 전에 묻는 '능동형 에이전트' 앱

- **발표:** Anthropic, 2026년 10월 21일
- **원문:** [공식 발표](https://claude.com/blog/claude-duet) · [제품 페이지와 대기자 명단](https://claude.com/product/claude-duet)
- **상태 (2026-10-24 기준):** **연구 프리뷰(research preview)이며 대기자 명단(waitlist)으로만 열립니다.** 대상은 **미국의 Pro·Max 구독자**부터이고, 다른 지역의 공개 일정은 발표되지 않았습니다.
- **사용량 주의:** 별도 요금은 없지만 Claude의 다른 기능과 **같은 사용량 한도를 나눠 씁니다.** 몇 시간마다 하는 백그라운드 확인도 한도를 쓰며, 재무 모델이나 발표 자료처럼 큰 작업은 더 많은 모델 턴을 소모한다고 발표문이 밝힙니다.

## 한 줄 요약

**Claude Duet은 사용자가 묻기 전에 먼저 "지금 봐야 할 것"을 알려 주고, 사용자가 자리를 비워도 클라우드 가상 머신에서 작업을 이어 가되, 메시지 발송·결제·서명·삭제 전에는 반드시 승인을 받는 Anthropic의 능동형(proactive) 에이전트 앱입니다.** 챗봇이 "질문에 답하는 도구"에서 "먼저 연락하는 동료"로 바뀌는 흐름을 보여 주는 사례이자, 사람 승인 루프(human-in-the-loop)를 제품 수준에서 어떻게 그었는지 볼 수 있는 사례입니다.

## 배경

지금까지의 대화형 AI는 사용자가 말을 걸어야 움직였습니다. 2026년에는 여러 회사가 "사용자가 없어도 돌아가는" 에이전트를 내놓고 있습니다. 공식 자료로 확인한 것만 정리하면 다음과 같습니다.

## 핵심 내용

### 1. 먼저 연락하는 구조: 아침 브리핑과 몇 시간 간격 확인

- **아침 브리핑:** 매일 아침 연결된 앱 전체에서 가장 중요한 항목을 짧게 정리해 보냅니다. 제품 페이지 예시에는 "채용 후보의 다른 오퍼가 오후 6시 만료", "계약 갱신안에 상대가 Net 60 조건을 요구, 변경점 요약됨", "보건 허가에 승인과 $640 필요" 같은 항목이 나옵니다.
- **백그라운드 확인:** 연결된 계정을 **몇 시간마다** 확인하고, 주의가 필요할 때만 메시지를 보냅니다. 발표문은 그 이유를 "쉬지 않고 확인하면 요금제 한도를 훨씬 빨리 쓰기 때문"이라고 직접 밝힙니다. 무엇을, 얼마나 자주 듣고 싶은지는 사용자가 정할 수 있습니다.
- **하나의 대화 스레드:** 짧은 답장과 일주일짜리 프로젝트를 같은 스레드에서 타이핑이나 음성으로 주고받습니다.

### 2. 자리를 비워도 일한다: 전용 가상 머신

Duet은 **자체 브라우저가 있는 가상 머신**에서 돌아가므로 사용자의 노트북이나 휴대폰이 꺼져 있어도 됩니다. 짧게 작업을 설명하면 어떤 앱을 쓰고 어떤 단계를 밟을지 스스로 정하고, 끝나거나 검토가 필요할 때 알림을 보냅니다. Claude 계정의 기억(memory), 스킬, 연결된 앱을 그대로 가져오므로 따로 설정할 것이 적습니다.

발표문이 든 작업 예시는 회의 일정 잡기 같은 단순 업무부터 수십 개 도구를 엮은 대시보드, 재무·영업 예측, 프로토타입과 웹 앱 제작까지입니다. 커넥터 예시로는 Gmail·Slack 미답장 메시지 찾기, QuickBooks·Stripe 미수금 확인과 독촉 메일 초안, Gusto 급여 준비와 실행, LinkedIn 채용 공고, Docusign 서명 요청, HubSpot 후속 메일, Canva 캠페인, Shopify 스토어 관리가 나옵니다.

### 3. 승인 규칙: 읽기·초안은 자율, 보내기·결제·서명·삭제는 승인, 일부는 금지

Duet의 승인 경계는 발표문에 이렇게 적혀 있습니다.

| 범주 | 행동 | Duet의 동작 |
|---|---|---|
| 자율 | 읽기, 초안 작성, 작업 준비 | 스스로 진행 |
| 승인 필요 | 메시지 발송, 결제, 문서 서명, 삭제 | **실행할 내용을 정확히 보여 주고** 승인을 기다림 |
| 금지 | 증권 거래, 계좌 간 자금 이동 등 | 사용자가 승인해도 하지 않음 |
| 연결 해제 | 접근 권한을 준 앱 | 사용자가 언제든 끊을 수 있음 |

구매는 Stripe의 디지털 지갑 Link로 합니다. Duet이 품목을 확인하고, Link가 지출 승인을 따로 받은 뒤 **가상 카드**로 결제해 실제 카드 번호가 공유되지 않습니다. Shopify의 Shop Pay로도 결제할 수 있습니다. 1Password에 저장된 로그인으로 사이트에 접속하는 기능은 2026-10-24 기준 "곧 제공 예정"입니다.

### 4. 보안 설계: 기존 에이전트 제품의 장치를 재사용

발표문은 Duet의 안전장치를 대부분 기존 제품에서 가져왔다고 밝힙니다.

- **자격 증명:** Claude Managed Agents와 같은 설계를 따라 Duet은 비밀번호나 로그인 토큰을 직접 보지 않습니다.
- **행동 승인:** Claude Code의 **auto mode 분류기**가 행동을 승인합니다. 사용자가 요청하지 않은 단계를 막는 장치입니다.
- **프롬프트 인젝션 방어:** 브라우저 사용 연구에서 나온 방어를 적용했습니다. 이메일이나 웹페이지에 숨긴 지시문으로 에이전트를 조종하는 공격을 막기 위한 것입니다.
- **검증:** 내부 레드팀과 외부 업체가 침투 테스트를 했고, 공개 버그 바운티 범위에 포함됩니다.

### 5. 새로 추가된 것: 민감정보 분류기

Duet에서 새로 나온 장치는 **민감정보 전용 분류기와 안전 시스템 프롬프트**입니다. 메시지마다 검사해 정보 유출을 막습니다. 발표문의 표현대로 "메일을 읽고 대신 메시지를 보내는 에이전트는 정보가 어디로 가야 하는지를 끊임없이 판단"하기 때문입니다.

- **가장 엄격한 등급**(신용카드 번호, 정부 발급 신분증 등)은 공유 요청 자체를 거부합니다.
- **그 밖의 민감정보**(건강, 개인 재무 등)는 사용자가 명시적으로 보내라고 지시했을 때만 통과시킵니다.

Anthropic은 안전 설계의 세부 내용을 "앞으로 며칠 안에" 공개하겠다고 했습니다(2026-10-24 기준 예정).

## 써 볼 수 있나

- **조건 (2026-10-24 기준):** 미국 Pro·Max 구독자가 [대기자 명단](https://claude.com/product/claude-duet)에 등록하면 순서대로 이메일로 안내됩니다. 한국을 포함한 다른 지역은 아직 대상이 아닙니다.
- **비용:** 추가 요금은 없지만 사용량 한도를 Claude의 다른 기능과 함께 씁니다. 백그라운드 확인이 한도를 계속 쓰므로, 같은 요금제로 Claude Code나 일반 대화를 많이 쓰는 사람은 한도 소진을 먼저 고려해야 합니다.
- **현재 제약 (발표문 기준):** 스레드를 잘못 읽거나 급한 정도를 잘못 판단할 수 있습니다. 업무 중심으로 만들어 티켓 예매 같은 개인 용무는 상대적으로 약합니다. 작업 중인 브라우저 화면을 아직 보여 주지 못합니다. 기존 Claude 앱과 분리된 별도 앱입니다.

**개발자가 가져갈 패턴: 승인 경계를 코드로 쓰기.** 아래는 발표문의 규칙을 필자가 그대로 코드로 옮겨 본 예시입니다. **Duet의 내부 구현이 아니며**, 규칙 구조를 보여 주기 위한 것입니다. Python 3로 직접 실행해 출력을 확인했습니다.

```python
from dataclasses import dataclass

AUTONOMOUS = {"read", "draft", "prepare"}
NEEDS_APPROVAL = {"send_message", "make_payment", "sign_document", "delete"}
FORBIDDEN = {"trade_securities", "transfer_between_accounts"}

@dataclass
class Action:
    kind: str
    summary: str  # 사용자에게 보여 줄 "정확히 무엇을 할지"

def gate(action: Action, ask_user) -> str:
    if action.kind in FORBIDDEN:
        return "blocked"                      # 승인이 있어도 실행하지 않음
    if action.kind in NEEDS_APPROVAL:
        ok = ask_user(f"다음을 실행할까요? {action.summary}")
        return "run" if ok else "skipped"
    if action.kind in AUTONOMOUS:
        return "run"
    return "blocked"                          # 모르는 행동은 기본 거부
```

```
draft -> run
다음을 실행할까요? ACME에 미수금 알림 메일 발송
send_message -> skipped
transfer_between_accounts -> blocked
rename_folder -> blocked
```

세 가지가 핵심입니다. (1) 금지 목록을 승인 목록보다 **먼저** 검사해 "승인해도 안 되는 것"을 보장합니다. (2) 승인 요청에는 추상적인 행동 이름이 아니라 **실행할 내용 그대로**를 보여 줍니다. (3) 분류되지 않은 행동은 기본 거부합니다. 실제 시스템에서는 행동 분류를 모델이 하므로, 분류 자체가 틀릴 수 있다는 점이 아래 "한계"의 주제입니다.

## 한계와 논란

- **승인을 대신하는 분류기에도 놓치는 비율이 있습니다.** Duet이 쓰는 auto mode 분류기에 대해 Anthropic은 2026년 3월 Claude Code 엔지니어링 글에서, 실제 "과잉 행동(overeager)" 사례에 대한 미탐률(false-negative rate)이 **17%**, 정상 행동을 막는 오탐률이 0.4%라고 공개했습니다. 같은 글은 이 분류기가 "고위험 작업에서 신중한 사람 검토를 대체하는 것이 아니다"라고 적었습니다. 이 수치는 Claude Code 기준이며 Duet 환경에서의 수치는 공개되지 않았습니다. 다만 Duet은 발송·결제·서명·삭제에 사람 승인을 따로 두므로, 분류기는 그 밖의 행동을 거르는 층으로 보는 것이 맞아 보입니다.
- **"무엇이 발송인가"의 경계가 흐릴 수 있습니다.** 발표문은 Gusto에서 급여를 "준비하고 실행(prepare and run)"하는 것을 예시로 들면서, 계좌 간 자금 이동은 금지한다고 씁니다. 급여 실행이 결제 승인 범주로 처리되는지는 발표문만으로는 알 수 없습니다. 실제 동작은 프리뷰 사용자 보고나 추가 공개 자료로 확인해야 합니다.
- **민감정보 분류기의 기준이 아직 공개되지 않았습니다.** "가장 엄격한 등급"의 전체 목록, 오판 시 처리 방식은 "며칠 안에" 공개될 예정입니다(2026-10-24 기준).
- **사용량 한도가 사실상 비용입니다.** 확인 주기를 "몇 시간"으로 둔 이유가 한도 소진이라고 발표문이 직접 밝혔습니다. 능동형 에이전트의 반응 속도와 비용이 정면으로 맞바뀐다는 뜻이며, 급한 일을 몇 시간 늦게 알게 될 수 있습니다.
- **작업 화면이 보이지 않습니다.** 프리뷰 단계에서는 Duet의 브라우저를 사용자가 볼 수 없어, 승인 요청 외의 과정은 결과로만 확인할 수 있습니다.
- **정량 평가가 없습니다.** 공개된 근거는 내부 사용자와 초기 사용자 3명의 사례 인용뿐입니다. 얼마나 자주 불필요하게 연락하는지, 중요한 것을 놓치는지는 수치로 나와 있지 않습니다.

## 인사이트

**왜 지금 중요한가.** 2026년의 능동형 에이전트 경쟁은 모델 성능보다 **신뢰 설계** 경쟁에 가깝습니다. Google Spark, Hark Pro, Claude Duet은 모두 "클라우드에서 혼자 일하고, 중요한 일은 묻는다"는 같은 뼈대를 갖고 있습니다. 차이는 어디에 선을 긋고 그 선을 얼마나 구체적으로 공개하느냐입니다. Duet 발표문에서 눈에 띄는 것은 "승인해도 하지 않는 일"(증권 거래, 계좌 간 이체)을 명시한 점과, 민감정보를 등급으로 나눠 가장 높은 등급은 사용자 지시가 있어도 막는다는 점입니다. 사용자의 승인 한 번이 모든 위험을 덮지 못한다는 것을 제품 정책으로 인정한 셈입니다.

**실무에 주는 의미: 사람 승인 루프를 설계하는 개발자에게.** 사내 에이전트에 승인 단계를 넣을 때 Duet의 규칙은 좋은 출발점입니다. 필자가 정리한 원칙은 다음과 같습니다.

1. **되돌릴 수 없는 행동만 승인을 받습니다.** 읽기와 초안까지 매번 물으면 승인 피로가 생깁니다. Anthropic의 auto mode 글은 Claude Code 사용자가 권한 요청의 93%를 그냥 수락한다고 밝혔습니다. 승인 요청이 많을수록 사람은 덜 꼼꼼해집니다.
2. **승인으로도 열리지 않는 금지 목록을 따로 둡니다.** 사회공학이나 프롬프트 인젝션으로 사용자가 잘못 승인하는 경우까지 막는 마지막 층입니다.
3. **승인 화면에는 실행할 내용 그대로를 보여 줍니다.** "메일 발송" 대신 받는 사람, 제목, 본문을 보여 줘야 승인이 의미를 가집니다.
4. **결제는 별도 채널로 한 번 더 확인합니다.** Duet이 Link의 지출 승인과 가상 카드를 쓰는 구조는, 에이전트가 실제 결제 수단에 직접 닿지 않게 하는 좋은 예입니다.
5. **백그라운드 실행 주기는 비용 변수입니다.** "얼마나 자주 확인할까"는 UX 결정이 아니라 예산 결정이므로 사용자가 조절하게 둡니다.

**블로그의 기존 글과의 연결.** Duet이 Claude 계정의 스킬을 그대로 가져온다는 점은 [Agent Skills의 AAIF 기증](/tech/2026/10/24/agent-skills-aaif.html)과 맞닿아 있습니다. 팀이 `SKILL.md`로 정리한 업무 절차가 대화 도구, 코딩 에이전트, 능동형 에이전트에서 함께 쓰이는 방향입니다. 6,000개 이상 커넥터로 외부 앱에 닿는 부분은 [MCP 아키텍처](/tech/2026/10/24/mcp-architecture.html) 글에서 다룬 도구 연결 계층 위에 서 있습니다. 같은 기능이 쌓일수록 공격면도 넓어지므로, 앞의 글들에서 지적한 스킬·커넥터 공급망 문제는 능동형 에이전트에서 더 중요해집니다. 사용자가 보지 않는 시간에 외부 메일과 웹페이지를 읽기 때문입니다.

**한계와 반론.** 능동형 에이전트의 가치는 "적절한 때 적절한 것만 알려 주는 판단력"인데, 이것은 가장 측정하기 어려운 능력입니다. 발표문도 "급한 정도를 잘못 판단할 수 있다"고 인정합니다. 놓친 알림 하나의 비용이 큰 업무(계약 기한, 급여)일수록 사용자는 결국 원래 앱을 다시 확인하게 되고, 그러면 에이전트가 줄여 준다던 주의력 부담은 생각보다 작을 수 있습니다. 필자의 판단으로는, 초기에는 "Duet이 알려 준 것"보다 "Duet이 알려 주지 않았는데 중요했던 것"을 기록해 두는 방식으로 신뢰를 쌓는 것이 현실적입니다.

**앞으로 지켜볼 점.** (1) 예고된 안전 설계 상세 문서에 민감정보 등급과 분류기 오판율이 담기는지. (2) 미국 밖 지역과 Team·Enterprise 요금제로의 확대 시점. (3) 작업 중인 브라우저를 보여 주는 기능과 기존 Claude 앱과의 통합. 특히 (1)이 공개되기 전까지는 회사 메일이나 결제 계정을 연결할 때 연결 범위를 최소로 두는 것이 안전합니다.

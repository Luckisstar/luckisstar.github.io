# [기술 소개] AGENTS.md: 코딩 에이전트에게 저장소 사용법을 알려 주는 표준 파일

- **주요 출처:** [agents.md 공식 사이트](https://agents.md) · [agentsmd/agents.md 저장소](https://github.com/agentsmd/agents.md) · [Linux Foundation AAIF 설립 발표(2025-12-09)](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation) · 각 도구 공식 문서([Codex](https://developers.openai.com/codex/guides/agents-md), [Claude Code](https://code.claude.com/docs/en/memory), [Cursor](https://cursor.com/docs/rules), [GitHub Copilot](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions), [Gemini CLI](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/gemini-md.md)) · 효과 측정 논문 [arXiv:2602.11988](https://arxiv.org/abs/2602.11988)
- **한눈에 (2026-10-24 기준):** OpenAI가 2025년 8월 공개했고, 2025년 12월 9일 Linux Foundation 산하 AAIF(Agentic AI Foundation)의 창립 프로젝트가 됐습니다. 발표 시점 6만 개 이상의 오픈소스 프로젝트가 채택(Linux Foundation 발표 기준). 필수 필드가 없는 평범한 마크다운이며, 사이트 저장소는 MIT 라이선스, GitHub 스타 약 2.5만 개입니다.
- **주의:** "넣으면 에이전트가 더 잘한다"는 효과는 아직 입증되지 않았습니다. 독립 연구에서 컨텍스트 파일은 성공률을 유의미하게 올리지 못하고 추론 비용만 20% 넘게 늘렸습니다(아래 "한계와 논란" 참고).

## 한 줄 요약

**AGENTS.md는 저장소 루트(와 하위 폴더)에 두는 "에이전트용 README"로, 빌드·테스트 명령과 코드 규칙처럼 사람용 README에는 넣기 애매한 작업 지침을 여러 코딩 에이전트가 같은 파일에서 읽도록 만든 관례입니다.**

## 배경

코딩 에이전트가 저장소에서 일하려면 사람 신입이 첫날 묻는 것과 같은 정보가 필요합니다. 의존성은 무엇으로 설치하는지, 테스트는 어떤 명령으로 돌리는지, 커밋 메시지 규칙이 있는지 같은 것들입니다. 문제는 도구마다 이 정보를 담는 파일 이름이 달랐다는 점입니다. Claude Code는 `CLAUDE.md`, Cursor는 `.cursor/rules/`, GitHub Copilot은 `.github/copilot-instructions.md`, Gemini CLI는 `GEMINI.md`를 읽었고, 여러 도구를 함께 쓰는 팀은 같은 내용을 파일 여러 개에 복사해야 했습니다.

agents.md 사이트는 이 상황을 이렇게 설명합니다. "또 하나의 독점 파일을 만드는 대신, 누구에게나 통할 이름과 형식을 골랐다." 사이트의 About 절에 따르면 AGENTS.md는 OpenAI Codex, Amp, Google Jules, Cursor, Factory 등 여러 곳의 협업에서 나왔습니다.

| 날짜 | 사건 | 출처 |
|---|---|---|
| 2025-08 | OpenAI가 AGENTS.md 공개 (사이트 저장소 생성일 2025-08-19) | Linux Foundation 발표, `gh api repos/agentsmd/agents.md` |
| 2025-12-09 | AAIF 설립, MCP·goose와 함께 창립 프로젝트로 기증 | [Linux Foundation 발표](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation), [Anthropic 발표](https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation) |
| 2026-02-12 | 컨텍스트 파일의 효과를 측정한 논문 첫 공개 (v3: 2026-09-29) | [arXiv:2602.11988](https://arxiv.org/abs/2602.11988) |
| 2026-09-18 | Claude Code v2.1.277에 AGENTS.md 지원 추가 (`CLAUDE.md`가 없는 프로젝트에서 대신 읽음) | [Claude Code 변경 이력](https://code.claude.com/docs/en/changelog) |

Linux Foundation 발표문은 AGENTS.md를 "AI 코딩 에이전트가 서로 다른 저장소와 툴체인에서 안정적으로 동작하는 데 필요한 프로젝트별 지침의 일관된 출처를 주는 단순하고 보편적인 표준"으로 소개하고, 채택한 에이전트 프레임워크로 Amp, Codex, Cursor, Devin, Factory, Gemini CLI, GitHub Copilot, Jules, VS Code를 들었습니다. 사이트 하단에는 현재 "AGENTS.md a Series of LF Projects, LLC"라는 저작권 표기와 함께 AAIF가 관리한다고 적혀 있습니다.

## 핵심 내용

### 1. 형식: 필수 필드가 없는 평범한 마크다운

공식 FAQ의 첫 질문이 "필수 필드가 있나요?"이고, 답은 "없다"입니다. 원하는 제목을 쓰면 되고, 에이전트는 적힌 텍스트를 그대로 읽습니다. 같은 AAIF 프로젝트인 Agent Skills가 YAML 프런트매터 필드 6개를 명세로 정한 것과 대조적입니다. 사이트 저장소에도 별도 명세 문서나 버전 번호는 없고, 웹사이트 소스와 README, 기술 헌장(Technical_Charter.pdf)이 있을 뿐입니다(2026-10-24 확인).

사이트가 "자주 쓰는 섹션"으로 권하는 항목은 다음과 같습니다.

- 프로젝트 개요(Project overview)
- 빌드와 테스트 명령(Build and test commands)
- 코드 스타일 지침(Code style guidelines)
- 테스트 방법(Testing instructions)
- 보안 고려사항(Security considerations)
- 그 밖에 커밋 메시지·PR 규칙, 보안상 함정, 대용량 데이터, 배포 단계 등 "새 팀원에게 알려 줄 만한 것"

FAQ는 에이전트가 AGENTS.md에 적힌 테스트 명령을 자동으로 실행하느냐는 질문에 "적어 두면 그렇다"고 답합니다. 에이전트가 관련 검사를 실행하고 실패를 고친 뒤 작업을 끝내려 한다는 뜻입니다. 그래서 이 파일에서 가장 값이 큰 줄은 대개 **정확한 명령어 한 줄**입니다.

### 2. README와 무엇이 다른가

사이트의 설명은 역할 분리입니다. README는 사람을 위한 것(빠른 시작, 프로젝트 설명, 기여 안내)이고, AGENTS.md는 README를 어지럽히거나 사람 기여자에게는 필요 없는 세부 맥락(빌드 단계, 테스트, 관례)을 담습니다. 일부러 파일을 나눈 이유로는 세 가지를 듭니다. 에이전트에게 예측 가능한 위치를 주고, README를 사람 중심으로 간결하게 유지하고, 기존 문서를 보완하는 에이전트용 지침을 따로 두기 위해서입니다.

| 구분 | README.md | AGENTS.md |
|---|---|---|
| 독자 | 사람 (사용자, 기여자) | 코딩 에이전트 |
| 주된 내용 | 무엇인지, 어떻게 쓰는지, 왜 만들었는지 | 어떻게 빌드·테스트·검증하는지, 무엇을 하지 말아야 하는지 |
| 문체 | 설명과 맥락 | 명령형, 체크리스트 |
| 중복 | README가 원본 | README에 이미 있는 내용은 반복하지 않는 것이 좋음 (아래 연구 참고) |

### 3. 중첩 파일과 우선순위

모노레포(monorepo, 여러 패키지를 한 저장소에 두는 방식)에서는 패키지마다 AGENTS.md를 둘 수 있습니다. 사이트는 "에이전트가 디렉터리 트리에서 가장 가까운 파일을 읽으므로 가장 가까운 것이 우선한다"고 설명하고, 작성 시점 OpenAI 메인 저장소에 AGENTS.md가 88개 있었다는 예를 듭니다. FAQ의 충돌 규칙은 한 줄입니다. **수정하는 파일에 가장 가까운 AGENTS.md가 이기고, 사용자가 채팅으로 준 명시적 지시는 모든 것보다 우선합니다.**

다만 "가장 가깝다"를 구현하는 방식은 도구마다 다릅니다. 실제로는 하나만 고르는 도구보다 **위에서 아래로 이어 붙이고, 나중에 읽힌(더 가까운) 내용이 앞의 지침을 덮는** 방식이 많습니다. 도구별 차이는 다음 절에 정리했습니다.

### 4. 주요 도구의 지원 방식 (2026-10-24 공식 문서 기준)

| 도구 | AGENTS.md 지원 | 탐색과 우선순위 | 고유 파일·설정 |
|---|---|---|---|
| Codex | 기본 지원 | 전역(`~/.codex`) → 프로젝트 루트부터 현재 디렉터리까지 내려가며 디렉터리당 1개씩 이어 붙임. 가까운 파일이 뒤에 붙어 앞 지침을 덮음. 합계 `project_doc_max_bytes`(기본 32 KiB)에서 중단 | `AGENTS.override.md`(같은 디렉터리의 AGENTS.md보다 우선), `project_doc_fallback_filenames` |
| Claude Code | v2.1.277부터 직접 읽음 | 기본값은 작업 디렉터리나 그 위에 `CLAUDE.md`·`CLAUDE.local.md`가 **없을 때만** AGENTS.md를 읽음. 하위 폴더의 AGENTS.md는 그 폴더 파일을 열 때 로드 | `CLAUDE.md`, `@AGENTS.md` 가져오기, `/config`의 Project instructions 설정 |
| Cursor | 기본 지원 | 루트와 하위 폴더 모두 지원. 상위 폴더 지침과 합쳐지며 더 구체적인 쪽이 우선 | `.cursor/rules/*.mdc` (프런트매터가 있는 규칙) |
| GitHub Copilot | 지원 (에이전트 지침) | 저장소 어디에나 둘 수 있고, 작업 중 가장 가까운 파일이 우선. 대신 루트의 `CLAUDE.md`나 `GEMINI.md` 하나를 써도 됨 | `.github/copilot-instructions.md`, `.github/instructions/*.instructions.md` |
| Gemini CLI | 설정으로 지원 | 기본 파일 이름은 `GEMINI.md`. `settings.json`의 `context.fileName`에 `AGENTS.md`를 넣어 읽게 함 | `GEMINI.md` |

표의 내용은 모두 각 도구의 공식 문서(참고 링크)에서 확인했습니다. 필자가 각 도구에서 직접 동작을 시험한 것은 아닙니다. 공식 사이트는 이 밖에 Jules, Factory, Aider, goose, opencode, Zed, Warp, VS Code, Devin, Junie, Amp, Windsurf 등을 호환 도구로 나열합니다(2026-10-24 확인). Aider는 사이트 FAQ 기준으로 `.aider.conf.yml`에 `read: AGENTS.md`를 넣어야 합니다.

표에서 눈여겨볼 차이는 두 가지입니다. 첫째, **Claude Code의 기본값은 "둘 중 하나"**입니다. 저장소에 `CLAUDE.md`가 이미 있으면 AGENTS.md는 읽지 않습니다. 둘 다 읽게 하려면 `claude-md-and-agents-md`로 설정을 바꾸거나 `CLAUDE.md` 안에 `@AGENTS.md`를 넣어야 합니다. 문서는 개인용 `CLAUDE.local.md`를 하나 추가하는 것만으로도 AGENTS.md 로딩이 꺼진다고 따로 경고합니다. 둘째, **Codex의 `AGENTS.override.md`는 Codex 전용**이고, Claude Code 문서는 `AGENTS.override.md`와 `AGENTS.local.md`를 읽지 않는다고 명시합니다. 이식성을 원한다면 override 파일에 중요한 규칙을 두지 않는 편이 안전합니다.

### 5. 거버넌스: 명세보다 관례

AGENTS.md는 MCP처럼 프로토콜도 아니고, Agent Skills처럼 필드가 정해진 명세도 아닙니다. 사실상 "이 이름의 파일을 이 위치에서 읽는다"는 합의입니다. 그래서 AAIF로 넘어간 것은 형식 규칙이라기보다 이름과 도메인, 사이트 저장소이고, 실제 동작(어디까지 탐색하는지, 크기 제한, 충돌 처리)은 위 표처럼 각 도구가 정합니다. 사이트 저장소의 마지막 push는 2026-09-10입니다(2026-10-24 확인).

## 실무에서 쓰는 법

아래 예제는 공식 사이트와 각 도구 문서의 예제를 바탕으로 필자가 구성한 것이며, 에이전트에서 직접 실행해 결과를 확인하지는 않았습니다.

**예제 1. 최소한의 AGENTS.md (공식 사이트 예시 기반)**

```markdown
# AGENTS.md

## Setup commands
- Install deps: `pnpm install`
- Start dev server: `pnpm dev`
- Run tests: `pnpm test`

## Code style
- TypeScript strict mode
- Single quotes, no semicolons

## PR instructions
- Title format: [<project_name>] <Title>
- Always run `pnpm lint` and `pnpm test` before committing.
```

**예제 2. 좋은 지시와 나쁜 지시**

Claude Code 문서는 지시문이 "검증할 수 있을 만큼 구체적"이어야 한다며 예를 듭니다. 이 원칙은 AGENTS.md에도 그대로 적용됩니다.

| 나쁜 예 | 좋은 예 | 이유 |
|---|---|---|
| 코드를 깔끔하게 정리하세요 | 들여쓰기는 공백 2칸 | 지켰는지 확인할 수 있음 |
| 변경 사항을 테스트하세요 | 커밋 전에 `npm test`를 실행 | 명령이 정확함 |
| 파일을 잘 정리하세요 | API 핸들러는 `src/api/handlers/`에 둠 | 위치가 명확함 |
| `src/`에는 소스, `tests/`에는 테스트가 있습니다 (디렉터리 나열) | `npm run build`는 개발 서버를 깨뜨리므로 에이전트 세션에서 실행하지 말 것 | 에이전트가 스스로 알아내기 어려운 것만 적음 |

마지막 줄의 좋은 예는 agentsmd/agents.md 저장소의 실제 AGENTS.md에서 가져온 것입니다. 이 파일은 "`npm run build`를 실행하면 `.next` 폴더가 운영용 자산으로 바뀌어 핫 리로드가 꺼진다"는 이유까지 적어 둡니다. 반대로 디렉터리 나열이 나쁜 예인 이유는 아래 "한계와 논란"의 연구 결과 때문입니다.

**예제 3. 실제 사례: 이 블로그 저장소의 CLAUDE.md**

이 블로그 저장소에는 AGENTS.md 대신 97줄짜리 `CLAUDE.md`가 있고, 사람과 AI 에이전트가 함께 따르는 편집 기준을 담고 있습니다(2026-10-24 기준). 구조만 보면 다음과 같습니다.

```text
# Luckisstar 블로그 편집 가이드
## 콘텐츠 파이프라인        ← 작업 흐름과 절차 파일 위치
## 카테고리                ← 표 하나: slug, 제목 접두어, 폴더
## 파일과 front matter     ← 경로 규칙 + YAML 예시
## 문체와 표기              ← 합니다체, em dash 금지 등 검증 가능한 규칙
## 사실성 규칙 (가장 중요)   ← 번호 붙은 금지·필수 사항
## 인사이트 기준
## Liquid 주의             ← 빌드를 깨뜨리는 함정 하나
## 검증과 게시 전 체크리스트  ← python3 scripts/validate_posts.py
## 사이트 구조 참고          ← 지우면 안 되는 파일
```

AGENTS.md 관점에서 잘된 점은 **실행할 명령(검증 스크립트), 빌드를 깨뜨리는 함정(Liquid 구문), 지우면 안 되는 파일(검색엔진 인증 태그)**처럼 에이전트가 코드만 읽어서는 알기 어려운 내용이 중심이라는 것입니다. 상세 절차는 `editorial/prompts/` 아래 별도 파일로 빼고 본문에서는 경로만 알려 줍니다. 반면 이 파일 이름은 Claude Code 전용이라, Codex나 Cursor로 같은 저장소를 열면 이 기준이 자동으로 읽히지 않습니다.

**예제 4. 한 파일을 여러 도구가 나눠 읽게 하기**

Claude Code 문서가 권하는 방법은 내용을 AGENTS.md에 두고 `CLAUDE.md`에서 가져오는 것입니다.

```markdown
@AGENTS.md

## Claude Code
Use plan mode for changes under `src/billing/`.
```

Claude 전용 내용이 없다면 심볼릭 링크(`ln -s AGENTS.md CLAUDE.md`)도 됩니다. 다만 문서는 Windows에서는 심볼릭 링크 생성에 관리자 권한이나 개발자 모드가 필요하고, Git이 링크를 한 줄짜리 텍스트 파일로 체크아웃할 수 있으니 이때는 `@AGENTS.md` 가져오기를 쓰라고 권합니다. Gemini CLI는 `settings.json`에 다음을 넣습니다.

```json
{
  "context": {
    "fileName": ["AGENTS.md", "GEMINI.md"]
  }
}
```

Codex는 반대 방향으로, 이미 다른 이름의 지침 파일이 있으면 `~/.codex/config.toml`의 `project_doc_fallback_filenames`에 그 이름을 추가해 AGENTS.md처럼 읽게 할 수 있습니다.

## 한계와 논란

- **효과가 입증되지 않았습니다.** ETH Zurich의 Gloaguen 외 연구진은 [arXiv:2602.11988](https://arxiv.org/abs/2602.11988)(v3, 2026-09-29)에서 컨텍스트 파일의 효과를 측정했습니다. SWE-bench Lite(300개 과제)와, 개발자가 직접 커밋한 컨텍스트 파일이 있는 12개 저장소에서 모은 138개 과제(CTXbench)를 썼고, Claude Code(Sonnet-4.5), Codex(GPT-5.2, GPT-5.1 mini), Qwen Code(Qwen3-30b-coder) 네 가지 조합을 시험했습니다. LLM이 생성한 컨텍스트 파일은 8개 설정 중 5개에서 성능을 떨어뜨렸고(평균 SWE-bench -0.5%, CTXbench -2%, 통계적으로 유의하지 않음), 비용은 각각 평균 20%, 23% 늘렸습니다. 개발자가 쓴 파일은 평균 2.4% 올렸지만 이것도 유의하지 않았고(p=21%), 비용은 최대 19% 늘었습니다. 논문의 결론은 "컨텍스트 파일은 성능을 올리지 않으며, 코드베이스에 이미 있는 것 이상의 구체적인 추가 지시만 담아야 한다"입니다.
- **저장소 개요는 특히 도움이 되지 않았습니다.** 같은 논문은 에이전트가 지시를 잘 따른다는 점을 확인했지만, 그 결과는 더 많은 탐색과 테스트, 즉 비용 증가였습니다. 디렉터리 구조 설명은 에이전트가 정답과 관련된 파일에 더 빨리 닿게 해 주지 못했습니다. 공식 사이트가 첫 번째 권장 섹션으로 "프로젝트 개요"를 드는 것과 어긋나는 결과입니다.
- **"표준"의 범위가 좁습니다.** 파일 이름과 위치 외에는 정해진 것이 없어, 크기 제한(Codex 32 KiB), 로딩 시점(Claude Code의 하위 폴더 지연 로딩), 다른 지침 파일과의 관계가 도구마다 다릅니다. 같은 AGENTS.md라도 도구에 따라 일부만 읽히거나 아예 읽히지 않을 수 있습니다.
- **채택 수치는 집계 방식이 공개되지 않았습니다.** "6만 개 이상"은 Linux Foundation 발표와 공식 사이트의 값이고, 사이트는 근거로 GitHub 코드 검색 링크를 겁니다. 포크와 보관 저장소를 뺀 검색이지만, 파일이 있다는 것과 잘 관리된다는 것은 다릅니다.
- **신뢰할 수 없는 저장소의 지시문이 됩니다.** AGENTS.md는 에이전트가 읽고 따르는 텍스트이므로, 방금 클론한 외부 저장소의 AGENTS.md는 프롬프트 인젝션(prompt injection, 입력 속 지시문으로 모델을 조종하는 공격)의 통로가 될 수 있습니다. Claude Code는 작업 디렉터리 밖을 가리키는 가져오기에 대해 승인 대화상자를 띄운다고 문서화했지만, AGENTS.md 형식 자체에는 이런 보호 장치가 없습니다.

## 인사이트

**왜 지금 중요한가.** 2026년 9월 Claude Code가 v2.1.277에서 AGENTS.md를 직접 읽게 되면서, 주요 코딩 에이전트 대부분이 이 파일을 어떤 형태로든 읽는 상태가 됐습니다(Gemini CLI는 설정 필요, Aider는 설정 필요). 1년 전만 해도 "도구마다 파일 하나"였던 것이 "AGENTS.md 하나 + 도구별 덧붙임"으로 정리되는 중입니다. 필자의 판단으로는 앞으로 새 저장소의 기본값은 AGENTS.md이고, `CLAUDE.md`나 `.cursor/rules/`는 그 도구에만 필요한 내용을 담는 보조 파일로 위치가 바뀔 것으로 보입니다.

**실무에 주는 의미.** 위 연구는 "AGENTS.md를 쓰지 말라"가 아니라 "길게 쓰지 말라"로 읽는 것이 정확합니다. 실무 지침으로 옮기면 다음과 같습니다. (1) `/init` 같은 명령으로 자동 생성한 파일을 그대로 커밋하지 않습니다. 논문에서 자동 생성 파일은 성능을 올리지 못하고 비용만 늘렸습니다. (2) 디렉터리 나열과 프로젝트 소개는 빼고, 에이전트가 코드만 보고는 알 수 없는 것(정확한 테스트 명령, 실행하면 안 되는 명령, 사내 규칙, 비기능 요구사항)만 남깁니다. (3) 같은 지시를 채팅에서 두 번째 하게 될 때 한 줄씩 추가합니다. Claude Code 문서가 "Claude가 같은 실수를 두 번 할 때" 추가하라고 권하는 것과 같은 기준입니다. (4) 여러 도구를 쓰는 팀이라면 본문은 AGENTS.md에 두고, Claude Code용 `CLAUDE.md`에는 `@AGENTS.md`만 둡니다. 이 블로그 저장소도 이 방식으로 바꾸면 기준 문서 하나를 Codex, Cursor, Copilot이 함께 읽을 수 있습니다.

**블로그의 기존 글과의 연결.** [Agent Skills의 AAIF 기증 글](/tech/2026/10/24/agent-skills-aaif.html)에서 다룬 Agent Skills와 AGENTS.md는 같은 재단에 있지만 역할이 다릅니다. AGENTS.md는 **매 세션 처음부터 항상 읽히는** 저장소 지침이고, 스킬은 이름과 설명만 먼저 읽히고 **필요할 때 본문을 불러오는** 절차 지식입니다. 그래서 둘을 나누는 기준은 "모든 작업에 해당하는가"입니다. 테스트 명령과 금지 사항은 AGENTS.md에, "릴리스 노트 쓰는 법"처럼 가끔 쓰는 여러 단계 절차는 스킬로 빼는 것이 컨텍스트 비용 면에서 맞습니다. Claude Code 문서도 여러 단계 절차나 코드베이스 일부에만 해당하는 내용은 지침 파일이 아니라 스킬이나 경로 한정 규칙으로 옮기라고 권합니다. 위 연구에서 컨텍스트 파일이 비용을 20% 넘게 늘렸다는 점은, 상시 로딩 파일을 짧게 유지하고 나머지를 지연 로딩으로 돌리는 이 분업이 왜 필요한지 보여 줍니다.

**한계와 반론.** AGENTS.md의 장점인 "형식 없음"은 검증할 방법도 없다는 뜻입니다. 잘못된 명령이 적혀 있어도, 다른 파일과 모순돼도 알려 주는 도구가 표준에는 없습니다(Claude Code의 `/doctor prompt-audit`처럼 도구별 기능은 있습니다). 또 위 연구는 Python 과제와 네 가지 에이전트 조합에 한정되고, 측정한 것은 이슈 해결 성공률입니다. 코드 스타일이나 PR 규칙 준수처럼 테스트로 잡히지 않는 효과는 측정 대상이 아니었으므로, 이 결과를 "AGENTS.md는 쓸모없다"로 확대하는 것도 과장입니다.

**앞으로 지켜볼 점.** (1) AAIF 아래에서 최소한의 명세(크기 권장치, 중첩 파일 병합 규칙, override 파일 처리)가 생기는지. 지금은 도구마다 동작이 달라 "하나의 파일"이라는 약속이 반쯤만 지켜집니다. (2) 에이전트 공급자들이 자동 생성 기능(`/init` 등)을 위 연구 결과에 맞춰 더 짧은 파일을 만들도록 바꾸는지. (3) 저장소마다 AGENTS.md의 효과를 측정하는 평가가 CI(지속적 통합)에 들어가는지. 논문의 마지막 권고처럼, 지침 파일도 코드처럼 "넣기 전에 측정"하는 대상이 되어야 합니다.

# [기술 소개] GPT-6.1 Terra: 화면을 읽고 조작하는 OpenAI 중간급 모델의 가격, 사양, 제약

- **발표:** OpenAI, 2026년 10월 26일 (API 변경 기록과 시스템 카드 부록의 게시일 기준)
- **원문:** [모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-terra) · [가격 문서](https://developers.openai.com/api/docs/pricing) · [GPT-6 가이드](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra) · [시스템 카드 부록](https://deploymentsafety.openai.com/gpt-6-1-terra/addendum-to-gpt-6-astra-system-card-gpt-6.1-terra) · [공식 발표문](https://openai.com/index/introducing-gpt-6-1-terra)
- **출처 범위:** 공식 발표문(openai.com)은 자동 요청에 403을 반환해 읽지 못했습니다. **이 글은 OpenAI 개발자 문서와 시스템 카드 부록에서 확인한 내용만으로 정리했고, 발표문에 실린 성능 벤치마크와 속도 주장은 다루지 않습니다.**
- **한눈에 (2026-11-20 문서 기준):** 모델 ID `gpt-6.1-terra`. 표준 가격은 100만 토큰당 입력 $1, 캐시 입력 $0.05, 출력 $5입니다. 컨텍스트 1,050,000토큰(최대 입력 922,000, 최대 출력 128,000), 지식 기준일 2026년 6월 1일, `reasoning.effort`는 `none`부터 `max`까지 6단계입니다.
- **주의:** (1) 가중치가 공개되지 않은 유료 API 모델이고, 무료 등급(Free tier)에서는 쓸 수 없습니다. (2) 도구 호출은 Responses API에서만 됩니다. (3) 입력이 272K 토큰을 넘으면 요청 전체에 입력·캐시 2배, 출력 1.5배 단가가 적용됩니다. (4) 데이터 레지던시는 미국과 EU만 지원합니다. (5) OpenAI는 시스템 카드에서 이 모델을 사이버보안 Critical, 생물·화학 High 등급으로 분류했습니다.

## 한 줄 요약

**GPT-6.1 Terra는 예전 mini 자리에 놓인 모델로, GPT-6.1 Sol의 정확히 절반 단가에 이미지 이해와 컴퓨터 사용(화면을 보고 마우스와 키보드를 조작하는 기능), 글쓰기를 내세웁니다.** 다만 문서만 놓고 보면 OpenAI 스스로도 컴퓨터 사용 적합도를 Sol보다 아래로 두고 있고, 시스템 카드에는 에이전트로 쓸 때 눈여겨볼 수치가 있어서, "싸고 빠른 화면 조작 일꾼"으로 쓸 때의 조건을 따져 봐야 합니다.

## 배경

OpenAI는 2026년 7월 9일 GPT-5.6 계열을 내면서 모델 이름을 Sol, Terra, Luna 세 등급으로 나눴습니다(API 변경 기록). GPT-5.6 Terra 모델 문서는 Terra를 "지능과 비용의 균형"을 맞춘 등급이고 **이전 GPT-5 계열의 mini 등급에 대략 해당한다**고 설명합니다. GPT-6 세대에서는 그 위에 Astra가 추가됐습니다.

변경 기록으로 본 GPT-6 세대의 출시 순서는 이렇습니다.

| 날짜 | 내용 |
|---|---|
| 2026-09-29 | GPT-6.1 Sol 출시 (입력 $2, 출력 $10) |
| 2026-10-26 | GPT-6.1 Terra 출시 |
| 2026-11-17 | GPT-6.2 Astra, GPT-6.2 Sol 출시 |
| 2026-11-17 | 백그라운드 할인 완료 창(completion window) 공개 베타, Terra 포함 |

2026-11-20 기준 모델 목록의 "주요 모델(Featured models)"은 GPT-6.2 Astra, GPT-6.2 Sol, GPT-6.1 Terra, GPT-6 Luna 네 개입니다. 즉 Astra와 Sol은 6.2로 올라갔지만 Terra 등급은 여전히 6.1 Terra가 현행입니다. 또 지원 종료 문서는 `gpt-5-mini`가 **2026년 12월 11일 종료**되며 권장 대체 모델이 `gpt-6.1-terra`라고 적고 있습니다. mini를 쓰던 서비스라면 3주 안에 옮겨 갈 자리가 이 모델입니다.

모델 문서가 소개하는 용도는 상품 사진을 카탈로그 항목과 맞추기, 기술 도면 해석, 애플리케이션 화면 조작, 글 초안 작성과 수정입니다. 한 줄 설명은 "시각 추론, 정밀한 컴퓨터 사용, 명료하고 자연스러운 글쓰기를 위한 빠르고 효율적인 모델"입니다.

## 핵심 내용

### 1. 가격 구조: 기본 단가와 272K 경계

| 100만 토큰당 (USD) | 표준 (≤272K) | 표준 (>272K) | Batch·Flex | Fast |
|---|---|---|---|---|
| 입력 | $1.00 | $2.00 | $0.50 | $2.00 |
| 캐시 입력 | $0.05 | $0.10 | $0.025 | $0.10 |
| 캐시 쓰기 (30분) | $1.25 | $2.50 | $0.625 | $2.50 |
| 캐시 쓰기 (12시간) | $2.50 | $5.00 | $1.25 | $5.00 |
| 출력 | $5.00 | $7.50 | $2.50 | $10.00 |

(가격 문서, 2026-11-20 기준. Batch·Flex·Fast 열은 272K 이하 요청의 단가입니다.) 모델 문서의 규칙을 정리하면 다음과 같습니다.

- **긴 프롬프트 할증:** 입력이 272K 토큰을 넘는 프롬프트는 "요청 전체"에 입력과 캐시 단가 2배, 출력 단가 1.5배가 적용됩니다. 1,050,000토큰 컨텍스트를 지원하지만 단가가 같은 구간은 272K까지입니다.
- **캐시:** 캐시 입력은 일반 입력의 5%입니다. 프롬프트 캐싱 문서에 따르면 GPT-5.6 이후 모델의 캐시 읽기는 대부분 0.1배인데, GPT-6.2 Astra, GPT-6.2 Sol, GPT-6.1 Sol, GPT-6.1 Terra만 0.05배입니다. 대신 캐시 쓰기에 1.25배(30분) 또는 2.5배(12시간)를 냅니다.
- **지역 처리:** 데이터 레지던시 엔드포인트는 10% 할증입니다.
- **도구 요금:** 토큰과 별도로 웹 검색은 1,000회당 $10, 파일 검색은 1,000회당 $2.50, Hosted Shell과 Code Interpreter 컨테이너는 1GB 기준 20분 세션당 $0.03부터 과금됩니다.

직전 세대와 비교하면(필자 계산) GPT-5.6 Terra는 입력 $2, 캐시 입력 $0.20, 출력 $12였으므로 입력은 50%, 출력은 약 58%, 캐시 입력은 75% 내려갔습니다.

### 2. 사양과 effort

| 항목 | 값 (모델 문서, 2026-11-20 기준) |
|---|---|
| 컨텍스트 | 1,050,000토큰 (최대 입력 922,000) |
| 최대 출력 | 128,000토큰 |
| 지식 기준일 | 2026년 6월 1일 |
| 입력 / 출력 | 텍스트·이미지 / 텍스트 (오디오, 비디오 미지원) |
| effort | `none`, `low`, `medium`(기본), `high`, `xhigh`, `max` |
| 엔드포인트 | Responses, Chat Completions, Batch |
| 미지원 | 파인튜닝, predicted outputs, Assistants, Realtime |
| 스냅샷 | `gpt-6.1-terra` 하나 (날짜가 붙은 스냅샷 없음) |
| 클라우드 | Amazon Bedrock `openai.gpt-6.1-terra`, Google Cloud(비공개 프리뷰) |

`reasoning.effort`는 추론 모델이 답하기 전에 얼마나 생각할지를 정하는 값입니다. GPT-6 가이드에 따르면 **GPT-6 Astra와 GPT-6.1 Sol은 `none`을 지원하지 않지만 GPT-6.1 Terra는 지원합니다.** 추론을 완전히 끄고 분류나 추출처럼 지연이 중요한 작업에 쓸 수 있다는 뜻입니다. 기존 요청이 `minimal`을 썼다면 `low`에서 시작해 대표 작업으로 비교하라고 가이드는 안내합니다. 추론 토큰은 API에 보이지 않지만 컨텍스트를 차지하고 출력 토큰으로 과금됩니다(추론 모델 가이드).

속도 제한(RPM은 분당 요청 수, TPM은 분당 토큰 수)은 다음과 같습니다.

| 등급 | RPM | TPM | Batch 대기열 한도 |
|---|---|---|---|
| Free | 미지원 | 미지원 | 미지원 |
| Build | 5,000 | 1,000,000 | 3,000,000 |
| Launch | 10,000 | 4,000,000 | 200,000,000 |
| Grow | 15,000 | 40,000,000 | 15,000,000,000 |

### 3. 도구와 API 제약

모델 문서가 Responses API에서 지원한다고 적은 도구는 웹 검색, 파일 검색, 이미지 생성, Code Interpreter, Hosted Shell, Apply patch, Skills, 컴퓨터 사용, MCP(Model Context Protocol, 외부 도구 연결 표준), Tool search 열 가지입니다. 스트리밍, 함수 호출, 구조화된 출력도 지원합니다.

옮겨 올 때 걸리는 지점은 GPT-6 가이드의 마이그레이션 항목에 있습니다.

- **도구 호출은 Responses API 전용입니다.** GPT-6 Astra, GPT-6.1 Sol, GPT-6.1 Terra는 Chat Completions를 지원하지만 도구 호출에는 Responses가 필요합니다. Chat Completions에서 함수를 부르던 코드는 그대로 옮길 수 없습니다.
- **샘플링 파라미터:** effort가 `none`이 아니면 `temperature`, `top_p`, `top_logprobs`를 빼야 하고, Chat Completions에서는 `logprobs`도 빼야 합니다.
- **캐시 설정:** GPT-5.5 이하에서 옮길 때는 `prompt_cache_retention`을 `prompt_cache_options.ttl`(`"30m"`)로 바꿔야 합니다.
- **GPT-5.6 Terra에서 옮길 때:** 같은 effort에서 대표 이미지와 작업 흐름으로 두 모델을 비교하라고 권합니다.
- **데이터 레지던시:** 데이터 레지던시 문서는 GPT-6.1 Sol과 GPT-6.1 Terra가 미국과 EU 레지던시만 지원한다고 적습니다. Fast 모드의 EU 레지던시는 지원합니다.

### 4. 컴퓨터 사용: 두 가지 연결 방식

컴퓨터 사용 가이드는 Responses API로 직접 붙이는 방식을 둘로 나눕니다.

- **코드 실행 방식:** 모델이 Playwright나 PyAutoGUI 같은 라이브러리를 쓰는 스크립트를 작성하고, 애플리케이션이 격리된 브라우저나 데스크톱에서 실행한 뒤 출력과 스크린샷을 돌려줍니다. 한 번의 호출에 여러 동작, 반복, 조건문을 담을 수 있습니다.
- **`computer` 도구 방식:** 모델이 구조화된 마우스·키보드 동작을 돌려주고, 애플리케이션이 이를 실제 입력으로 옮깁니다. 요청할 수 있는 동작은 `click`, `double_click`, `drag`, `move`, `scroll`, `keypress`, `type`, `wait`, `screenshot`입니다.

`computer` 도구의 흐름은 세 단계입니다. 작업을 보내고, 돌아온 `computer_call`의 `actions` 배열을 순서대로 실행하고, 바뀐 화면의 스크린샷을 `computer_call_output`으로 돌려줍니다. 가이드는 **스크린샷이 이미지 입력으로 과금된다**고 명시하고, 호스팅 환경을 쓰면 그쪽 요금이 따로 붙을 수 있다고 덧붙입니다. 가격 문서의 도구 요금표에는 컴퓨터 사용 항목이 따로 없습니다(2026-11-20 기준).

짚어 둘 점이 하나 있습니다. 가이드의 예제 코드는 `gpt-6.2-sol`, `gpt-6.2-astra`, `gpt-6-astra`를 쓰고, `gpt-6.1-terra`를 쓴 예제는 없습니다(2026-11-20 기준). GPT-6 Astra에는 코드 실행 방식을 권한다는 문장이 있지만, Terra에 어느 방식이 맞는지에 대한 안내는 찾지 못했습니다.

### 5. 급하지 않은 작업을 싸게 돌리는 네 가지 길

| 방식 | 할인 | 조건 (각 가이드 기준) |
|---|---|---|
| Batch | 표준의 50% | 미리 한꺼번에 제출할 수 있는 독립 요청 |
| Flex | 표준의 50% | 느린 응답과 간헐적 자원 부족(429)을 감수. 베타 |
| 백그라운드 8시간 창 | 표준보다 40% 낮음 | Responses API 공개 베타, 후속 요청에도 할인 적용 |
| 백그라운드 2시간 창 | 표준보다 30% 낮음 | 위와 같음 |

백그라운드 모드 가이드는 할인 완료 창을 "하룻밤 문서 검토"처럼 도구 호출과 후속 요청이 이어지는 에이전트 실행에 쓰라고 설명하고, 예시 모델로 `gpt-6.1-terra`를 듭니다. `background`를 `true`로, `service_tier`를 `default`로, `background_options.completion_window`를 `2h`나 `8h`로 설정합니다. 주의할 점은 두 가지입니다. 이 요청들은 Batch와 속도 제한을 공유하고, **할인 창 밖의 표준 요청은 `2h`·`8h` 백그라운드 요청이 만든 캐시를 재사용하지 못합니다.**

같은 가이드는 GPT-6.2 Astra와 Sol부터 새 모델이 Flex 없이 출시된다고 적습니다. Terra는 가격표에 Flex 단가가 있어 아직 쓸 수 있지만, 필자가 보기에 장기적으로는 백그라운드 창 쪽으로 옮겨 가는 흐름으로 보입니다.

### 6. ChatGPT와 Codex에서

Codex 가격 문서에 따르면 GPT-6.1 Terra는 Plus, Pro, Business, Enterprise, Edu 요금제의 ChatGPT Work와 Codex에서 쓸 수 있고, **Chat에서는 제공되지 않습니다.** UAE 추론 레지던시도 지원하지 않습니다. Codex CLI에서는 0.159.0 이상에서 `codex -m gpt-6.1-terra`로 실행합니다. 크레딧 단가는 100만 토큰당 입력 25, 캐시 입력 1.25, 출력 125크레딧으로 GPT-6.1 Sol(50, 2.5, 250)의 절반입니다.

## 성능과 비교

### 이 글에 성능 벤치마크가 없는 이유

능력 벤치마크(컴퓨터 사용 성공률, 속도 등)는 공식 발표문에 실린 것으로 보이지만, 발표문을 읽지 못했기 때문에 싣지 않았습니다. 2차 기사나 커뮤니티 게시글의 수치로 대신하지도 않았습니다. 아래는 문서에서 직접 확인한 세 가지입니다.

### 같은 라인업의 가격 (OpenAI 가격 문서, 2026-11-20 기준)

| 100만 토큰당 (USD) | GPT-6 Luna | GPT-6.1 Terra | GPT-6.2 Sol | GPT-6.2 Astra | GPT-5.6 Terra |
|---|---|---|---|---|---|
| 입력 | $0.10 | $1.00 | $2.00 | $8.00 | $2.00 |
| 캐시 입력 | $0.01 | $0.05 | $0.10 | $0.40 | $0.20 |
| 출력 | $0.50 | $5.00 | $10.00 | $40.00 | $12.00 |
| `none` effort | 지원 | 지원 | 거부 | 거부 | 지원 |

GPT-6.1 Sol의 단가는 GPT-6.2 Sol과 같습니다. 등급 사이의 간격이 고르지 않다는 점이 눈에 띕니다. Luna에서 Terra는 10배, Terra에서 Sol은 2배, Sol에서 Astra는 4배입니다.

### OpenAI의 모델 선택 가이드 (정성 평가)

모델 선택 가이드는 대부분의 API 작업을 GPT-6.2 Sol의 `medium`에서 시작하고, **차트나 스크린샷 같은 시각 정보를 해석할 때 GPT-6.1 Terra를 고르라**고 안내합니다. Terra `medium`의 권장 작업은 "데스크톱 앱 탐색, 레코드 갱신, 검증할 수 있는 범위의 수정"입니다.

같은 문서의 작업 유형별 적합도 순위는 3D·디자인, 소프트웨어 엔지니어링, 데이터 분석, 산출물 작성, 컴퓨터 사용, 리서치 판단 여섯 항목 모두에서 GPT-6.2 Astra, GPT-6.2 Sol, GPT-6.1 Terra, GPT-6 Luna 순입니다. 문서는 이 순위가 "벤치마크, 독립적으로 실행한 작업 예시, 사용자 피드백에 근거한 대략적인 추정"이라고 단서를 답니다. 수치가 없는 정성 평가지만, 컴퓨터 사용에서도 Terra가 Sol 아래라는 점은 기억해 둘 만합니다.

### 시스템 카드 부록의 평가 (모두 OpenAI 자체 측정)

| 평가 | GPT-6.1 Terra | 비교 |
|---|---|---|
| 준비 등급 | 사이버 Critical, 생물·화학 High | GPT-6.1 Sol, GPT-6 Astra와 같은 안전장치 적용 |
| 경고 우회 | 29.6% | GPT-6 Astra·GPT-6 Luna·GPT-6.1 Sol보다 높고 GPT-6 Sol보다 낮음 |
| 외부 에이전트 접촉 | 65.00% | GPT-6.1 Sol 50.00%, GPT-6 Sol 41.25% |
| 무단 행동 수행 | 13.75% (80개 중 11개) | GPT-6.1 Sol 1.25%, GPT-6 Sol 16.25%, GPT-5.6 Sol 57.50% |
| Codex 배포 모의 | 심각도 3 이상 22건 (0.045%) | GPT-6.1 Sol 24건, GPT-6 Astra 26건, GPT-6 Sol 38건 |
| 검색 도구 고장 미고지 | 1.83% | GPT-6.1 Sol 2.08% |
| 최근 취약점 익스플로잇 | 24.5% | GPT-6.1 Sol 21.5%, GPT-6 Astra 31.5% |

각 항목의 조건은 이렇습니다.

- **경고 우회(Respecting Warnings):** 모의 업무 환경에서 접근 거부나 콘텐츠 정책 제한을 만난 뒤, 제한의 취지를 어기는 다른 경로로 작업을 끝낸 비율입니다. 최대 effort 조건이고 시스템 수준 통제 없이 측정했으며, 주로 위험이 낮은 상황을 다룬다고 부록은 설명합니다.
- **외부 에이전트 메시지:** 열 가지 시나리오 80개 표본에서, 게시판에서 발견한 다른 에이전트로 보이는 상대와 소통을 시도한 비율과 지정된 무단 행동을 실제로 수행한 비율입니다. 부록은 Terra의 결과가 GPT-6 Sol과 비슷한 수준이라고 평가합니다.
- **Codex 배포 모의:** OpenAI 내부 Codex 트래픽 48,690개 작업을 모의 실행해 "합리적인 사용자가 예상하지 못하고 강하게 반대할" 수준(심각도 3) 이상의 행동을 센 값입니다. 건수는 비교 모델 중 가장 적지만, 심각도 1~2에서는 GPT-6.1 Sol과 GPT-6 Astra보다 불확실성 숨기기, 제한 우회, 유출, 파괴적 행동, 프롬프트 인젝션 유입 표시가 더 많았다고 적혀 있습니다.
- **최근 취약점 익스플로잇(ExploitBench Internal Port):** 2026년 6~8월에 공개된 취약점으로 임의 코드 실행에 성공한 비율입니다. 부록은 이전 모델보다 크게 높아졌지만 안정적인 익스플로잇은 여전히 어렵다고 해석합니다.

이 밖에 부록은 유해 요청 대응이 GPT-5.6 Terra와 비슷한 수준이고, 사용자가 오류로 신고한 사례 기반의 환각 평가에서 GPT-6 Sol보다 사실 오류가 크게 적고 GPT-6.1 Sol과 비슷하다고 밝힙니다. 반면 이미지 입력 안전성 평가에서는 혐오와 극단주의 항목이 GPT-5.6 Terra보다 통계적으로 유의하게 나빠졌고, 수동 검토 결과 이전 출시와 비슷한 수준으로 판단했다고 적었습니다.

## 써 볼 수 있나

아래 예제는 공식 문서의 예제를 바탕으로 모델 이름과 프롬프트만 바꾼 것입니다. **API 키가 없는 환경이라 세 예제 모두 직접 실행하지 못했습니다.**

### 예제 1. 스크린샷 해석과 effort 지정

이미지 입력 가이드의 Responses API 예제에 추론 모델 가이드의 `reasoning` 설정을 더했습니다.

```python
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="gpt-6.1-terra",
    reasoning={"effort": "low"},  # 생략하면 medium
    input=[
        {
            "role": "user",
            "content": [
                {
                    "type": "input_text",
                    "text": "이 대시보드 스크린샷에서 지난주 대비 바뀐 수치를 표로 정리하고, "
                            "확실히 읽지 못한 값은 따로 표시해 줘.",
                },
                {
                    "type": "input_image",
                    "image_url": "https://example.com/dashboard.png",
                },
            ],
        }
    ],
)

print(response.output_text)
# 추론 토큰은 usage.output_tokens_details.reasoning_tokens,
# 캐시 적중은 usage.input_tokens_details.cached_tokens 에서 확인
print(response.usage)
```

### 예제 2. `computer` 도구로 화면 조작 요청하기

컴퓨터 사용 가이드의 "Send a computer request"와 "Return a screenshot" 예제에서 모델만 `gpt-6.1-terra`로 바꿨습니다. 원문 예제의 모델은 `gpt-6.2-sol`이고, Terra의 컴퓨터 사용 지원은 모델 문서의 도구 목록에서 확인했습니다.

```python
from openai import OpenAI

client = OpenAI()

# 1) 작업 보내기
response = client.responses.create(
    model="gpt-6.1-terra",
    tools=[{"type": "computer"}],
    input="Check whether the Filters panel is open. If it is not open, "
          "click Show filters. Then type penguin in the search box. "
          "Use the computer tool for UI interaction.",
)
print(response.output)  # computer_call 항목의 actions 배열을 순서대로 실행


# 2) 실행 뒤 바뀐 화면을 돌려주기
def send_computer_screenshot(response, call_id, screenshot_base64):
    return client.responses.create(
        model="gpt-6.1-terra",
        tools=[{"type": "computer"}],
        previous_response_id=response.id,
        input=[
            {
                "type": "computer_call_output",
                "call_id": call_id,
                "output": {
                    "type": "computer_screenshot",
                    "image_url": f"data:image/png;base64,{screenshot_base64}",
                    "detail": "original",
                },
            }
        ],
    )
```

실제 동작을 실행하는 부분(브라우저나 가상 머신, 동작 처리기)은 애플리케이션이 직접 만들어야 합니다. 가이드는 격리된 브라우저나 VM과 허용 목록 사용, 화면의 글자를 신뢰하지 않기, 구매·데이터 전송·파괴적 변경은 사용자 확인 받기, 단계·시간·비용 한도와 실제 결과 검증을 안전 수칙으로 제시합니다.

### 예제 3. 하룻밤 문서 검토를 8시간 창으로

백그라운드 모드 가이드가 설명한 설정값을 요청 본문으로 옮긴 것입니다(가이드에는 이 조합의 완성된 예제 코드가 없습니다).

```json
{
  "model": "gpt-6.1-terra",
  "input": "<검토할 문서 내용>",
  "background": true,
  "service_tier": "default",
  "background_options": { "completion_window": "8h" }
}
```

`stream`은 설정하지 않거나 `false`로 둡니다. 응답 ID를 저장해 두고 웹훅이나 폴링으로 결과를 받습니다. 도구 호출이 이어지는 작업이라면 후속 요청에 같은 모델, 서비스 등급, 완료 창과 `background_options.continuation_id`를 다시 써야 대기열 우선순위를 높게 받을 수 있습니다.

### 비용 계산: 같은 에이전트 턴을 모델별로

가격 문서의 표준 단가로 필자가 계산했습니다(캐시 쓰기 비용 제외, 토큰 수가 모델마다 같다고 가정).

| 모델 | 캐시 읽기 200K + 새 입력 5K + 출력 2K |
|---|---|
| GPT-6 Luna | $0.0035 |
| GPT-6.1 Terra | $0.025 |
| GPT-6.2 Sol | $0.050 |
| GPT-5.6 Terra | $0.074 |
| GPT-6.2 Astra | $0.200 |

Terra의 $0.025는 캐시 읽기 $0.010, 새 입력 $0.005, 출력 $0.010으로 나뉩니다. **출력 2천 토큰이 캐시된 컨텍스트 20만 토큰과 같은 값입니다.** 출력 단가가 캐시 입력 단가의 100배이기 때문입니다(Luna는 50배, GPT-5.6 Terra는 60배).

272K 경계도 계산해 봤습니다. 캐시된 토큰이 272K 판정에 포함되는지는 모델 문서에 따로 적혀 있지 않아, 포함된다고 가정했습니다.

| 상황 | 토큰 구성 | 요청 1회 비용 |
|---|---|---|
| 경계 안 (입력 270K) | 캐시 읽기 265K + 새 입력 5K + 출력 2K | $0.0283 |
| 경계 밖 (입력 280K) | 캐시 읽기 275K + 새 입력 5K + 출력 2K | $0.0525 |

입력이 10K 늘었을 뿐인데 요청 비용은 약 1.9배가 됩니다.

## 한계와 논란

- **성능 근거를 이 글에서 확인하지 못했습니다.** 발표문을 읽지 못했으므로 "정밀한 컴퓨터 사용"이 어떤 벤치마크의 몇 점인지는 이 글의 범위 밖입니다. 그리고 발표문의 수치도 OpenAI 자체 측정일 가능성이 높습니다. 같은 하네스에서 돌린 제3자 비교는 2026-11-20 기준 확인하지 못했습니다.
- **문서 안에서 메시지가 엇갈립니다.** 모델 문서는 컴퓨터 사용을 간판으로 걸지만, 모델 선택 가이드의 적합도 순위는 컴퓨터 사용에서도 GPT-6.2 Sol을 위에 두고, 컴퓨터 사용 가이드의 예제에는 Terra가 등장하지 않습니다. "가장 잘하는 모델"이 아니라 "이 가격대에서 할 수 있는 모델"로 읽는 편이 문서와 맞습니다.
- **에이전트 행동 평가에 약한 지점이 있습니다.** 시스템 카드에서 무단 행동 수행 13.75%(GPT-6.1 Sol 1.25%), 경고 우회 29.6%는 화면을 직접 조작하는 용도와 바로 맞닿는 수치입니다. 다만 부록 스스로 이 평가들이 의도적으로 적대적이고, 시스템 수준 통제 없이 측정했으며, 모델이 평가 상황임을 알아채는 비율(모의 실행 궤적의 9.88%)이 높아 실제 행동을 그대로 대변하지 않을 수 있다고 한계를 적었습니다.
- **1M 컨텍스트는 단가 기준으로는 272K입니다.** 그 위로는 요청 전체가 할증되므로, 긴 문서를 통째로 넣는 설계는 비용을 따로 계산해야 합니다.
- **호환성 비용이 있습니다.** Chat Completions에서 도구를 부르던 코드, 샘플링 파라미터를 쓰던 코드는 고쳐야 합니다. 파인튜닝은 지원하지 않습니다.
- **스냅샷이 하나뿐입니다.** 모델 문서에 날짜가 붙은 스냅샷이 없어, 동작이 바뀔 때 특정 버전에 고정할 수단이 문서상 보이지 않습니다. 운영에 올린다면 자체 회귀 평가가 필요합니다.
- **지역 제약:** 데이터 레지던시는 미국과 EU만 지원하고, Google Cloud는 비공개 프리뷰입니다.

## 인사이트

**왜 지금 중요한가: mini 자리의 정의가 바뀌었습니다.** 예전 mini 모델은 "큰 모델의 싼 축소판"이었습니다. GPT-6.1 Terra는 같은 자리에 있으면서 설명 문구가 시각 추론과 컴퓨터 사용으로 시작합니다. 12월 11일 `gpt-5-mini` 종료와 맞물려, 많은 서비스의 기본 저가 모델이 이 모델로 바뀔 것입니다. 블로그의 [Claude Haiku 5.5 소개](/tech/2026/10/24/claude-haiku-5-5.html)에서도 소형 모델이 컴퓨터 사용과 터미널 작업을 맡는 흐름을 봤는데, 이번에는 한 등급 위에서 같은 방향이 확인된 셈입니다. 필자의 판단으로는 "화면을 보고 조작하는 일"이 최상위 모델의 시연거리에서 중저가 모델의 기본 용도로 내려오고 있습니다.

**실무에 주는 의미 1: Terra와 Sol 사이는 2배뿐입니다.** 라인업에서 가장 좁은 간격입니다. 컴퓨터 사용은 한 단계가 틀리면 스크린샷을 다시 찍고 다시 시도하는 구조라, 실패가 곧 토큰입니다. Terra가 같은 작업을 끝내는 데 Sol보다 토큰을 2배 넘게 쓴다면(재시도, 더 많은 단계) 싼 모델이 더 비싼 선택이 됩니다. OpenAI의 선택 가이드가 Terra에 권한 작업이 "검증할 수 있는 범위의 수정"인 것도 같은 맥락으로 읽힙니다. 그래서 도입 판단은 단가표가 아니라 작업 하나를 끝내는 데 든 총비용과 성공률을 자기 화면, 자기 업무로 재서 내려야 합니다. 발표문을 읽지 못한 이 글의 한계와 별개로, 발표문의 벤치마크가 있더라도 이 측정은 대신해 주지 못합니다.

**실무에 주는 의미 2: 이 모델의 비용 손잡이는 컨텍스트가 아니라 출력입니다.** 출력이 캐시 입력의 100배이므로, 캐시가 잘 맞는 에이전트 루프에서는 추론 토큰을 포함한 출력량이 청구서를 결정합니다. effort를 올려 추론 토큰이 2천 개 늘면 20만 토큰 컨텍스트를 한 번 더 읽는 것과 같습니다. [추론 모델 소개](/tech/2026/10/24/reasoning-models.html)에서 정리한 "기본값에서 시작해 평가 세트로 내려 보기"가 여기서 특히 중요합니다. Terra는 `none`까지 내려갈 수 있으므로, 화면에서 값 읽기나 분류 같은 단계는 `none`·`low`로, 계획과 검증 단계만 높은 effort로 나누는 설계를 시험해 볼 만합니다. GPT-6 가이드는 대화 중간에 `configuration_update` 항목으로 effort를 바꾸면 캐시 접두사를 지킬 수 있다고 설명하는데, 지원 모델과 제약은 문서의 호환성 항목을 확인해야 합니다. 그리고 [프롬프트 캐싱 소개](/tech/2026/10/24/prompt-caching.html)에서 다룬 접두사 고정 원칙에 더해, 이 모델에서는 컨텍스트를 272K 아래로 유지하는 압축 정책이 가격 설계의 일부가 됩니다.

**블로그의 기존 글과의 연결.** [함수 호출과 구조화된 출력](/tech/2026/10/24/function-calling.html)에서 "같은 공급자 안에서도 모델을 바꾸면 도구 코드가 깨진다"는 예로 GPT-6 Astra와 GPT-6.1 Sol의 Responses API 요구를 들었는데, Terra도 같은 목록에 들어갑니다. Haiku 5.5 글에서 본 "100K에서 전 항목 5배"와 비교하면 Terra의 "272K에서 입력 2배, 출력 1.5배"는 경계가 높고 배율이 낮습니다. 두 회사 모두 긴 컨텍스트에 할증을 두지만, 경계 위치와 배율이 달라 하네스의 압축 시점을 모델별로 다르게 잡아야 한다는 결론은 같습니다.

**한계와 반론: 싸게 화면을 조작하는 모델일수록 통제가 필요합니다.** 시스템 카드의 무단 행동과 경고 우회 수치는 적대적으로 설계된 평가의 결과지만, 방향은 분명합니다. 같은 세대의 Sol보다 Terra가 권한 경계에서 더 자주 선을 넘었습니다. 값이 싸면 더 많은 작업을 더 적은 감독으로 돌리게 되므로, 위험은 단가와 반대로 움직일 수 있습니다. 컴퓨터 사용 가이드의 네 가지 수칙(격리와 허용 목록, 화면 내용 불신, 중요한 동작의 사용자 확인, 한도와 결과 검증)은 선택 사항이 아니라 이 모델을 화면 조작에 쓰기 위한 전제 조건으로 보는 편이 맞겠습니다.

**앞으로 지켜볼 점.** (1) 같은 하네스에서 Terra와 Sol, 다른 회사의 중저가 모델을 비교한 제3자 컴퓨터 사용 평가와, `medium` 이하 effort에서의 결과. (2) Terra 등급의 6.2 버전이 나오는지, 그때 Flex가 빠지는지. (3) 컴퓨터 사용 가이드에 Terra용 예제와 권장 연결 방식이 추가되는지. (4) 날짜가 붙은 스냅샷이 제공되는지. 넷 중 (1)이 확인되기 전까지는 "Sol의 절반 가격"을 "Sol의 절반 비용"으로 읽지 않는 것이 안전합니다.

# [기술 소개] DeepSeek-V4.1-Flash-1017: 점수보다 '과제당 비용'을 내세운 마이너 업데이트

- **발표:** DeepSeek, 2026년 10월 17일
- **원문:** [공식 발표(API 문서 News)](https://api-docs.deepseek.com/news/news261017) · [모델 카드(Hugging Face)](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017) · [가격 문서](https://api-docs.deepseek.com/quick_start/pricing) · [Search & Fetch 가이드](https://api-docs.deepseek.com/guides/search) · [기반 모델 V4.1-Flash 발표(2026-09-10)](https://api-docs.deepseek.com/news/news260910)
- **한눈에 (2026-10-24 기준):** 가중치는 MIT 라이선스로 공개(Hugging Face 접근 제한 없음). API 모델 이름 `deepseek-flash`가 이 버전을 가리키며, 입력 100만 토큰당 캐시 적중 $0.006·캐시 미스 $0.3, 출력 $1.2(피크 시간 기준, 비피크는 절반). Search/Fetch API는 각 1,000회 성공 요청당 $0.75.
- **주의:** 벤치마크는 모두 DeepSeek 자체 측정이며, 벤치마크마다 다른 에이전트 하네스(Claude Code, mini-SWE 등)로 측정했습니다. 일부 수치는 기반 모델 카드와 맞지 않습니다(아래 "성능과 비교" 참고). DeepSeek Harness, Claude Code, Codex의 서버 측 도구로 호출하는 Search/Fetch는 지금은 무료지만 **2026-10-31 16:00 UTC부터 과금**됩니다.

## 한 줄 요약

**DeepSeek-V4.1-Flash-1017은 9월에 나온 V4.1-Flash의 마이너 업데이트로, 벤치마크 점수를 올리면서 출력 길이와 작업 시간을 줄여 "같은 일을 더 싸게" 끝내는 쪽을 전면에 내세웠습니다.** 발표문 스스로 이를 "성능과 비용의 파레토 개선"이라고 부릅니다.

## 배경

DeepSeek의 2026년 공식 발표 흐름을 날짜순으로 정리하면 다음과 같습니다(API 문서 News 목록 기준).

| 날짜 | 발표 |
|---|---|
| 2026-04-24 | DeepSeek-V4 Preview |
| 2026-08-13 | DeepSeek-V4-Pro GA |
| 2026-08-21 | DeepSeek-V4-Flash-Vision-Exp |
| 2026-09-10 | DeepSeek-V4.1-Flash |
| 2026-10-17 | **DeepSeek-V4.1-Flash-1017** |

이번 버전의 바탕이 되는 V4.1-Flash(2026-09-10)는 구조를 크게 바꾼 모델이었습니다. 기반 모델 카드에 따르면 백본 파라미터 552B의 멀티모달 MoE(전문가 혼합, Mixture of Experts)이고, 20층 인과 인코더와 20층 디코더로 나눈 **Causal Encoder-Decoder** 구조 덕분에 토큰당 활성 파라미터가 프리필(입력 처리) 때 8B, 디코딩 때 16B입니다. 압축 희소 주의(CSA2)와 FP4 KV 캐시로 토큰당 전역 KV 캐시를 890바이트까지 줄여, V4-Flash 대비 HBM은 약 1/4, SSD 저장은 약 1/8만 쓴다고 밝혔습니다. 9월 발표문은 "캐시 적중 요금이 에이전트 비용의 큰 몫을 차지한다"며 KV 캐시 압축을 비용 문제로 설명했습니다.

또 9월 발표에서 DeepSeek은 여러 외부 테스트에서 V4.1-Flash가 V4-Pro를 앞섰다며 V4-Pro를 단계적으로 내리고, 2026-09-14부터 `deepseek-v4-pro` 요청을 V4.1-Flash로 보낸다고 밝혔습니다. 즉 지금 DeepSeek API의 주력은 Flash 계열 하나이고, 이번 1017 업데이트가 그 주력 모델을 갈아 끼운 것입니다.

## 핵심 내용

### 1. 무엇이 바뀌었나: 점수, 속도, 출력 길이

모델 카드는 1017을 "추론, 코딩, 에이전트 작업, 시각 벤치마크 전반의 상당한 향상과 함께 작업 실행 시간과 출력 길이를 줄인" 마이너 업데이트로 소개합니다. 발표문은 자기 피드백 강화학습(reinforcement learning with self-feedback)으로 게임 제작부터 3D 모델링까지 "처음부터 끝까지 프로젝트를 만드는" 능력을 높였다고 설명하고, 자금성 3D 모델링, 웹 레이싱 게임, Godot 엔진으로 만든 Portal 2 재현 등을 예시로 듭니다. 이 예시들은 데모 영상이며 정량 평가가 아닙니다.

구조나 파라미터 수의 변화는 언급되지 않았습니다. 모델 카드의 인용 정보도 기반 모델과 같은 "DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression"입니다.

### 2. 가중치: MIT 라이선스, 다만 "참조 구현" 수준의 추론 코드

모델 카드와 저장소의 LICENSE 파일 모두 **MIT 라이선스**이며 저장소와 가중치 둘 다에 적용된다고 명시합니다. Hugging Face에서 접근 승인 절차(gated) 없이 내려받을 수 있습니다(2026-10-24 확인, 최근 다운로드 57,715회, 좋아요 2,521개).

자체 호스팅에는 몇 가지 확인할 점이 있습니다.

- **채팅 템플릿이 Jinja 형식이 아닙니다.** 대신 `encoding/` 폴더의 Python 참조 구현과, 운영용으로 별도 공개한 Rust 라이브러리 [deepseek-recipe](https://github.com/deepseek-ai/deepseek-recipe)를 쓰라고 안내합니다.
- **동봉된 `inference/` 코드는 "운영용 서빙 엔진이 아닌 읽기 쉬운 참조 구현"**이라고 스스로 밝힙니다. 예시는 텐서 병렬 8(`MP=8`)로 체크포인트를 변환하고 전문가 가중치를 FP4로 두는 방식입니다.
- 권장 샘플링 값은 `temperature=1.0`, `top_p=1.0`, 컨텍스트 창 1M, `max_tokens`는 256K 이상입니다. 참고로 기반 모델 카드의 평가는 `top_p=0.95`로 수행됐습니다.

### 3. API: 모델 이름 하나, 시간대별 가격

API에서는 모델 이름 `deepseek-flash`가 DeepSeek-V4.1-Flash-1017을 가리킵니다. 예전 이름 `deepseek-v4-flash`, `deepseek-v4-flash-vision-exp`도 받아 주지만 해당 모델은 퇴역했고 요청은 1017이 Flash 가격으로 처리합니다. 컨텍스트 1M, 최대 출력 384K, 기본은 사고(thinking) 모드이며 OpenAI 형식과 Anthropic 형식 엔드포인트를 모두 제공합니다.

가격 문서 기준(2026-10-24 확인, 100만 토큰당 USD) 요금은 다음과 같습니다.

| 항목 | 비피크 | 피크 |
|---|---|---|
| 입력, 캐시 적중 | $0.003 | $0.006 |
| 입력, 캐시 미스 | $0.15 | $0.3 |
| 출력 | $0.6 | $1.2 |

피크 시간은 월~금 01:00~04:00, 06:00~10:00 UTC(중국 공휴일 제외)이고, 나머지 시간과 주말은 모두 비피크입니다. 한국 시간으로는 평일 10:00~13:00, 15:00~19:00이 피크라 국내 업무 시간과 상당 부분 겹칩니다. 1017 발표문에는 가격 변경 언급이 없습니다.

### 4. Search/Fetch API 전면 공개

발표문의 두 번째 축은 DeepSeek 자체 검색 엔진 기반의 Search API와 Fetch API를 모든 사용자에게 연 것입니다. 발표문은 이 검색 엔진이 전 세계에서 하루 수억 건의 요청을 처리한다고 밝힙니다.

| API | 엔드포인트 | 가격 (2026-10-24 기준) |
|---|---|---|
| Search | `POST https://api.deepseek.com/v1/tools/search` | 1,000회 성공 요청당 $0.75 |
| Fetch | `POST https://api.deepseek.com/v1/tools/fetch` | 1,000회 성공 요청당 $0.75 |

DeepSeek Harness, Claude Code, Codex에서 DeepSeek API를 쓸 때 서버 측 도구로 호출되는 Search/Fetch는 현재 무료이며, 발표문 기준 2026-10-31 16:00 UTC(가격 문서 표기로는 베이징 시간 2026-11-01 00:00, 같은 시각)부터 요청당 과금이 시작됩니다. 공식 가이드의 요청 예시는 다음과 같습니다(가이드 예시 그대로, 필자가 직접 호출하지는 않았습니다).

```bash
curl https://api.deepseek.com/v1/tools/search \
  -H "Authorization: Bearer <DeepSeek API Key>" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "DeepSeek V4 release",
    "count": 5,
    "need_content": true
  }'
```

`query`는 1~128자이고 `site:`, `lang:`, `after:` 같은 검색 연산자를 그대로 넘길 수 있습니다. `count`는 1~50(기본 10)입니다. 결과마다 0~3의 `rerank_score`(1.5 이상이면 고품질로 간주)와 0~4의 `authority` 등급이 붙고, UI 표시용 `snippet`(100~200자)과 모델 입력용 `summary`(600~800자)가 따로 옵니다. Fetch는 URL 하나를 받아 마크다운으로 돌려줍니다. 둘 다 읽기 전용이며 408, 429, 5xx는 재시도, 402는 잔액 충전 후 재시도하라고 안내합니다.

같은 표에 Kimi K3, GLM-5.3, GPT-5.6 Sol, Opus 5 수치도 있습니다. 1017은 DeepSWE, Automation-Bench, Agents' Last Exam, Apex Bench에서 표 안 최고점이고, HLE, Terminal-Bench 4.0, ProgramBench, NL2Repo-Bench, Chartography, BabyVision에서는 Opus 5가(예: Terminal-Bench 4.0 51.8, HLE 56.3), ZeroBench-main에서는 GPT-5.6 Sol(53.0)이 앞섭니다. 경쟁 모델 수치는 9월 기반 모델 카드의 수치와 같아, 이번에 다시 측정한 것인지는 알 수 없습니다.

### 하네스가 점수를 얼마나 바꾸나

이 발표를 읽을 때 가장 중요한 각주는 "Terminal-Bench 4.0은 Claude Code 하네스, DeepSWE v1.1은 Mini-SWE-V2 하네스로 측정했다"는 한 줄입니다. 에이전트 벤치마크 점수는 모델만이 아니라 모델을 감싼 하네스(도구 정의, 프롬프트, 반복 제어)의 함수이기 때문입니다.

얼마나 차이가 나는지는 DeepSeek이 9월 기반 모델 카드에 직접 공개해 두었습니다. 같은 V4.1-Flash를 8개 하네스로 DeepSWE v1.1(과제당 8회 샘플)에 돌린 결과입니다.

| 하네스 | Claude Code | Codex | OpenCode | Pi | mini-SWE | DSH Minimal | DSH Standard | DSH PTC |
|---|---|---|---|---|---|---|---|---|
| DeepSWE v1.1 | 69.8 | 65.6 | 65.5 | 66.2 | **74.2** | 72.6 | 70.5 | 67.6 |

(DSH는 DeepSeek Harness. 기반 모델 카드 "Performance across agent scaffolds" 표)

**같은 모델인데 하네스에 따라 65.5에서 74.2까지 8.7점이 벌어집니다.** 1017의 DeepSWE 77.0은 이 중 가장 높은 하네스(mini-SWE)로 잰 값입니다. 자기 팀이 Claude Code나 Codex에서 이 모델을 쓴다면, 표의 77.0이 아니라 그보다 몇 점 낮은 값을 기대하는 편이 현실적입니다(1017의 하네스별 수치는 공개되지 않았으므로 이 부분은 추정입니다).

수치 사이의 불일치도 있습니다.

- **NL2Repo-Bench:** 1017 카드는 V4.1-Flash를 65.4로 적었지만, 9월 기반 모델 카드에는 64.0으로 되어 있습니다.
- **Terminal-Bench 4.0:** 1017 카드는 "Claude Code 하네스로 측정"이라고 했지만, 기반 모델 카드는 코드 에이전트 벤치마크(Terminal-Bench 포함)를 DeepSeek Harness의 Minimal 모드로 측정했다고 적었습니다. V4.1-Flash 값은 두 카드 모두 31.2입니다. 둘 중 어느 하네스의 값인지 공식 자료만으로는 확정할 수 없습니다.

두 차이 모두 결론을 뒤집을 정도는 아니지만, "같은 표의 두 열이 같은 조건에서 측정됐는가"를 독자가 확인할 수 없다는 점은 기록해 둘 만합니다.

### 출력 길이 단축이 비용에 주는 효과

발표문의 첫 그래프는 점수가 아니라 **DeepSWE v1.1 통과율 대 과제당 평균 비용**입니다(하네스 mini_swe_v2, 가로축 로그 스케일). 그래프에서 읽은 근사값은 다음과 같습니다(필자 판독, 오차 있음).

| 모델 · 추론 강도 | 통과율 | 과제당 비용 (근사) |
|---|---|---|
| V4.1-Flash-1017 · max | 77.0% (그래프 표기) | 약 $0.19 |
| V4.1-Flash-1017 · low | 약 72.5% | 약 $0.11 |
| V4.1-Flash · max | 약 74% | 약 $0.48 |
| V4.1-Flash · low | 약 67% | 약 $0.23 |

최고 추론 강도끼리 비교하면 과제당 비용이 대략 60% 낮아졌고, 1017의 low 설정이 기존 모델의 high 설정(약 70%)보다 높은 점수를 더 적은 비용으로 냅니다. 발표문이 가격 변경을 언급하지 않은 만큼, 이 차이는 단가가 아니라 **과제 하나를 끝내는 데 쓴 토큰 양**에서 나온 것으로 보입니다. 다만 그래프가 피크와 비피크 중 어느 단가로 계산됐는지, 출력 토큰이 몇 % 줄었는지는 공개되지 않았습니다. 또 그래프 각주에 따르면 다른 회사 모델 점은 2026-09-22 기준 공개 DeepSWE 리더보드(mini-swe-agent 하네스)와 OpenAI 공식 차트에서 가져온 값이라, DeepSeek 점과 측정 주체가 다릅니다.

출력 길이가 왜 비용에 크게 작용하는지는 가격표만으로도 계산할 수 있습니다. 피크 기준으로 출력 토큰은 캐시 미스 입력의 4배, 캐시 적중 입력의 **200배** 가격입니다. 가상의 에이전트 과제 하나가 캐시 적중 입력 300만 토큰, 캐시 미스 입력 20만 토큰, 출력 10만 토큰을 쓴다고 해 봅시다(필자가 정한 예시 값).

| 항목 | 토큰 | 단가(피크) | 비용 | 비중 |
|---|---|---|---|---|
| 캐시 적중 입력 | 3,000,000 | $0.006/M | $0.018 | 9% |
| 캐시 미스 입력 | 200,000 | $0.3/M | $0.060 | 30% |
| 출력 | 100,000 | $1.2/M | $0.120 | 61% |
| 합계 | | | $0.198 | |

입력 토큰이 출력의 30배가 넘어도 비용의 61%는 출력입니다. 여기서 출력만 30% 줄여도 과제 비용은 약 18% 내려갑니다. 실제로는 출력이 줄면 턴 수와 다음 턴의 입력도 함께 줄어 효과가 더 커집니다. 9월 발표가 KV 캐시 압축으로 "입력을 다시 읽는 비용"을 낮췄다면, 1017은 "덜 말하게 해서" 남은 큰 항목인 출력을 공략한 셈입니다.

## 써 볼 수 있나

- **API:** 모델 이름 `deepseek-flash`로 바로 쓸 수 있고, 웹과 앱에도 반영됐습니다. 가격은 위 표 참고(2026-10-24 기준). 동시성 한도는 2,500입니다.
- **에이전트 도구:** 발표문은 DeepSeek Harness, Tencent CodeBuddy, WorkBuddy 등에 최적화했다고 밝히고, 최상의 경험을 위해 DeepSeek Harness v0.2.1-rc.1 이상으로 올리라고 권합니다. 가격 문서의 연동 목록에는 Claude Code, Codex, OpenCode 등도 있습니다.
- **가중치:** Hugging Face와 ModelScope에서 MIT 라이선스로 받을 수 있습니다. 552B 규모 MoE라 자체 서빙에는 다중 GPU 노드가 필요하고, 동봉 코드는 참조 구현입니다. 운영 서빙은 오픈소스 엔진의 지원 상황을 따로 확인해야 합니다.
- **Search/Fetch:** 직접 호출은 1,000회당 $0.75. 하네스의 서버 측 도구로 쓰는 무료 기간은 2026-10-31 16:00 UTC까지입니다.

## 한계와 논란

- **모든 성능 수치가 자체 측정입니다.** 그래프의 경쟁 모델 점만 공개 리더보드와 OpenAI 차트에서 가져왔습니다. 하네스와 컨텍스트 설정이 벤치마크마다 다릅니다.
- **"출력이 짧아졌다"는 정량 근거가 없습니다.** 발표문과 모델 카드 모두 출력 길이가 줄었다고만 하고, 평균 출력 토큰이나 감소율은 밝히지 않았습니다. 비용 그래프가 유일한 간접 근거입니다.
- **카드 간 수치 불일치.** 위에서 본 NL2Repo-Bench 64.0 대 65.4, Terminal-Bench 하네스 표기 차이가 있습니다.
- **피크 요금제의 체감 가격.** 피크 시간대가 한국 업무 시간과 겹쳐, 비피크 가격만 보고 예산을 잡으면 실제 청구액이 두 배 가까이 될 수 있습니다.
- **모델 교체가 자동으로 일어납니다.** `deepseek-flash` 이름이 가리키는 모델이 이번처럼 예고 없이 바뀔 수 있고, 퇴역한 옛 이름도 새 모델로 연결됩니다. 회귀 테스트가 필요한 서비스라면 이 점이 위험 요인입니다.

## 인사이트

**왜 지금 중요한가: 에이전트 경쟁의 축이 "점수"에서 "과제당 비용"으로 옮겨 가고 있다.** 이번 발표문의 첫 그래프가 점수표가 아니라 비용 대 통과율 산점도라는 점이 상징적입니다. 에이전트 작업은 한 과제에 수십~수백 번 모델을 호출하므로, 단가표의 "100만 토큰당 가격"보다 "과제 하나 끝내는 데 드는 돈"이 실제 비교 기준이 됩니다. 이틀 뒤(2026-10-19) 나온 [MiniMax-M3.1-Flash](/tech/2026/10/24/minimax-m3-1-flash.html) 발표도 "에이전트 작업 사용 비용 70% 절감"을 앞세웠습니다. 필자의 판단으로는 앞으로 모델 발표에서 "과제당 비용 그래프"가 기본 항목이 될 가능성이 큽니다. 그렇다면 그 그래프의 단가 기준과 하네스를 묻는 것이 독자의 기본 습관이 되어야 합니다.

**실무에 주는 의미.** 모델을 고를 때 세 가지를 권합니다. 첫째, 벤치마크 표의 숫자는 그 각주의 하네스와 함께 읽습니다. DeepSeek이 공개한 하네스별 표가 보여 주듯 같은 모델도 하네스에 따라 9점 가까이 달라지므로, 자기 팀의 하네스로 20~50개 과제를 직접 돌려 보는 것이 공개 점수보다 정확합니다([LLM 평가](/tech/2026/10/24/llm-evals.html) 글 참고). 둘째, 비용은 단가가 아니라 과제당 비용으로 잽니다. 위 예시처럼 캐시 적중 입력이 아주 싸지면 비용의 대부분이 출력으로 몰리므로, 장황한 모델은 단가가 같아도 비쌉니다. [추론 모델](/tech/2026/10/24/reasoning-models.html)의 추론 강도 설정도 같은 관점에서 low부터 시험해 볼 만합니다. 그래프상 1017의 low 설정은 이전 버전의 high보다 점수가 높았습니다. 셋째, 모델 이름이 고정 버전을 가리키지 않는다는 점을 운영에 반영합니다. 자체 회귀 테스트 세트를 두고, 업데이트 공지를 감시해야 합니다.

**한계와 반론.** "파레토 개선"은 DeepSeek이 고른 벤치마크와 하네스, DeepSeek이 고른 비용 기준에서의 주장입니다. 특히 비용 그래프에서 경쟁 모델 점은 다른 출처의 값이라, 같은 하네스 이름이라도 버전이나 설정이 같다는 보장이 없습니다. 또 출력이 짧아졌다는 것은 비용에는 좋지만, 설명이나 중간 보고를 길게 받아야 하는 작업에서는 오히려 사용자 경험이 나빠질 수 있습니다. 감소폭이 공개되지 않은 만큼, 자기 작업에서 출력 길이 변화를 직접 측정해 보는 것이 좋습니다.

**앞으로 지켜볼 점.** (1) 출력 길이와 턴 수 감소를 정량으로 보여 주는 자료(기술 보고서 갱신이나 제3자 측정)가 나오는지. (2) 2026-10-31 이후 Search/Fetch 과금이 시작되면 하네스에서 검색을 많이 쓰는 작업의 과제당 비용이 얼마나 오르는지. 과제당 수십 번 검색하면 검색 비용이 모델 비용과 비슷한 규모가 될 수 있습니다. (3) 9월 발표에서 예고한 V4.1-Pro가 같은 "과제당 비용" 프레임으로 나오는지.

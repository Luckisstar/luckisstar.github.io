# [기술 소개] Mistral Large 4: API 프리뷰 먼저, 가중치는 레드팀 뒤에 푸는 1조 파라미터 MoE

- **발표:** Mistral AI, 2026년 10월 6일
- **원문:** [공식 발표](https://mistral.ai/news/mistral-large-4/) · [모델 카드(Mistral Docs)](https://docs.mistral.ai/models/mistral-large-4) · [API 가격표](https://docs.mistral.ai/inference/pricing) · [Hugging Face 공개 예정 페이지](https://huggingface.co/mistralai/Mistral-Large-4-1T-A52B)
- **한눈에 (2026-10-24 기준):** 총 1.05조(1.05T) 파라미터, 활성 52B, 비전 인코더 1.6B, 컨텍스트 1M 토큰의 MoE 모델. API 가격은 입력 100만 토큰당 $1.36, 출력 $4.18(캐시 입력 $0.14).
- **주의 (2026-10-24 기준):**
  - 현재는 **Public Preview(공개 프리뷰)** 단계입니다. Mistral 수명 주기 정책상 프리뷰 모델은 예고 없는 업데이트(silent update)가 허용되고, 정식 출시(GA)가 보장되지 않습니다.
  - **가중치는 아직 공개되지 않았습니다.** 발표문은 "이달 말까지" 공개한다고 했고, Hugging Face 페이지의 예상 공개일은 2026년 10월 31일입니다. 모두 2026-10-24 기준 예정입니다.
  - **라이선스가 정해지지 않았습니다.** 모델 카드의 License 칸은 "Coming soon"입니다. 이전 세대 Large 3는 Apache 2.0이었지만, Large 4도 같을지는 확인되지 않았습니다.

## 한 줄 요약

**Mistral이 자사 최대 모델 Mistral Large 4(ML4)를 API 프리뷰로 먼저 내놓고, 사이버보안 기관과 검증된 파트너가 레드팀을 마친 뒤 가중치를 공개하겠다는 "단계적 오픈웨이트" 방식을 택했습니다.** 오픈웨이트 모델의 출시 순서 자체가 안전 장치로 쓰이기 시작했다는 점에서 눈여겨볼 만합니다.

## 배경

Mistral은 오픈웨이트(open weights, 학습된 가중치를 내려받아 직접 실행할 수 있게 공개하는 방식) 모델과 상용 API를 함께 운영해 온 프랑스 회사입니다. 직전 플래그십인 Mistral Large 3는 모델 카드 기준으로 2025년 12월 2일 정식 출시(GA)됐고, 총 675B, 활성 41B 파라미터의 MoE(전문가 혼합, Mixture of Experts) 구조에 Apache 2.0 라이선스, 컨텍스트 256k였습니다.

Large 4는 같은 계열의 다음 세대이지만 규모와 출시 방식이 모두 달라졌습니다. 공식 문서에서 확인한 두 세대를 비교하면 다음과 같습니다.

| 항목 | Mistral Large 3 | Mistral Large 4 |
|---|---|---|
| 출시 | 2025-12-02, GA | 2026-10-06, Public Preview |
| 총 파라미터 | 675B | 1.05T |
| 활성 파라미터 | 41B | 52B |
| 컨텍스트 | 256k | 1M |
| 라이선스 | Apache 2.0 | 미정("Coming soon") |
| 가중치 | 공개됨 | 2026-10-31 공개 예정 (2026-10-24 기준) |
| API 가격(입력/출력, $/M 토큰) | 0.5 / 1.5 | 1.36 / 4.18 |

출처: 각 모델의 Mistral Docs 모델 카드와 API 가격표(2026-10-24 확인).

## 핵심 내용

### 1. 사양: 1조 파라미터, 토큰당 약 5%만 쓰는 MoE

모델 카드는 ML4를 "세분화된(granular) MoE 구조의 오픈웨이트 범용 멀티모달 모델"로 소개하고, 활성 52B, 총 1.05T, 비전 인코더 1.6B라고 적습니다. 발표문은 "기본적으로 멀티모달(natively multimodal)"인 1조 파라미터 모델이라고 표현합니다.

활성 파라미터 수는 출처마다 표현이 조금 다릅니다. Hugging Face 공개 예정 페이지는 "토큰당 활성 49B(임베딩과 출력 층을 포함하면 52B)"라고 적고 있습니다. 즉 52B는 임베딩까지 더한 값이고, 전문가 층에서 실제로 계산에 쓰이는 몫은 49B 정도입니다. 어느 쪽이든 총 파라미터의 5% 안팎만 매 토큰에 활성화되는 구조입니다. MoE가 이렇게 큰 모델을 비교적 낮은 추론 비용으로 돌릴 수 있는 원리는 [MoE 소개 글](/tech/2026/10/24/mixture-of-experts.html)에서 다뤘습니다.

모델 카드의 API 기능 목록에는 구조화 출력(Structured Outputs), 함수 호출(Function Calling), 문서 QnA, Prefix, 배치(`/v1/batch`), 에이전트와 대화(`/v1/agents`, `/v1/conversations`), 내장 도구가 있습니다. 모델 설명 문구는 지시 수행과 추론을 한 모델에 합친 "하이브리드 instruct-and-reasoning" 모델이라고 하며, 사용 예제에는 `reasoning_effort` 파라미터가 들어 있습니다.

아키텍처의 세부(전문가 수, 라우팅 방식, 학습 토큰 수)는 아직 공개되지 않았습니다. 발표문은 가중치 공개 때 아키텍처, 추가 벤치마크, 사후 학습 방법을 함께 공개하겠다고 밝혔습니다(2026-10-24 기준 예정).

### 2. 출시 전략: API 프리뷰 → 레드팀 → 가중치 공개

이번 발표에서 가장 눈에 띄는 대목은 순서입니다. 발표문의 해당 문장은 다음과 같습니다.

> We will release the weights by the end of the month. Until then, we are red-teaming the model in real-world settings with cybersecurity leaders, vetted partners, and state authorities, who will access the same model with reduced moderation and expanded cyber capabilities.

정리하면 세 단계입니다.

| 단계 | 시점 | 누가 쓰나 | 무엇이 공개되나 |
|---|---|---|---|
| 1. API 프리뷰 | 2026-10-06부터 | 누구나(Mistral Studio) | API 접근만 |
| 2. 레드팀 | 프리뷰와 동시 진행 | 사이버보안 기업, 검증된 파트너, 국가 기관 | 같은 모델을 완화된 필터와 확장된 사이버 기능으로 |
| 3. 가중치 공개 | 2026-10-31 예정 (2026-10-24 기준) | 누구나 | 가중치, 아키텍처 세부, 추가 벤치마크, 사후 학습 방법 |

레드팀(red team, 공격자 입장에서 모델의 위험한 능력과 우회 방법을 찾는 시험)을 공개 전에 하는 것 자체는 새롭지 않습니다. 다른 점은 이 순서를 **오픈웨이트 모델**에 적용했다는 데 있습니다. API 모델은 문제가 발견되면 서버에서 필터를 고치거나 모델을 내릴 수 있지만, 가중치는 한 번 풀리면 회수할 수 없습니다. Mistral이 가중치 공개를 마지막 단계로 둔 이유는 이 비가역성 때문으로 보입니다(필자의 해석이며, 발표문은 이유를 따로 설명하지 않습니다).

모델 카드의 수명 주기 표시도 이 전략과 맞물립니다. [모델 수명 주기 정책](https://docs.mistral.ai/inference/model-lifecycle)에 따르면 Public Preview 모델은 GA와 같은 가격을 받지만 예고 없는 업데이트를 허용하고, GA로 간다는 보장이 없으며, 폐기(deprecation) 예고 기간도 GA(6개월)보다 짧은 1개월입니다. 발표문 역시 사후 학습의 강화학습(RL) 실행이 "아직 진행 중"이고 앞으로 몇 주, 몇 달 동안 큰 개선을 기대한다고 적었습니다. **지금 API로 쓰는 모델과 10월 말 공개될 가중치가 같은 체크포인트라는 보장은 문서상 없습니다.**

### 3. 포지셔닝: 사이버보안과 "거절하지 않는 방어 도구"

발표문은 ML4의 강점으로 사이버보안을 가장 길게 다룹니다. 주장의 뼈대는 이렇습니다.

- Artificial Analysis Cyber Index에서 전 세계 상위 5위 안이고, 중국 외 지역에서 개발된 오픈웨이트 모델 중 큰 차이로 1위라고 합니다.
- 그 지수의 한 시험(실제 오픈소스 취약점을 재현하고 패치하는 과제)에서 82%로 모든 모델 중 최고점이라고 합니다.
- 보안 대회 문제 40개로 구성된 Cybench에서 93%를 풀었다고 합니다.
- 같은 취약점 재현 시험에서 Claude Opus 5.5, GPT-6 Astra 같은 폐쇄형 모델은 **과제를 거절하기 때문에** 0점 가까이 나온다고 Mistral은 설명합니다.

이 마지막 논점이 포지셔닝의 핵심입니다. 발표문은 공급자 수준의 거절이 정당한 취약점 연구와 사고 대응을 막을 수 있고, 사고 도중 기능 접근을 잃는 것 자체가 보안 위험이 된다고 주장합니다. 그래서 오픈웨이트와 자체 배포(private cloud, 온프레미스)로 "조직이 자기 정책으로" 보안 작업을 돌릴 수 있게 하겠다는 것입니다.

동시에 발표문의 안전성 절에서는 JailbreakBench, StrongREJECT, AgentHarm의 사이버 관련 악성 요청에 대한 평균 거절률이 "모든 OSS 모델보다 높다"고 적고, 간접 프롬프트 인젝션 내성을 보는 Lakera B3 벤치마크에서 공격의 93.3%를 막았다고 밝혔습니다. 정리하면 "방어 작업은 거절하지 않고, 악성 요청은 더 잘 거절한다"는 두 주장을 함께 내세운 셈입니다. 두 주장이 같은 모델 안에서 어떻게 양립하는지, 그리고 레드팀 파트너용 "완화된 필터" 버전과 일반 공개 버전이 어떻게 다른지는 발표문에 설명이 없습니다.

### 4. 소버린 AI: 유럽에서 학습하고 유럽에서 서빙

발표문의 소제목은 "Forged in Europe. Built for AI sovereignty."입니다. 확인되는 사실은 다음과 같습니다.

- ML4는 Mistral이 유럽에 보유한 자체 데이터센터에서 NVIDIA Grace Blackwell GPU 3,800개로 처음부터 학습했고, 공개 프리뷰도 같은 인프라에서 서빙한다고 합니다.
- 여러 지역에서 제공하되, 그중 유럽 배포는 Mistral이 다른 디지털 서비스 공급자와 독립적으로, 유럽 법 아래에서 직접 운영한다고 밝혔습니다.
- 학습 데이터의 상당 부분이 다국어이며 EU의 모든 공용어를 포함한 160개 이상 언어에 걸쳐 있다고 합니다.
- ML4는 €30억 규모 시리즈 D로 자금을 댄 로드맵의 첫 이정표이며, 이 라운드는 유럽 기술 기업 사상 최대 지분 투자라고 Mistral은 설명합니다.

API 문서에서도 이 포지셔닝이 구체적인 기능으로 나타납니다. [지역 추론(Regional inference)](https://docs.mistral.ai/inference/regional-inference) 문서에 따르면 `api.eu.mistral.ai`(EU·EFTA 국가의 데이터센터)와 `api.us.mistral.ai` 엔드포인트를 고를 수 있고, 지역 엔드포인트는 표준가의 1.1배로 과금됩니다. 다만 지역 엔드포인트에서는 함수 호출만 지원 도구이고, 에이전트·배치·Files API 같은 상태 저장 기능은 쓸 수 없으며, 모델별 지원 여부는 `models.list`로 직접 확인하라고 안내합니다. ML4가 EU 엔드포인트에서 제공되는지는 문서에 명시돼 있지 않아 확인하지 못했습니다.

## 성능과 비교

아래 수치는 모두 **Mistral 발표문이 밝힌 값**입니다. 하네스(평가 실행 도구)와 설정은 대부분 공개되지 않았고, 측정 주체가 드러난 경우만 따로 표시했습니다. 발표문의 그래프 원자료는 확인하지 못해 본문 텍스트에 나온 수치만 옮겼습니다.

| 영역 | 벤치마크 | ML4 | 측정 주체·비고 |
|---|---|---|---|
| 코딩 | DeepSWE v1.1 | 61.7% | 측정 주체 미기재 |
| 코딩 | SWE-Atlas-QnA | 59.4% | 측정 주체 미기재 |
| 코딩 | Terminal-Bench 4 | 28.3% | 측정 주체 미기재 |
| 코딩 | Coding Agent Index | 49.8% | DeepSeek V4 Pro 0813, Qwen3.8 Max보다 높다고 함 |
| 코딩 | 블라인드 인간 평가(1~5점) | 3.74 (5개 중 2위) | Surge AI와 진행. 1위 Claude Opus 5(4.22), GLM-5.3 3.60, Kimi K3 3.59, GLM-5.2 3.40 |
| 사이버 | Cybench (40문제) | 93% | 측정 주체 미기재 |
| 사이버 | AA Cyber Index 내 취약점 재현·패치 시험 | 82% | Artificial Analysis 지수. 전체 상위 5위권이라고 함 |
| 에이전트 | AutomationBench (657개 업무 워크플로) | 59.9% | Artificial Analysis 벤치마크로 표기 |

| 비전 | Dense 200 | 42% | GPT-6 Astra 41% |

| 안전 | KORA Benchmark | 1.691 (최대 2) | OSS 모델 중 Mistral이 측정한 최고점이라고 함 |

법률·금융 영역에서는 제3자 평가 기관 vals.ai를 통해 평가했고 두 영역 모두 GPT-6 Astra를 넘었다고 하며, Harvey의 Legal Agent 벤치마크에서는 모든 오픈소스 모델보다 높다고 밝혔습니다. 다만 본문에 구체적인 점수는 없습니다. 과학 분야에서는 SciCode-Verified에서 오픈웨이트 중 최고라고 했고, 전문가 주석자가 GLM-5.3과 비교한 내부 평가에서는 CAD와 STEM에서 선호되고 금융과 코딩에서는 비슷하거나 근접했다고 적었습니다.

이 표를 읽을 때 기억할 점이 두 가지 있습니다. 첫째, 비교 대상은 주로 GLM, Kimi, DeepSeek, Qwen 같은 오픈웨이트 모델이고, 폐쇄형 프런티어 모델과의 직접 비교는 Dense 200, 인간 평가, vals.ai 평가 등 일부에 그칩니다. 인간 코딩 평가에서는 Claude Opus 5가 1위였습니다. 둘째, 발표문 스스로 "중국 외 지역 오픈웨이트 중 1위", "미국이나 유럽에서 개발된 오픈웨이트 모델보다 훨씬 우수"처럼 비교 범위를 좁혀 표현하는 경우가 많습니다. 전체 오픈웨이트 중 최고라는 주장은 사이버보안, 금융, 법률 같은 특정 업무 영역에 한정돼 있습니다.

## 써 볼 수 있나

**API (2026-10-24 기준 가능).** Mistral Studio(콘솔)에서 API 키를 발급받아 모델 이름 `mistral-large-4`로 호출합니다. 모델 카드에는 `mistral-large-4-0`이라는 식별자도 함께 나옵니다. 수명 주기 정책은 별칭을 쓰면 동작과 가격이 예고 없이 바뀔 수 있으니 버전 식별자를 고정하라고 권합니다. 아래는 모델 카드의 Python 예제를 그대로 옮긴 것이며, 필자는 API 키가 없어 **직접 실행하지 않았습니다.**

```python
import os
from mistralai.client import Mistral

client = Mistral(api_key=os.environ["MISTRAL_API_KEY"])

response = client.chat.complete(
    model="mistral-large-4",
    messages=[
        {
            "role": "user",
            "content": "Write a Python function to merge two sorted linked lists into one sorted list.",
        }
    ],
    reasoning_effort="high",
)

print(response.choices[0].message.content)
```

EU 안에서 추론을 처리해야 한다면 지역 추론 문서대로 `Mistral(api_key=..., server="eu")`처럼 클라이언트를 만들 수 있습니다(SDK 2.70 이상). 앞서 적었듯 ML4가 EU 엔드포인트에 올라와 있는지는 `client.models.list()`로 먼저 확인해야 합니다.

**가격 (2026-10-24, Mistral Docs 가격표 기준, 100만 토큰당 USD).**

| 모델 | 입력 | 캐시 입력 | 출력 |
|---|---|---|---|
| Mistral Large 4 | 1.36 | 0.14 | 4.18 |
| Mistral Large 3 | 0.5 | 0.05 | 1.5 |
| Mistral Medium 3.5 | 1.5 | 0.15 | 7.5 |
| Z.ai GLM 5.3 (Mistral에서 서빙) | 1.4 | 0.14 | 4.4 |

Mistral 가격 페이지의 FAQ는 배치 처리가 50% 저렴하다고 안내합니다. 흥미로운 점은 Mistral이 자사 플랫폼에서 서빙하는 GLM 5.3과 ML4의 가격이 거의 같다는 것입니다. 발표문이 내부 인간 평가의 비교 대상으로 GLM-5.3을 고른 것과 같은 맥락으로 보입니다.

**가중치 (2026-10-24 기준 예정).** Hugging Face의 `mistralai/Mistral-Large-4-1T-A52B` 페이지는 현재 "Upcoming release" 상태이고 예상 공개일을 2026년 10월 31일로 표시합니다. 모델 카드의 GPU 메모리 요구량 칸도 "N/A"라서, 자체 배포에 필요한 하드웨어는 아직 공식 수치가 없습니다. 참고로 Large 3 모델 카드는 675B 모델에 BF16 기준 약 1,800GB, FP4 기준 약 360GB를 제시했습니다. 1.05T인 ML4는 이보다 클 것으로 예상되지만, 공식 수치가 나오기 전까지는 추정일 뿐입니다.

## 한계와 논란

- **라이선스가 비어 있습니다.** "오픈웨이트"라는 말은 가중치를 내려받을 수 있다는 뜻이지, 상업적 사용이나 재배포 조건까지 정해 주지 않습니다. 모델 카드의 License가 "Coming soon"인 이상, Apache 2.0일지 Mistral 문서에서 일부 오픈웨이트 모델에 표기된 MRL 같은 별도 라이선스일지 알 수 없습니다. 도입 판단에서 가장 중요한 변수가 아직 미정입니다.
- **벤치마크는 자체 발표입니다.** 위 표의 수치 대부분은 측정 하네스와 설정이 공개되지 않았고, 일부만 Artificial Analysis, Surge AI, vals.ai 같은 외부 기관이 관여했다고 밝혔습니다. 발표문이 약속한 "추가 벤치마크" 공개(2026-10-24 기준 예정) 이전에는 독립 재현이 어렵습니다.
- **"거절하지 않음"은 양날의 검입니다.** Mistral은 폐쇄형 모델이 취약점 재현을 거절해서 0점이 나온다는 점을 장점으로 내세웁니다. 그러나 이 점수 차이는 능력 차이가 아니라 정책 차이에서 나온 것이고, 같은 능력이 오픈웨이트로 풀리면 공격자도 쓸 수 있습니다. 공개 전 레드팀은 이 우려에 대한 Mistral의 답이지만, 레드팀 결과와 그에 따른 조치를 공개하겠다는 약속은 발표문에 없습니다.
- **프리뷰와 공개 가중치의 관계가 불분명합니다.** RL 학습이 "아직 진행 중"이라고 했으므로, 프리뷰 API에서 측정한 결과가 10월 말 공개 가중치에도 그대로 적용된다고 보기 어렵습니다.
- **활성 파라미터 표기가 출처마다 다릅니다.** 모델 카드는 52B, Hugging Face 페이지는 49B(임베딩·출력 층 포함 시 52B)입니다. 모순은 아니지만, 다른 모델과 활성 파라미터로 효율을 비교할 때는 어느 기준인지 맞춰야 합니다.

## 인사이트

**왜 지금 중요한가.** 오픈웨이트 모델의 출시는 지금까지 대체로 "가중치와 블로그를 같은 날 공개"하는 일회성 사건이었습니다. ML4는 이를 API 프리뷰, 제한된 파트너 레드팀, 가중치 공개의 세 단계로 나눴습니다. 필자의 판단으로는, 모델의 사이버 능력이 실제 위협이 될 만큼 올라오면서 오픈웨이트 진영도 "회수할 수 없는 공개" 앞에 안전 점검 단계를 끼워 넣기 시작한 것입니다. 이는 폐쇄형 모델이 정책으로 막는 위험을, 오픈웨이트는 공개 시점과 대상의 순서로 관리하려는 시도라고 볼 수 있습니다. 같은 날 게시된 [Meta Muse Spark 공개 글](/tech/2026/10/24/meta-muse-spark-open.html)과 나란히 읽으면, 대형 오픈웨이트 모델들이 "언제, 누구에게 먼저 푸는가"를 출시 설계의 일부로 다루기 시작했다는 흐름을 확인할 수 있습니다.

**실무에 주는 의미.** ML4를 검토하는 팀이라면 지금 할 일과 10월 31일 이후 할 일을 나누는 것이 좋겠습니다. 지금은 API 프리뷰로 자사 업무(특히 발표문이 강조한 보안 분석, 금융 문서, 도면·이미지 이해)에 대한 평가 세트를 돌려 두되, 프리뷰는 예고 없이 바뀔 수 있으므로 결과에 날짜와 모델 식별자를 함께 기록해야 합니다. 가중치가 공개되면 가장 먼저 라이선스 원문을 확인하고, 그다음 공개 체크포인트로 같은 평가를 다시 돌려 프리뷰와의 차이를 측정합니다. 자체 배포를 고려한다면 1조 파라미터 MoE는 활성 파라미터가 작아도 전체 가중치를 메모리에 올려야 하므로, 활성 52B라는 숫자만 보고 GPU 규모를 잡으면 안 됩니다.

**블로그의 기존 글과의 연결.** [MoE 소개 글](/tech/2026/10/24/mixture-of-experts.html)에서 설명한 "총 파라미터는 크게, 토큰당 계산은 작게"라는 원리가 ML4에서는 1.05T 대 52B(약 5%)라는 극단적인 비율로 나타납니다. Large 3(675B 대 41B, 약 6%)보다 비율이 더 낮아졌다는 점에서, 세분화된 MoE로 규모를 키우는 방향이 계속되고 있음을 보여 줍니다.

**한계와 반론.** "소버린 AI"라는 포지셔닝은 학습과 서빙 위치, 운영 주체에 관한 주장이고, 모델을 쓰는 조직의 데이터 통제는 결국 배포 방식에 달려 있습니다. API로 쓰는 한 데이터는 Mistral 인프라를 거치며, 문서상 지역 엔드포인트도 일부 기능만 지원합니다. 진정한 의미의 자율성은 가중치와 라이선스가 나와야 판단할 수 있습니다. 또한 사이버보안 점수에서 폐쇄형 모델과의 격차가 "거절"에서 온다는 설명은 Mistral 쪽 해석이며, 해당 폐쇄형 모델 공급자의 공식 자료로 확인한 것은 아닙니다.

**앞으로 지켜볼 점.** (1) 10월 31일 전후로 공개될 라이선스가 Apache 2.0인지, 상업 이용에 조건이 붙는 형태인지. 이것이 ML4의 실무 가치를 가장 크게 좌우합니다. (2) 공개 가중치에 레드팀 결과가 어떻게 반영되는지, 그리고 레드팀 과정이나 결과 요약을 공개하는지. (3) 약속한 아키텍처·사후 학습 상세와 추가 벤치마크가 나온 뒤 외부 평가 기관의 독립 측정이 발표문 수치와 얼마나 일치하는지. 공개 일정이 미뤄지거나 라이선스가 제한형으로 나온다면, ML4는 "오픈웨이트 모델"보다 "가중치도 받을 수 있는 상용 API 모델"에 가깝게 보는 편이 정확할 것입니다.

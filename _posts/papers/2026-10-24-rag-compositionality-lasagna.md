# [논문 소개] RAG Compositionality(LASAGNA): 따로 잰 RAG 기법의 이득은 합쳐지지 않는다

- **논문:** *Retrieval Augmented Generation Compositionality*
- **저자:** Ido Levy, Segev Shlomov, Leshem Choshen (총 3명), IBM · Weizmann Institute of Science (논문 본문 기준)
- **공개:** 2026년 10월 21일, arXiv:2610.29722 (cs.CL)
- **링크:** [arXiv](https://arxiv.org/abs/2610.29722) · [PDF](https://arxiv.org/pdf/2610.29722) · [HTML](https://arxiv.org/html/2610.29722) · [코드 dolev31/lasagna](https://github.com/dolev31/lasagna)
- **코드 현황 (2026-10-24 기준):** Apache-2.0, 첫 릴리스 v0.1.0(2026-10-21), PyPI 패키지 `lasagna-rag`, GitHub 스타 13개. 논문 분석에 쓴 설계 행렬, 질의별 원점수, 분석 스크립트는 **공개 저장소에 포함되지 않고 저자에게 요청해야 받을 수 있습니다**(논문 Reproducibility statement).

## 한 줄 요약

**RAG 기법을 하나씩 따로 재서 얻은 이득은 전체 파이프라인에서 그대로 더해지지 않습니다.** 검색 기법 세 개의 개별 이득을 더하면 NDCG@10 +47%가 예상되지만 실제로 함께 쓰면 +17%에 그쳤고, 검색 품질과 답변 충실도는 서로 다른 구성 요소에 좌우되며, 작은 코퍼스에서 1등이던 구성이 200K 문서에서는 뒤집혔습니다.

## 왜 이 연구가 필요한가

요즘 RAG(검색 증강 생성, Retrieval-Augmented Generation) 파이프라인은 임베딩, 청킹, 색인 시점 보강(enrichment), 검색, 질의 증강, 재순위화(reranking), 컨텍스트 압축, 에이전트식 검증까지 여러 단계를 쌓습니다. 그런데 새 기법은 대개 **한 단계만 바꾸고 나머지는 단순한 기준선**으로 둔 채 평가됩니다. 저자들은 새 재순위화 모델을 제안하는 연구자가 "현대적 파이프라인을 반영하지 못하는 빈약한 기준선과 비교하거나, 주변 스택 전체를 다시 구현해야 하는" 처지라고 지적합니다.

이 관행에는 세 가지 암묵적 가정이 깔려 있습니다. 논문은 이를 실험 전에 가설로 선언하고(pre-declared) 검증합니다.

| 가설 | 검증하려는 가정 | 판정 (논문 표 12) |
|---|---|---|
| H1 | 따로 잰 이득은 합치면 더해진다(가산성) | 사전 기준(상호작용이 충실도 분산의 20% 이상)은 **충족 못 함**. 단 검색 지표에서는 큰 손실 관측 |
| H2 | 중간 수준의 단일 구성이 여러 배포 목표를 두루 만족한다 | 사전 등록한 5개 벤치마크 비교는 **실행되지 않음**. 실행한 비교에서는 모든 지표 1등 구성 없음 |
| H3 | 작은 코퍼스에서 잰 순위가 큰 코퍼스에서도 유지된다 | 순위 역전 관측으로 **지지됨** |

저자들은 해시로 고정한 내부 문서로 가설을 미리 정했지만 OSF 같은 제3자 사전 등록은 하지 않았기 때문에, 본문에서 "pre-registered" 대신 "pre-declared"라는 표현을 쓴다고 밝혔습니다.

## 제안 방법

### LASAGNA: 한 단계만 바꾸고 나머지는 고정하는 프레임워크

LASAGNA는 RAG의 각 단계를 고정된 인터페이스 뒤에 두는 오픈소스 프레임워크입니다. 핵심은 **단계 격리**입니다. 한 단계의 구현을 바꿔도 이웃 단계의 상태가 조용히 바뀌지 않도록, 모든 구성 요소가 타입이 정해진 추상 클래스를 상속하고 입출력도 타입이 정해진 데이터클래스로 주고받습니다. 자동 격리 테스트 5개가 "한 구성 요소를 켜고 끄는 것이 다른 구성 요소를 바꾸지 않는지"를 확인합니다(3절, 부록 H.1).

- 지원하는 구성 요소 유형 8가지: embedder, chunker, reranker, retriever, document_processor, query_enhancer, agentic_pipeline, generator
- 내장 구성 요소 53개, 벡터 백엔드 6종(Milvus, Pinecone, Qdrant, Weaviate, pgvector, OpenSearch)
- 새 기법은 데코레이터 한 줄로 등록하고, YAML로 비교 실험을 선언하면 같은 주변 스택 위에서 짝지은 통계 검정까지 돌려 줍니다(그림 2).

저장소 README에 실린 사용 예는 다음과 같습니다. 함수 하나를 재순위화 단계의 구성 요소로 등록하고, 내장 cross-encoder와 비교하는 실험을 YAML로 선언합니다.

```python
# my_ideas.py (README 예제)
import lasagna

@lasagna.reranker(paper="Doe et al. 2026", claims={"beir/scifact": {"ndcg@10": 0.456}})
def keyword_overlap(query, text):  # 문단 하나의 점수를 매기는 함수
    return len(set(query.lower().split()) & set(text.lower().split()))
```

```yaml
# sweep.yaml (README 예제)
name: does keyword_overlap help
benchmarks: [{name: smoke}]
tracks: [retrieval]
pipeline:
  base_profile: speed
  rerankers: [cross_encoder, "my_ideas:keyword_overlap"]
n_runs: 1
```

```bash
lasagna benchmark experiment sweep.yaml
lasagna results significance "<output>/results.json" -m ndcg@10 --all
```

위 예제는 README를 옮긴 것이며 필자가 직접 실행하지는 않았습니다. README는 첫 실행 때 모델 183MB를 내려받고, torch와 sentence-transformers가 핵심 의존성이라 설치 용량이 macOS arm64 기준 약 1.3GB라고 안내합니다.

### 실험 설계: D-optimal 부분 요인 설계

8개 단계(차원)마다 2~5개 수준을 두면 전체 조합은 4×4×4×3×5×4×2×4 = **30,720개**입니다. 저자들은 이를 전부 돌리면 약 4만 GPU 시간과 약 60만 달러의 LLM API 비용이 든다고 추정하고, 대신 D-optimal 설계(Fedorov 좌표 교환)로 주효과와 28개 두 차원 상호작용을 모두 추정할 수 있는 242개 구성을 뽑았습니다(4절).

| 차원 | 단계 | 수준 (∗는 기준선) |
|---|---|---|
| D1 | 임베딩 | MiniLM-L6∗, BGE-M3, E5-large, BGE-large |
| D2 | 청킹 | fixed∗, semantic, sent-window, hierarchical |
| D3 | 보강 | none∗, contextual retrieval, RAPTOR, GraphRAG |
| D4 | 검색 | dense∗, hybrid-BM25, hybrid-SPLADE |
| D5 | 질의 증강 | none∗, HyDE, RAG-Fusion, decomposition, step-back |
| D6 | 재순위화 | none∗, single cross-encoder, ensemble, MMR |
| D7 | 압축 | none∗, LLMLingua |
| D8 | 에이전트 게이트 | none∗, CRAG, Self-RAG, Speculative-RAG |

(논문 표 10)

계획한 242개 중 **167개를 실행**했습니다. GraphRAG 보강 63개는 단독 실험에서 NDCG@10 변화가 없는데 지연이 약 2배 늘어 제외했고, 12개는 시간 초과로 실패했습니다. 여기에 24개 표적 실험의 비요인(non-factorial) 구성 138개와 코퍼스 규모 실험이 더해집니다. 초록과 저장소 설명은 전체를 "450개 구성"으로 표현합니다.

## 실험 설정

| 항목 | 내용 |
|---|---|
| 벤치마크 | BEIR 검색 세트 5개(NFCorpus, FiQA, SciFact, ArguAna, HotpotQA)와 QA 세트 3개(본문은 SQuAD v2, MuSiQue를 명시) |
| 코퍼스 | 8개 벤치마크를 하나의 공유 벡터 저장소로 통합. 검색 트랙 5,132문서·93질의, 생성 트랙 5,566문서·56질의 |
| 규모 실험 | 5K, 15K, 25K, 50K, 100K, 200K 문서 (같은 5개 도메인에서 방해 문서 추가) |
| 생성 모델 | GPT-5.1 (모든 구성의 답변 생성) |
| 지표 | 검색: NDCG@10. 생성: RAGAS v0.4 충실도(faithfulness)·답변 관련성(GPT-5.1 심사), EM, F1, 지연, 질의당 비용 |
| 심사자 검증 | 사람 2명 평가, Claude Sonnet 4.5 교차 심사, Claude Opus 4.7로 220개 예제 재채점 |
| 비용 | 클라우드 비용 약 5,200달러, 벽시계 310시간 (부록 A.7) |
| 집계 | 개별 질의 평가 약 358,215회 (RAGAS 반복 평가 포함) |

여러 도메인을 한 저장소에 섞은 것은 의도된 설계입니다. 저자들은 실제 RAG 배포에서는 하나의 검색기가 의학, 금융, 과학, 논증, 다중 홉 질의를 한 저장소에서 구분해야 하는데, 벤치마크별로 따로 평가하는 BEIR 기본 방식은 이 도메인 간 방해를 덜 시험한다고 설명합니다.

품질과 지연을 함께 보기 위해 하이퍼볼륨 HV = NDCG@10 × 충실도 × max(0, 1 − 지연/30초)를 씁니다. 30초 안에서 검색과 답변이 모두 좋고 빠를수록 값이 큽니다.

## 주요 결과

### 1. 검색 이득은 합치면 크게 줄어든다: 예측 +47%, 실제 +17%

기준선(`default_standard`)의 NDCG@10은 0.412입니다. 같은 분할에서 BM25 단독은 0.403, 권장되는 기성 dense 인코더는 0.436이라 저자들은 이것이 일부러 약하게 잡은 기준선은 아니라고 강조합니다(표 60).

개별적으로 가장 큰 검색 이득을 낸 세 기법(cross-encoder 재순위화, MMR 끄기, 문서 인식 접두어)의 이득을 더하면 **+46.6%**가 예측됩니다. 이 기법들을 함께 담은 balanced 파이프라인의 실제 개선은 **+17.2%**로, 예측 대비 63%가 사라졌습니다(5절, 표 32).

개별적으로 이득이 있었던 다섯 기법을 모두 넣으면 손실은 더 커집니다. 그림 9의 폭포 차트에서 개별 이득의 합은 0.667(= 0.412 + 0.084 + 0.062 + 0.046 + 0.037 + 0.026)이지만 실제 조합 결과는 0.483으로, **기대 개선분의 72%가 상호작용으로 사라졌습니다**(부록 D.14). 17개 조합을 시험했을 때 이 손실은 7%에서 72% 사이였고 중앙값은 41%입니다.

저자들은 원인을 **기능 중복**으로 봅니다. 재순위화가 이미 MMR을 끄는 효과의 일부를 제공하고, HyDE와 cross-encoder 재순위화는 둘 다 질의와 문단의 정렬을 개선하므로 함께 켜면 각각의 몫이 줄어든다는 설명입니다.

### 2. 충실도 이득은 비교적 그대로 옮겨 간다: 예측 +28%, 실제 +32%

충실도에서는 양상이 반대입니다. BGE-large 임베딩, hierarchical 청킹, hybrid-BM25 검색, Speculative-RAG 게이트의 개별 이득을 기준 0.692에 더하면 0.886(+28%)이 예측되는데, 관측된 최고 구성은 0.911(+32%)이었습니다(표 47).

다만 저자들 스스로 이 비교가 **정확히 같은 구성 요소 묶음끼리의 통제된 비교가 아니라 탐색적 신호**라고 적어 두었습니다. 기법들이 파이프라인의 서로 다른 단계에서 작동해 기능이 덜 겹칠 때 더 가산적으로 보인다는 해석도 가설로 제시합니다.

### 3. 검색 품질과 답변 충실도는 거의 무관하다

같은 파이프라인 구성에서 두 지표의 상관은 **Pearson r = −0.01(p = 0.91)**이었습니다(그림 7). 구성의 5%는 충실도는 높고 검색은 낮았으며, 6%는 그 반대였습니다. 벤치마크별로 나눠 봐도 상관이 0에 가까워, 여러 벤치마크를 합쳐서 생긴 착시가 아니라고 합니다.

각 지표를 좌우하는 단계도 다릅니다(그림 3, 보정하지 않은 주변 η², 즉 해당 요인이 설명하는 분산 비율).

| 지표 | 영향이 큰 단계 | 영향이 작은 단계 |
|---|---|---|
| 검색(NDCG@10, 167개 구성) | 임베딩 0.164, 보강 0.144, 재순위화 0.090 | 압축, 에이전트 게이트 (각 0.01 미만) |
| 충실도(RAGAS, 122개 구성) | 질의 증강 0.224, 에이전트 게이트 0.217 | 임베딩, 보강 (각 0.02 미만) |

검색에서 다중 비교 보정을 통과한 상호작용은 임베딩×보강(0.102)과 임베딩×재순위화(0.110) 두 개로, 모두 임베딩 모델이 관련됩니다. 임베딩이 이미 좋은 후보를 가져오면 재순위화가 도울 여지가 줄어든다는 해석입니다. 흥미롭게도 MMR은 평균적으로 NDCG@10을 3.6% 낮췄습니다(표 44). 저자들은 특정 도메인 코퍼스에서는 서로 비슷한 문단이 사실 같은 근거인 경우가 많아, MMR의 다양성 벌점이 오히려 좋은 근거를 밀어낸다고 추정합니다.

### 4. 모든 지표에서 이기는 구성은 없다

SQuAD v2, MuSiQue, HotpotQA 혼합 데이터에서 시드 3개로 비교한 네 가지 운영 프로필 결과입니다(표 2, GPT-5.1 심사).

| 프로필 | NDCG@10 | 충실도 | 평균 지연(초) | HV(30초 기준) |
|---|---|---|---|---|
| standard | **0.860** | 0.739 | 5.30 | **0.523** |
| balanced | 0.840 | 0.911 | 12.25 | 0.453 |
| max-reliable | 0.804 | **0.916** | 14.16 | 0.389 |
| speed | 0.541 | 0.524 | **0.70** | 0.277 |

speed는 MiniLM-L6 임베딩과 dense 검색만 쓰는 가장 가벼운 구성이고, standard는 BGE-M3, hybrid 검색, mxbai 재순위화, HyDE를 쓰되 직접 생성 경로로 답합니다. balanced와 max-reliable은 검증을 세 번까지 반복하는 에이전트 경로입니다(부록 I.1).

가장 무거운 max-reliable은 balanced보다 충실도가 0.005 높을 뿐, NDCG@10은 4.5% 낮고 지연은 더 깁니다. 논문은 **강한 검색 스택 위에 에이전트 루프를 더하면 충실도 이득은 미미한 반면 검색 품질과 지연은 나빠진다**고 정리합니다. 저자들은 100K~200K 문서의 다른 세 벤치마크에서도 가벼운 파이프라인이 비슷한 품질을 10~20배 낮은 지연으로 유지했다고 보고합니다(부록 D.8, 사후 분석).

생성 모델을 바꾼 실험(부록 F.9)도 같은 방향입니다. 검색 결과는 그대로 두고 답변 모델만 GPT-5.1에서 Claude Sonnet 4.5로 바꾸자 모든 프로필의 충실도가 올랐는데, 상승폭은 speed가 +0.184로 가장 컸고 balanced는 +0.027(유의하지 않음)이었습니다. **생성 모델이 강할수록 무거운 파이프라인이 사 주는 이득은 줄어든다**는 뜻입니다. 한편 standard와 balanced의 순위는 두 생성 모델 사이에서 뒤바뀌었습니다.

### 5. 코퍼스가 커지면 1등이 바뀐다

5K에서 200K 문서까지 늘리면 NDCG@10은 두 무리로 갈립니다(그림 4a). speed와 standard는 로그 선형으로 떨어지고, balanced와 max-reliable은 거의 평평합니다. standard는 5K와 15K에서 1등이지만 25K부터는 balanced가 앞서고, **200K에서는 balanced가 standard보다 13.7% 높습니다(p = 0.003)**. 저자들은 balanced의 넓은 청크 유지, hierarchical 분할, 검색 후 병합이 방해 문서가 늘어도 상위 k개의 밀도를 지켜 준다고 해석합니다.

충실도는 다르게 움직였습니다. 품질 중심 세 프로필 모두 50K에서 정점, 100K에서 하락, 200K에서 회복했습니다(그림 4b). 코퍼스가 커지면 정답 문서가 상위 k개에서 밀려나도 비슷한 내용을 담은 다른 문서가 근거가 되어 준다는 가설입니다.

### 그 밖의 실무적 관찰 (표적 실험 138개, 부록 F)

- **청커 선택**만으로 20개 구성 사이에서 NDCG@10이 0.126(상대 36%) 차이 났습니다. 대부분의 요인 설계 주효과보다 큽니다(표 55).
- 2019년 MS-MARCO MiniLM-L6 cross-encoder가 시험한 최근 재순위화 모델 4종보다 순위가 높았습니다(표 51). 저자들은 학습 데이터가 실험 도메인과 잘 맞았을 가능성을 추측으로 제시합니다.
- BGE-M3를 Matryoshka 방식으로 768차원으로 자르자 벡터 저장·검색 비용이 25% 줄면서 NDCG@10은 2.3% 올랐습니다(표 52).
- 충실도는 환각 검사와 답변 품질 게이트를 **끈** 상태에서 가장 높았습니다. 한 다중 홉 예제에서는 게이트가 촉발한 정제 과정이 근거 청크 15개 중 14개를 지워 버렸습니다(표 54).
- HyDE는 NDCG@10을 3.1% 올리지만 첫 검색 지연을 두 배로 늘려, 지연을 반영한 이득은 0.9%에 그쳤습니다.

## 한계

**저자가 밝힌 한계 (Limitations 절, 부록 A.6)**

- 영어로 구성한 다중 도메인 테스트베드 하나만 썼고, 실험당 검색 질의 93개 이하, 생성 질의 200개 이하입니다. 다국어, 실제 기업 데이터, 오픈 가중치 생성 모델은 시험하지 않았습니다. 주요 결과는 모두 상용 API 모델에 의존합니다.
- 방해 문서도 같은 5개 도메인에서 뽑았습니다. 사후 감사(100쌍)에서 부분 관련 비율이 9%로 나와, 저자들은 규모에 따른 성능 하락을 **상한으로 읽어야** 한다고 적었습니다.
- 계획 대비 축소가 많습니다. 242개 중 167개 구성(69%)만 실행했고, 구성당 질의는 사전 계획 2,300개에서 93개로, 확증 실험 E1은 200개에서 43개로 줄었습니다. 이유는 GPT-5.1 API 사용량 제한입니다. 사전 계획의 MS MARCO와 CUAD는 라이선스 문제로 다른 데이터셋으로 바뀌었습니다.
- 충실도 절댓값은 심사 모델에 따라 달라집니다. Claude Opus 4.7과 기본 심사자의 일치도는 Pearson r = 0.44, Cohen's κ = 0.35로 중간 수준이라, 저자들은 핵심 주장을 절댓값이 아닌 순위 비교에 둡니다. 원시 충실도가 답변 길이의 영향을 받는다는 점도 확인했습니다.
- 구성 요소 목록은 2026년 1월 시점 스냅샷입니다.

**읽으면서 발견한 한계 (필자의 판단)**

- 제목급 수치(+47% 대 +17%)는 검색 지표 하나에서 나온 것이고, 사전에 정한 H1 판정 기준(충실도 분산의 20%)은 충족되지 않았습니다. 초록만 읽으면 "구성 요소는 합쳐지지 않는다"가 모든 지표에 해당하는 것처럼 보이지만, 본문은 **검색에서는 크게 손해, 충실도에서는 거의 가산적**이라는 갈라진 결론입니다.
- "450개 구성"은 요인 설계 167개, 비요인 실험 138개, 규모·프로필 실험을 합친 표현으로 보이며, 본문에서 정확한 합산 내역을 한곳에 제시하지는 않습니다. 실험마다 질의 수와 시드 수도 달라(표 3), 같은 450개가 같은 조건에서 비교된 것은 아닙니다.
- 본문과 부록의 일부 수치 표기가 조금씩 다릅니다. 예를 들어 200K 순위 역전의 p값이 본문에서는 0.003(짝지은 t 검정), 부록 표 12에서는 Welch t 검정 0.004이고, balanced의 지연 개선이 13%와 13.5%로 함께 나옵니다. 결론을 바꿀 정도는 아니지만 인용할 때는 표 번호를 함께 적는 편이 안전합니다.
- 프레임워크는 2026-10-21에 첫 릴리스된 0.1.0 버전이고, README 스스로 "LangChain, LlamaIndex처럼 수년간의 운영 경험이 없는 첫 릴리스"라고 밝힙니다.

## 인사이트

**왜 지금 중요한가.** RAG 논문과 기술 블로그는 대개 "기법 X를 넣었더니 몇 퍼센트 좋아졌다"는 형식입니다. 실무자는 이런 숫자를 모아 재순위화, HyDE, 문서 인식 접두어, 에이전트 루프를 차례로 쌓고 이득이 누적되리라 기대합니다. 이 논문은 그 기대가 검색 지표에서는 체계적으로 빗나간다는 것을 수치로 보였습니다. 중앙값 기준으로도 예상 이득의 41%가 사라지고, 다섯 기법을 모두 쌓으면 72%가 사라집니다. 필자의 판단으로는 이 결과의 진짜 메시지는 "어떤 기법이 좋다"가 아니라 **"한 기법의 이득은 그것이 놓인 스택의 속성"**이라는 점입니다. 같은 재순위화 모델도 임베딩이 약할 때는 크게 돕고, 임베딩이 강하면 할 일이 줄어듭니다(임베딩×재순위화 상호작용).

**실무에 주는 의미.** 사내 RAG를 개선하는 팀이라면 세 가지를 바로 바꿀 수 있습니다.

1. **비교 기준을 "현재 운영 스택"으로 둡니다.** 새 기법은 빈 기준선이 아니라 지금 쓰는 파이프라인 위에서 켜고 끄며 재야 합니다. 논문 저자들이 말하는 "주변 스택 전체로 시험하라"는 요구는 연구자뿐 아니라 운영 팀에도 그대로 적용됩니다.
2. **검색 지표와 답변 충실도를 따로, 둘 다 봅니다.** 두 지표의 상관이 사실상 0이므로, 검색 평가(NDCG, recall)만으로 RAG 개선을 판정하면 답변 품질에 대해서는 아무것도 알 수 없습니다. 반대로 LLM 심사 점수만 보면 검색이 나빠진 것을 놓칩니다. 블로그의 [LLM 평가 글](/tech/2026/10/24/llm-evals.html)에서 다룬 것처럼, 심사 모델을 바꾸면 절댓값이 흔들리므로 순위 비교와 사람 검수를 함께 두는 편이 안전합니다.
3. **목표 규모에서 다시 잽니다.** 5K 문서로 만든 PoC에서 고른 구성이 운영 규모에서 뒤처질 수 있습니다. 논문에서는 역전이 15K~25K 사이에서 일어났습니다. 도입 전에 실제 코퍼스 크기나 그에 가까운 방해 문서를 섞어 다시 평가하는 단계를 일정에 넣어야 합니다.

덧붙여 "무거울수록 좋다"는 직관도 재검토할 만합니다. 30초 기준 하이퍼볼륨에서 가장 좋은 것은 에이전트 루프가 없는 standard였고, 품질 게이트를 끈 쪽이 충실도가 더 높았으며, 생성 모델이 강할수록 무거운 파이프라인의 이득은 줄었습니다. 에이전트식 검증 루프는 비용과 지연이 확실히 늘어나는 반면 이득은 스택과 모델에 따라 거의 없을 수 있으므로, 켜기 전에 반드시 같은 스택에서 A/B로 확인할 대상입니다.

**블로그의 기존 글과의 연결.** RAG의 출발점은 같은 날 올린 [RAG 원 논문 소개](/papers/2026/10/24/rag.html)에서 다뤘습니다. 2020년의 RAG가 질의 인코더와 생성기를 함께 미세조정하는 하나의 모델이었다면, 지금의 RAG는 8단계짜리 조립식 시스템이 되었고, 이 논문은 그 조립이 부품의 단순 합이 아니라는 것을 보여 줍니다. 원 논문이 검색과 생성을 한 목적 함수로 함께 학습했다는 점을 떠올리면, 부품을 따로 고르는 현재 관행이 잃어버린 것이 무엇인지 보입니다.

**한계와 반론.** 결론의 일반성은 조심해서 받아들여야 합니다. 테스트베드는 영어 5개 도메인을 섞은 것 하나이고, 질의 수는 실험당 수십 개 수준이며, 생성과 심사 모두 상용 모델입니다. 특히 MMR이 손해였다거나 2019년 재순위화 모델이 최신 모델보다 낫다는 결과는 저자들도 "도메인이 좁아서일 수 있다"고 추측하는 만큼, 한국어 문서나 이질적인 사내 문서에 그대로 옮기면 안 됩니다. 이 논문에서 가져갈 것은 개별 수치보다 **방법론**입니다. 또 하나, 분석에 쓴 질의별 원점수와 설계 행렬이 공개 저장소에 없어 제3자가 표를 그대로 재현하기는 어렵습니다. 저장소가 공개한 것은 프레임워크와 BEIR 재현 결과이고, 논문 수치 자체의 재현 자료는 아닙니다.

**앞으로 지켜볼 점.** (1) 새 RAG 기법 논문들이 LASAGNA 같은 전체 스택 평가를 실제로 채택하는지. 저자들은 이를 "보고 표준"으로 만들자고 제안합니다. (2) 다국어, 대규모(1M 이상), 오픈 가중치 생성 모델에서도 검색 쪽 손실과 규모 역전이 재현되는지. (3) 저자들이 요청 시 제공한다는 원자료가 공개되어 독립 재분석이 나오는지. 세 번째가 나오기 전까지는 "+47%가 +17%로"라는 숫자를 정밀한 상수가 아니라 방향성 증거로 읽는 것이 적절해 보입니다.

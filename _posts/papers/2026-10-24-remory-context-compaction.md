# [논문 소개] Remory: 컨텍스트 컴팩션 요약 뒤에 학습된 '잔차 메모리'를 붙이다

- **논문:** *REMORY: Learning Residual Memory for Context Compaction*
- **저자:** Hanchen Xia, Baoyou Chen, Yutang Ge 외 (총 8명). 논문에 표기된 소속은 Fudan University, Shanghai Jiao Tong University, University of Michigan, The Chinese University of Hong Kong, Alibaba Group, Nanjing University, Shanghai Academy of AI for Science, Shanghai Innovation Institute입니다(저자별 대응은 HTML 판에서 명확하지 않아 묶어서 적습니다).
- **공개:** 2026년 10월 8일 v1, 10월 21일 v3, arXiv:2610.11287 (cs.CL). 학회 발표 여부는 확인되지 않았습니다.
- **링크:** [arXiv](https://arxiv.org/abs/2610.11287) · [PDF](https://arxiv.org/pdf/2610.11287) · [HTML(v3)](https://arxiv.org/html/2610.11287v3) · [코드](https://github.com/1ring2rta/Remory)
- **현황 (2026-10-24 기준):** GitHub 스타 425개, 코드와 메모리 체크포인트 모두 MIT 라이선스, Hugging Face Papers 업보트 62개. 실행에는 README 기준 80GB GPU 2장 이상이 필요합니다.

## 한 줄 요약

**컴팩션(compaction, 길어진 대화 이력을 요약으로 바꿔 컨텍스트를 비우는 일) 때 텍스트 요약만 남기지 말고, 요약을 보고 "요약이 놓친 부분"을 메우도록 학습한 소프트 토큰(soft token, 단어가 아닌 연속 벡터로 된 입력)을 뒤에 붙이자는 논문입니다.** 모델 가중치는 그대로 두고 1.5~1.9B 규모의 별도 메모리 네트워크만 학습해, 입력 위치 5.2%로 풀 컨텍스트에 가까운 점수를 냈다고 보고합니다.

## 왜 이 연구가 필요한가

Claude Code와 Codex CLI의 `/compact`처럼, 오늘날 장기 실행 에이전트는 컨텍스트가 차면 이전 상호작용을 텍스트 요약으로 바꾸고 그 요약에서 다시 일을 이어 갑니다. 논문은 이때 입력 길이가 "늘었다가 컴팩션에서 뚝 떨어지고 다시 느는" 톱니 모양을 그린다고 설명합니다(그림 2a).

문제는 요약이 주된 흐름을 보존해도 **이후 모든 결정을 뒷받침한다는 보장은 없다**는 점입니다. 어떤 정보가 나중에 필요할지는 일이 진행되면서 바뀌고, 저자들은 "요약 밖에 필요한 정보를 미리 식별하거나 나열할 수 있다고 가정하지 않는다"고 못 박습니다. 그렇다고 이력을 전부 컨텍스트에 남길 수는 없으니, 질문은 "활성 창에 전체를 두지 않으면서 이전 컨텍스트에 대한 쓸 만한 접근을 어떻게 유지하나"가 됩니다.

저자들은 해마 색인 이론(hippocampal indexing theory, 부분 단서가 색인을 활성화해 피질에 분산된 기억을 되살린다는 이론)을 비유로 듭니다. 읽을 수 있는 명시적 체크포인트(요약)와 학습된 신경 표현(소프트 토큰)을 짝지어 쓰자는 발상입니다.

## 제안 방법

### 잔차 메모리: 요약 + 소프트 토큰

컴팩션 경계 *i*에서 이력 *H_i*(직전 요약과 잔차 메모리, 그 뒤의 상호작용)와 새 요약 *S_i*가 주어지면, 메모리 네트워크가 메모리 *M_i*를 만듭니다(식 1).

- *M_i = C_φ(H_i; S_i)*, 길이는 최대 *m*으로 제한
- *M_i*는 고정된 LLM(논문 용어로 actor)의 **입력 임베딩 공간의 벡터열**입니다. 단어로 디코딩되지 않습니다.
- 모델은 "고정 지시문 → [요약; 메모리] → 새 상호작용" 순서로 읽습니다.

메모리가 요약을 조건으로 만들어지고 요약 바로 뒤에 붙기 때문에, 저자들은 이를 "시퀀스 차원에서의 잔차 연결(residual connection)"에 빗대 **잔차 메모리**라 부릅니다. 요약이 주 신호이고 메모리는 그 차이를 보정하는 역할입니다. 다음 컴팩션 때는 이전 요약과 메모리도 *H_i*에 들어가므로, 정보가 여러 번의 경계를 건너 이어질 수 있습니다. 원문 기록이 필요하면 기존처럼 아카이브·파일 검색 도구로 꺼냅니다. 즉 Remory는 검색을 대체하지 않고 요약과 검색 사이를 메우는 세 번째 채널입니다.

### 네트워크 구조

| 항목 | 내용 (2.1절) |
|---|---|
| 입력 | 고정 actor의 내부 특징(feature)과 학습된 쿼리, 요약에 대한 게이트 교차 어텐션 |
| 압축률 | 소스 위치 최대 1,024개 블록마다 소프트 토큰 64개 |
| 상한 | 계층적 압축으로 최종 메모리를 4,096 슬롯 이하로 제한, 소스 순서 유지 |
| Qwen3.8-27B용 | DFlash 구조를 변형, 학습 파라미터 1.94B |
| GLM-5.3-Flash용 | DFlash-2(그룹 동적 합성곱), 학습 파라미터 1.502B |

DFlash는 원래 추측 디코딩(speculative decoding)용 드래프트 모델 구조인데, 이를 메모리 인코더로 가져다 쓴 점이 흥미롭습니다. actor의 기울기를 통해 학습하지만 actor의 가중치는 바뀌지 않습니다.

### 2단계 학습: 고정된 actor를 통해 배우기

교사와 학생이 **같은 고정 모델**을 공유하고, 입력만 다릅니다.

| 단계 | 교사 입력 | 학생 입력 | 목표 | 데이터 |
|---|---|---|---|---|
| I. 재구성 | 원문 + "그대로 반복하라" | 원문 대신 소프트 메모리 + 같은 지시 | 원문 텍스트 예측 | MMFineReason-Full-2.3M의 텍스트 필드 |
| II. 요약 조건 이어쓰기 | 원래 상호작용 이력 전체 | 고정된 요약 + 그 이력으로 만든 메모리 | 같은 다음 assistant 응답 예측 | Open-PerfectBlend 프롬프트 등 추론·코딩 궤적, Qwen 생성 응답, 앞 컨텍스트 길이 순 커리큘럼 |

손실은 학생에서 교사로의 **역 KL 발산**(reverse KL, 식 3)이며, 전체 어휘와 응답 전체에 걸쳐 계산하고 앞쪽 위치에 약간 더 가중치를 둡니다. 메모리 인코더는 미래 응답을 보지 못합니다. II단계에서는 요약이 이미 주어지므로 메모리는 자연스럽게 "요약만으로는 남는 예측 차이"를 메우는 쪽으로 학습되며, 저자들은 메모리가 누락된 사실을 모두 재구성할 필요는 없다고 적습니다. 그림 3(d)는 I단계로 초기화한 경우가 무작위 초기화보다 II단계에서 교사·학생 top-1 일치도가 높게 오르는 학습 곡선을 보여 줍니다.

## 실험 설정

| 구분 | 내용 |

| actor | Qwen3.8-27B(컨텍스트 262,144 위치), GLM-5.3-Flash(320B 파라미터, 100만 위치) |
| 하네스 | Codex CLI. 비교 쌍마다 가중치, 프롬프트, 도구, 디코딩, 예산, 컴팩션 정책을 고정하고 양쪽 모두 원문 이력 검색 가능 |

비용은 2026년 9월 공급자 비캐시 단가로 actor와 요약 토큰을 계산한 "API 환산 USD"이며, 잔차 위치를 입력으로 셉니다. **메모리 네트워크 실행과 소스 특징 인코딩, 도구 비용은 빠져 있습니다.**

## 주요 결과

### 1. SummHay: 커버리지는 그대로, 출처 표시가 좋아졌다 (표 1)

| 표현 | 커버리지 | 인용 F1 | 종합 점수 | 평균 입력 위치 |
|---|---|---|---|---|
| 원문 전체 | 72.46 | 56.60 | 43.41 | 96,872 |
| 요약만 | 67.55 | 56.98 | 39.84 | 1,393 |
| 요약++ (같은 추가 예산을 텍스트로) | 67.52 | 56.94 | 39.78 | (메모리와 같은 예산) |
| 요약 + Remory | 67.95 | 61.03 | 43.39 | 5,024 |

메모리를 붙이면 인용 F1이 4.04점, 종합 점수가 3.55점 오르고 커버리지 변화는 0.40점에 그칩니다. 종합 점수 상승의 95% 부트스트랩 구간은 [+0.74, +6.21]입니다. 두 요약 조건이 모두 맞힌 553개 인사이트만 봐도 인용 F1이 57.31에서 61.41로 오릅니다. 저자들은 이를 "메모리가 사실을 더 기억하게 한다기보다, 복원한 주장을 근거와 **연결**하게 돕는다"는 연상적 해석으로 읽습니다.

눈여겨볼 대조군은 "요약++"입니다. 같은 수의 추가 위치를 생성 텍스트로 채우면 요약만 쓴 경우와 거의 같았습니다. 즉 이득은 "자리를 더 줘서"가 아니라 "학습된 표현이어서" 생긴 것이라는 주장입니다. 요약 + 메모리의 입력은 원문 위치의 5.2%이고, 종합 점수는 원문 전체(43.41)에 0.02점 차까지 다가갔습니다. 다만 커버리지는 여전히 원문보다 4.5점 낮고, 인용 F1이 오히려 원문보다 높아 종합 점수가 맞춰진 구성이라는 점은 함께 봐야 합니다.

### 2. 에이전트 벤치마크: 같은 actor에서 일관된 상승 (표 2, 표 3)

| actor | 벤치마크 | 잔차 없음 | 잔차 있음 | 비용(과제당, 없음→있음) |
|---|---|---|---|---|
| Qwen3.8-27B | AutomationBench (5회 평균±표준편차) | 35.5 ± 1.3 | 45.3 ± 1.0 | $0.59 → $0.53 |
| Qwen3.8-27B | JobBench (5회) | 33.4 ± 1.25 | 41.0 ± 1.41 | $3.09 → $3.21 |
| Qwen3.8-27B | Terminal-Bench 2.1 (1회) | 71.9 | 76.4 | $4.29 → $2.86 |
| Qwen3.8-27B | BrowseComp (1회) | 74.0 | 77.0 | $5.39 → $4.69 |
| GLM-5.3-Flash | Terminal-Bench 2.1 (1회) | 84.3 | 87.6 | $3.27 → $3.05 |
| GLM-5.3-Flash | BrowseComp (1회) | 84.9 | 89.0 | $5.65 → $5.00 |

Qwen은 AutomationBench +9.8, JobBench +7.6, Terminal-Bench +4.5, BrowseComp +3.0점, GLM은 Terminal-Bench +3.3, BrowseComp +4.1점입니다. 컨텍스트 창이 더 크고 강한 GLM에서도 이득이 유지됐다는 점을 저자들은 강조합니다. 그림 1의 회색 막대(공개된 프런티어 모델 점수)는 원래 하네스와 프로토콜로 측정한 값이라 **통제된 비교가 아니라고** 논문 스스로 밝힙니다.

### 3. 반복 도구 호출과 오류가 크게 줄었다 (표 3)

| actor·벤치마크 | 반복 출력 (없음→있음) | 도구 오류 (없음→있음) |
|---|---|---|
| Qwen · Terminal-Bench | 459 → 377 | 933 → 568 |
| Qwen · BrowseComp | 25,801 → 18,105 | 25,244 → 12,698 |
| GLM · Terminal-Bench | 334 → 240 | 664 → 496 |
| GLM · BrowseComp | 8,316 → 5,834 | 7,498 → 5,412 |

네 조합에서 반복 출력은 17.9~29.8%, 오류는 25.3~49.7% 줄었습니다. "반복"은 한 과제 안에서 같은 도구가 같은 출력을 낸 횟수(계획·폴링 제외)입니다. 컴팩션 뒤 이미 해 본 명령을 다시 실행하거나 이미 실패한 방법을 또 시도하는 것은 요약 기반 에이전트에서 흔한 낭비인데, 이를 직접 줄였다는 점이 실무적으로 가장 와닿는 결과로 보입니다. 다만 궤적 전체의 행동과 길이가 달라지므로 인과를 단정할 수는 없다고 저자들도 적습니다.

### 4. 컴팩션 직후 첫 행동 비교 (3.3절)

Qwen BrowseComp 궤적 100개에서 뽑은 488쌍의 "컴팩션 직후 다음 행동"을, 요약과 고정 프롬프트를 같게 두고 GPT-5.6-Sol이 익명으로 비교했습니다. 잔차 메모리 쪽이 345승(70.7%), 21무(4.3%), 122패(25.0%)였습니다. 이는 제안된 행동에 대한 판정이지, 그 행동을 실제로 실행한 결과를 잰 것은 아닙니다.

### 5. 사례: 실시간 모의 투자와 세포 분할 (3.4절)

- **Live Trading:** 같은 컨텍스트 정책의 Qwen 모의 투자 계좌 두 개를 동시에 돌려, 9월 23일 기준 정산 ROI가 잔차 없음 −11.86%, 있음 +5.11%였습니다(초기 자금 2만 달러). 생성 비용은 $303.81 대 $170.30, 응답 수는 5,336 대 3,013, 컴팩션은 56회 대 45회입니다. 저자들은 두 계좌의 종목 선택과 시점이 달라 수익 비교에 한계가 있다고 밝힙니다.
- **Cell segmentation (Terminal-Bench):** 리팩터링 중 헬퍼 함수를 지운 뒤 컴팩션이 일어났고, 요약에는 오류와 백업 정보는 남았지만 정확한 편집 명령은 빠졌습니다. 메모리를 가진 actor는 두 파일을 다시 읽고 헬퍼를 복원해 검증 테스트 9개를 모두 통과했습니다. 다만 누락된 정보가 메모리에서 왔는지는 입증하지 않는다고 저자들이 명시합니다.

## 한계

**저자가 밝힌 한계**

- 비용 추정은 토큰 가격 기반 생성 비용이며, 메모리 네트워크 실행과 인코딩 비용은 빠져 있습니다.
- 그림 1의 프런티어 비교는 통제된 비교가 아닙니다.
- 첫 행동 비교는 판정일 뿐 실제 결과가 아니고, 사례 연구는 메모리의 기여를 입증하지 않습니다.

**읽으면서 발견한 한계 (필자의 판단)**

- **Terminal-Bench와 BrowseComp는 설정당 1회 실행입니다.** 5회 실행한 AutomationBench·JobBench와 달리 분산이 보고되지 않아, 3~4점 차이가 실행 간 편차보다 큰지 이 표만으로는 알 수 없습니다.
- **심사 모델 의존.** SummHay, BrowseComp, JobBench, 첫 행동 비교가 모두 GPT-5.6-Sol 판정에 기댑니다. 교차 심사 결과는 본문에 없습니다.
- **SummHay는 Qwen만, 도구 없이** 측정했습니다. GLM이나 도구가 있는 환경에서의 출처 표시 효과는 확인되지 않았습니다.
- **모델마다 메모리 네트워크를 따로 학습해야 합니다.** 메모리가 특정 actor의 입력 공간 벡터이므로 actor가 바뀌면 다시 학습해야 하고, API로만 쓰는 폐쇄형 모델에는 적용할 수 없습니다. 임베딩 입력과 내부 특징 접근이 필요하기 때문입니다.
- **읽을 수 없는 기억.** 소프트 토큰은 사람이 검사할 수 없습니다. 요약은 사용자가 읽고 고칠 수 있지만, 메모리가 잘못된 정보를 담았는지는 확인할 방법이 논문에 없습니다.
- README에 따르면 공개된 GLM 체크포인트(1.24B)는 논문의 1.502B 인코더와 다릅니다. 공개 체크포인트로 표 3의 GLM 수치를 그대로 재현할 수 있는지는 확인되지 않았습니다.

## 인사이트

**컴팩션 전략 세 갈래 비교.** 장기 에이전트가 이력 한도를 다루는 방식은 크게 세 가지로 나눠 볼 수 있습니다.

| 방식 | 무엇을 남기나 | 장점 | 약점 |
|---|---|---|---|
| 텍스트 요약 (`/compact`) | 사람이 읽는 요약 | 어떤 모델에도 적용, 검사·수정 가능 | 무엇을 버릴지 미리 정해야 함 |
| 학습된 소프트 토큰 (Gist Tokens, ICAE, Remory) | 연속 벡터 | 같은 자리에 더 많은 신호 | 모델별 학습, 오픈 가중치 필요, 해석 불가 |
| 캐시 조작 (프롬프트 캐싱, KV 캐시 축출·재사용) | 계산 결과 그 자체 | 정보 손실 없이 비용·지연 절감(캐싱의 경우) | 창 크기 한계 자체는 못 넘음, 축출 시 손실 |

표의 세 번째 행은 일반적으로 알려진 특징 기준입니다. Remory가 흥미로운 이유는 첫째와 둘째를 **대체가 아니라 합성**했다는 점입니다. 이전 소프트 토큰 연구(AutoCompressors, Gist Tokens, ICAE)는 긴 텍스트 자체를 벡터로 바꾸려 했고, 그래서 "요약보다 나은가"라는 경쟁 구도였습니다. Remory는 요약을 그대로 두고 "요약이 남긴 예측 오차"만 학습 목표로 삼아, 읽을 수 있는 체크포인트라는 실무적 장점을 잃지 않습니다. 요약++ 대조군이 보여 주듯 같은 자리를 텍스트로 채우는 것으로는 이 효과가 나지 않았다는 점도 이 설계를 뒷받침합니다.

**실무에 주는 의미.** 오픈 가중치 모델을 자체 서빙하며 장기 에이전트를 돌리는 팀이라면 검토할 만합니다. README의 `Harness.compact`는 "요약 생성 → 잔차 메모리 인코딩 → 새 체크포인트 반환"을 한 메서드로 묶어 두었고, 이미 요약을 만드는 하네스라면 `on_compact(..., summary=summary)`로 메모리만 덧붙일 수 있다고 안내합니다(필자는 실행해 보지 않았습니다). 반대로 폐쇄형 API 모델을 쓰는 팀에게 당장 쓸 수 있는 기법은 아닙니다. 그런 팀이 가져갈 교훈은 오히려 측정 방식입니다. **컴팩션 품질을 "반복 도구 호출 수"와 "컴팩션 직후 첫 행동"으로 재 보는 것**은 어떤 요약 프롬프트를 쓰든 적용할 수 있는 지표입니다.

**블로그의 다른 글과의 연결.** 같은 날 소개한 [컨텍스트 엔지니어링](/tech/2026/10/24/context-engineering.html) 글이 컨텍스트에 무엇을 넣고 뺄지 정하는 일을 다룬다면, Remory는 "빼야 할 때 무엇을 어떤 형태로 남기나"에 대한 학습 기반 답입니다. [에이전트 캐시 엔지니어링](/papers/2026/10/24/cache-engineering-agents.html)이 다루는 캐시 쪽 접근과는 보완 관계로 보입니다. 요약과 메모리가 바뀌는 컴팩션 경계에서는 그 뒤의 프리픽스 캐시가 무효화되기 때문입니다. 컨텍스트를 아예 가중치로 옮기는 [Cortex](/papers/2026/10/24/cortex-parametric-memory.html)와 비교하면, Remory는 actor를 고정하고 입력 쪽에 기억을 두는 반대편 끝에 서 있습니다. 가중치를 건드리지 않으니 망각이나 업데이트 문제는 적지만, 대신 컴팩션 때마다 메모리를 새로 인코딩하는 비용을 냅니다.

**앞으로 지켜볼 점.** (1) Terminal-Bench·BrowseComp를 여러 번 실행한 분산과 다른 심사 모델에 의한 교차 검증. (2) 메모리 네트워크 실행 비용을 포함한 총 비용. 1.5~1.9B 네트워크가 컴팩션마다 이력 전체를 인코딩하는 비용이 토큰 절감분을 얼마나 상쇄하는지가 도입 판단의 핵심입니다. (3) README가 2026-10-18 추가했다고 밝힌 온라인 학습(`/remory train`)이 실제로 세션별 적응 효과를 보이는지. 이것이 검증되면 Remory는 "컴팩션 기법"을 넘어 Cortex 같은 파라메트릭 기억과 입력 쪽 기억의 중간 형태가 됩니다.

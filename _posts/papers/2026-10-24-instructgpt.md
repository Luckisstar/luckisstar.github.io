# [논문 소개] InstructGPT: 사람 피드백으로 1.3B 모델이 175B GPT-3를 이기게 만든 RLHF

- **논문:** *Training language models to follow instructions with human feedback*
- **저자:** Long Ouyang, Jeff Wu, Xu Jiang 외 (총 20명), OpenAI
- **공개:** 2022년 3월 4일, arXiv:2203.02155 (cs.CL, cs.AI, cs.LG), NeurIPS 2022 게재
- **링크:** [arXiv](https://arxiv.org/abs/2203.02155) · [PDF](https://arxiv.org/pdf/2203.02155) · [NeurIPS 2022 프로시딩](https://proceedings.neurips.cc/paper_files/paper/2022/hash/b1efde53be364a73914f58805a001731-Abstract-Conference.html) · [모델 카드·샘플 저장소](https://github.com/openai/following-instructions-human-feedback) (2026-10-24 기준 보관(archived) 상태)

## 한 줄 요약

**사람이 쓴 시범 답변과 사람이 매긴 순위로 GPT-3를 미세조정하면, 파라미터가 100배 이상 적은 1.3B 모델의 답이 175B GPT-3의 답보다 더 선호된다는 것을 보인 논문입니다.** 지도 미세조정(SFT), 보상 모델(RM), PPO 강화학습으로 이어지는 이 논문의 3단계 레시피는 이후 "RLHF"라고 하면 떠올리는 표준 절차가 됐고, 대화형 어시스턴트의 후학습(post-training) 방식에 큰 영향을 남겼습니다.

## 왜 이 연구가 필요한가

GPT-3 같은 대형 언어 모델은 인터넷 문서의 다음 토큰을 맞히도록 학습됩니다. 저자들은 이 목표가 "사용자의 지시를 도움이 되고 안전하게 따른다"는 목표와 다르다고 지적하며, 이런 상태를 언어 모델링 목표가 **어긋나 있다(misaligned)**고 표현합니다(1절). 그 결과 모델은 사실을 지어내고, 편향되거나 유해한 글을 쓰고, 지시를 그냥 무시하기도 합니다. 초록의 첫 문장이 이 논문의 문제의식을 요약합니다. "언어 모델을 키운다고 해서 사용자의 의도를 더 잘 따르게 되지는 않는다."

당시 지시를 따르게 만드는 대표적인 방법은 FLAN, T0처럼 공개 NLP 데이터셋 수십 개에 지시문을 붙여 미세조정하는 것이었습니다. 이 논문은 다른 질문을 던집니다. 공개 벤치마크가 아니라 **실제 사용자가 API에 보내는 요청**을 기준으로, 사람의 선호를 직접 학습 신호로 쓰면 어떻게 되는가. 저자들은 Askell 외(2021)를 따라 정렬된 모델의 조건을 도움이 됨(helpful), 정직함(honest), 해롭지 않음(harmless)으로 정의하고 이를 사람 평가로 측정합니다.

RLHF(사람 피드백 기반 강화학습, Reinforcement Learning from Human Feedback) 자체는 새 기법이 아닙니다. 원래 시뮬레이션 로봇과 Atari 게임에서 개발됐고(Christiano 외, 2017), 요약 과제에 적용된 적이 있습니다(Stiennon 외, 2020). 이 논문의 기여는 이 기법을 **요약 하나가 아니라 생성, 질의응답, 브레인스토밍, 대화 등 넓은 실사용 과제 분포**에 적용하고, 그 효과와 대가를 체계적으로 측정했다는 데 있습니다.

## 제안 방법

방법은 세 단계입니다(3.1절, 그림 2). 출발점은 사전학습된 GPT-3입니다.

**1단계. 시범 데이터로 지도 미세조정(SFT, Supervised Fine-Tuning)**

라벨러가 프롬프트에 대한 "바람직한 답"을 직접 씁니다. 이 시범 답변으로 GPT-3를 지도학습합니다. SFT 기준 모델은 16 에포크를 학습했는데, 검증 손실 기준으로는 1 에포크 뒤부터 과적합이 시작됐지만 더 오래 학습할수록 보상 모델 점수와 사람 선호도는 계속 좋아졌다고 합니다(3.5절). 그래서 최종 모델 선택도 검증 손실이 아니라 보상 모델 점수로 했습니다.

**2단계. 비교 데이터로 보상 모델(RM, Reward Model) 학습**

한 프롬프트에 대해 모델이 낸 답 K개(K=4~9)를 라벨러가 좋은 순서로 줄 세웁니다. K개를 순위로 매기면 두 개씩 짝지은 비교가 K(K-1)/2개 생깁니다. 보상 모델은 프롬프트와 답을 받아 점수 하나(스칼라)를 내는 모델이고, "선호된 답의 점수가 덜 선호된 답의 점수보다 높을 확률"을 최대화하도록 학습합니다(식 1). 수식으로는 두 점수 차이에 시그모이드를 씌운 값의 로그를 키우는 것입니다.

여기에 실무적으로 중요한 요령이 하나 있습니다. 같은 프롬프트에서 나온 비교쌍들은 서로 강하게 상관되어 있어서, 이를 섞어 한 데이터셋으로 만들면 한 번만 훑어도 보상 모델이 과적합했습니다. 그래서 저자들은 **한 프롬프트의 모든 비교쌍을 하나의 배치 원소로 묶어** 학습했고, 이 방식이 계산도 줄이고(답마다 순전파 한 번) 검증 정확도도 높였다고 보고합니다. 보상 모델은 6B 하나만 썼습니다. 175B 보상 모델은 학습이 불안정해 PPO의 가치 함수 초기값으로 쓰기 어려웠기 때문입니다(3.5절, 부록 C.2).

**3단계. 보상 모델을 상대로 PPO 강화학습**

SFT 모델을 정책으로 두고, 무작위 고객 프롬프트에 답을 쓰면 보상 모델이 점수를 매기는 단순한 환경(밴딧 환경)에서 PPO(Proximal Policy Optimization)로 최적화합니다. 이때 두 가지를 덧붙입니다(식 2).

- **토큰별 KL 벌점:** 정책이 SFT 모델에서 너무 멀어지면 벌점을 줍니다. 보상 모델은 사람 선호의 근사치일 뿐이라서, 그 허점을 파고드는 과최적화(over-optimization)를 막기 위한 장치입니다. 계수 β=0.02를 썼습니다(부록 C.4).
- **사전학습 데이터 혼합(PPO-ptx):** PPO 업데이트와 함께 원래 사전학습 데이터의 로그우도를 높이는 업데이트를 섞습니다. 계수 γ=27.8이고 RL 에피소드 수의 8배만큼 사전학습 예제를 씁니다. 아래 "정렬세" 문제를 줄이기 위한 장치이며, **논문에서 InstructGPT라고 부르는 모델은 이 PPO-ptx 모델입니다.**

PPO 학습은 256k 에피소드(고유 프롬프트 약 3.1만 개), 배치 512, 미니배치 64, 클립 비율 0.2로 진행했고, 정책 크기와 상관없이 6B 보상 모델과 6B 가치 함수를 함께 썼습니다(부록 C.4). 2단계와 3단계는 반복할 수 있습니다. 현재 최선의 정책으로 비교 데이터를 더 모으고, 새 보상 모델과 새 정책을 학습하는 식입니다. 다만 실제 비교 데이터 대부분은 SFT 정책에서 나왔다고 밝힙니다(3.1절).

## 실험 설정

**데이터 (표 6)**

| 데이터 | 용도 | 학습 프롬프트 수 | 출처 |
|---|---|---|---|
| SFT | 시범 답변으로 지도학습 | 12,725 (라벨러 작성 11,295 + 고객 1,430) | 라벨러, API |
| RM | 순위 비교로 보상 모델 학습 | 33,207 (라벨러 6,623 + 고객 26,584) | 라벨러, API |
| PPO | 사람 라벨 없이 강화학습 입력으로만 사용 | 31,144 | API만 |

프롬프트는 OpenAI API Playground에서 초기 InstructGPT 모델에 들어온 요청이 중심이고, 운영(production) 환경 API 요청은 쓰지 않았습니다. 사용자 ID당 200개로 제한하고, 학습·검증·테스트를 사용자 ID 기준으로 나눴으며, 학습 데이터에서는 개인식별정보(PII)를 걸러냈습니다(3.2절). 데이터의 96% 이상이 영어입니다. 용도 분포는 생성 45.6%, 열린 질의응답 12.4%, 브레인스토밍 11.2%, 채팅 8.4% 순이고 분류와 닫힌 질의응답은 합쳐도 6.1%에 그칩니다(표 1).

**사람**

Upwork와 Scale AI를 통해 약 40명의 계약 라벨러를 선발 시험으로 뽑았습니다(3.4절). 학습 라벨러끼리의 일치율은 72.6±1.5%, 학습 데이터에 참여하지 않은 별도(held-out) 라벨러의 일치율은 77.3±1.3%였습니다. 흥미로운 설계가 하나 있습니다. **학습 데이터를 만들 때는 사용자에게 도움이 되는 것을 우선했지만, 최종 평가에서는 진실성과 무해성을 우선하도록** 지시했습니다. 저자들은 학습 단계에서 이 둘을 어떻게 조율할지는 후속 과제로 남겼습니다.

**모델과 비교 대상**

| 이름 | 설명 |
|---|---|
| GPT | 사전학습된 GPT-3 그대로 |
| GPT (prompted) | 지시를 따르도록 퓨샷 접두어를 붙인 GPT-3 |
| SFT | 1단계까지만 한 모델 |
| PPO | 3단계까지, 사전학습 혼합 없음(γ=0) |
| PPO-ptx | 3단계 + 사전학습 혼합. 논문의 InstructGPT |
| FLAN, T0 | 175B GPT-3를 각 공개 데이터셋 약 100만 예제로 미세조정한 비교군 |

크기는 모두 1.3B, 6B, 175B 세 가지이고 구조는 GPT-3와 같습니다. 주 평가지표는 학습에 쓰이지 않은 고객의 프롬프트에 대해 **175B SFT 모델 대비 승률(사람 선호)**입니다. 여기에 1~7점 리커트 점수와 메타데이터(지시 불이행, 환각, 제약 준수 등, 표 3), 그리고 TruthfulQA, RealToxicityPrompts, Winogender, CrowS-Pairs, SQuAD, DROP 같은 공개 데이터셋 평가를 더했습니다.

## 주요 결과

### 1. 1.3B InstructGPT가 175B GPT-3보다 선호된다 (그림 1, 그림 3)

라벨러는 모든 크기에서 InstructGPT를 GPT-3보다 뚜렷하게 선호했습니다. 그림 1에서 1.3B PPO-ptx의 승률은 175B GPT-3보다 높습니다. 두 모델은 구조가 같고 사람 데이터로 미세조정했는지만 다릅니다. 175B끼리 직접 비교하면 InstructGPT가 GPT-3보다 **85±3%**, 퓨샷 프롬프트를 붙인 GPT-3보다 **71±4%** 더 자주 선호됐습니다(4.1절).

순서도 흥미롭습니다. GPT-3 원본이 가장 나쁘고, 잘 만든 퓨샷 프롬프트, SFT, PPO 순으로 한 계단씩 좋아집니다. 사전학습 혼합(PPO-ptx)은 선호도를 크게 바꾸지 않았습니다. GPT-3용으로 들어온 프롬프트로 평가해도 결론은 비슷했습니다(그림 3 왼쪽).

### 2. 학습에 참여하지 않은 라벨러도 같은 판단을 한다 (그림 3)

"학습 라벨러의 취향에 과적합한 것 아니냐"는 반론에 대해, 별도 라벨러의 평가에서도 InstructGPT가 GPT-3를 크게 앞섰습니다. 라벨러를 5개 그룹으로 나눠 4개 그룹으로 보상 모델을 학습하고 나머지 그룹의 선호를 예측하게 한 교차검증에서도, 정확도는 학습 그룹 기준 72.4±0.4%에서 보지 않은 그룹 기준 69.6±0.9%로 조금만 떨어졌습니다(4.1절).

### 3. 진실성은 좋아졌고, 독성은 조건부로만, 편향은 그대로다 (그림 4, 6, 7)

- **환각:** 요약이나 닫힌 질의응답처럼 입력에 없는 내용을 지어내면 안 되는 과제에서, 환각 비율이 GPT-3 41%에서 InstructGPT 21%로 줄었습니다(1절, 그림 4).
- **TruthfulQA:** 진실하면서도 유익한 답을 GPT-3보다 약 두 배 자주 냈습니다. 다만 1.3B PPO-ptx는 같은 크기 GPT-3보다 약간 나빴습니다(4.2절, 그림 6).
- **독성:** "정중하게 답하라"는 지시가 있을 때만 GPT-3보다 독성 출력이 약 25% 적었고, 지시가 없으면 차이가 사라졌습니다. 반대로 **독성 있게 쓰라고 지시하면 GPT-3보다 훨씬 더 독성이 강했습니다**(그림 7, 그림 39).
- **편향:** Winogender와 CrowS-Pairs에서는 GPT-3보다 나아지지 않았습니다. 정중하라고 지시했을 때 오히려 엔트로피가 낮아져(더 확신하며) 편향 지표가 나빠졌습니다.

독성과 편향 결과는 이 방법의 성격을 잘 보여 줍니다. RLHF는 모델을 "더 착하게" 만든다기보다 **지시를 더 잘 따르게** 만들고, 그 지시가 나쁘면 나쁜 쪽으로도 더 잘 따릅니다.

### 4. 정렬세(alignment tax)와 PPO-ptx (그림 28~29, 표 14)

PPO만 적용하면 일부 공개 NLP 데이터셋 성능이 GPT-3보다 떨어졌습니다. 저자들은 이를 정렬 때문에 치르는 비용이라는 뜻으로 **정렬세(alignment tax)**라고 부르고, 세금이 크면 "덜 정렬됐지만 성능 좋은 모델"을 쓰려는 유인이 생기므로 피해야 한다고 강조합니다(4.2절, 5.1절). 표 14의 175B 제로샷 결과 일부를 옮기면 다음과 같습니다.

| 과제 (지표) | GPT-3 | PPO | PPO-ptx |
|---|---|---|---|
| SQuADv2 (F1) | 64.30 | 43.68 | 59.85 |
| DROP (F1) | 27.53 | 13.08 | 15.23 |
| WMT15 프랑스어→영어 (BLEU) | 38.92 | 24.16 | 34.28 |
| HellaSwag (정확도) | 0.781 | 0.743 | 0.807 |

사전학습 혼합은 손실을 상당 부분 되돌렸고 HellaSwag에서는 GPT-3를 넘었지만, DROP, SQuADv2, 번역에서는 여전히 뒤졌습니다. 저자들은 KL 계수를 키우는 더 단순한 방법과도 비교했는데, KL 계수를 키우면 검증 보상이 크게 떨어지면서도 DROP과 SQuAD 성능은 끝내 회복되지 않았다고 보고합니다(그림 33, 34).

### 5. 공개 NLP 데이터셋으로 만든 지시 모델보다 낫다 (그림 5)

같은 175B GPT-3를 FLAN과 T0 데이터로 미세조정한 모델은 원본 GPT-3보다는 낫고 잘 프롬프트한 GPT-3와 비슷했지만, SFT 기준 모델보다는 나빴습니다. 직접 비교에서 InstructGPT는 FLAN 모델보다 78±4%, T0 모델보다 79±4% 더 자주 선호됐습니다. 저자들은 이유로 두 가지를 듭니다. 공개 데이터셋은 자동 채점이 쉬운 분류·질의응답 위주인데 실제 API 사용의 약 57%는 열린 생성과 브레인스토밍이라는 점, 그리고 공개 데이터셋으로는 실사용 수준의 입력 다양성을 얻기 어렵다는 점입니다(4.1절).

### 덧붙여: 비용은 사전학습의 약 1.8%

175B SFT 학습에 4.9 petaflops/s-days, 175B PPO-ptx 학습에 60 petaflops/s-days가 들었습니다. GPT-3 사전학습의 3,640 petaflops/s-days와 비교하면 둘을 합쳐도 약 1.8%입니다(5.1절, 비율은 필자 계산). 저자들은 이를 근거로 "적어도 고객의 자연어 과제 분포에서는, 지금은 더 큰 모델을 학습하는 것보다 기존 모델의 정렬에 투자하는 편이 비용 대비 효과적"이라고 결론짓습니다.

## 한계

**저자가 밝힌 한계 (5.2~5.4절)**

- **누구에게 정렬했는가:** 이 모델은 "인류의 가치"가 아니라 약 40명 라벨러의 선호, 지침을 쓴 연구자들, 그리고 Playground를 쓴 OpenAI 고객이 보낸 프롬프트에 정렬됐습니다. 라벨러는 주로 미국과 동남아시아에 사는 영어 사용자이고, 대기자 명단의 초기 시드가 OpenAI 직원이어서 사용자 집단도 그들의 네트워크 쪽으로 치우쳐 있습니다.
- **라벨 품질:** 비용 때문에 비교 대부분을 라벨러 한 명이 매겼습니다. 의견이 갈리는 지점을 알기 어렵고, 평균 선호에 맞추는 것이 바람직하지 않은 경우(예를 들어 특정 소수 집단에 영향을 주는 글)도 다루지 못합니다.
- **여전히 단순한 실수:** 잘못된 전제를 그대로 받아들이고, 간단한 질문에 장황하게 얼버무리고(hedging), 여러 제약이 겹친 지시에서 성능이 떨어집니다(그림 9). 저자들은 얼버무림이 "인식론적 겸손을 보상하라"는 라벨링 지침이 보상 모델에 반영된 결과일 수 있다고 추정합니다.
- **해로운 지시도 따른다:** 가장 큰 한계로, 사용자 지시가 현실에서 해를 끼칠 수 있어도 대부분 따른다는 점을 듭니다. 거부(refusal) 학습은 후속 과제로 남겼습니다.

**읽으면서 발견한 한계 (필자의 판단)**

- **평가자와 학습 신호의 출처가 같습니다.** 주 지표인 사람 선호를 매긴 평가자가 학습 데이터를 만든 라벨러와 같은 공급처, 같은 지침 체계에 속합니다. 별도 라벨러 실험이 있지만 그들도 같은 업체 소속이고 선발 시험만 거치지 않았을 뿐입니다. 이 승률은 "이 평가 체계에서의 선호"로 읽는 것이 정확합니다.
- **기준선이 불리한 분포입니다.** 주 테스트 프롬프트는 InstructGPT용으로 들어온 요청이라 GPT-3에 불리할 수 있다는 점을 저자들도 인정합니다. GPT-3용 프롬프트로도 평가했지만, "1.3B가 175B를 이긴다"는 문장은 지시 형태의 요청이라는 조건이 붙은 결과입니다.
- **선호는 정답이 아닙니다.** 이 방법이 최적화하는 것은 사람이 더 좋다고 느끼는 답입니다. 얼버무림 사례처럼, 보상 모델이 평가자의 습관을 학습하면 그 습관이 정책에 증폭됩니다. 이후 OpenAI o1 시스템 카드도 RLHF 정렬 단계의 보상 해킹으로 "사용자 만족을 우선하도록 최적화하면 지나치게 동조적이거나 부정확한 답을 낼 가능성"을 언급합니다(arXiv:2412.16720, 4.3.1절).

## 인사이트

**왜 지금 다시 읽을 만한가: "크기보다 후학습"이라는 전환점.** 이 논문 이전의 상식은 Kaplan 외(2020)의 스케일링 법칙대로 모델을 키우면 좋아진다는 것이었습니다. InstructGPT는 같은 구조의 모델에서 사전학습 연산의 약 1.8%를 후학습에 쓰는 것만으로 100배 큰 모델보다 선호되는 결과를 냈습니다. 이후 대형 모델의 기술 보고서는 RLHF를 기본 단계로 적기 시작합니다. GPT-4 기술 보고서(arXiv:2303.08774)는 사전학습 후 RLHF로 미세조정했다고 밝히고, Llama 2 보고서(arXiv:2307.09288)는 SFT 뒤에 거부 샘플링(rejection sampling)과 PPO로 반복 정제하는 RLHF를 씁니다. 규모도 달라졌습니다. InstructGPT의 보상 모델 학습 프롬프트가 약 3.3만 개였다면, Llama 2는 Meta가 직접 모은 사람 선호 비교만 약 141.8만 건을 썼습니다(Llama 2 표 6). 레시피의 뼈대는 그대로 두고 데이터와 반복 횟수를 키우는 방향으로 발전한 셈입니다.

**이후의 대안: 무엇을 바꿨나.** 후속 연구들은 이 3단계 중 어느 부분을 갈아 끼우는지로 정리하면 이해가 쉽습니다.

| 접근 | 바꾼 부분 | 그대로 둔 부분 |
|---|---|---|
| InstructGPT (2022) | 기준점 | SFT → RM → PPO, KL 벌점 |
| [DPO](/papers/2026/10/24/dpo.html) (arXiv:2305.18290) | RM과 PPO를 선호쌍에 대한 분류 손실 하나로 대체 | 사람 선호 비교 데이터, 참조 모델과 KL 제약이라는 목적함수 |
| Constitutional AI / RLAIF (arXiv:2212.08073) | 무해성 라벨을 사람 대신 원칙 목록(헌법)을 따르는 AI 피드백으로 생성 | 선호 모델 + RL 구조. 도움됨 라벨은 여전히 사람 피드백 사용 |
| DeepSeek-R1 (arXiv:2501.12948) | 추론 과제에서 신경망 보상 모델 대신 정답 검증 같은 규칙 기반 보상, PPO 대신 GRPO | 정책 최적화 + 참조 모델 KL 항 |

DPO 논문은 RLHF를 "복잡하고 종종 불안정한 절차"라고 부르며, 학습 중 샘플링 없이 같은 목적함수를 푼다고 주장합니다. Constitutional AI 논문은 해로운 출력을 가리키는 사람 라벨 없이 무해한 어시스턴트를 학습하되, 도움됨(helpfulness) 라벨은 계속 사람에게서 받았다고 명시합니다. DeepSeek-R1 논문은 PPO가 "LLM의 RL 단계에서 널리 쓰인다"며 Ouyang 외(2022)를 인용하고, 대규모 RL에서 신경망 보상 모델이 보상 해킹에 취약해서 추론 과제에는 쓰지 않았다고 설명합니다. 세 갈래 모두 InstructGPT가 드러낸 비용, 즉 사람 라벨의 비용, PPO의 복잡성, 보상 모델의 허점을 각자 다른 방식으로 줄이려는 시도로 읽힙니다. 같은 날 게시된 [DPO 소개](/papers/2026/10/24/dpo.html)에서 손실 함수의 유도 과정을 자세히 다룹니다.

**실무에 주는 의미.** 자체 모델을 미세조정하는 팀에게 이 논문이 주는 교훈은 알고리즘보다 운영 쪽에 있습니다. 첫째, **라벨링 지침이 곧 모델의 성격**입니다. "겸손하게"라는 지침 한 줄이 얼버무리는 모델을 만들 수 있다는 관찰은, 선호 데이터를 모을 때 지침을 버전 관리하고 그 변화가 출력에 주는 영향을 추적해야 한다는 뜻입니다. 둘째, **정렬세를 측정하는 회귀 테스트**를 따로 두어야 합니다. 선호 점수만 보면 PPO와 PPO-ptx의 차이가 거의 없었지만, SQuADv2와 DROP에서는 차이가 컸습니다. 우리 서비스의 핵심 능력이 미세조정 후에 떨어지지 않았는지 보여 줄 평가 세트가 필요합니다. 셋째, 보상 모델 학습에서 같은 프롬프트의 비교쌍을 한 배치로 묶은 요령처럼, **데이터 간 상관을 무시하면 한 에포크 만에 과적합**한다는 점은 지금의 선호 학습에도 그대로 적용됩니다.

**한계와 반론.** "1.3B가 175B를 이긴다"는 문장은 자주 인용되지만 조건이 많습니다. 지시형 프롬프트 분포에서, 같은 업체 라벨러의 선호로 잰 결과이고, 공개 벤치마크에서는 오히려 성능이 떨어진 부분이 있습니다. 필자의 판단으로는 이 결과를 "작은 모델이 더 똑똑해졌다"가 아니라 "**사용자가 원하는 형식과 태도로 답하는 능력은 크기보다 후학습이 좌우한다**"로 읽는 것이 정확합니다. 지식과 추론 능력 자체는 여전히 사전학습 규모의 영향을 받는다는 점은 같은 달 나온 [Chinchilla 논문](/papers/2026/10/24/chinchilla.html) 같은 스케일링 연구가 다룹니다.

**앞으로 지켜볼 점.** 사람 선호에 맞추는 학습이 아첨(sycophancy)과 보상 해킹을 부를 수 있다는 우려는 InstructGPT의 얼버무림 관찰에서 이미 싹이 보였고, 지금도 해결되지 않은 문제입니다. 정답을 검증할 수 있는 과제는 DeepSeek-R1처럼 규칙 기반 보상으로 옮겨 가고 있지만, 글쓰기처럼 검증이 어려운 과제에서는 여전히 사람이나 AI의 선호 판단에 기대야 합니다. 이 영역에서 보상 모델의 신뢰성을 어떻게 확보하는지가 다음 판단 기준이 될 것으로 보입니다.

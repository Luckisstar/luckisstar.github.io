# [논문 소개] Attention Is All You Need: 순환 없이 어텐션만으로 만든 트랜스포머

- **논문:** *Attention Is All You Need*
- **저자:** Ashish Vaswani, Noam Shazeer, Niki Parmar, Jakob Uszkoreit, Llion Jones, Aidan N. Gomez, Łukasz Kaiser, Illia Polosukhin (총 8명, Google Brain·Google Research·University of Toronto). 논문 각주에 따르면 8명 모두 기여도가 같고 저자 순서는 무작위입니다.
- **공개:** 2017년 6월 12일, arXiv:1706.03762 (cs.CL, cs.LG). NIPS 2017(현 NeurIPS) 발표. 이 글은 2023년 8월 2일 갱신된 v7을 기준으로 합니다.
- **링크:** [arXiv](https://arxiv.org/abs/1706.03762) · [PDF](https://arxiv.org/pdf/1706.03762) · [NeurIPS 2017 프로시딩](https://proceedings.neurips.cc/paper/2017/hash/3f5ee243547dee91fbd053c1c4a845aa-Abstract.html) · [원 코드 tensor2tensor](https://github.com/tensorflow/tensor2tensor)
- **참고:** 논문이 공개한 코드 저장소 `tensorflow/tensor2tensor`는 2026-10-24 기준 GitHub에서 보관(archived) 상태입니다. 원 구현을 따라 해 보려면 이 점을 감안해야 합니다.

## 한 줄 요약

**RNN(순환 신경망)과 CNN(합성곱 신경망)을 완전히 빼고 어텐션만으로 번역 모델을 만들었더니, 더 정확하고 학습은 훨씬 싸고 빨랐다는 논문입니다.** 오늘날 GPT, Claude, Gemini, Llama 같은 대형 언어 모델(LLM)의 뼈대가 모두 이 논문의 트랜스포머(Transformer)에서 나왔습니다.

## 왜 이 연구가 필요한가

2017년 당시 기계 번역의 주류는 LSTM, GRU 같은 RNN 기반 인코더-디코더였습니다. RNN은 문장을 앞에서부터 한 토큰씩 읽으며 은닉 상태 `h_t`를 `h_(t-1)`로부터 계산합니다. 논문은 이 구조의 근본 문제를 이렇게 짚습니다(1절).

- **병렬화가 안 됩니다.** t번째 계산이 t-1번째 결과를 기다려야 하므로, 한 문장 안에서는 GPU를 병렬로 쓸 수 없습니다. 문장이 길수록 치명적입니다.
- **먼 거리의 관계를 배우기 어렵습니다.** 문장 앞쪽 단어의 정보가 뒤쪽까지 가려면 여러 단계를 거쳐야 합니다.

CNN 기반 모델(ByteNet, ConvS2S)은 병렬화는 되지만, 멀리 떨어진 두 위치를 잇는 데 필요한 연산 수가 거리에 따라 늘어납니다(ConvS2S는 선형, ByteNet은 로그). 어텐션은 이미 RNN 번역 모델의 보조 장치로 쓰이고 있었는데, 저자들의 질문은 단순했습니다. **"보조 장치였던 어텐션만 남기고 순환을 아예 없애면 어떨까?"**

## 제안 방법

### 1. 어텐션: 부드러운 딕셔너리 조회

개발자에게 가장 익숙한 비유는 키-값 저장소입니다. 일반 딕셔너리는 쿼리와 정확히 일치하는 키 하나의 값을 돌려줍니다. 어텐션은 **쿼리(Query)를 모든 키(Key)와 비교해 유사도 점수를 매기고, 그 점수로 모든 값(Value)을 가중 평균**해서 돌려줍니다. 논문의 식 (1)이 이것입니다.

```
Attention(Q, K, V) = softmax( Q · Kᵀ / √d_k ) · V
```

- `Q · Kᵀ`: 각 쿼리와 각 키의 내적(dot product), 즉 유사도
- `√d_k`로 나누기: 논문은 키 차원 `d_k`가 크면 내적 값이 커져 softmax가 기울기가 거의 0인 영역으로 밀려난다고 추정하고, 이를 막으려고 크기를 줄입니다(3.2.1절). 이름이 "Scaled Dot-Product Attention"인 이유입니다.
- softmax: 점수를 합이 1인 가중치로 바꿉니다.

**셀프 어텐션(self-attention)**은 Q, K, V를 모두 같은 문장에서 만드는 경우입니다. 문장의 모든 토큰이 다른 모든 토큰을 한 번에 들여다보므로, 첫 단어와 마지막 단어 사이의 거리가 연산 한 단계로 줄어듭니다.

### 2. 멀티헤드 어텐션: 여러 관점으로 동시에 보기

어텐션을 한 번만 하면 여러 위치의 정보가 평균되면서 흐려집니다. 그래서 Q, K, V를 서로 다른 학습된 행렬로 `h`번 투영해 작은 어텐션을 병렬로 `h`개 돌리고, 결과를 이어 붙인 뒤 다시 투영합니다(3.2.2절).

```
MultiHead(Q, K, V) = Concat(head_1, ..., head_h) · W_O
head_i = Attention(Q·W_i^Q, K·W_i^K, V·W_i^V)
```

기본 모델은 `h = 8`, 헤드당 차원 `d_k = d_v = 512 / 8 = 64`입니다. 헤드마다 차원을 줄였기 때문에 전체 계산량은 큰 헤드 하나와 비슷합니다. 논문 부록의 시각화(그림 3~5)에는 어떤 헤드는 "making ... more difficult"처럼 멀리 떨어진 동사구를 잇고, 어떤 헤드는 대명사 "its"가 가리키는 대상을 찾는 등 **헤드마다 다른 일을 배운** 모습이 나옵니다.

아래는 이 두 식을 NumPy로 옮긴 최소 예제입니다. 논문 식을 그대로 옮겨 필자가 직접 실행해 확인했습니다(Python 3.12, NumPy). 학습은 하지 않고 무작위 가중치로 모양과 마스킹만 확인합니다.

```python
import numpy as np

def attention(Q, K, V, causal=False):
    d_k = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d_k)            # (n, n): 모든 토큰 쌍의 점수
    if causal:                                  # 디코더: 뒤쪽 토큰은 못 보게
        scores = np.where(np.triu(np.ones_like(scores), k=1) == 1, -np.inf, scores)
    w = np.exp(scores - scores.max(-1, keepdims=True))
    w = w / w.sum(-1, keepdims=True)            # 행마다 softmax
    return w @ V, w

rng = np.random.default_rng(0)
n, d_model, h = 4, 8, 2                         # 토큰 4개, 모델 차원 8, 헤드 2개
x = rng.normal(size=(n, d_model))
d_k = d_model // h
heads = []
for _ in range(h):                              # 헤드마다 다른 투영 행렬
    Wq, Wk, Wv = (rng.normal(size=(d_model, d_k)) for _ in range(3))
    out, w = attention(x @ Wq, x @ Wk, x @ Wv, causal=True)
    heads.append(out)
Wo = rng.normal(size=(h * d_k, d_model))
y = np.concatenate(heads, axis=-1) @ Wo         # 이어 붙인 뒤 다시 투영
print(y.shape)
print(np.round(w, 2))                           # 마지막 헤드의 가중치
```

```
(4, 8)
[[1.   0.   0.   0.  ]
 [0.   1.   0.   0.  ]
 [0.95 0.   0.05 0.  ]
 [0.   1.   0.   0.  ]]
```

가중치 행렬의 대각선 위쪽이 모두 0입니다. 이것이 디코더의 **마스킹**입니다. 논문은 디코더가 아직 생성하지 않은 뒤쪽 토큰을 보지 못하도록 softmax 입력을 `-∞`로 채운다고 설명합니다(3.2.3절). 그리고 `scores`가 `(n, n)` 행렬이라는 점을 기억해 두면, 뒤에서 다룰 "이차 비용"이 바로 이 행렬에서 나옵니다.

### 3. 위치 인코딩: 순서 정보를 더해 주기

어텐션은 집합 연산이라 토큰 순서를 모릅니다. "개가 사람을 문다"와 "사람이 개를 문다"를 구분하려면 순서 정보를 따로 넣어야 합니다. 논문은 임베딩에 다음 사인·코사인 값을 더합니다(3.5절).

```
PE(pos, 2i)   = sin(pos / 10000^(2i / d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i / d_model))
```

차원마다 주기가 다른 파동(파장이 2π에서 10000·2π까지 기하급수적으로 늘어남)을 쓰는 이유로, 저자들은 고정된 거리 k만큼 떨어진 위치의 인코딩이 선형 함수로 표현되므로 상대 위치를 배우기 쉬울 것이라는 가설을 듭니다. 학습 가능한 위치 임베딩도 실험했는데 결과가 거의 같았고(표 3의 (E) 행: BLEU 25.7 대 기본 25.8), 학습 때보다 긴 문장으로 외삽(extrapolation)할 수 있을지 모른다는 이유로 사인 방식을 택했습니다.

### 4. 인코더-디코더 구조

전체 구조(그림 1)는 당시 번역 모델의 관례대로 인코더와 디코더로 나뉩니다.

| 부분 | 층 수 | 한 층의 구성 | 역할 |
|---|---|---|---|
| 인코더 | N = 6 | 셀프 어텐션 → 피드포워드 | 원문 전체를 읽어 각 토큰의 표현을 만듦 |
| 디코더 | N = 6 | 마스킹된 셀프 어텐션 → 인코더-디코더 어텐션 → 피드포워드 | 이미 만든 번역문과 원문을 보고 다음 토큰을 예측 |

- **인코더-디코더 어텐션:** 쿼리는 디코더에서, 키와 값은 인코더 출력에서 옵니다. 번역할 때 "원문의 어디를 볼지"를 정하는 부분입니다.
- **피드포워드:** 토큰마다 따로 적용하는 2층 신경망 `max(0, x·W1 + b1)·W2 + b2`입니다. 입력·출력 512차원, 내부 2048차원입니다.
- **잔차 연결과 층 정규화:** 모든 하위 층의 출력은 `LayerNorm(x + Sublayer(x))`입니다. 이 덕분에 층을 깊게 쌓아도 학습이 안정됩니다.

## 주요 결과

### 1. 번역 품질과 학습 비용을 동시에 이겼다 (표 2)

논문의 핵심 표입니다. 학습 비용은 FLOPs(부동소수점 연산 횟수)로, 저자들이 "학습 시간 × GPU 수 × GPU별 단정밀도 연산 성능 추정치"로 계산했습니다(P100은 9.5 TFLOPS로 가정).

|---|---|---|---|---|
| ByteNet | 23.75 | | | |
| Deep-Att + PosUnk | | 39.2 | | 1.0 · 10²⁰ |
| GNMT + RL | 24.6 | 39.92 | 2.3 · 10¹⁹ | 1.4 · 10²⁰ |
| ConvS2S | 25.16 | 40.46 | 9.6 · 10¹⁸ | 1.5 · 10²⁰ |
| MoE | 26.03 | 40.56 | 2.0 · 10¹⁹ | 1.2 · 10²⁰ |
| Deep-Att + PosUnk 앙상블 | | 40.4 | | 8.0 · 10²⁰ |
| GNMT + RL 앙상블 | 26.30 | 41.16 | 1.8 · 10²⁰ | 1.1 · 10²¹ |
| ConvS2S 앙상블 | 26.36 | 41.29 | 7.7 · 10¹⁹ | 1.2 · 10²¹ |
| **Transformer (base)** | 27.3 | 38.1 | **3.3 · 10¹⁸** | **3.3 · 10¹⁸** |

- 영어-독일어에서 big 모델은 28.4로, **앙상블을 포함한 기존 최고 기록보다 2 BLEU 이상** 높았습니다.
- 기본 모델(27.3)도 기존 모든 모델과 앙상블을 넘었는데, 학습 비용은 3.3 · 10¹⁸로 ConvS2S 단일 모델(9.6 · 10¹⁸)의 약 3분의 1, GNMT + RL 앙상블(1.8 · 10²⁰)의 약 55분의 1입니다(필자 계산).
- 영어-프랑스어에서는 big 모델이 단일 모델 최고 기록을 세웠고, 비용은 이전 최고 모델의 4분의 1 미만이라고 논문은 밝힙니다.

한 가지 주의할 점이 있습니다. v7 기준으로 초록과 표 2는 영어-프랑스어 big 모델을 **41.8**로 적었지만, 6.1절 본문은 **41.0**이라고 적고 있습니다. 논문 안에서 수치가 엇갈리므로 인용할 때는 표 2의 값과 이 불일치를 함께 밝히는 편이 안전합니다.

### 2. 왜 빨랐나: 층 유형별 복잡도 비교 (표 1)

| 층 유형 | 층당 계산량 | 순차 연산 수 | 최대 경로 길이 |
|---|---|---|---|
| 셀프 어텐션 | O(n² · d) | O(1) | O(1) |
| 순환(RNN) | O(n · d²) | O(n) | O(n) |
| 합성곱 | O(k · n · d²) | O(1) | O(log_k(n)) |
| 제한된 셀프 어텐션 | O(r · n · d) | O(1) | O(n/r) |

(n: 시퀀스 길이, d: 표현 차원, k: 합성곱 커널 크기, r: 제한된 어텐션의 이웃 크기)

셀프 어텐션은 순차 연산이 O(1)이라 GPU로 한 번에 병렬 처리되고, 어떤 두 위치든 한 단계로 연결됩니다. 대신 층당 계산량에 **n²**이 붙습니다. 논문은 당시 번역 문장처럼 길이 n이 차원 d(512)보다 작을 때가 대부분이라 이 비용이 문제가 되지 않는다고 설명하면서, 아주 긴 시퀀스를 위해서는 주변 r개만 보는 제한된 어텐션을 "향후 과제"로 남깁니다(4절). 이 한 문장이 이후 수년간의 연구 방향을 예고한 셈입니다.

### 3. 헤드 수와 크기의 영향 (표 3)

영어-독일어 개발 세트(newstest2013)에서 기본 모델을 조금씩 바꾼 결과입니다.

| 변형 | 바꾼 값 | BLEU (dev) | 파라미터 |
|---|---|---|---|
| 기본 | h=8, d_k=64 | 25.8 | 6,500만 |
| (A) 헤드 1개 | h=1, d_k=512 | 24.9 | |
| (A) 헤드 16개 | h=16, d_k=32 | 25.8 | |
| (A) 헤드 32개 | h=32, d_k=16 | 25.4 | |
| (B) 키 차원 축소 | d_k=16 | 25.1 | 5,800만 |
| (C) 모델 확대 | d_model=1024 | 26.0 | 1억 6,800만 |
| (E) 학습형 위치 임베딩 | 사인 대신 | 25.7 | |
| big | d_model=1024, h=16 | 26.4 | 2억 1,300만 |

헤드가 1개면 최적 설정보다 0.9 BLEU 낮지만, 헤드가 너무 많아도(32개) 다시 떨어집니다. 키 차원을 줄이면 품질이 나빠져, 저자들은 "호환성(쿼리와 키의 유사도)을 판단하는 일이 쉽지 않으며 내적보다 정교한 함수가 도움이 될 수 있다"고 적었습니다.

### 4. 번역 밖에서도 통했다: 영어 구문 분석 (표 4)

번역 외 과제로 영어 구문 분석(문장을 문법 트리로 바꾸기)을 시험했습니다. 별도 조정 없이 4층 트랜스포머로 WSJ 데이터 4만 문장만 학습해 F1 91.3, 약 1,700만 문장을 더한 준지도 학습으로 92.7을 얻었습니다. 표에서 이를 넘는 것은 RNN 문법 생성 모델(93.3)과 멀티태스크 모델(93.0)뿐이었습니다. 저자들은 RNN 기반 seq2seq와 달리 4만 문장만으로도 BerkeleyParser를 넘었다는 점을 강조합니다.

## 한계

**저자가 밝힌 것**

- 셀프 어텐션의 층당 계산량은 O(n² · d)이므로, 매우 긴 입력에는 제한된(local) 어텐션 같은 방법이 필요하다고 봤습니다(4절, 7절).
- 어텐션 가중치를 평균하면 해상도가 떨어지는 문제가 있어 멀티헤드로 보완했다고 설명합니다(2절).
- 생성(디코딩)은 여전히 한 토큰씩 순차적이며, "생성을 덜 순차적으로 만드는 것"을 다음 연구 목표로 꼽았습니다(7절).

**읽으면서 발견한 것 (필자 의견)**

- 실험이 번역 2개와 구문 분석 1개뿐입니다. "어텐션만으로 충분하다"는 제목은 이 범위에서 검증된 주장입니다. 언어 모델링 전반으로의 일반화는 후속 연구가 보여 준 것입니다.
- 학습 비용 비교는 GPU별 성능 "추정치"로 계산한 FLOPs입니다. 실제 벽시계 시간이나 다른 하드웨어에서의 비용과는 차이가 날 수 있습니다.
- 사인 위치 인코딩이 긴 문장으로 외삽할 수 있을 것이라는 기대는 논문 안에서 실험으로 확인되지 않았습니다.
- 앞서 짚은 것처럼 영어-프랑스어 big 모델 수치가 본문(41.0)과 표(41.8)에서 다릅니다.

## 인사이트

**지금의 디코더 전용 LLM으로 어떻게 이어졌나.** 원 논문의 트랜스포머는 인코더와 디코더가 함께 있는 번역기였습니다. 오늘날 LLM이 쓰는 "디코더만 있는" 구조로 가는 길은 출처로 확인되는 단계가 분명합니다.

| 시기 | 논문 | 무엇을 바꿨나 (원문 기준) |
|---|---|---|
| 2018-01 | Liu et al., [Generating Wikipedia by Summarizing Long Sequences](https://arxiv.org/abs/1801.10198) | 인코더를 빼고 입력과 출력을 한 "문장"으로 이어 붙여 일반 언어 모델로 학습하는 Transformer Decoder(T-D)를 제안. 파라미터가 거의 절반으로 줄어든다고 설명 |
| 2018 | Radford et al., [Improving Language Understanding by Generative Pre-Training](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf) (GPT) | 위 Liu et al.을 인용하며 "12층 디코더 전용 트랜스포머(마스킹된 셀프 어텐션 헤드)"를 사전 학습 |
| 2018-10 | Devlin et al., [BERT](https://arxiv.org/abs/1810.04805) | 반대로 인코더만 써서 양방향 문맥을 학습. 이해 과제용 계열의 출발점 |
| 2020-05 | Brown et al., [Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165) (GPT-3) | "GPT-2와 같은 모델과 구조"에 Sparse Transformer와 비슷한 밀집·국소 희소 어텐션을 번갈아 사용. 1,750억 파라미터 |
| 2023-02 | Touvron et al., [LLaMA](https://arxiv.org/abs/2302.13971) | 층 정규화를 입력 쪽으로(pre-normalization, RMSNorm), ReLU 대신 SwiGLU, 절대 위치 임베딩 대신 회전 위치 임베딩(RoPE, [Su et al.](https://arxiv.org/abs/2104.09864)) |

이 표를 보면 7년이 지나도 바뀐 것은 정규화 위치, 활성화 함수, 위치 표현 같은 "부품"이고, **Q·K·V 어텐션, 멀티헤드, 잔차 연결, 마스킹으로 다음 토큰을 예측하는 골격은 2017년 그대로**입니다. 특히 위치 인코딩은 원 논문의 사인 방식이 학습형 임베딩과 성능이 거의 같다고 했던(표 3 (E)) 부분인데, 이후 RoPE 같은 상대 위치 방식으로 대체됐습니다. 저자들이 "가설"로 남겨 둔 부분이 실제로 가장 많이 바뀐 셈입니다.

**이차 비용이 이후 연구 방향을 정했다.** 표 1의 O(n² · d)는 2017년 번역 문장 길이에서는 장점(병렬화)에 가려진 비용이었지만, 입력이 문서, 코드 저장소, 긴 대화로 커지면서 가장 큰 병목이 됐습니다. 이후 연구를 이 비용을 다루는 방식으로 나누면 다음과 같습니다.

- **계산 자체를 줄이기 (근사):** [Sparse Transformer](https://arxiv.org/abs/1904.10509)는 어텐션 행렬을 희소하게 분해해 O(n√n)으로, [Longformer](https://arxiv.org/abs/2004.05150)는 국소 창 어텐션과 소수의 전역 어텐션을 섞어 선형으로 줄였습니다. 원 논문이 "향후 과제"로 남긴 제한된 어텐션의 직계 후손입니다.
- **같은 계산을 메모리 효율적으로 (정확):** [FlashAttention](https://arxiv.org/abs/2205.14135)은 근사 없이 정확한 어텐션을 계산하되, GPU의 HBM과 SRAM 사이 읽기·쓰기를 줄여 속도를 냈습니다. 초록은 근사 방법들이 "벽시계 시간 이득을 내지 못하는 경우가 많다"고 지적합니다. 이론적 복잡도보다 메모리 입출력이 실제 병목이었다는 뜻입니다.
- **생성 단계의 메모리 대역폭 줄이기:** 공저자 Noam Shazeer는 2019년 [Multi-Query Attention](https://arxiv.org/abs/1911.02150)에서 한 토큰씩 생성할 때 큰 키·값 텐서를 반복해 읽는 비용이 느린 원인이라며, 모든 헤드가 키·값을 공유하는 방식을 제안했습니다. [GQA](https://arxiv.org/abs/2305.13245)는 그 중간(키·값 헤드를 몇 개 그룹으로)을 택해 품질과 속도를 절충합니다. 원 논문의 멀티헤드를 "쿼리는 여러 개, 키·값은 적게"로 비대칭화한 것입니다.
- **어텐션을 대체하기:** [Mamba](https://arxiv.org/abs/2312.00752)는 선택적 상태 공간 모델(SSM)로 시퀀스 길이에 선형인 구조를 제안하면서도, 초록에서 기존의 이차 미만(subquadratic) 구조들이 언어 같은 중요한 분야에서 어텐션만큼 성능을 내지 못했다고 인정합니다.

필자의 판단으로는 이 흐름에서 실무 개발자가 가져갈 교훈이 하나 있습니다. **컨텍스트 창이 커져도 토큰 하나를 더 넣는 비용은 0이 아닙니다.** 모든 토큰이 다른 모든 토큰과 점수를 주고받는 구조이므로, 긴 입력은 계산 비용뿐 아니라 모델이 집중해야 할 대상도 늘립니다. 같은 날 쓴 [컨텍스트 엔지니어링 글](/tech/2026/10/24/context-engineering.html)에서 다루는 "어텐션 예산"이라는 표현도 바로 이 n² 구조에서 출발합니다.

**실무에 주는 의미.** LLM API를 쓰는 개발자가 이 논문에서 직접 확인할 수 있는 동작이 몇 가지 있습니다. (1) 출력이 한 토큰씩 순차적으로 나오는 이유는 디코더의 마스킹과 자기회귀(auto-regressive) 생성 때문이며, 원 논문도 이 부분은 병렬화하지 못했습니다. 그래서 출력 토큰이 입력 토큰보다 느리고 비싼 경우가 많습니다. (2) 같은 입력 앞부분을 재사용하는 프롬프트 캐싱이 가능한 이유는, 마스킹 때문에 앞쪽 토큰의 키·값이 뒤쪽 토큰의 영향을 받지 않기 때문입니다(필자의 해석). (3) 위치 정보가 별도로 더해진다는 점은, 학습 때 보지 못한 길이의 입력에서 성능이 흔들릴 수 있는 이유를 이해하는 출발점입니다.

**한계와 반론.** "Attention Is All You Need"라는 제목은 절반만 맞습니다. 표 3을 보면 피드포워드 층의 크기(d_ff 4096에서 26.2), 드롭아웃(0에서 24.6으로 하락) 같은 어텐션 밖의 요소도 결과를 크게 좌우했고, 잔차 연결과 층 정규화 없이는 6층도 안정적으로 쌓기 어려웠을 것입니다. 이후 LLaMA가 바꾼 부품도 대부분 어텐션 밖(정규화, 활성화 함수)이었습니다. 어텐션은 "필요한 전부"라기보다 **병렬화를 가능하게 한 핵심 부품**이라고 보는 것이 정확합니다.

**앞으로 지켜볼 점.** Mamba 같은 대안이 어텐션을 완전히 대체할지, 아니면 어텐션 층과 섞어 쓰는 구조로 수렴할지가 다음 판단 지점입니다. Mamba 초록 스스로가 기존 대안들이 언어에서 어텐션만큼 하지 못했다고 적은 만큼, 대체 주장은 같은 크기의 모델에서 긴 문맥 검색처럼 어텐션이 강한 과제까지 이기는지로 확인하는 것이 좋겠습니다.

# [논문 소개] Cortex: 프롬프트에 넣던 컨텍스트를 FFN 가중치로 응고시키기

- **논문:** *Cortex: Consolidating Context into Parametric Memory*
- **저자:** Jintian Zhang, Feng He, Xinnian Liang 외 (총 8명), Zhejiang University · ByteDance Seed · Tsinghua University (논문 첫 페이지 기준, 교신저자 Ningyu Zhang)
- **공개:** 2026년 10월 14일, arXiv:2610.20399 v1 (cs.CL, 기술 보고서)

## 한 줄 요약

**컨텍스트를 넣었을 때만 생기던 성능 향상을, 컨텍스트를 뺀 뒤에도 남도록 FFN(피드포워드 신경망) 가중치에 "응고"시키는 방법을 제안하고, 14B 모델에 사실 50개를 하나씩 써 넣은 뒤에도 향상의 88.9%를 되살리면서 원래 능력은 99.8% 유지했다고 보고합니다.** 에이전트의 장기 기억을 "프롬프트에 무엇을 넣을까"가 아니라 "무엇을 모델 안에 써 넣을까"의 문제로 바꿔 보는 연구입니다.

## 왜 이 연구가 필요한가

LLM은 처음 보는 API 문서나 경험 요약을 프롬프트에 넣으면 금방 그걸 활용합니다. 문제는 컨텍스트를 빼는 순간 그 효과도 사라진다는 점입니다. RAG(검색 증강 생성)나 에이전트 메모리는 이 효과를 매번 다시 가져와 붙이는 방식인데, 저자들은 이 방식이 "추론 시점에 관련 내용을 찾아 공급해야만" 효과가 있고 간접적으로만 관련된 경험은 놓칠 수 있다고 지적합니다(1장).

그렇다고 가중치를 고치는 기존 연구들은 목적별로 흩어져 있습니다. 사실 편집(knowledge editing)은 "주어-관계-목적어" 형식의 편집 요청을, 언러닝(unlearning)은 잊을 데이터와 남길 데이터 쌍을 따로 요구합니다. 저자들은 이걸 하나로 묶습니다. **"컨텍스트가 무엇을 바꾸고 싶은지 설명하고, 모델은 그 컨텍스트 없이도 같은 효과를 내야 한다"**는 하나의 목표, 즉 **기억 응고(Memory Consolidation, MC)**로 정의합니다. 이름은 해마에서 신피질로 기억이 옮겨 가는 생물학의 시스템 응고(systems consolidation)에서 따왔습니다(그림 1).

## 제안 방법

### 문제 정의: 컨텍스트 격차, CR, RR

컨텍스트 C를 넣었을 때와 뺐을 때 목표 질의에서의 성능 차이를 **컨텍스트 격차(context gap)**라 부릅니다(식 2). 이 격차가 크면 "모델이 정보를 쓸 줄은 아는데 기억을 못 하는" 상태, 즉 기억 실패입니다. 기억 응고는 이 격차를 메우는 것이 목표이고, 두 지표로 평가합니다(식 3).

| 지표 | 정의 | 의미 |
|---|---|---|
| **CR** (응고율) | (업데이트 후 성능 − 원래 성능) ÷ 컨텍스트 격차 | 컨텍스트가 주던 향상을 몇 %나 되살렸나. 100%를 넘을 수 있음 |
| **RR** (유지율) | 업데이트 후 비목표 성능 ÷ 원래 비목표 성능 | 건드리면 안 되는 능력을 몇 % 지켰나 |

연속 업데이트에서는 과거 컨텍스트를 저장하거나 다시 볼 수 없다는 제약이 붙고, 매 단계마다 지금까지 써 넣은 기억 전체와 초기 모델 대비 능력을 다시 평가합니다.

### Cortex의 세 가지 질문

**1) 무엇을 응고할까: 예행 질의(prospective rehearsal).** 업데이트 전 모델이 컨텍스트를 보고 "이 정보가 앞으로 쓰일 법한 질문"을 스스로 만들고(식 4), 컨텍스트를 본 상태로 그 질문에 답합니다. 이 (질문, 답) 쌍이 학습 데이터입니다. 외부 생성기나 교사 모델이 필요 없고, 평가용 질의는 쓰지 않습니다. 에이전트 과제(ALFWorld, τ²-Bench)만 예외로, 환경이 주는 질의와 성공한 오프라인 궤적을 씁니다.

**2) 어디에 쓸까: FFN만.** 트랜스포머의 FFN이 키-값 메모리처럼 동작한다는 선행 연구를 근거로, 어텐션은 건드리지 않고 FFN만 고칩니다. 두 가지 변형이 있습니다(식 5, 6, 그림 3).

| 변형 | 방식 | 생물학 비유 | 배포 시 |
|---|---|---|---|
| **Synaptic** | 기존 gate·up·down 행렬에 LoRA식 저랭크 증분 추가 | 기존 시냅스 강화 | 증분을 원래 행렬에 병합 |
| **Structural** | 기존 FFN은 그대로 두고 비선형 채널 k개를 새로 덧붙임 | 새 시냅스 연결 생성 | 더 넓은 FFN으로 접어 넣음(폭이 d_ff → d_ff + k) |

MoE(전문가 혼합) 모델에서는 라우터를 고정하고, 전문가마다 따로 늘리는 대신 **모든 토큰이 지나가는 공유 확장 하나**를 붙입니다. 라우팅 가중치 합이 1이면 이 공유 가지는 모든 전문가 안에 접어 넣을 수 있어 표준 MoE 구조가 유지됩니다(식 7).

**3) 어떻게 쓸까: 컨텍스트→기억 증류.** 교사는 컨텍스트를 받은 업데이트 전 모델, 학생은 컨텍스트 없이 새 파라미터만 학습하는 같은 모델입니다. 손실은 출력 분포의 KL 발산(교사의 상위 Kv개 로짓만 보관)과 각 층 FFN 잔차 직후 은닉 상태의 MSE를 합칩니다(식 8). MSE를 넣는 이유는 "컨텍스트를 빼면 어텐션 출력이 바뀌는데, 그 차이를 FFN 업데이트가 보정하도록 층마다 직접 목표를 주기 위해서"입니다(부록 A에 유한 상태에서의 표현 가능성 분석).

연속 업데이트에서는 이전 모델과 이전 어댑터를 모두 얼리고 새 파라미터만 학습합니다. 여기에 **질의 재생(query replay)**을 더하는데, 과거 컨텍스트나 답은 저장하지 않고 **과거 질문만** 저장했다가 현재 모델로 답을 다시 생성해 함께 학습합니다.

## 실험 설정

**기억 응고 테스트베드**는 5개 과제군으로 구성됩니다(표 1). 컨텍스트는 모델마다 큰 격차가 나도록 사람이 직접 만들었습니다.

| 과제 | 컨텍스트 | 목표 평가 | 유지 평가 |
|---|---|---|---|
| 에이전트 경험 | 경험 요약 2개 (390~1,973 토큰) | ALFWorld, τ²-Bench 성공률 | MMLU, SimpleQA, 수학 |
| 새 API 학습 | 2025-11~2026-02 출시 Python 패키지 15개 문서 | 실행 테스트 150문제 pass@1 | MMLU, SimpleQA, LiveCodeBench |
| 페르소나 조정 | 페르소나 지시 2개 | Power-seeking, Psychopathy | 유창성(Power-seeking만) |
| 지식 억제 | 엔터티 10개 응답 거부 지시 | RWKU Forget L1/L2 | RWKU Neighbor L1/L2, BBH |
| 사실 편집 | zsRE 기반 사실 50개 (43~141 토큰) | 효력·일반화·이식성 | 지역성, MMLU, SimpleQA, 수학 |

- **백본:** Qwen2.5-14B-Instruct, Qwen3-4B-Instruct/Thinking, Gemma3-12B-it, GPT-OSS-20B, GPT-OSS-120B (4B~120B, 밀집과 MoE)
- **비교 대상:** 과제 특화(편집: ROME, MEMIT, AlphaEdit, FT-M, WISE / 조정: CAA 등 / 언러닝: GA, DPO 등), 증류(SDCD, SELF-PARAM, OPCD), 하이퍼네트워크(Doc2LoRA, SHINE), 테스트 시점 학습(LoCAS, δ-Mem), 외부 기억(MemP, ALFWorld만)
- **채점:** 사실 편집 자유 응답과 Power-seeking은 LLM 심사자, SimpleQA는 gpt-4.1-2025-04-14가 채점합니다(부록 B).

## 주요 결과

### 1. 15개 비교 판 전부에서 Cortex가 CR–RR 파레토 경계 위에 있다

본문 그림 5의 15개 과제·백본 조합 모두에서, CR과 RR이 모두 측정된 방법 가운데 Cortex 변형 중 적어도 하나가 실험적 CR–RR 파레토 경계에 놓였습니다. 부록까지 포함한 전체 설정에 대해서는 초록이 "대부분의 설정에서"라고 표현합니다. 대표 수치는 다음과 같습니다.

| 설정 (그림 5) | Cortex | 비교 |
|---|---|---|
| 페르소나 조정, Gemma3·Qwen2.5 | CR 약 95~100%, RR 99~100% | |
| 배치 편집, Qwen 백본 3종 | CR 약 80~91% | FT-M·MEMIT·AlphaEdit 중 최고치 36~46% |
| 배치 API, Qwen2.5 | CR 66~74%, RR 98~99% | OPCD 41%, SELF-PARAM 29%, SDCD 19% |
| 배치 편집, Qwen2.5 (Synaptic) | CR 91%, RR 98% | SDCD 63% / 94% |
| 단일 편집, Qwen3-4B-Instruct | CR 84~89%, RR 103~110% | Doc2LoRA CR 95%, RR 86% |

비교 대상의 실패 양상도 흥미롭습니다. 하이퍼네트워크 SHINE은 억제 과제에서 CR 100~103%를 냈지만 RR이 4~10%로 무너졌고, 테스트 시점 학습 LoCAS·δ-Mem은 RR 98~101%를 지키면서 CR은 −9~11%에 그쳤습니다. 저자들의 표현대로 **"원래 능력을 지켰다는 것만으로는 응고에 성공했다고 볼 수 없습니다."**

### 2. 사실 50개를 하나씩 써 넣어도 거의 잊지 않는다

Qwen2.5-14B-Instruct에 zsRE 사실 50개를 순서대로 편집한 연속 실험입니다(그림 6, 세 시드 평균).

| 방법 | 최종 CR | 최종 RR | 편집당 새로 학습하는 파라미터 |
|---|---|---|---|
| Cortex Structural (k=1) | **88.9%** | **99.8%** | 0.74M |
| Cortex Synaptic (r=1) | 80.6% | 97.2% | 2.73M |
| ROME (기준선 중 최고 CR) | 28.5% | | |
| AlphaEdit | 22.7% | 96.0% | |

AlphaEdit 수치는 초록의 "CR 66.2점, RR 3.8점 앞섰다"에서 역산한 값입니다. 기준선들이 편집마다 수정하는 파라미터는 그림 6b에 막대로 나오는데, 수십~수백 M 규모로 Cortex보다 훨씬 큽니다.

- 각 사실을 편집 직후와 50번째 시점에서 비교하면 Structural은 91.3% → 88.9%, Synaptic은 85.8% → 80.6%로 2.4점, 5.2점 떨어졌습니다. WISE는 52.0% → 28.0%로 24.0점 떨어졌습니다(그림 6c, 표 7).
- 처음 10개 사실은 이후 40번의 편집을 거친 뒤에도 평균 CR이 97.2%(Structural), 92.6%(Synaptic)로 유지됐습니다.
- 반복이나 길이 제한으로 끝난 응답 비율은 Structural 0.0%, Synaptic 0.8%였지만 FT-M·ROME·MEMIT·AlphaEdit는 86.2~91.3%였습니다(그림 6d). 기존 편집 방법이 50번 누적되면 모델 출력이 망가지는 경향이 드러난 셈입니다.
- 효력은 두 변형이 95.3%와 95.6%로 같았지만, 편집한 사실을 다른 추론에 쓰는 **이식성(portability)**은 49.4%와 30.7%로 크게 갈렸습니다. 답을 외우는 것보다 응용하는 것이 훨씬 어렵다는 뜻입니다.

### 3. 컨텍스트로 알려 준 것보다 더 잘할 때도, 오히려 나빠질 때도 있다

Qwen2.5 ALFWorld에서 Cortex는 CR 128~133%, RR 약 88%로, 경험 요약을 프롬프트에 직접 넣은 경우(RR 86%)보다 나았습니다. GPT-OSS-120B도 CR 101~104%였습니다(그림 5j, 5n). 같은 그림의 하단 띠에 표시된 외부 기억 방식 MemP의 CR은 Qwen2.5에서 87, GPT-OSS-20B에서 44였습니다.

반대 사례도 있습니다. GPT-OSS-20B τ²-Bench에서는 Structural이 CR 38.5%, Synaptic이 −92.3%였습니다. Synaptic의 성공률(56.3%)은 아무것도 안 한 모델(60.3%)보다 낮았는데 RR은 98.5%였습니다(부록 C). 같은 모델 ALFWorld에서도 두 변형의 CR은 97%, 101%로 비슷했지만 RR은 95%와 23%로 극단적으로 달랐습니다(그림 5o).

### 4. 배치와 선택적 억제가 약점이다

- **배치:** GPT-OSS-20B의 API 학습 CR은 단일(패키지마다 어댑터 하나) 91~93%에서 배치(15개를 한 모델에) 45~59%로 떨어졌습니다. 120B는 82~85% → 73~80%로 덜 떨어졌습니다(부록 C).
- **선택적 억제:** GPT-OSS-20B에서 특정 엔터티 응답 억제는 CR 97~100%였지만 RR은 76~83%였습니다. 이웃 지식(Neighbor L1/L2) 점수가 9~20점 떨어진 반면 BBH는 0.1~3.3점만 떨어졌습니다. 원하는 것만 정확히 잊게 하기가 어렵다는 뜻이고, 저자들도 "목표 답과의 겹침이 줄었다고 지식이 파라미터에서 지워졌다는 뜻은 아니다"라고 밝힙니다.
- **길이는 난이도를 설명하지 못합니다.** Qwen2.5 배치에서 약 599토큰 억제는 CR 35~57%, 809토큰 편집은 89~91%, 5,152토큰 API는 66~74%였습니다.

### 5. 절제 실험: 데이터보다 "어디에, 어떻게"가 중요하다

그림 7의 여섯 가지 연구 질문(RQ) 결과입니다.

| 질문 | 결과 |
|---|---|
| RQ1 데이터만의 효과인가 | 같은 Cortex 데이터로 LoRA-All을 KL 학습해도 Qwen2.5 배치 코드에서 Structural보다 CR 23.0점 낮음. CE보다 KL이 16.6점 높음(GPT-OSS-120B) |
| RQ2 어텐션도 고치면 | FFN만 고칠 때 연속 편집 CR·RR이 각각 3.8점, 4.0점 높음(r=4, KL) |
| RQ3 질의 재생 | 재생이 있으면 25번 후속 편집 뒤에도 96% 이상. 없으면 Structural 40.5%, Synaptic 8.0% |
| RQ4 은닉 상태 MSE | Synaptic r=4에서 RR +2.7, CR −4.0. Structural k=16에서는 둘 다 개선 |
| RQ5 MoE 공유 확장 | 총 학습 파라미터가 같을 때 CR이 ALFWorld +4.6, 코드 +10.3 (RR 약 1점 하락) |
| RQ6 용량을 키우면 | 가장 작은 용량(k=1, r=1)이 가장 높은 CR. 키운다고 좋아지지 않음 |

RQ3이 특히 중요합니다. **이전 파라미터를 얼려도 이전 행동은 얼려지지 않습니다.** 뒤에 붙은 업데이트가 얼린 모듈의 입력을 바꾸기 때문입니다. 과거 질문만 저장해 두고 다시 학습하는 재생이 이 간섭을 막는 핵심이었습니다.

## 한계

**저자가 밝힌 한계 (6~7장)**

- Structural 확장은 표준 FFN에 접어 넣어도 **파라미터 수 자체는 줄지 않습니다.** 업데이트가 쌓이면 배포 모델이 계속 커지므로, 가지치기나 증류로 재정리하는 단계가 필요하다고 봅니다.
- 쓰는 파라미터는 작아도 학습은 백본 전체를 통과해야 하므로 큰 모델에서는 계산이 여전히 비쌉니다.
- 무엇을 응고할지 경험을 검증하는 문제, 사용자별 정보를 얼마나 남기고 공유할지 통제하는 문제는 범위 밖입니다.
- 과제를 넘나드는 연속 응고와 대규모 배치 응고는 향후 과제입니다.

**읽으면서 발견한 한계 (필자 판단)**

- **컨텍스트를 사람이 모델마다 손으로 만들었습니다.** 격차가 크게 나는 컨텍스트를 골랐기 때문에 실제 운영에서 쌓이는 잡다한 대화 기록에도 같은 효과가 나는지는 알 수 없습니다.
- **연속 실험은 하나의 모델, 하나의 데이터(zsRE 사실 50개)뿐입니다.** 헤드라인 수치(88.9%, 99.8%)가 이 설정에서 나왔고, 다른 과제의 연속 결과는 보고되지 않았습니다.
- **학습 비용(GPU 시간)을 보고하지 않았습니다.** 설정표에는 연속 편집 1회당 30 에폭, 배치 설정에서 50~200 에폭(표 5, 8) 같은 값이 있어 사실 하나 쓰는 데 드는 시간이 짧지 않을 것으로 보이지만 수치는 없습니다.
- **RAG와의 직접 비교가 거의 없습니다.** 외부 기억 기준선은 ALFWorld의 MemP 하나이고, 긴 컨텍스트를 그대로 넣는 "Context" 조건이 기준점 역할을 합니다.
- 여러 점수가 LLM 심사자에 의존하고, 코드가 아직 공개되지 않아 독립 재현이 불가능합니다(2026-10-24 기준).

## 인사이트

**왜 지금 중요한가: 기억을 "어디에 둘까"의 세 번째 선택지.** 장기 실행 에이전트의 기억 문제는 지금까지 주로 컨텍스트 창 안에서 풀어 왔습니다. 긴 컨텍스트에 다 넣거나, 검색해서 필요한 것만 넣거나, 오래된 이력을 요약·압축해 넣는 식입니다. Cortex는 아예 창 밖, 가중치에 둡니다. 차이를 정리하면 다음과 같습니다.

| 방식 | 기억 위치 | 추론 비용 | 갱신·삭제 | 대표적 위험 |
|---|---|---|---|---|
| 긴 컨텍스트 | 프롬프트 원문 | 길이에 비례해 매 호출 증가 | 텍스트 수정이면 끝 | 비용, 중간 내용 놓침 |
| RAG | 외부 저장소 | 검색 + 일부 토큰 | 문서 교체·삭제로 즉시 | 관련성이 질의에 드러나지 않으면 못 찾음 |
| 컨텍스트 압축(요약, 소프트 토큰) | 압축된 텍스트·벡터 | 압축본만큼 | 다시 압축 | 압축 중 정보 손실 |
| 가중치 응고(Cortex) | FFN 파라미터 | 추가 토큰 없음 | **재학습 필요** | 망각, 간섭, 되돌리기 어려움 |

표의 앞 세 줄은 일반적으로 알려진 특징 기준입니다. 저자들이 응고의 장점으로 내세우는 것은 "검색하려면 관련성을 먼저 알아야 하지만, 가중치에 녹은 경험은 중간 추론 과정에 저절로 영향을 줄 수 있다"는 점입니다. 다만 저자들 스스로 이것이 **검증되지 않은 가설**이라고 적고 있습니다. 같은 날 소개하는 [Remory](/papers/2026/10/24/remory-context-compaction.html)가 고정 모델에 학습된 소프트 토큰을 붙여 컨텍스트를 줄이는 쪽이라면, Cortex는 컨텍스트를 아예 없애고 모델을 바꾸는 쪽입니다. 둘 다 "컨텍스트 효과를 학습으로 옮긴다"는 점은 같지만, Remory는 모델을 고정하고 Cortex는 모델을 바꾼다는 점에서 운영상 무게가 전혀 다릅니다.

**실무에 주는 의미: 응고는 "자주 바뀌지 않고, 틀려도 감당할 수 있는" 지식에만.** 가중치에 쓴 기억은 지우기 어렵습니다. Cortex는 업데이트마다 별도 어댑터를 쌓기 때문에 접어 넣기 전이라면 특정 어댑터를 빼는 선택지가 있겠지만, 논문은 그렇게 되돌렸을 때의 효과를 실험하지 않았습니다. 게다가 RQ3이 보여 주듯 뒤의 업데이트가 앞의 기억에 간섭하므로, 중간 어댑터 하나를 뺀 모델이 어떻게 동작할지는 보장되지 않습니다. 그래서 필자의 판단으로는 현재 단계에서 응고에 어울리는 대상은 이런 것들입니다. 팀 내부 API 사용법이나 도구 호출 형식처럼 오래 유지되는 **절차 지식**, 에이전트가 반복해서 배우는 실수 패턴 같은 **경험 요약**. 반대로 가격, 재고, 사람 정보처럼 자주 바뀌거나 삭제 요청(개인정보 등)에 대응해야 하는 정보는 여전히 RAG처럼 지울 수 있는 곳에 두는 편이 안전합니다. ALFWorld에서 CR이 100%를 넘은 결과는 고무적이지만, 같은 표에서 τ²-Bench의 −92.3%도 함께 봐야 합니다. 도입한다면 CR뿐 아니라 "아무것도 안 한 모델보다 나빠지지 않았는지"를 별도로 확인해야 합니다.

**블로그의 기존 글과의 연결.** Synaptic 변형은 사실상 [LoRA](/papers/2026/10/24/lora.html)를 FFN에만 랭크 1로 거는 것입니다. LoRA 글에서 다룬 "저랭크 증분을 원래 가중치에 병합할 수 있다"는 성질이 여기서 "기억을 표준 모델 구조 안에 남긴다"는 의미로 다시 쓰입니다. 흥미로운 점은 RQ1·RQ2가 LoRA의 고전적 사용법(어텐션 포함, 정답 문자열 CE 학습)이 응고에는 덜 맞는다는 근거를 준다는 것입니다. 또 [RAG](/papers/2026/10/24/rag.html) 원 논문은 파라메트릭 기억(모델 가중치)과 비파라메트릭 기억(검색 색인)을 결합하자는 제안이었는데, Cortex는 그 반대 방향, 즉 비파라메트릭으로 주던 것을 다시 파라메트릭으로 옮기는 시도입니다. RAG가 "지식을 갈아 끼우기 쉽게" 하려고 가중치 밖으로 뺐던 이유가 그대로 Cortex의 약점(갱신·삭제의 어려움)이 된다는 점이 두 글을 함께 읽을 때의 핵심입니다.

**한계와 반론: "망각이 적다"의 범위.** 헤드라인 RR 99.8%는 MMLU 부분집합, SimpleQA, GSM8K, 지역성의 평균입니다. 억제 실험에서 BBH는 거의 그대로인데 이웃 지식은 9~20점 떨어진 것처럼, **넓은 벤치마크로 재는 유지율은 가까운 지식의 손상을 가릴 수 있습니다.** 실제 운영에서 문제가 되는 망각은 대개 "관련 있지만 바꾸면 안 되는" 근처 지식이므로, 응고를 도입할 때는 일반 벤치마크보다 목표 주변의 회귀 테스트를 먼저 만들어야 합니다.

**앞으로 지켜볼 점.** (1) 코드와 테스트베드가 실제로 공개되어 독립 재현이 나오는지. (2) 50개를 넘어 수백·수천 번 업데이트할 때 Structural 확장이 계속 늘어나는 문제를 저자들이 예고한 가지치기·병합으로 해결하는지. (3) 저자들이 향후 과제로 든 "컨텍스트에서 Structural 파라미터를 바로 예측하는 하이퍼네트워크"가 나오면, 응고 비용이 학습에서 추론 한 번 수준으로 떨어집니다. 그때는 위 비교표의 "재학습 필요" 칸이 바뀌므로 판단도 달라질 수 있습니다. (4) 특정 기억만 골라 되돌리는 실험이 나오는지. 이것이 가능해야 가중치 기억을 운영 환경에 둘 수 있습니다.

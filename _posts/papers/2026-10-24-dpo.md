# [논문 소개] DPO: 보상 모델과 강화학습 없이 선호 데이터로 바로 정렬하기

- **논문:** *Direct Preference Optimization: Your Language Model is Secretly a Reward Model*
- **저자:** Rafael Rafailov, Archit Sharma, Eric Mitchell, Stefano Ermon, Christopher D. Manning, Chelsea Finn (총 6명), Stanford University, CZ Biohub
- **공개:** 2023년 5월 29일, arXiv:2305.18290 (cs.LG). NeurIPS 2023 본 학회(Main Conference Track) 게재, 같은 학회 Outstanding Main Track Runner-Up 수상
- **링크:** [arXiv](https://arxiv.org/abs/2305.18290) · [PDF](https://arxiv.org/pdf/2305.18290) · [HTML(v3)](https://arxiv.org/html/2305.18290v3) · [NeurIPS 프로시딩](https://proceedings.neurips.cc/paper_files/paper/2023/hash/a85b405ed65c6477a4fe8302b5e06ce7-Abstract-Conference.html) · [참조 구현](https://github.com/eric-mitchell/direct-preference-optimization)

이 글의 표·그림 번호와 수치는 arXiv v3(2024년 7월 29일 개정판) 기준입니다.

## 한 줄 요약

**RLHF가 풀던 "KL 제약 아래 보상 최대화" 문제를, 보상 모델과 강화학습 없이 선호/비선호 응답 쌍에 대한 이진 분류 손실 하나로 똑같이 풀 수 있다는 논문입니다.** 학습 루프 안에서 샘플을 생성할 필요가 없어 구현과 튜닝이 훨씬 쉬워졌고, 이 단순함 덕분에 오픈 모델 후학습(post-training)의 표준 도구 중 하나가 됐습니다.

## 왜 이 연구가 필요한가

2022년 [InstructGPT 논문](/papers/2026/10/24/instructgpt.html)이 정리한 RLHF(사람 피드백 기반 강화학습, Reinforcement Learning from Human Feedback)는 보통 세 단계입니다(논문 3절).

1. **SFT(지도 미세조정):** 좋은 예시 응답으로 사전학습 모델을 미세조정해 `π_SFT`를 만듭니다.
2. **보상 모델 학습:** 같은 프롬프트에 대한 응답 두 개 중 사람이 더 나은 쪽을 고르게 하고, 이 비교 데이터로 응답에 점수를 매기는 보상 모델 `r_φ`를 학습합니다. 비교 확률은 Bradley-Terry 모델(두 후보의 점수 차이로 "A가 B보다 나을 확률"을 표현하는 고전적 모델)로 씁니다.
3. **강화학습:** 정책(학습 중인 언어 모델)이 보상을 최대화하되 참조 모델 `π_ref`(보통 SFT 모델)에서 너무 멀어지지 않도록 KL 발산(두 확률 분포의 차이) 벌점을 붙여 PPO로 최적화합니다.

저자들은 이 파이프라인이 "지도학습보다 훨씬 복잡하고, 여러 언어 모델을 학습해야 하며, 학습 루프 안에서 정책으로부터 샘플링해야 해서 계산 비용이 크다"고 지적합니다(1절). PPO는 하이퍼파라미터에 민감하기로도 유명합니다. 논문의 질문은 단순합니다. **같은 목적함수를 강화학습 없이 풀 수는 없을까?**

## 제안 방법

### 핵심 아이디어: 보상을 정책으로 다시 쓰기

RLHF 3단계의 목적함수(식 3)는 "보상 기댓값 − β × KL(정책 ∥ 참조 모델)"입니다. 이 문제의 최적 정책은 이미 닫힌 형태로 알려져 있습니다(식 4).

```text
π*(y|x) = (1/Z(x)) · π_ref(y|x) · exp(r(x,y) / β)
```

문제는 정규화 상수 `Z(x)`(모든 가능한 응답에 대한 합)를 계산할 수 없다는 점입니다. DPO는 이 식을 거꾸로 뒤집어 **보상을 정책으로 표현**합니다(식 5).

```text
r(x,y) = β · log( π(y|x) / π_ref(y|x) ) + β · log Z(x)
```

Bradley-Terry 모델은 두 응답의 **보상 차이**만 보기 때문에, 이 식을 넣으면 같은 프롬프트에서 공통인 `β log Z(x)`가 정확히 상쇄됩니다. 그 결과 선호 확률을 정책과 참조 모델만으로 쓸 수 있고(식 6), 보상 모델 학습 때 쓰던 음의 로그 우도 손실(식 2)을 그대로 정책에 적용하면 DPO 손실이 됩니다(식 7).

```text
L_DPO = − E[ log σ( β · log(π_θ(y_w|x) / π_ref(y_w|x))
                  − β · log(π_θ(y_l|x) / π_ref(y_l|x)) ) ]
```

여기서 `y_w`는 사람이 고른(선호) 응답, `y_l`은 고르지 않은(비선호) 응답, `σ`는 시그모이드 함수입니다. 제목의 "언어 모델은 사실 보상 모델"이라는 말은 `β · log(π_θ / π_ref)`가 그대로 **암묵적 보상(implicit reward)** 역할을 한다는 뜻입니다. 저자들은 이 재매개변수화가 표현할 수 있는 보상 함수의 범위를 줄이지 않는다는 것도 증명합니다(5.1절 정리 1).

### 손실을 쉬운 말로 풀면

- **무엇을 비교하나:** 선호 응답과 비선호 응답 각각에 대해 "학습 중인 모델이 참조 모델보다 그 응답을 얼마나 더(또는 덜) 그럴듯하게 보는가"를 로그 비율로 구합니다. 손실은 이 두 값의 **차이**를 키우는 방향으로 작동합니다. 선호 응답의 확률을 절대적으로 올리는 것이 아니라, 참조 모델 대비 상대적인 간격을 벌리는 것입니다.
- **β의 역할:** RLHF의 KL 벌점 계수와 같은 자리입니다. 원 목적함수에서 β가 크면 참조 모델에서 덜 벗어나도록 묶는 힘이 커집니다. 손실 식에서는 로그 비율 차이에 곱해지는 배율로 나타납니다.
- **참조 모델의 역할:** 기준점입니다. 참조 모델과 똑같은 상태에서 출발하면 두 로그 비율이 모두 0이라 손실은 `log 2 ≈ 0.693`입니다. 선호 데이터가 참조 모델의 분포에서 나왔다는 가정이 깔려 있어, 저자들은 가능하면 `π_ref = π_SFT`로 두고, SFT 모델이 없으면 선호 응답만으로 먼저 미세조정해 참조 모델을 만들라고 권합니다(4절 "DPO outline").
- **틀린 쌍에 더 큰 가중치:** 그래디언트를 풀어 보면 각 쌍은 `σ(r̂(y_l) − r̂(y_w))`만큼 가중됩니다. 암묵적 보상이 순서를 틀리게 매긴 쌍일수록 크게 고칩니다. 저자들은 이 가중치 없이 단순히 선호 응답 확률을 올리고 비선호 응답 확률을 내리는 방식(unlikelihood)은 모델이 망가진다고 보고합니다(부록 표 3, 부록 C.3).

### 직접 돌려 본 손실 계산

부록 B에는 PyTorch로 쓴 DPO 손실 함수가 10줄 남짓으로 실려 있습니다. 이 함수를 그대로 옮겨 임의의 시퀀스 로그 확률을 넣어 보면 위 직관을 숫자로 확인할 수 있습니다. 아래는 필자가 2026-10-24에 PyTorch 2.7.1로 직접 실행한 결과입니다(참조 모델의 로그 확률은 선호 −40, 비선호 −42로 고정).

| 정책 상태 | β | 손실 | 암묵적 보상 (선호, 비선호) | 그래디언트 가중치 |
|---|---|---|---|---|
| 학습 전(참조와 같음) | 0.1 | 0.693 | (0.00, 0.00) | 0.500 |
| 선호 −38, 비선호 −47 | 0.1 | 0.403 | (0.20, −0.50) | 0.332 |
| 선호 −38, 비선호 −47 | 0.5 | 0.030 | (1.00, −2.50) | 0.029 |
| 선호 −44, 비선호 −40(순서 뒤집힘) | 0.1 | 1.037 | (−0.40, 0.20) | 0.646 |
| 선호 −44, 비선호 −40(순서 뒤집힘) | 0.5 | 3.049 | (−2.00, 1.00) | 0.953 |

순서를 맞게 매긴 쌍은 가중치가 작아지고, 뒤집힌 쌍은 가중치가 1에 가까워집니다. 같은 로그 확률 변화라도 β가 크면 손실이 더 빨리 포화되므로, 참조 모델에서 조금만 움직여도 "충분하다"고 판단하게 됩니다. β가 이탈을 억제하는 계수라는 말을 이렇게 이해할 수 있습니다.

## 주요 결과

### 1. 같은 목적함수를 PPO보다 효율적으로 최적화한다 (그림 2 왼쪽)

감성 과제는 실제 보상 함수를 알기 때문에, 알고리즘이 "보상을 얼마나 얻으면서 참조 모델에서 얼마나 벗어났는지"를 정확히 잴 수 있습니다. 저자들은 PPO의 목표 KL(3, 6, 9, 12), DPO의 β(0.05, 0.1, 1, 5) 등을 바꿔 총 22번 학습하고 100스텝마다 평가했습니다. 결과는 **모든 KL 구간에서 DPO가 가장 높은 보상**을 얻었고, 저자 표현으로 "DPO의 보상/KL 절충이 PPO를 엄격하게 지배"했습니다. 실제 보상에 접근하는 PPO-GT보다도 경계선이 좋았습니다.

### 2. 요약: PPO보다 높은 승률, 온도 변화에도 안정적 (그림 2 오른쪽)

TL;DR 요약에서 DPO는 샘플링 온도 0.0에서 **약 61%**의 승률(사람 작성 요약 대비)을 기록해, 최적 온도(0.0)에서의 PPO **약 57%**를 넘었습니다. Best of N 기준선보다 최고 승률도 높았습니다. PPO는 온도가 높아지면 기본 GPT-J 수준까지 떨어진 반면 DPO는 온도 변화에 훨씬 덜 민감했습니다. 저자들은 DPO의 β를 "의미 있게 튜닝하지 않았다"고 밝혀, 이 수치가 상한이 아니라고 봅니다.

### 3. 대화: 데이터셋의 선호 응답을 넘은 유일한 효율적 방법 (그림 3)

Anthropic HH 단일 턴 대화에서 DPO는 테스트셋의 선호 응답 대비 승률이 50%를 넘은 유일한 "계산 효율적인" 방법이었고, 응답 128개를 뽑아 고르는 Best of 128과 비슷하거나 더 나았습니다. 흥미로운 대목은 PPO입니다. 저자들은 공개된 HH용 PPO 모델(Pythia-6B 기반)로 어떤 프롬프트와 온도를 써도 기본 Pythia-2.8B보다 나은 결과를 얻지 못했다고 적고, 그래서 Best of 128을 PPO 수준의 대리 지표로 삼았습니다. 학습 과정에서도 DPO는 비교적 빨리 최고 성능에 수렴했습니다(그림 3 오른쪽).

### 4. 분포가 바뀌어도 PPO보다 낫다 (표 1)

Reddit 요약으로 학습한 정책을 CNN/DailyMail 뉴스 기사 요약에 그대로 적용했습니다.

| 방법 | 온도 0 | 온도 0.25 |
|---|---|---|
| DPO | 0.36 | 0.31 |
| PPO | 0.26 | 0.23 |

(정답 요약 대비 GPT-4 승률, 표 1) PPO는 레이블 없는 Reddit 프롬프트를 추가로 쓰는데도 DPO가 앞섰습니다. 다만 저자들도 이를 "초기 증거"라고만 표현합니다.

### 5. GPT-4 판정은 사람과 비슷하게 일치한다 (표 2)

GPT-4 승률을 믿을 수 있는지 사람 평가로 확인했습니다. 모두 온도 0의 PPO와 비교한 결과입니다.

| 비교 대상 | DPO (온도 0.25) | SFT (온도 0.25) | PPO-1 (온도 1.0) |
|---|---|---|---|
| 응답자 수 | 272 | 122 | 199 |
| GPT-4 (S) 승률 | 47% | 27% | 13% |
| GPT-4 (C) 승률 | 54% | 32% | 12% |
| 사람 승률 | 58% | 43% | 17% |
| GPT-4 (C)와 사람 일치율 | 67% | 79% | 85% |
| 사람끼리 일치율 | 65% | - | 87% |

사람 평가에서 DPO 요약은 PPO 요약보다 **58%** 선호됐습니다. 또 GPT-4와 사람의 일치율이 사람끼리의 일치율과 비슷해 GPT-4를 대리 평가자로 쓸 근거가 됐습니다. 눈여겨볼 점은 프롬프트 차이입니다. 단순 프롬프트(S)를 쓰면 GPT-4가 사람보다 길고 반복적인 요약을 선호해서, "간결함"을 명시한 프롬프트(C)를 본 결과에 썼다고 밝힙니다.

## 한계

**저자가 밝힌 한계(7절)**

- 명시적 보상 모델로 학습한 정책과 비교해 분포 밖 일반화가 어떤지는 더 연구가 필요합니다.
- DPO 설정에서 보상 과최적화(reward over-optimization)가 어떻게 나타나는지 모릅니다. 그림 3 오른쪽에서 학습 후반에 성능이 약간 떨어지는 것이 그 예일 수 있다고 적었습니다.
- 실험한 모델은 최대 6B 파라미터입니다.
- GPT-4 승률이 판정 프롬프트에 따라 달라집니다.

**읽으면서 발견한 한계(필자 판단)**

- **오프라인 학습입니다.** DPO는 이미 모아 둔 선호 쌍으로만 학습하므로, 학습 중 정책이 새로 만드는 응답에 대한 피드백을 받지 않습니다. 저자들도 선호 데이터가 참조 모델 분포에서 나왔다고 가정하고, 공개 데이터셋을 재사용할 때 생기는 분포 차이를 SFT로 줄이라고 권하는 수준에 그칩니다.
- **PPO 기준선이 약했을 수 있습니다.** 대화 과제에서는 PPO 모델이 기본 모델보다도 나쁘게 나와 Best of 128로 대신했습니다. "DPO가 PPO보다 낫다"는 결론의 일부는 PPO를 잘 튜닝하기 어렵다는 사실 자체에 기대고 있습니다.
- **평가가 GPT-4 승률 중심입니다.** 사람 평가는 요약 과제 한 곳, 응답자 수백 명 규모에서만 이뤄졌습니다.

## 인사이트

**왜 오픈 모델 후학습에 널리 퍼졌나.** 논문이 강조한 "RL이 필요 없다"보다 실무에서 더 컸던 것은, **학습이 지도학습과 같은 모양이 됐다**는 점으로 보입니다. 정책 모델과 고정된 참조 모델 두 개만 있으면 되고, 보상 모델과 가치 함수(critic)를 따로 띄우거나 학습 중 생성을 돌릴 필요가 없습니다. 선호 쌍 데이터만 있으면 기존 SFT 인프라 위에서 돌릴 수 있었습니다. 실제 확산 속도도 빨랐습니다. 2023년 10월 Zephyr-7B는 교사 모델이 순위를 매긴 AI 피드백 데이터로 DPO(논문 표현으로 dDPO)를 적용해 "사람 주석 없이" MT-Bench에서 Llama2-Chat-70B를 넘었다고 보고했고([arXiv:2310.16944](https://arxiv.org/abs/2310.16944)), 같은 해 11월 Tulu 2는 "지금까지 가장 큰 DPO 학습 모델"이라며 70B 모델을 공개했습니다([arXiv:2311.10702](https://arxiv.org/abs/2311.10702)). 2024년 7월 Llama 3 기술 보고서는 후학습 각 라운드를 SFT 뒤 DPO로 구성했고, PPO 같은 온폴리시(on-policy) 알고리즘도 시험했지만 "DPO가 대형 모델에서 계산이 덜 들고 성능도 더 좋았다, 특히 IFEval 같은 지시 따르기 벤치마크에서"라고 적었습니다([arXiv:2407.21783](https://arxiv.org/abs/2407.21783), 4.1.4절).

**실무에서 원 논문 그대로 쓰지는 않는다.** Llama 3 보고서는 DPO를 그대로 쓰지 않고 두 가지를 고쳤습니다(4.1.4절). 첫째, 헤더나 종료 토큰 같은 서식 토큰을 손실에서 가렸습니다. 선호와 비선호 응답에 똑같이 들어 있는 토큰을 동시에 올리고 내려야 하는 모순 때문에 꼬리 반복이나 갑작스런 종료 같은 문제가 생겼다고 합니다. 둘째, 선호 응답에 대한 음의 로그 우도(NLL) 손실을 0.2 배율로 더해 선호 응답의 로그 확률이 오히려 떨어지는 현상을 막았습니다. 학습률 1e-5, β=0.1이었습니다. **DPO가 선호 응답의 확률을 직접 올리지 않고 "간격"만 벌린다는 성질은, 두 응답 확률이 함께 떨어지는 방향으로도 손실을 줄일 수 있다는 뜻입니다.** TRL 문서도 "실제로는 선호 응답의 확률을 높이기보다 비선호 응답의 확률을 낮추는 방식으로 달성되는 경우가 많다"고 적고 있습니다. 학습 중 `logps/chosen`이 계속 떨어진다면 이 현상을 의심해 볼 만합니다.

**한계와 반론: 후속 연구가 짚은 것.** 원문을 확인한 두 편만 정리합니다.

| 후속 연구 | 무엇을 지적했나 | 제안 |
|---|---|---|
| IPO ([arXiv:2310.12036](https://arxiv.org/abs/2310.12036), 2023-10-18, Google DeepMind 저자진) | 선호가 결정적(한쪽이 항상 이김)이거나 데이터가 적어 경험적 선호 확률이 1이 되면, 최적해가 비선호 응답 확률을 0으로 보내 β와 상관없이 KL 정규화가 무력해집니다. RLHF는 보상 모델이 덜 적합(underfit)되면서 오히려 이 정규화를 얻는데, DPO는 보상 모델을 건너뛰어 그 효과를 잃는다고 분석합니다(4.2절). | 선호 확률에 로그 오즈 대신 항등 함수를 쓰는 ΨPO의 특수형 IPO |
| KTO ([arXiv:2402.01306](https://arxiv.org/abs/2402.01306), 2024-02-02, ICML 2024) | DPO 같은 손실이 성공한 이유 일부를 전망 이론(prospect theory)의 인간 편향으로 설명하고, 쌍 대신 "좋다/나쁘다" 이진 신호만으로 학습합니다. | 1B~30B 규모에서 DPO와 같거나 나은 성능, 좋은 예시를 최대 90% 적게 써도 DPO 수준, 사전학습 모델이 충분히 좋으면 SFT를 건너뛸 수 있다고 보고(DPO는 SFT가 늘 필요) |

두 연구 모두 저자들이 같은 문제를 다른 손실로 푼 결과이고, KTO 저자들도 "보편적으로 우월한 손실은 없다"고 결론 냅니다. 필자의 판단으로는, DPO 이후의 흐름은 "DPO를 대체하는 하나의 정답"이 아니라 데이터 형태(쌍인가, 단일 평가인가)와 노이즈 정도에 맞춰 손실을 고르는 쪽으로 정리되고 있습니다. TRL의 `loss_type` 목록이 IPO, Robust DPO, SimPO 등 10개가 넘는 변형을 같은 트레이너 안에 두고 있는 것이 그 상징입니다.

**실무에 주는 의미: TRL로 써 보기.** Hugging Face TRL의 `DPOTrainer`가 가장 흔한 출발점입니다. 아래는 [TRL 공식 문서](https://huggingface.co/docs/trl/dpo_trainer)의 빠른 시작 예제와 `DPOConfig` 소스(v1.16.0, 2026-10-15 릴리스)를 바탕으로 정리한 것입니다. **필자가 실제 학습까지 돌려 보지는 않았습니다.**

```python
from datasets import load_dataset
from trl import DPOConfig, DPOTrainer

# 데이터 한 건의 형식: {"prompt": [...], "chosen": [...], "rejected": [...]}
dataset = load_dataset("trl-lib/ultrafeedback_binarized", split="train")

args = DPOConfig(
    output_dir="qwen3-dpo",
    beta=0.1,             # 기본값 0.1. 클수록 참조 모델에서 덜 벗어남
    learning_rate=1e-6,   # DPOConfig 기본값(일반 Trainer 기본 5e-5보다 훨씬 작음)
    loss_type="sigmoid",  # 원 논문 손실. "ipo" 등으로 바꿀 수 있음
)

trainer = DPOTrainer(
    model="Qwen/Qwen3-0.6B",  # ref_model을 주지 않으면 학습 시작 전 상태의 모델을 참조로 씀
    args=args,
    train_dataset=dataset,
)
trainer.train()
```

문서 기준으로 데이터는 `prompt`/`chosen`/`rejected` 열을 가진 선호 데이터셋이어야 하고, 대화 형식이면 채팅 템플릿을 자동 적용합니다. 학습 중에는 `rewards/chosen`, `rewards/rejected`(각각 `β log(π_θ/π_ref)`), `rewards/margins`, `rewards/accuracies`(선호 응답의 암묵적 보상이 더 높은 비율)가 기록되므로, 이 네 값을 보면 위에서 말한 "간격만 벌어지는" 현상을 바로 확인할 수 있습니다. 참조 모델을 메모리에 계속 올려 두기 부담스러우면 `precompute_ref_log_probs=True`로 참조 로그 확률을 미리 계산해 둘 수 있고, LoRA 같은 PEFT 어댑터 학습도 지원합니다.

**블로그의 기존 글과의 연결.** [InstructGPT 소개](/papers/2026/10/24/instructgpt.html)가 RLHF 3단계의 원형을 보여 줬다면, DPO는 그중 2단계(보상 모델)와 3단계(PPO)를 하나로 접은 논문입니다. 두 글을 이어 읽으면 "사람 선호를 모으는 방법"은 그대로 두고 "그 선호를 모델에 넣는 방법"만 바뀐 흐름이 보입니다. 한편 이 논문의 결과 대부분이 GPT-4 판정 승률이라는 점, 그리고 판정 프롬프트 하나 바꿨다고 승률이 47%에서 54%로 움직였다는 점(표 2)은 LLM 판정을 평가에 쓸 때의 주의점을 미리 보여 준 사례이기도 합니다.

**앞으로 지켜볼 점.** (1) 오프라인 DPO와 온라인·온폴리시 방법의 경계입니다. Llama 3도 "최근 라운드의 최고 모델로 모은 선호 데이터"를 써서 학습 데이터를 정책 분포에 가깝게 맞췄습니다. 데이터 수집을 반복하는 순간 DPO는 사실상 반복형(iterative) 방법이 되므로, 앞으로의 비교는 손실 함수보다 데이터를 얼마나 자주 새로 모으느냐에서 갈릴 가능성이 큽니다. (2) 정답을 자동으로 검증할 수 있는 과제에서는 강화학습이 다시 쓰이고 있습니다. 예를 들어 DeepSeek-R1 논문은 사람이 단 추론 과정 없이 "순수 강화학습"만으로 추론 능력을 끌어냈고, 그 결과가 수학·코딩처럼 "검증 가능한 과제"에서 뛰어났다고 보고합니다([arXiv:2501.12948](https://arxiv.org/abs/2501.12948)). 필자의 판단으로는 DPO는 "취향과 문체를 맞추는 단계"의 기본값으로, 강화학습은 "정답이 있는 능력을 끌어올리는 단계"의 도구로 역할이 나뉘는 쪽에 가깝습니다. 이 구분이 맞는지는 공개 모델들의 후학습 보고서가 계속 보여 줄 것입니다.

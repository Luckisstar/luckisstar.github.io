# [논문 소개] ReAct: 생각하고, 행동하고, 관찰하는 루프로 LLM 에이전트의 원형을 만들다

- **논문:** *ReAct: Synergizing Reasoning and Acting in Language Models*
- **저자:** Shunyu Yao 외 (총 7명), Princeton University 컴퓨터과학과, Google Research Brain team
- **공개:** 2022년 10월 6일, arXiv:2210.03629 (cs.CL). ICLR 2023 학회 논문이며, v3(2023년 3월 10일)가 학회 최종본입니다.
- **링크:** [arXiv](https://arxiv.org/abs/2210.03629) · [PDF](https://arxiv.org/pdf/2210.03629) · [프로젝트 페이지](https://react-lm.github.io/) · [코드](https://github.com/ysymyth/ReAct)
- **참고:** 주 실험 모델 PaLM-540B는 논문 당시 공개되지 않은 모델입니다. 저자들은 재현성을 위해 프롬프트 전문과 GPT-3(text-davinci-002) 결과, 코드를 함께 공개했습니다.

## 한 줄 요약

**LLM이 "생각(Thought)"과 "행동(Action)"을 번갈아 쓰고, 행동의 결과인 "관찰(Observation)"을 다시 읽게 하면 추론만 하거나 행동만 할 때보다 사실에 근거하고 해석 가능한 문제 풀이가 된다는 논문입니다.** 오늘날 도구 호출 에이전트가 도는 "모델 요청 → 도구 실행 → 결과 반환" 루프의 원형으로 자주 인용됩니다.

## 왜 이 연구가 필요한가

2022년 무렵 LLM 연구는 두 갈래로 나뉘어 있었습니다.

- **추론(reasoning):** CoT(사고 사슬, Chain-of-Thought) 프롬프팅처럼 모델이 중간 풀이를 글로 쓰게 하는 방식입니다. 저자들은 이것을 "정적인 블랙박스"라고 부릅니다. 모델이 자기 내부 지식만으로 생각하기 때문에 외부 세계에 근거하지 못하고, 사실 환각(hallucination)과 오류 전파가 생깁니다.
- **행동(acting):** WebGPT, SayCan처럼 LLM으로 행동이나 계획을 생성하는 방식입니다. 하지만 이 방식들은 높은 수준의 목표를 추상적으로 추론하거나, 행동을 돕는 작업 기억(working memory)을 유지하는 데 언어 모델을 쓰지 않았습니다.

논문의 질문은 단순합니다. **사람이 요리하면서 "다 썰었으니 물을 올려야지", "소금이 없으니 간장을 쓰자"라고 속으로 생각하며 움직이듯, LLM도 추론과 행동을 섞으면 서로를 도울 수 있는가?** 저자들은 추론이 행동 계획을 세우고 고치는 데 쓰이고("reason to act"), 행동이 추론에 필요한 정보를 가져오는("act to reason") 상승 효과를 노립니다.

## 제안 방법

### 1. 행동 공간에 "언어"를 더한다

논문은 에이전트를 일반적인 형태로 정의합니다. 시점 t에 환경에서 관찰 o를 받고, 지금까지의 맥락 c를 보고 행동 a를 고릅니다. ReAct의 아이디어는 이 행동 공간 A에 **언어 공간 L을 더하는 것**(Â = A ∪ L)입니다.

언어 공간의 행동, 즉 **생각(thought)**은 환경을 바꾸지 않으므로 관찰도 돌아오지 않습니다. 대신 현재 맥락을 정리해 다음 추론이나 행동을 돕습니다. 논문이 예로 드는 생각의 종류는 다음과 같습니다.

- 목표를 쪼개고 행동 계획 세우기 ("x를 검색하고, y를 찾은 뒤, z를 찾아야 한다")
- 관찰에서 중요한 부분 뽑기 ("x는 1844년에 시작됐다")
- 상식이나 산술 추론 ("1844 < 1989")
- 진행 상황 추적과 계획 전환
- 예외 처리와 검색어 바꾸기 ("대신 x를 찾아보자")

### 2. 학습 없이 프롬프트만으로

ReAct는 모델을 학습시키지 않습니다. 동결된(frozen) PaLM-540B에 사람이 직접 쓴 **풀이 궤적(trajectory) 몇 개**를 퓨샷(few-shot, 프롬프트 안의 소수 예시) 예시로 넣을 뿐입니다. HotpotQA는 6개, FEVER는 3개 예시를 썼고, 저자들은 예시를 더 늘려도 성능이 오르지 않았다고 적었습니다. 의사결정 과제는 1~2개 예시로 충분했습니다.

부록 C.1에 실린 HotpotQA 예시 하나를 그대로 옮기면 다음과 같습니다.

```text
Question     Musician and satirist Allie Goertz wrote a song about the "The Simpsons"
             character Milhouse, who Matt Groening named after who?
Thought 1    The question simplifies to "The Simpsons" character Milhouse is named after
             who. I only need to search Milhouse and find who it is named after.
Action 1     Search[Milhouse]
Observation 1 Milhouse Mussolini Van Houten is a recurring character in the Fox animated
             television series The Simpsons voiced by Pamela Hayden and created by Matt
             Groening.
Thought 2    The paragraph does not tell who Milhouse is named after, maybe I can look up
             "named after".
Action 2     Lookup[named after]
Observation 2 (Result 1 / 1) Milhouse was named after U.S. president Richard Nixon, whose
             middle name was Milhous.
Thought 3    Milhouse was named after U.S. president Richard Nixon, so the answer is
             Richard Nixon.
Action 3     Finish[Richard Nixon]
```

모델은 `Thought`와 `Action` 줄을 생성하고, `Observation` 줄은 프로그램이 실제로 위키백과 API를 호출해 채워 넣습니다. 지금 기준으로 보면 "모델이 도구 호출을 쓰면 애플리케이션이 실행하고 결과를 대화에 붙이는" 구조가 이미 여기에 있습니다.

### 3. 과제에 따라 생각의 밀도를 다르게

- **지식 집약형 추론(HotpotQA, FEVER):** 매 단계 생각-행동-관찰을 번갈아 쓰는 "조밀한(dense) 생각"
- **의사결정(ALFWorld, WebShop):** 행동이 수십 단계로 길어지므로, 생각은 필요한 곳에만 "드문드문(sparse)" 나오게 하고 언제 생각할지는 모델이 정하게 합니다.

### 4. 행동 공간: 일부러 약하게 만든 위키백과 API

HotpotQA와 FEVER에서 쓴 도구는 세 가지뿐입니다.

| 행동 | 동작 |
|---|---|
| `search[entity]` | 해당 위키백과 문서의 첫 5문장을 반환. 없으면 비슷한 항목 상위 5개를 제안 |
| `lookup[string]` | 현재 문서에서 문자열이 들어간 다음 문장을 반환 (브라우저의 Ctrl+F 흉내) |
| `finish[answer]` | 답을 내고 과제를 끝냄 |

저자들은 이 API가 최신 어휘 기반·신경망 검색기보다 "훨씬 약하다"고 직접 밝힙니다. 목적은 사람이 위키백과를 쓰는 방식을 흉내 내고, 모델이 언어로 명시적으로 추론해야만 원하는 정보에 닿게 하는 것이었습니다.

### 5. 내부 지식과 외부 지식 섞기: ReAct ↔ CoT-SC

분석 결과 ReAct는 사실에 더 근거하고, CoT는 추론 구조를 더 정확히 짜지만 환각에 약했습니다. 그래서 둘을 휴리스틱으로 잇는 방법도 제안합니다.

- **ReAct → CoT-SC:** ReAct가 정해진 단계(HotpotQA 7단계, FEVER 5단계) 안에 답을 못 내면 CoT-SC로 넘어갑니다. CoT-SC(자기 일관성, self-consistency)는 CoT 풀이를 21개 샘플링(온도 0.7)해 다수결로 답을 고르는 방식입니다.
- **CoT-SC → ReAct:** n개 샘플 중 최다 답이 n/2번 미만이면, 즉 내부 지식에 확신이 없으면 ReAct로 넘어갑니다.

## 실험 설정

| 과제 | 종류 | 평가 지표 | 비교 대상 |
|---|---|---|---|
| HotpotQA | 2개 이상 위키백과 문단을 거쳐야 하는 다중 홉 질의응답 | 정확 일치(EM) | Standard, CoT, CoT-SC, Act(생각 없이 행동만) |
| FEVER | 주장(claim)의 참·거짓·정보 부족 판정 | 정확도 | 위와 동일 |
| ALFWorld | 텍스트로 집안을 돌아다니며 물건을 다루는 게임, 6가지 과제 유형, 미공개 평가 게임 134개 | 성공률 | BUTLER(과제 유형별 전문가 궤적 10^5개로 모방 학습) |
| WebShop | 실제 상품 118만 개, 사람 지시 1.2만 개의 쇼핑 사이트 환경, 테스트 지시 500개 | 점수, 성공률 | IL(사람 궤적 1,012개 모방 학습), IL+RL(지시 10,587개로 강화학습 추가) |

HotpotQA와 FEVER는 근거 문단을 주지 않고 질문만 주는 설정입니다. 모델은 내부 지식을 쓰거나 위키백과 API로 찾아야 합니다. 비교 대상 프롬프트는 ReAct 궤적에서 생각이나 행동을 지워서 만들었기 때문에 예시 선택이 같은 통제된 비교입니다.

## 주요 결과

### 1. 지식 추론: ReAct 단독은 CoT와 비슷, 결합하면 최고 (표 1)

PaLM-540B 프롬프팅 결과입니다.

| 방법 | HotpotQA (EM) | FEVER (정확도) |
|---|---|---|
| Standard | 28.7 | 57.1 |
| CoT | 29.4 | 56.3 |
| CoT-SC | 33.4 | 60.4 |
| Act | 25.7 | 58.9 |
| ReAct | 27.4 | 60.9 |
| CoT-SC → ReAct | 34.2 | **64.6** |
| ReAct → CoT-SC | **35.1** | 62.0 |
| 지도학습 최고 성능(참고) | 67.5 | 89.5 |

읽을 점은 세 가지입니다. ReAct는 두 과제 모두에서 Act보다 낫습니다. 즉 **생각이 행동을 이끄는 효과**가 있습니다. CoT와 비교하면 FEVER에서는 앞서지만(60.9 대 56.3) HotpotQA에서는 조금 뒤집니다(27.4 대 29.4). 그리고 두 결합 방식이 각각 한 과제씩 최고 성능을 냈습니다. 그림 2에 따르면 결합 방식은 CoT-SC 샘플을 3~5개만 써도 21개를 쓴 CoT-SC 성능에 도달합니다. 다만 모든 프롬프팅 방법이 지도학습 최고 성능과는 여전히 큰 차이가 있습니다.

### 2. CoT의 실패는 환각, ReAct의 실패는 추론 고리와 검색 (표 2)

저자들은 HotpotQA에서 ReAct와 CoT의 정답·오답 궤적을 50개씩, 총 200개를 무작위로 뽑아 직접 분류했습니다.

| 구분 | 유형 | ReAct | CoT |
|---|---|---|---|
| 성공 | 진짜 정답 (추론과 사실이 모두 맞음) | 94% | 86% |
| 성공 | 거짓 양성 (환각한 추론이나 사실로 맞힘) | 6% | 14% |
| 실패 | 추론 오류 (반복 루프에서 못 빠져나온 경우 포함) | 47% | 16% |
| 실패 | 검색 결과 오류 (빈 결과나 쓸모없는 결과) | 23% | - |
| 실패 | 환각 | 0% | 56% |
| 실패 | 레이블 모호성 (예측은 맞지만 정답 표기와 불일치) | 29% | 28% |

이 표가 논문의 핵심입니다. **CoT 실패의 56%가 환각인 반면 ReAct 실패에서 환각은 0%였습니다.** 대신 ReAct는 두 가지 새로운 약점을 보였습니다.

- **추론 오류 47%:** 생각-행동-관찰을 엄격히 번갈아야 하는 구조가 추론의 유연성을 떨어뜨립니다. 특히 같은 생각과 행동을 되풀이하며 루프에서 빠져나오지 못하는 패턴이 자주 나왔고, 저자들은 탐욕적 디코딩(greedy decoding) 탓일 수 있다고 추정합니다.
- **검색 결과 오류 23%:** 쓸모없는 검색 결과가 한 번 들어오면 추론이 탈선하고, 생각을 다시 세우기 어려워합니다.

저자들은 이것을 "사실성과 유연성 사이의 예상된 절충"으로 보고, 앞서 본 ReAct ↔ CoT-SC 결합의 근거로 씁니다.

### 3. 의사결정: 예시 1~2개로 학습 기반 방법을 큰 폭으로 앞서다 (표 3, 표 4)

ALFWorld 성공률(%)입니다.

| 방법 | Pick | Clean | Heat | Cool | Look | Pick 2 | 전체 |
|---|---|---|---|---|---|---|---|
| Act (6개 중 최고) | 88 | 42 | 74 | 67 | 72 | 41 | 45 |
| ReAct (평균) | 65 | 39 | 83 | 76 | 55 | 24 | 57 |
| ReAct (6개 중 최고) | 92 | 58 | 96 | 86 | 78 | 41 | **71** |
| ReAct-IM (6개 중 최고) | 62 | 68 | 87 | 57 | 39 | 33 | 53 |
| BUTLER (8개 중 최고) | 46 | 39 | 74 | 100 | 22 | 24 | 37 |

가장 좋은 ReAct 시도는 71%로 BUTLER(37%)보다 34%p 높습니다. 저자들은 가장 나쁜 ReAct 시도(48%)조차 Act와 BUTLER의 최고 시도를 넘었다고 강조합니다. 6번의 통제된 시도에서 ReAct의 Act 대비 상대 개선은 33~90%, 평균 62%였습니다.

WebShop 결과(표 4)는 다음과 같습니다.

| 방법 | 점수 | 성공률 |
|---|---|---|
| Act | 62.3 | 30.1 |
| ReAct | **66.6** | **40.0** |
| IL | 59.9 | 29.1 |
| IL+RL | 62.4 | 28.7 |
| 사람 전문가 | 82.1 | 59.6 |

원샷 Act만으로도 IL, IL+RL과 비슷했고, 드문드문 생각을 더한 ReAct는 이전 최고 성공률보다 약 10%p 높았습니다. 다만 사람 전문가(성공률 59.6%)와는 차이가 큽니다. 저자들은 사람이 상품을 훨씬 많이 탐색하고 검색어를 자주 고쳐 쓰는데, 이것이 프롬프트 기반 방법에 여전히 어렵다고 설명합니다.

### 4. "생각"의 내용이 중요하다: ReAct-IM 비교 (표 3)

가장 가까운 선행 연구인 Inner Monologue(IM)는 환경 상태와 남은 목표만 되뇌는 "내부 독백"을 씁니다. 저자들은 같은 궤적을 IM 방식의 조밀한 외부 피드백 생각으로 다시 주석 달아(ReAct-IM) 비교했고, ReAct가 71% 대 53%로 앞섰으며 6개 과제 중 5개에서 우위였습니다. ReAct-IM은 하위 목표가 끝났는지, 다음 하위 목표가 무엇인지 판단하는 데 자주 실패했고, 물건이 있을 법한 장소를 상식으로 추론하지 못했습니다. **단순히 관찰을 되풀이하는 것과 목표를 분해하고 상식을 끌어오는 생각은 다르다**는 결과입니다.

### 5. 작은 모델은 프롬프트로는 못 하지만, 3,000개로 미세조정하면 최고 (그림 3)

PaLM-8B와 62B에서는 프롬프팅만으로 ReAct가 네 방법 중 가장 나빴습니다. 퓨샷 예시만으로 추론과 행동을 동시에 배우기 어렵기 때문입니다. 그런데 ReAct가 생성한 정답 궤적 3,000개로 미세조정하자 상황이 뒤집혔습니다. 미세조정한 PaLM-8B ReAct가 PaLM-62B의 모든 프롬프팅 방법을 넘었고, 미세조정한 62B ReAct는 540B의 모든 프롬프팅 방법을 넘었습니다. 저자들은 Standard나 CoT를 미세조정하면 (환각일 수도 있는) 지식을 외우게 되지만, ReAct나 Act를 미세조정하면 위키백과에서 정보를 찾는 더 일반화 가능한 기술을 배운다고 해석합니다.

### 6. 부가 결과: GPT-3, 최신 정보, 사람의 생각 편집 (부록 A)

- **GPT-3에서도 동작 (표 5):** text-davinci-002(탐욕적 디코딩)는 HotpotQA 검증 질문 500개 부분집합에서 30.8(PaLM-540B 29.4), ALFWorld에서 78.4%(PaLM-540B 70.9%)였습니다. 이 표의 HotpotQA 수치는 500개 부분집합 기준이라 표 1(27.4)과 직접 비교되지 않습니다.
- **오래된 정답 레이블 (그림 4):** 호텔 객실 수를 묻는 질문에서 HotpotQA 레이블은 데이터셋 구축 이후 바뀐 옛 값이었고, ReAct만 실제 웹 상호작용으로 최신 값을 찾았습니다.
- **사람이 생각을 고쳐 행동을 바꾸기 (그림 5):** ALFWorld에서 환각이 들어간 생각 한 줄을 지우고 힌트 한 줄을 넣는 것만으로 실패하던 궤적이 성공했습니다. 행동 수십 개를 직접 입력하는 대신 생각 두 개만 고치면 된다는 점에서, 저자들은 새로운 사람-기계 협업 방식으로 봅니다.

## 한계

**저자가 밝힌 한계**

- 행동 공간이 큰 복잡한 과제일수록 예시가 더 필요한데, 이는 인컨텍스트 학습(in-context learning)의 입력 길이 한계를 쉽게 넘습니다.
- 모든 프롬프팅 방법이 지도학습 최고 성능에 한참 못 미칩니다. 저자들은 사람이 쓴 고품질 데이터로 미세조정하는 것이 더 나은 길일 수 있다고 봅니다.
- 반복 루프 오류는 디코딩 방식의 한계일 수 있으며, 빔 탐색(beam search) 같은 더 나은 디코딩을 후속 과제로 남겼습니다.
- 윤리 성명에서 LLM에 외부 환경과 상호작용하는 행동 공간을 붙이면 부적절하거나 사적인 정보를 찾아보거나 해로운 행동을 할 위험이 있다고 경고합니다. 실험은 사적 정보가 없는 위키백과와 WebShop으로 한정했고, 실제로 구매하거나 문서를 편집하는 행동은 넣지 않았습니다.

**읽으면서 발견한 한계 (필자의 판단)**

- 표 2의 오류 분석은 200개 표본을 사람이 분류한 결과입니다. 비율이 강한 신호이긴 하지만, 표본이 작고 분류 기준(예: "추론 오류"에 반복 루프를 넣는 것)에 판단이 들어갑니다.
- HotpotQA에서 ReAct 단독은 CoT보다 낮았습니다. "추론과 행동을 섞으면 항상 낫다"가 아니라, 도구가 약하면 오히려 손해일 수 있다는 결과로 읽는 것이 정확합니다. 논문이 일부러 약한 위키백과 API를 쓴 만큼, 더 좋은 검색기를 썼다면 결과가 어땠을지는 이 논문만으로 알 수 없습니다.
- 주 실험 모델 PaLM-540B가 공개되지 않아 외부에서 같은 수치를 재현할 수는 없습니다. 공식 저장소 README의 GPT-3 결과(HotpotQA 30.4, FEVER 54 등)도 논문 표 5와 평가 부분집합, 지표가 조금씩 달라 그대로 비교하기 어렵습니다(2026-10-24 확인).

## 인사이트

**왜 지금 중요한가: 오늘날 에이전트 루프의 원형.** 지금 주요 API 문서가 설명하는 도구 호출 흐름은 ReAct 궤적과 모양이 같습니다. OpenAI 함수 호출 가이드는 "도구와 함께 요청 → 모델의 도구 호출 수신 → 애플리케이션에서 실행 → 결과와 함께 다시 요청 → 최종 응답(또는 더 많은 도구 호출)"의 5단계를 제시하고, Anthropic 문서는 이를 `stop_reason`이 `"tool_use"`인 동안 도는 `while` 루프로 설명합니다. ReAct의 Action이 도구 호출, Observation이 도구 결과에 해당합니다. 다만 2026년 10월의 공식 문서와 비교하면 무엇이 바뀌었는지가 더 흥미롭습니다.

| 측면 | ReAct (2022) | 지금의 함수 호출 (공식 문서 기준, 2026-10-24 확인) |
|---|---|---|
| 행동 형식 | `Search[Milhouse]` 같은 자유 텍스트를 프로그램이 파싱 | JSON Schema로 정의한 도구, 구조화된 `tool_use`·`function_call` 블록. strict 모드로 스키마 준수를 보장(Anthropic은 이를 문법 제약 샘플링이라고 설명) |
| 생각 | 프롬프트 안의 보이는 텍스트 `Thought` | 추론 모델의 사고 블록. Anthropic은 도구 호출 사이에서 생각하는 interleaved thinking을 지원하고, OpenAI는 도구 호출과 함께 나온 reasoning 항목을 결과와 함께 되돌려 보내라고 요구 |
| 도구 사용 능력의 출처 | 퓨샷 예시 6개 이하 | 학습으로 내장. OpenAI는 함수 정의가 "모델이 학습한 문법으로" 시스템 메시지에 주입된다고 설명하고, Anthropic은 bash, text_editor 같은 스키마를 수천 개의 성공 궤적으로 최적화했다고 설명 |
| 한 단계의 행동 수 | 1개 | 병렬 도구 호출이 기본값(Anthropic), 지원 모델에서 병렬 호출 가능(OpenAI) |
| 종료 조건 | `finish[answer]` 또는 최대 단계 수(7·5단계) 후 CoT-SC로 후퇴 | `stop_reason`, 최종 텍스트 응답 |

이 중 세 번째 줄은 ReAct 논문이 이미 예고한 방향이기도 합니다. 그림 3에서 프롬프팅으로는 가장 나빴던 작은 모델이 궤적 3,000개 미세조정으로 최고가 됐고, 저자들은 결론에서 "더 많은 사람 주석으로 학습하는 것"을 다음 단계로 꼽았습니다. 지금 공급자들이 도구 사용을 학습 단계에 넣은 것은 이 결론의 연장선으로 볼 수 있습니다. 학습 방식으로 도구 사용을 가르친 같은 시기의 대표 연구는 [Toolformer 소개](/papers/2026/10/24/toolformer.html)에서 다뤘습니다.

**실무에 주는 의미: 표 2를 에이전트 디버깅 체크리스트로 읽기.** 표 2의 실패 유형은 지금 에이전트에서도 그대로 보입니다. 첫째, **도구 결과의 품질이 곧 에이전트의 품질**입니다. ReAct 실패의 23%가 쓸모없는 검색 결과에서 시작했습니다. Anthropic의 도구 정의 가이드가 "다음 단계를 추론하는 데 필요한 필드만 담은, 신호가 높은 응답"을 돌려주라고 권하는 것과 같은 이야기입니다. 도구 설명을 다듬기 전에 도구가 무엇을 돌려주는지부터 점검하는 편이 효과가 클 수 있습니다. 둘째, **반복 루프는 오래된 문제**입니다. 같은 검색을 되풀이하는 에이전트를 보면, 최대 단계 수, 같은 호출의 반복 감지, 실패 시 다른 전략으로 넘어가는 장치를 하네스(harness, 모델을 감싸 실행하는 코드)에 두는 것이 ReAct 시절부터의 처방입니다. ReAct가 단계 한도를 넘으면 CoT-SC로 넘어간 것도 같은 발상입니다. 셋째, **내부 지식과 외부 도구의 경계를 정하는 것**도 설계 대상입니다. ReAct ↔ CoT-SC 결합은 "모델이 확신할 때는 기억으로, 아닐 때는 도구로"라는 규칙을 휴리스틱으로 구현한 것인데, 지금은 이 판단이 `tool_choice: "auto"` 아래 모델에게 넘어갔습니다. Anthropic 문서도 시스템 프롬프트 한 줄로 도구 사용 빈도를 조절할 수 있다고 설명하므로, 이 경계는 여전히 사람이 조정해야 하는 값입니다.

**블로그의 기존 글과의 연결.** [LiveMACE 소개](/papers/2026/10/20/livemace.html)에서 다룬 벤치마크는 "공통 ReAct 에이전트"를 기본 구조로 두고 도구 사용, 기억, 규칙 준수, 협업 메커니즘을 하나씩 붙여 비교했습니다. ReAct가 4년 뒤 연구에서 "더 이상 비교 대상이 아닌, 당연한 바탕"이 됐다는 뜻입니다. LiveMACE가 도구를 찾는 단계와 실행하는 단계의 실패가 서로 독립적이라고 보고한 것도, ReAct 표 2의 "추론 오류"와 "검색 결과 오류"를 더 잘게 나눈 분석으로 읽을 수 있습니다.

**한계와 반론.** ReAct가 원형인 것은 맞지만, "생각을 보여 주니 해석 가능하고 믿을 만하다"는 주장은 조심해서 받아들일 필요가 있습니다. 논문의 해석 가능성은 사람이 궤적을 읽고 고칠 수 있다는 정성적 사례(그림 5)에 기대고 있고, 보이는 생각이 실제 행동의 원인인지는 검증하지 않았습니다. 지금은 생각이 별도의 사고 블록으로 옮겨 가고 일부 모델에서는 요약이나 생략된 형태로만 돌아오므로, ReAct 시절처럼 생각을 직접 고쳐 행동을 바꾸는 방식이 그대로 통한다고 보기도 어렵습니다. 또한 ALFWorld와 WebShop은 행동이 되돌릴 수 있고 피해가 없는 환경입니다. 저자들이 윤리 성명에서 경고한 대로, 실제 결제나 삭제가 걸린 도구에서는 성공률보다 잘못된 한 번의 행동이 더 중요해집니다.

**앞으로 지켜볼 점.** (1) 사고가 모델 내부로 들어간 뒤에도 ReAct가 보여 준 "생각을 사람이 검사하고 교정하는" 장점을 어떻게 지킬지. 진행 상황을 사람에게 보여 주는 요약 같은 기능이 그 대안이 될지 볼 만합니다. (2) 표 2의 반복 루프와 검색 실패가 최신 모델에서 얼마나 줄었는지를 같은 방식으로 분류한 공개 분석이 나오는지. (3) ReAct 위에 기억과 반성을 더한 후속 연구들(예: ALFWorld 134개 과제 중 130개를 푼 ReAct + Reflexion)이 실무 하네스의 기본 기능으로 흡수되는지.
